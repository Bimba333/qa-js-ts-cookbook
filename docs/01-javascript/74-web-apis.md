> Кто выполняет асинхронную работу?

Короткий ответ: JavaScript делегирует долгую работу среде выполнения через API.

## Теория

### Язык и среда выполнения — разные вещи

Нужно различать:

| Что это | Примеры | Кто предоставляет |
| --- | --- | --- |
| язык JavaScript | переменные, функции, объекты, Promise | спецификация языка |
| API среды выполнения | `setTimeout`, `fetch`, DOM, файловая система | браузер или Node.js |

Web APIs — это возможности браузерной среды выполнения, доступные JavaScript-коду в браузере. Node.js предоставляет собственные API среды выполнения. Общая идея одна: JavaScript получает дополнительные возможности от среды, в которой выполняется.

Практическое следствие: код, работающий в браузере, может не работать в Node — и наоборот. Обращение к `document` в Node даёт ошибку не потому, что язык сломан, а потому, что такого API в этой среде нет.

### Кто на самом деле ждёт

Это главная мысль главы, объясняющая асинхронность до конца.

Движок JavaScript однопоточен и ничего не ждёт. Когда код вызывает `setTimeout()`, отсчёт времени ведёт **среда выполнения** — не движок. Пока она считает, движок занят обычным выполнением кода.

То же с сетевым запросом: соединение, передачу и получение ответа обслуживает среда. JavaScript получает только момент готовности.

В этой главе `fetch()` упоминается только как пример API среды выполнения. Подробная работа сетевых запросов будет изучаться отдельно.

### Разделение обязанностей

| Кто | Что делает |
| --- | --- |
| движок JavaScript | выполняет код, ведёт Call Stack |
| среда выполнения | ведёт отсчёт, обслуживает сеть и события |
| Event Loop | переносит готовые продолжения в стек |

Эта таблица закрывает вопрос «как однопоточный язык делает несколько дел»: он их не делает — их делает среда, а язык обрабатывает результаты по одному.

## Внутренний механизм

### Что происходит при вызове `setTimeout()`

1. движок вызывает API среды выполнения и передаёт ему функцию и задержку;
2. среда регистрирует таймер и **сразу возвращает управление**;
3. движок продолжает выполнять следующие строки;
4. когда задержка истекла, среда кладёт функцию в очередь макрозадач;
5. Event Loop переносит её в Call Stack, как только тот освободится.

Важно: шаг 4 — это попадание **в очередь**, а не выполнение. Между истечением задержки и фактическим вызовом может пройти сколько угодно времени, если стек занят.

### Параллельна среда, а не ваш код

Это не означает, что весь JavaScript-код выполняется параллельно. Асинхронная часть передаётся среде выполнения, а сам обратный вызов выполнится позже в обычном JavaScript-выполнении.

Проверить это просто: сто одновременных таймеров действительно отсчитываются одновременно — но сто их колбэков выполнятся по одному, друг за другом, когда освободится стек.

### Node.js и браузер: одна модель, разные API

Набор API различается, но схема одна:

| Задача | Браузер | Node.js |
| --- | --- | --- |
| отложить выполнение | `setTimeout` | `setTimeout` |
| сетевой запрос | `fetch`, `XMLHttpRequest` | `fetch`, модули HTTP |
| работа с интерфейсом | DOM | нет |
| файлы | ограниченно | файловая система |

Для автотестов это различие практическое: код тестового раннера выполняется в Node, а код страницы — в браузере, и доступные им API разные. Именно поэтому в главах про Playwright обращение к `document` возможно только внутри выполнения на странице.

## Распространённые мифы

**Миф: `setTimeout` — часть языка JavaScript.**
Это API среды выполнения. Язык описывает синтаксис и объекты, а таймеры даёт браузер или Node.

**Миф: движок ведёт отсчёт времени.**
Отсчёт ведёт среда. Движок в это время выполняет обычный код.

**Миф: истечение задержки означает выполнение колбэка.**
Он попадает в очередь. Выполнение произойдёт, когда освободится стек.

**Миф: много таймеров — много параллельного JavaScript.**
Параллельно идёт отсчёт. Колбэки выполняются по одному.

**Миф: код одинаково работает в браузере и в Node.**
Набор API разный: `document` есть только в браузере, файловая система — только в Node.

## Частые вопросы

**Почему `document is not defined` в Node?**
DOM — браузерный API. В Node его нет.

**Кто ждёт во время сетевого запроса?**
Среда выполнения. Движок в это время свободен для другого кода.

**Почему колбэк таймера выполнился позже заявленной задержки?**
Он ждал в очереди, пока стек не освободился.

**Значит ли асинхронность, что кода выполняется больше одновременно?**
Нет. Одновременно работает среда, а JavaScript обрабатывает результаты по одному.

**Где проходит граница между языком и средой?**
Язык — синтаксис, типы, объекты. Среда — таймеры, сеть, интерфейс, файлы.

## Распространённые ошибки

### Ошибка 1. Считать `setTimeout()` частью языка JavaScript

`setTimeout()` предоставляет среда выполнения. JavaScript-код только вызывает этот API.

### Ошибка 2. Думать, что Web APIs выполняют тело обратного вызова вместо JavaScript

Среда выполнения ожидает событие. Тело функции выполняется позже как JavaScript-код.

### Ошибка 3. Не различать JavaScript Engine и среду выполнения

Engine выполняет JavaScript-код. Среда выполнения предоставляет дополнительные API и инфраструктуру.

Web APIs объясняют, кто занимается долгими асинхронными задачами.
