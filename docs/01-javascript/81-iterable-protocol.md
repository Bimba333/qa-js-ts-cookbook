# Iterable Protocol

## Связь с предыдущей главой

Предыдущий модуль завершил практическую асинхронную часть:

Теперь мы возвращаемся к данным. В JavaScript часто нужно пройти по набору значений: тестам, логам, артефактам, строкам отчета.

Но не все значения обходятся одинаково.

## Главный вопрос

> Почему `for...of` работает с массивами, но не работает с обычными объектами?

Короткий ответ: `for...of` работает с iterable-объектами. Объект считается iterable, если он знает, как начать итерацию через `Symbol.iterator`.

## Мотивация

В тестовом фреймворке есть набор тест-кейсов:

```javascript
const testCases = [
  'login test',
  'checkout test',
  'report test',
];
```

По массиву можно пройти:

```javascript
for (const testCase of testCases) {
  console.log(testCase);
}
```

Но если данные лежат в обычном объекте:

```javascript
const testSuite = {
  smoke: 'login test',
  regression: 'checkout test',
};
```

`for...of` напрямую не знает, с чего начать и какой порядок использовать.

## Теория

Iterable Protocol — это соглашение JavaScript.

Объект является iterable, если у него есть метод с ключом `Symbol.iterator`.

Iterable не выдает значения самостоятельно.

Он предоставляет JavaScript способ получить iterator, который затем возвращает значения по одному.

`for...of` не спрашивает: "Это массив?"

Он спрашивает:

Встроенные iterable-объекты:

* Array;
* String;
* Map;
* Set.

```javascript
for (const letter of 'QA') {
  console.log(letter);
}
```

Строка не массив, но она iterable. Поэтому `for...of` может пройти по ее символам.

### `for...of` спрашивает о протоколе, а не о типе

`for...of` не спрашивает: «Это массив?» Он спрашивает: **«Есть ли у объекта метод с ключом `Symbol.iterator`?»**

Проверяется это легко:

```javascript
const plain = { a: 1 };
for (const v of plain) { }   // TypeError: plain is not iterable
```

Обычный объект не iterable — у него нет `Symbol.iterator`. Именно поэтому по объекту нельзя пройти через `for...of`, хотя по массиву и строке можно.

Чтобы обойти свойства объекта, их сначала превращают в iterable:

```javascript
Object.entries({ a: 1, b: 2 });   // [['a', 1], ['b', 2]] — массив, а значит iterable
```

### Свой iterable пишется в несколько строк

Протокол открыт: любой объект можно сделать пригодным для `for...of`, добавив нужный метод.

```javascript
const range = {
  from: 1,
  to: 3,
  [Symbol.iterator]() {
    let current = this.from;
    const to = this.to;
    return {
      next: () => current <= to
        ? { value: current++, done: false }
        : { value: undefined, done: true },
    };
  },
};

[...range];   // [1, 2, 3]
```

Это не трюк, а обычный механизм языка: встроенные коллекции устроены так же.

### Протокол используют не только циклы

Один и тот же протокол задействован везде, где значения берутся «по одному»:

| Конструкция | Требует iterable |
| --- | --- |
| `for...of` | да |
| spread `[...value]` | да |
| деструктуризация массива | да |
| `Array.from()` | да |
| `Promise.all([...])` | да |
| `new Map()`, `new Set()` | да |

Поэтому `[...{ a: 1 }]` даёт ту же ошибку, что и `for...of`: spread тоже работает через протокол. А `[...'QA']` возвращает `['Q', 'A']`, потому что строка iterable.

Знание протокола объясняет сразу весь этот набор конструкций, а не каждую по отдельности.

### Iterable не хранит состояние обхода

Iterable не выдаёт значения самостоятельно. Он предоставляет JavaScript способ получить iterator, который затем возвращает значения по одному.

Разделение существенно: iterable можно обходить многократно, потому что каждый обход получает **новый** итератор. Проверено — два вызова `Symbol.iterator` у одного массива дают независимые итераторы, и каждый начинает сначала.

Подробности того, как устроен сам итератор, — в следующей главе.

## Распространённые мифы

**Миф: `for...of` работает с любым объектом.**
Только с iterable. Обычный объект даёт `TypeError: not iterable`.

**Миф: iterable — это про массивы.**
Это соглашение: строка, `Map`, `Set` и любой ваш объект с `Symbol.iterator` тоже iterable.

**Миф: spread и `for...of` устроены по-разному.**
Оба используют один протокол, поэтому и ошибки у них одинаковые.

**Миф: iterable сам выдаёт значения.**
Он возвращает итератор, а значения выдаёт уже тот.

**Миф: обойти iterable можно только один раз.**
Каждый обход получает новый итератор и начинает сначала.

## Частые вопросы

**Почему `for...of` не работает с объектом?**
У него нет `Symbol.iterator`. Нужны `Object.keys()`, `Object.values()` или `Object.entries()`.

**Как сделать свой объект пригодным для `for...of`?**
Добавить метод `[Symbol.iterator]()`, возвращающий итератор.

**Почему spread даёт ту же ошибку, что и цикл?**
Он тоже работает через протокол iterable.

**Какие встроенные типы являются iterable?**
Array, String, Map, Set и ещё несколько — все, где есть `Symbol.iterator`.

**Можно ли обойти один iterable дважды?**
Да, если он выдаёт новый итератор на каждый обход.

## Распространённые ошибки

### Ошибка 1. Думать, что `for...of` работает с любым объектом

Обычный объект не становится iterable автоматически.

### Ошибка 2. Путать iterable и массив

Массив iterable, но не каждый iterable является массивом.

### Ошибка 3. Искать порядок обхода там, где он не задан

Если объект не описывает правило итерации, `for...of` не должен угадывать порядок.

## Краткие итоги

Iterable Protocol объясняет, почему одни значения можно обходить через `for...of`, а другие нельзя.

Главное:

* iterable-объект знает, как начать итерацию;
* `Symbol.iterator` является точкой входа в обход;
* Array, String, Map и Set уже являются iterable;
* обычный объект не становится iterable автоматически;
* `for...of` работает не с "массивностью", а с наличием правила итерации.
