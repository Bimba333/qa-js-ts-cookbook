# Iterators

## Связь с предыдущей главой

Предыдущая глава показала:

Но начать обход недостаточно. JavaScript должен получать значения одно за другим.

## Главный вопрос

> Что на самом деле происходит внутри `for...of`?

Короткий ответ: `for...of` получает iterator и вызывает у него `next()`.

## Мотивация

Представим набор тестов:

```javascript
const testCases = ['login', 'checkout', 'report'];
```

`for...of` выводит значения последовательно:

```text
login
checkout
report
```

Но JavaScript не получает весь результат сразу. Он спрашивает по одному: «следующее значение есть?» — и получает либо значение, либо признак завершения.

## Теория

Iterator — это объект, который умеет возвращать следующий результат итерации.

У iterator есть метод `next()`.

`next()` возвращает объект вида:

```javascript
{
  value: 'login',
  done: false
}
```

Где:

* `value` — текущее значение;
* `done` — закончилась ли итерация.

Когда значения закончились:

```javascript
{
  value: undefined,
  done: true
}
```

### Как выглядит обход на самом деле

Итератор можно получить и использовать вручную — это то, что `for...of` делает за вас:

```javascript
const it = ['a', 'b'][Symbol.iterator]();

it.next();   // { value: 'a', done: false }
it.next();   // { value: 'b', done: false }
it.next();   // { value: undefined, done: true }
```

Обратите внимание на последний вызов: `done: true` приходит **отдельным** шагом, уже без значения. Именно поэтому цикл выполняет тело ровно два раза, а `next()` вызывается три.

### Итератор одноразовый

Ключевое отличие от iterable: итератор хранит состояние обхода и не перезапускается.

```javascript
it.next();   // { done: true } — и так будет всегда
```

Исчерпанный итератор навсегда остаётся исчерпанным. Новый обход требует нового итератора — и его выдаёт iterable, как показано в предыдущей главе. Два вызова `Symbol.iterator` у одного массива дают независимые итераторы, каждый со своим состоянием.

Отсюда практическое правило: iterable можно передавать и обходить многократно, итератор — нет.

### Итератор сам является iterable

Небольшая, но полезная деталь: встроенные итераторы имеют собственный `Symbol.iterator`, возвращающий самих себя.

```javascript
typeof it[Symbol.iterator] === 'function';   // true
```

Благодаря этому итератор можно передать в `for...of` напрямую. Но помните про одноразовость: такой обход продолжится с текущей позиции и завершится навсегда.

### `break` сообщает итератору о прерывании

Протокол предусматривает необязательный метод `return()` — его вызывают, когда обход прекращают досрочно:

```javascript
for (const v of source) {
  if (v === 2) break;   // здесь вызовется source-итератор.return()
}
```

Проверено: при `break` метод `return()` итератора действительно вызывается. Это механизм освобождения ресурсов — итератор, читающий файл или соединение, получает шанс закрыть их.

Для обычных массивов это незаметно, но объясняет, почему досрочный выход из цикла безопасен и для «тяжёлых» источников данных.

### Зачем это знать

Прямая работа с итераторами в прикладном коде встречается редко. Но модель объясняет вещи, которые иначе выглядят несвязанными:

- почему `for...of` работает с любым iterable одинаково;
- почему генераторы из следующей главы вписываются в тот же цикл;
- почему обход коллекции можно приостановить и продолжить;
- почему исчерпанный источник данных не начинает сначала.

## Главная ментальная модель

Главная модель главы: **итератор хранит позицию обхода и выдаёт по одному значению, пока не сообщит `done: true`**.

Iterator похож на выдачу тест-кейсов из очереди: за один запрос выдается только один следующий элемент.

## Распространённые мифы

**Миф: `done: true` приходит вместе с последним значением.**
Это отдельный вызов `next()` уже без значения.

**Миф: исчерпанный итератор можно перезапустить.**
Нельзя. Нужен новый итератор от iterable.

**Миф: iterable и iterator — синонимы.**
Первый умеет выдавать итераторы, второй хранит состояние конкретного обхода.

**Миф: `break` просто прекращает цикл.**
Он ещё и вызывает `return()` итератора, давая источнику закрыть ресурсы.

**Миф: итератор нельзя передать в `for...of`.**
Можно: встроенные итераторы сами являются iterable. Но обход будет одноразовым.

## Частые вопросы

**Сколько раз вызовется `next()` для массива из двух элементов?**
Три: два со значениями и один с `done: true`.

**Почему повторный обход дал пустой результат?**
Обходили итератор, а не iterable: он уже был исчерпан.

**Зачем нужен метод `return()`?**
Чтобы источник данных мог освободить ресурсы при досрочном выходе из цикла.

**Как получить итератор вручную?**
Вызвать `value[Symbol.iterator]()`.

**Где это встречается на практике?**
В генераторах, потоковых источниках данных и всюду, где значения выдаются по одному.

## Распространённые ошибки

### Ошибка 1. Думать, что iterator — это сам массив

Iterator не хранит весь массив как новая коллекция. Он хранит процесс последовательного получения значений.

### Ошибка 2. Игнорировать `done`

Если не смотреть на `done`, можно пытаться работать с `undefined` как с реальным значением.

### Ошибка 3. Считать `value` всегда полезным

Когда `done: true`, значение завершения обычно не используется в обычном обходе.

## Краткие итоги

Iterator объясняет, как значения появляются одно за другим.

Главное:

* iterable начинает обход;
* iterator продолжает обход;
* `next()` возвращает объект `{ value, done }`;
* `done: false` означает, что значение есть;
* `done: true` означает, что обход завершен.
