В тестовом фреймворке после выполнения теста могут быть готовы две задачи:

Сохранение результата часто должно произойти как можно раньше после текущего кода, до более крупных отложенных задач вроде таймера.

Для таких продолжений используется очередь Microtasks.

## Теория

### Задачи с приоритетом

Microtasks — это задачи с высоким приоритетом, которые выполняются после завершения текущего синхронного кода и перед macrotasks.

К Microtasks относятся:

```text
обработчики Promise
queueMicrotask()
```

Здесь обработчики Promise означают функции, переданные в `then()` и `catch()`. Подробные внутренние состояния Promise не нужны для этой главы.

`Promise.then()` и `queueMicrotask()` оба планируют работу в microtask queue, хотя обычно используются для разных задач. Внутренние различия их реализации в этой главе не нужны.

### Базовый порядок

| Очередь | Когда выполняется |
| --- | --- |
| текущий синхронный код | сейчас, до конца |
| microtasks | сразу после него, **вся очередь целиком** |
| macrotasks | после того, как микрозадач не осталось |

Слова «вся очередь целиком» — самая важная часть. Event Loop не берёт одну микрозадачу и не переходит к таймеру: он опустошает очередь полностью.

### Приоритет проверяется

```javascript
const order = [];
setTimeout(() => order.push('таймер'), 0);
Promise.resolve()
  .then(() => { order.push('микро 1'); return Promise.resolve(); })
  .then(() => order.push('микро 2'));
```

Результат: `['микро 1', 'микро 2', 'таймер']`.

Обратите внимание на вторую микрозадачу: она была **создана** уже во время обработки очереди — и всё равно выполнилась раньше таймера, который стоял в очереди дольше. Микрозадачи, порождённые микрозадачами, обрабатываются в том же проходе.

### Чем это опасно

Отсюда следует неприятная возможность: бесконечно порождая микрозадачи, можно полностью заблокировать макрозадачи.

```javascript
function loop() {
  Promise.resolve().then(loop);   // очередь микрозадач никогда не опустеет
}
```

Такой код не нагружает процессор бесконечным циклом в привычном смысле, но таймеры и события перестают выполняться совсем. Это редкий случай, однако он хорошо объясняет, почему приоритет микрозадач — не просто «чуть раньше».

### Почему приоритет вообще нужен

Микрозадачи предназначены для завершения текущей логической операции. Когда Promise разрешается, его обработчики логически принадлежат тому же «моменту», что и разрешение: нежелательно, чтобы между ними успел выполниться таймер или обработчик события.

Это даёт предсказуемость: цепочка `.then()` отрабатывает целиком, не перемежаясь посторонними задачами.

## Внутренний механизм

Упрощённая схема прохода:

```text
1. выполнить текущий синхронный код до конца
2. опустошить очередь микрозадач целиком
3. взять одну макрозадачу
4. вернуться к шагу 2
```

Пример:

```javascript
console.log('start');

setTimeout(function timer() {
  console.log('timer');
}, 0);

Promise.resolve().then(function promiseHandler() {
  console.log('promise');
});

console.log('finish');
```

Порядок:

```text
start
finish
promise
timer
```

`promise` выводится раньше `timer`, потому что обработчик Promise попадает в microtask queue.

## Главная ментальная модель

Главная модель главы: **микрозадачи завершают текущую логическую операцию и выполняются раньше любых отложенных задач**.

```text
синхронный код → ВСЕ микрозадачи → одна макрозадача
```

## Распространённые мифы

**Миф: микрозадачи выполняются «чуть быстрее».**
Дело не в скорости, а в приоритете: вся их очередь опустошается до первой макрозадачи.

**Миф: Event Loop берёт по одной микрозадаче между таймерами.**
Он обрабатывает очередь целиком, включая задачи, порождённые в процессе.

**Миф: микрозадача, созданная позже таймера, выполнится после него.**
Она выполнится раньше: приоритет важнее времени постановки.

**Миф: микрозадачами нельзя заблокировать программу.**
Можно: бесконечное порождение микрозадач не даёт выполниться ни одной макрозадаче.

**Миф: `queueMicrotask()` и `then()` принципиально различаются.**
Оба планируют работу в одну и ту же очередь.

## Частые вопросы

**Что выполнится раньше — `then()` или `setTimeout(fn, 0)`?**
Обработчик Promise: микрозадачи имеют приоритет.

**Выполнится ли микрозадача, созданная внутри микрозадачи, в том же проходе?**
Да. Очередь обрабатывается до полного опустошения.

**Зачем микрозадачам приоритет?**
Чтобы логически связанная работа завершилась целиком, не перемежаясь посторонними задачами.

**Можно ли «зависнуть» на микрозадачах?**
Да, если порождать их бесконечно: макрозадачи перестанут выполняться.

**Когда использовать `queueMicrotask()`?**
Когда нужно отложить работу до конца текущего синхронного кода, но выполнить её раньше таймеров.

## Распространённые ошибки

### Ошибка 1. Думать, что Promise выполняется параллельно с текущей строкой

Обработчик Promise не прерывает текущий синхронный код. Он выполняется после освобождения Call Stack.

### Ошибка 2. Ожидать, что таймер всегда идет раньше Promise

Даже если `setTimeout()` написан раньше, Microtasks имеют приоритет после текущего кода.

### Ошибка 3. Считать `queueMicrotask()` заменой таймера

`queueMicrotask()` планирует короткую задачу с высоким приоритетом, а не задержку по времени.

Microtasks объясняют, почему некоторые отложенные действия выполняются раньше таймеров.

* обработчики `then()` и `catch()` относятся к Microtasks;
