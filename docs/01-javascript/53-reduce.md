# reduce()

## Связь с предыдущей главой

Предыдущая глава объяснила `filter()`.

Главная модель была такой: `filter()` отбирает элементы и возвращает массив, сохраняя их форму.

`filter()` выбирает часть elements.

Теперь появляется новая задача: не получить array, а вычислить один итог по всему списку.

## Главный вопрос

> Как агрегировать множество значения в один result?

Ответ этой главы: использовать `reduce()`.

## Предварительные требования

Для этой главы нужно понимать:

* что array method может проходить по каждому element;
* что callback может возвращать value;
* что `map()` возвращает transformed array;
* что `filter()` возвращает subset array;
* что report может быть одним итоговым object или number.

Не требуется знать следующие array methods или сложные accumulator patterns. Они будут изучаться позже.

## Цели обучения

После главы вы будете понимать:

* зачем существует `reduce()`;
* что такое accumulator;
* что такое initial value;
* как каждый element влияет на итог;
* почему result может быть number, string, object или array;
* как собирать summary для Automation QA report.

## Мотивация

Есть test cases:

```javascript
const testCases = [
  { id: 'T-1', title: 'login smoke', status: 'passed', priority: 'high' },
  { id: 'T-2', title: 'create order', status: 'failed', priority: 'high' },
  { id: 'T-3', title: 'pay order', status: 'passed', priority: 'medium' },
  { id: 'T-4', title: 'logout smoke', status: 'skipped', priority: 'low' },
];
```

Нужно получить один summary:

```javascript
{
  passed: 2,
  failed: 1,
  skipped: 1
}
```

Это уже не transformation каждого element и не selection subset.

Нужна операция, которая постепенно собирает один итог: берёт накопленное значение, текущий элемент и возвращает новое накопленное значение.

## Теория

### Перенос промежуточного результата

`reduce()` проходит по array и переносит промежуточный результат от шага к шагу.

```javascript
const result = array.reduce(function (accumulator, element, index) {
  return nextAccumulator;
}, initialValue);
```

| Часть | Что означает |
| --- | --- |
| `accumulator` | результат, накопленный к этому шагу |
| `element` | текущий элемент массива |
| `initialValue` | начальное состояние накопления |
| возвращаемое значение | accumulator для следующего шага |

Главное отличие от `map()` и `filter()`: те возвращают массив, а `reduce()` — **одно** значение любой формы. Этим значением может быть число, строка, объект или снова массив.

### `initialValue` задаёт не только старт, но и тип

Начальное значение определяет, с чем работает первый вызов callback. Если его не передать, поведение меняется заметно:

```javascript
[10, 20, 30].reduce((acc, x, i) => acc + x, 0);
// вызовы: (0,10,0) (10,20,1) (30,30,2) — три вызова

[10, 20, 30].reduce((acc, x, i) => acc + x);
// вызовы: (10,20,1) (30,30,2) — два вызова, обход начинается со второго элемента
```

Без `initialValue` первый элемент становится начальным accumulator, а обход начинается со второго. Для суммы чисел разницы почти нет, а для накопления объекта она принципиальна: аккумулятором окажется элемент массива, а не пустой объект.

### Пустой массив и отсутствие начального значения

Комбинация «пустой массив без `initialValue`» — ошибка времени выполнения:

```text
TypeError: Reduce of empty array with no initial value
```

С начальным значением тот же вызов спокойно вернёт его: `[].reduce((a, x) => a + x, 0)` даст `0`.

Практическое правило: `initialValue` передают всегда, кроме случаев, когда массив заведомо непуст и первый элемент действительно годится как старт.

## Внутренний механизм

### Концептуальные шаги

1. взять `initialValue` как текущий accumulator (или первый элемент, если значение не передано);
2. вызвать callback с текущим accumulator и текущим элементом;
3. результат вызова сделать новым accumulator;
4. повторить для следующего элемента;
5. когда элементы закончились — вернуть accumulator.

Вся работа сводится к одному вопросу на каждом шаге: как текущий элемент меняет accumulator.

### Трассировка накопления

Для подсчёта статусов прогона:

```javascript
['pass', 'fail', 'pass'].reduce((acc, status) => ({
  ...acc,
  [status]: (acc[status] ?? 0) + 1,
}), {});
// { pass: 2, fail: 1 }
```

| Шаг | accumulator до | элемент | accumulator после |
| --- | --- | --- | --- |
| 1 | `{}` | `pass` | `{ pass: 1 }` |
| 2 | `{ pass: 1 }` | `fail` | `{ pass: 1, fail: 1 }` |
| 3 | `{ pass: 1, fail: 1 }` | `pass` | `{ pass: 2, fail: 1 }` |

Каждый вызов получает текущий accumulator и возвращает следующий — этого достаточно для основной модели.

### Возврат обязателен

Callback без `return` вернёт `undefined`, и оно станет accumulator для следующего шага — дальше всё сломается тихо. Это та же ловушка, что у `map()` из главы 51, но последствия хуже: ошибка не в одном элементе, а во всей цепочке накопления.

## Главная ментальная модель

Главная модель этой главы: **вход → единственный накопленный результат**.

Ключевой вопрос при чтении `reduce()`: как текущий элемент меняет accumulator?

Полезно держать рядом три метода из предыдущих глав:

| Метод | Вопрос | Результат |
| --- | --- | --- |
| `map()` | во что превратить каждый? | массив той же длины |
| `filter()` | какие оставить? | массив от 0 до N |
| `reduce()` | что получится из всех вместе? | одно значение любой формы |

## Примеры Automation QA

Status summary:

```javascript
const summary = testCases.reduce(function (accumulator, testCase) {
  accumulator[testCase.status] = accumulator[testCase.status] + 1;
  return accumulator;
}, { passed: 0, failed: 0, skipped: 0 });
```

CI report часто требует один итоговый object, а не набор строк. Здесь `reduce()` явно собирает summary из списка test cases.

## Распространённые мифы

**Миф: `reduce()` возвращает массив.**
Он возвращает одно значение. Им может быть и массив, но это решение вашего callback.

**Миф: `initialValue` — необязательная мелочь.**
Без него обход начинается со второго элемента, а первый становится accumulator. Для накопления объекта это меняет всё.

**Миф: на пустом массиве `reduce()` вернёт `undefined`.**
Без `initialValue` он выбросит `TypeError`. С ним — вернёт само начальное значение.

**Миф: `reduce()` подходит для любых задач с массивом.**
Если результат — массив той же длины, читается `map()`; если подмножество — `filter()`. `reduce()` берут, когда нужна свёртка.

**Миф: забытый `return` затронет один элемент.**
Он ломает всю цепочку: `undefined` станет accumulator для следующего шага.

## Частые вопросы

**Когда можно не передавать `initialValue`?**
Когда массив заведомо непуст и его первый элемент годится как стартовое значение.

**Как посчитать количество по категориям?**
Накапливать объект: ключ — категория, значение — счётчик.

**Чем `reduce()` отличается от цикла?**
Ничем принципиально. Он выразительнее, когда виден результат накопления, и хуже, когда логика шага сложная.

**Почему результат вдруг стал `undefined`?**
Скорее всего, в callback пропущен `return` — обычно из-за фигурных скобок.

**Можно ли с помощью `reduce()` получить массив?**
Да, если accumulator — массив. Но для простого преобразования читается `map()`.

## Распространённые ошибки

### Ошибка 1. Не возвращать accumulator

Если callback не возвращает next accumulator, следующий шаг получает неправильное value.

### Ошибка 2. Выбирать `reduce()` для простой transformation

Если нужен array same length, обычно лучше `map()`.

### Ошибка 3. Забывать initial value

Initial value делает начальное состояние aggregation явным и читаемым.

## Краткие итоги

`reduce()` начинает с initial value, передает accumulator от шага к шагу и возвращает один final result.

Главное: используйте `reduce()`, когда нужен summary, count, report object или другой единый итог.
