> Как продолжить код после асинхронной операции?

Короткий ответ: передать функцию, которую вызовут позже.

## Теория

### Функция, переданная на будущее

Обратный вызов — это функция, которую передают другому коду для будущего вызова.

Важная идея: вы не вызываете эту функцию сами. Вы отдаёте её тому, кто знает, **когда** её нужно вызвать. Обратный вызов описывает, что нужно сделать после результата.

```javascript
setTimeout(function afterDelay() {
  console.log('время вышло');
}, 100);
```

Здесь `afterDelay` передана среде выполнения. Та вызовет её, когда истечёт задержка — а код тем временем продолжит работу, как показано в главе 70.

### Обратный вызов не обязательно асинхронный

Стоит развести два понятия, которые часто слипаются. Колбэк — это способ **передачи** функции, а не признак асинхронности:

```javascript
[1, 2, 3].map((x) => x * 2);   // колбэк, но выполняется синхронно
setTimeout(fn, 0);             // колбэк, выполняется позже
```

`map`, `filter`, `forEach` из глав 50–52 принимают колбэки и вызывают их немедленно. Асинхронным код делает не колбэк, а то, что операция передана среде выполнения.

### Соглашение «ошибка первым аргументом»

Если операция может завершиться ошибкой, часто используют два значения:

```text
callback(error, result)
```

Читают это так: первый аргумент — ошибка или `null`, второй — результат, который есть только при отсутствии ошибки.

```javascript
readConfig('config.json', function done(error, config) {
  if (error) {
    return handleError(error);
  }
  useConfig(config);
});
```

Это распространённое соглашение многих API, а не обязательное правило языка JavaScript. Конкретная функция сама решает, какие аргументы и в каком порядке передавать в обратный вызов. В разных библиотеках сигнатура может отличаться — это лишь одно из наиболее распространённых соглашений.

Ключевая деталь: проверка ошибки идёт **первой**, и после неё обычно стоит `return`. Забытый `return` приводит к тому, что код продолжит работать с отсутствующим результатом.

### Почему появились Promise

У колбэков есть три системные проблемы, которые видны на любом реальном коде:

| Проблема | В чём выражается |
| --- | --- |
| вложенность | каждый следующий шаг уходит вправо |
| обработка ошибок | проверять нужно в каждом колбэке отдельно |
| доверие к чужому коду | неизвестно, вызовут ли колбэк один раз, ноль или три |

Третья — самая неочевидная. Передавая функцию чужому API, вы полагаетесь на его дисциплину: ничто не мешает вызвать колбэк дважды или не вызвать вовсе.

В этой главе мы не изучаем Promise и `async/await`. Они появятся позже как более удобные способы управления асинхронным результатом — и решают ровно эти три проблемы.

## Внутренний механизм

### Что происходит на высоком уровне

1. код вызывает функцию и передаёт ей обратный вызов;
2. вызванная функция запускает работу — синхронную или асинхронную;
3. управление возвращается вызывающему коду;
4. когда результат готов, обратный вызов вызывается с этим результатом;
5. тело обратного вызова выполняется как обычный код.

Пятый шаг объясняет, почему внутри колбэка работают все привычные правила: замыкания из главы 65 сохраняют доступ к окружению, а `this` из главы 66 определяется формой вызова — то есть тем, как колбэк вызвал чужой код.

### Потеря `this` в колбэке

Отсюда самая частая ошибка при передаче метода как колбэка:

```javascript
setTimeout(reporter.report, 0);           // this потерян
setTimeout(() => reporter.report(), 0);   // this сохранён
```

Чужой код вызывает переданную функцию без объекта перед точкой — и привязка исчезает. Решение то же, что в главе 67: стрелочная обёртка или `bind()`.

## Распространённые мифы

**Миф: колбэк — это всегда асинхронность.**
`map` и `forEach` принимают колбэки и вызывают их немедленно. Асинхронность создаёт не колбэк, а передача работы среде.

**Миф: `callback(error, result)` — правило языка.**
Это распространённое соглашение. Конкретный API может использовать любую сигнатуру.

**Миф: проверку ошибки можно поставить после работы с результатом.**
Результата при ошибке нет. Проверка идёт первой, и после неё нужен `return`.

**Миф: переданный колбэк гарантированно вызовется один раз.**
Это зависит от дисциплины чужого кода. Promise такую гарантию даёт, колбэк — нет.

**Миф: метод, переданный как колбэк, сохранит свой объект.**
Вызов произойдёт без объекта перед точкой, и `this` будет потерян.

## Частые вопросы

**Почему внутри колбэка `this` стал `undefined`?**
Его вызвал чужой код без объекта. Нужна стрелочная обёртка или `bind()`.

**Зачем `return` после проверки ошибки?**
Иначе выполнение продолжится и обратится к отсутствующему результату.

**Видит ли колбэк переменные из места объявления?**
Да, через замыкание — это обычная функция со всеми привычными правилами.

**Чем Promise лучше колбэка?**
Он решает вложенность, разрозненную обработку ошибок и даёт гарантию однократного результата.

**Все ли колбэки выполняются позже?**
Нет. Момент вызова определяет тот код, которому вы передали функцию.

## Распространённые ошибки

### Ошибка 1. Вызывать обратный вызов сразу при передаче

Нужно передать функцию, а не результат ее выполнения.

### Ошибка 2. Забывать обработку ошибки

Если операция может завершиться неуспешно, обратный вызов должен учитывать ошибку.

### Ошибка 3. Строить слишком глубокую цепочку обратных вызовов

Когда один обратный вызов запускает второй, второй запускает третий, код становится трудно читать. Promise решает именно эту проблему управления.
