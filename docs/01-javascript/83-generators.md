# Generators

## Связь с предыдущей главой

Предыдущая глава показала iterator:

Такой механизм точный, но ручное создание iterator быстро становится многословным.

## Главный вопрос

> Почему появились генераторы?

Короткий ответ: генератор автоматически создает iterator и позволяет выдавать значения через `yield`.

## Мотивация

Если нужно выдавать тесты по одному, ручной iterator требует хранить индекс и возвращать `{ value, done }`:

Генератор позволяет записать ту же идею как последовательность выдачи:

```javascript
function* testCaseGenerator() {
  yield 'login';
  yield 'checkout';
  yield 'report';
}
```

Код читается как список значений, которые будут выданы по одному.

## Теория

Функция-генератор объявляется через `function*`.

```javascript
function* createReportEntries() {
  yield 'logs';
  yield 'screenshot';
}
```

Вызов функции-генератора не выполняет тело сразу. Он возвращает объект-генератор (generator object).

Этот объект является iterator:

```javascript
const entries = createReportEntries();

console.log(entries.next());
```

Генератор не заменяет Iterator Protocol. Он автоматически реализует его: снаружи мы все равно работаем с iterator-механизмом из предыдущей главы.

`yield` останавливает выполнение функции-генератора и отдает значение наружу.

## Внутренний механизм

Генератор хранит позицию между вызовами `next()`.

Следующий `next()` продолжает с места остановки:

Поэтому генератор остается связан с той же моделью `next()`, `value` и `done`.

### Тело не выполняется до первого `next()`

Вызов функции-генератора создаёт объект и **ничего не выполняет**. Первая строка тела сработает только при первом `next()`:

```javascript
function* gen() {
  console.log('тело началось');   // выполнится не при вызове gen()
  yield 'a';
}

const g = gen();      // ничего не напечатано
g.next();             // 'тело началось', затем { value: 'a', done: false }
```

Это и есть ленивость: генератор производит значения по требованию, а не заранее. Поэтому бесконечный генератор безопасен — он вычислит ровно столько значений, сколько запросят:

```javascript
function* infinite() { let n = 0; while (true) yield n++; }
const it = infinite();
[it.next().value, it.next().value, it.next().value];   // [0, 1, 2]
```

Обычная функция с таким циклом зависла бы навсегда.

### `return` внутри генератора ведёт себя особенно

Значение, возвращённое через `return`, приходит вместе с `done: true`:

```javascript
function* gen() { yield 'a'; return 'итог'; }
// next(): { value: 'a', done: false }
// next(): { value: 'итог', done: true }
```

Но `for...of` и spread это значение **игнорируют**: `[...gen()]` даёт `['a']`. Они забирают только значения, пришедшие с `done: false`.

Практический вывод: возвращать полезный результат через `return` генератора можно, но получить его удастся лишь ручным обходом через `next()`.

### Обмен значениями в обе стороны

`yield` не только отдаёт значение наружу, но и получает значение обратно — аргумент следующего `next()` становится результатом выражения `yield`:

```javascript
function* dialog() {
  const answer = yield 'вопрос';
  return 'получено: ' + answer;
}

const d = dialog();
d.next();          // { value: 'вопрос', done: false }
d.next('ответ');   // { value: 'получено: ответ', done: true }
```

Это отличает генератор от обычного итератора: обход становится диалогом, а не односторонней выдачей.

### Досрочное завершение и делегирование

Метод `return()` завершает генератор немедленно, как `break` в цикле:

```javascript
g.return('прервано');   // { value: 'прервано', done: true }
g.next();               // { done: true } — генератор исчерпан
```

Это тот же механизм, который `for...of` использует при `break` — связь с главой 82 прямая.

Конструкция `yield*` передаёт управление другому генератору или iterable:

```javascript
function* inner() { yield 1; yield 2; }
function* outer() { yield 'начало'; yield* inner(); yield 'конец'; }

[...outer()];   // ['начало', 1, 2, 'конец']
```

Значения вложенного источника попадают в общий поток, как будто написаны на месте.

## Главная ментальная модель

Главная модель главы: **функция, которая умеет приостанавливаться на `yield` и продолжаться с того же места по требованию**.

Генератор похож на сценарий тестового отчета: каждая строка `yield` говорит, какой следующий элемент можно выдать.

## Пример Automation QA

Генератор удобно использовать, когда отчетные записи нужно выдавать последовательно:

```javascript
function* reportEntries() {
  yield 'collect logs';
  yield 'capture screenshot';
  yield 'upload report';
}

for (const entry of reportEntries()) {
  console.log(entry);
}
```

Фреймворк получает значения по одному, а код генерации остается читаемым.

## Распространённые мифы

**Миф: вызов генератора выполняет его тело.**
Он создаёт объект. Тело начинает выполняться с первого `next()`.

**Миф: бесконечный цикл в генераторе повесит программу.**
Не повесит: значения вычисляются по требованию.

**Миф: `return` генератора попадёт в результат `for...of`.**
Игнорируется: цикл забирает только значения с `done: false`.

**Миф: генератор — односторонняя выдача значений.**
Аргумент `next()` возвращается в `yield`, делая обход диалогом.

**Миф: генератор заменяет протокол итератора.**
Он его реализует автоматически. Снаружи работает тот же механизм `next()`, `value`, `done`.

## Частые вопросы

**Когда выполнится первая строка генератора?**
При первом вызове `next()`, а не при вызове функции.

**Как получить значение из `return` генератора?**
Ручным обходом через `next()`: в `for...of` оно не попадёт.

**Зачем передавать значение в `next()`?**
Чтобы вернуть результат в точку `yield` — так строится двусторонний обмен.

**Что делает `yield*`?**
Делегирует выдачу другому генератору или iterable, вставляя его значения в общий поток.

**Как досрочно завершить генератор?**
Вызвать `return()` — так же, как это делает `break` в цикле.

## Распространённые ошибки

### Ошибка 1. Думать, что вызов функции-генератора сразу выполняет тело

Вызов возвращает генератор. Выполнение начинается при `next()` или `for...of`.

### Ошибка 2. Путать `return` и `yield`

`yield` выдает очередное значение и оставляет генератор продолжимым. `return` завершает его.

### Ошибка 3. Считать генератор асинхронным механизмом

Обычные генераторы из этой главы синхронны. Асинхронные генераторы будут отдельной темой позже.

## Краткие итоги

Генератор упрощает создание iterator.

Главное:

* `function*` создает функцию-генератор;
* вызов функции-генератора возвращает генератор;
* `yield` выдает значение наружу;
* генератор можно обходить через `for...of`;
* генераторы помогают писать итерацию без ручного `next()`.
