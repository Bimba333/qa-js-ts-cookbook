# this: углубленное повторение

## Связь с предыдущей главой

Предыдущая глава объяснила Closure: функция может сохранять доступ к лексическому окружению, где была создана.

Теперь мы смотрим на другую часть поведения функций. Функция может быть вызвана как метод объекта:

```javascript
logger.log('start test');
```

Внутри `log` может использоваться `this`. Нужно понять, на что он указывает.

## Главный вопрос

> Что означает `this`?

Ответ этой главы: `this` зависит от того, как функция вызвана.

## Предварительные требования

Для этой главы нужно понимать:

* что функция может быть свойством объекта;
* что объект может хранить данные и методы;
* что вызов функции создает Execution Context;
* что Closure и `this` решают разные задачи.

## Цели обучения

После главы вы будете понимать:

* зачем нужен `this`;
* как обычный вызов метода определяет `this`;
* почему потеря связи с объектом меняет поведение;
* чем `this` отличается от Closure;
* почему эта тема важна для вспомогательных функций и объектов отчетности.

## Мотивация

В Automation QA Framework может быть объект logger:

```javascript
const Logger = {
  prefix: 'smoke',
  log(message) {
    console.log(`[${this.prefix}] ${message}`);
  },
};
```

Когда мы вызываем:

```javascript
Logger.log('start test');
```

`this` внутри `log` указывает на `Logger`.

Но если сохранить метод отдельно:

```javascript
const log = Logger.log;
log('start test');
```

связь с объектом теряется. Поэтому `this` нельзя понимать как "объект, где функция была объявлена". Важно смотреть на форму вызова.

## Теория

`this` — это значение, которое JavaScript определяет во время вызова функции.

Для обычного вызова метода:

```mermaid
flowchart TD
    N1["object.method()"]
    N2["this = object"]
    N1 --> N2
```

Это правило относится к обычному вызову метода, который рассматривается в этой главе. Другие формы вызова будут изучаться дальше.

`this` не является Closure. Closure связан с местом создания функции. `this` связан с тем, как функция вызвана.

```mermaid
flowchart TD
    N1["Closure → где функция создана"]
    N2["this → как функция вызвана"]
    N1 --> N2
```

## Внутренний механизм

Пример:

```javascript
const Reporter = {
  name: 'console reporter',
  report(testName) {
    console.log(`${this.name}: ${testName}`);
  },
};

Reporter.report('login');
```

JavaScript видит форму вызова:

```mermaid
flowchart TD
    N1["Reporter.report(...)"]
    N2["объект выполнения = Reporter"]
    N3["this = Reporter"]
    N1 --> N2
    N2 --> N3
```

Если метод отделить:

```javascript
const report = Reporter.report;
report('login');
```

вызов уже не имеет объекта выполнения перед точкой.

```mermaid
flowchart TD
    N1["report(...)"]
    N2["нет объекта перед точкой"]
    N3["this не будет Reporter"]
    N1 --> N2
    N2 --> N3
```

### Что происходит при отделении метода

Самое практичное следствие правила «`this` определяется вызовом» видно, когда метод отрывают от объекта:

```javascript
const report = Reporter.report;
report('login');
```

Объекта перед точкой больше нет, и в строгом режиме `this` становится `undefined`. В модулях и внутри классов код всегда строгий, поэтому обращение к `this.name` даст ошибку чтения свойства у `undefined`.

Именно так ломаются передачи методов в колбэки:

```javascript
setTimeout(Reporter.report, 0);       // this потерян
items.forEach(Reporter.report);       // this потерян
```

Способ сохранить привязку — тема следующей главы: `bind()`, стрелочная обёртка или вызов через объект.

### Строгий режим не подменяет `this` на глобальный объект

Ещё одна деталь, которая отличает современный код от старых примеров в интернете:

```javascript
greet.call(null, 'Привет');   // this остаётся null → TypeError
```

В нестрогом режиме `null` подменялся бы глобальным объектом, и ошибка проявилась бы позже и непонятнее. В модулях подмены нет — падение происходит сразу и по делу.

### Стрелочные функции не получают свой `this`

Стрелка не создаёт собственное значение `this` — она берёт его из места, где была создана:

```javascript
const Reporter = {
  name: 'reporter',
  arrow: () => this?.name,   // не имеет отношения к Reporter
};
```

Метод-стрелка в литерале объекта — частая ошибка: объект не создаёт области видимости, поэтому `this` берётся из внешнего кода, а не из объекта.

Обратная сторона делает стрелки полезными:

```javascript
const obj = {
  name: 'внешний',
  make() {
    return { name: 'вложенный', run: () => this.name };
  },
};

obj.make().run();   // 'внешний' — this взят из make()
```

Здесь стрелка сохранила `this` метода, в котором была создана, и это ровно то поведение, которое нужно в колбэках.

### Обычная вложенная функция теряет `this`

Для сравнения — та же ситуация без стрелки:

```javascript
const o = {
  n: 'o',
  m() {
    return (function () { return this?.n; })();   // undefined
  },
};
```

Внутренняя функция вызвана сама по себе, без объекта перед точкой — значит, `this` не связан. До появления стрелок эту проблему обходили через `const self = this`, и такой код до сих пор встречается.

### Сводка форм вызова

| Форма вызова | Чему равен `this` |
| --- | --- |
| `obj.method()` | `obj` |
| `fn()` (строгий режим) | `undefined` |
| стрелочная функция | `this` места создания |
| `fn.call(obj)` / `fn.apply(obj)` | `obj` |
| `new Fn()` | новый объект |

Последние две строки — темы следующих глав; здесь важно, что все они определяются **вызовом**, а не местом объявления функции.

## Распространённые мифы

**Миф: `this` определяется тем, где функция объявлена.**
Он определяется формой вызова. Исключение — стрелки, у которых своего `this` нет вовсе.

**Миф: отделённый метод сохраняет объект.**
Без объекта перед точкой `this` в строгом режиме становится `undefined`.

**Миф: в строгом режиме `this` подменяется глобальным объектом.**
Не подменяется: `call(null)` оставляет `null`, и ошибка возникает сразу.

**Миф: стрелка в литерале объекта получает сам объект.**
Объект не создаёт области видимости; `this` берётся из внешнего кода.

**Миф: вложенная обычная функция наследует `this` метода.**
Не наследует. До стрелок для этого использовали `const self = this`.

## Частые вопросы

**Почему `this` стал `undefined` в колбэке?**
Метод передали как функцию, и вызов произошёл без объекта перед точкой.

**Как сохранить привязку при передаче метода?**
Через `bind()` или стрелочную обёртку — подробности в следующей главе.

**Когда стрелка — правильный выбор?**
Когда нужно сохранить `this` окружающего кода: в колбэках и обработчиках.

**Когда стрелка — ошибка?**
Когда она объявлена как метод объекта и должна обращаться к самому объекту.

**Зачем знать про нестрогий режим?**
Чтобы понимать старые примеры, где `this` неожиданно оказывался глобальным объектом.

## Распространённые ошибки

### Ошибка 1. Думать, что `this` определяется местом объявления функции

Для обычного метода важна форма вызова, а не место написания функции.

### Ошибка 2. Терять метод при передаче

Если сохранить метод в переменную, объект перед точкой исчезает.

### Ошибка 3. Путать Closure и `this`

Closure сохраняет доступ к лексическому окружению. `this` определяется вызовом.

## Использование в Automation QA

В тестовых фреймворках `this` часто важен для:

* методов reporter;
* методов logger;
* вспомогательных функций API client;
* retry managers;
* объектов с конфигурацией.

Если метод зависит от `this`, его нельзя бездумно отделять от объекта.
