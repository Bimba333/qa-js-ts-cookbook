## Главный вопрос

> Как сделать собственный объект iterable?

Короткий ответ: добавить метод `Symbol.iterator`, который возвращает iterator.

## Мотивация

В тестовом фреймворке тестовый набор может быть не просто массивом, а объектом с метаданными:

```javascript
const testSuite = {
  name: 'smoke',
  owner: 'qa-team',
  tests: ['login', 'checkout', 'report'],
};
```

Логически мы хотим обходить именно `tests`:

```javascript
for (const test of testSuite) {
  console.log(test);
}
```

Но обычный объект сам по себе не iterable. Нужно явно описать правило обхода.

## Теория

### Два способа реализовать `Symbol.iterator`

Чтобы объект стал iterable, у него должен быть метод `Symbol.iterator`. Есть два практических способа:

1. вернуть ручной iterator с `next()`;
2. использовать generator внутри `Symbol.iterator`.

Ручной вариант показывает механизм. Generator-вариант обычно короче и читабельнее.

### Ручной итератор

```javascript
const range = {
  from: 1,
  to: 3,
  [Symbol.iterator]() {
    let current = this.from;
    const to = this.to;
    return {
      next: () => current <= to
        ? { value: current++, done: false }
        : { done: true },
    };
  },
};

[...range];   // [1, 2, 3]
```

Здесь видно всё устройство: состояние `current` живёт в замыкании, а `next()` решает, продолжать или завершить обход.

### Тот же объект через генератор

```javascript
const range = {
  from: 1,
  to: 3,
  *[Symbol.iterator]() {
    for (let i = this.from; i <= this.to; i++) yield i;
  },
};

[...range];   // [1, 2, 3]
```

Результат идентичен, но кода вдвое меньше: генератор сам создаёт объект с `next()`, сам хранит позицию и сам сообщает о завершении.

Звёздочка перед именем метода — сокращённая запись метода-генератора.

### Оба варианта дают повторяемый обход

Важное свойство, которое легко потерять: `Symbol.iterator` вызывается **при каждом** обходе и должен возвращать свежий итератор.

```javascript
[...range];   // [1, 2, 3]
[...range];   // [1, 2, 3] — снова полностью
```

Проверено для обеих реализаций. Ошибка появляется, если итератор создать один раз и возвращать его же: второй обход получит уже исчерпанный итератор и вернёт пустой результат.

Это прямое следствие разделения ролей из глав 81 и 82: iterable выдаёт итераторы, итератор хранит позицию.

### Когда какой вариант выбирать

| Ситуация | Вариант |
| --- | --- |
| нужна прозрачность механизма | ручной итератор |
| обычная последовательность значений | генератор |
| сложная логика с ветвлениями и делегированием | генератор |
| нужен `return()` для освобождения ресурсов | ручной, либо `try/finally` в генераторе |

В прикладном коде почти всегда выигрывает генератор. Ручная реализация полезна для понимания и для случаев, где нужен полный контроль над объектом итератора.

## Внутренний механизм

### Что делает `for...of` с вашим объектом

Когда `for...of` получает собственный объект, процесс тот же, что и для массива:

1. запросить у объекта `Symbol.iterator` и вызвать его;
2. получить итератор;
3. вызывать `next()` до `done: true`;
4. при досрочном выходе вызвать `return()`, если он есть.

Оба подхода подчиняются одному правилу: `Symbol.iterator` должен дать JavaScript объект, из которого можно получать значения.

### Что именно скрывает генератор

Генератор-вариант выполняет ровно ту же работу, просто движок берёт её на себя:

| Задача | Ручной вариант | Генератор |
| --- | --- | --- |
| хранение позиции | переменная в замыкании | состояние генератора |
| формирование `{ value, done }` | вручную | автоматически |
| завершение обхода | вернуть `{ done: true }` | достичь конца тела |
| реакция на `break` | реализовать `return()` | выполнить `finally`, если он есть |

Последняя строка полезна на практике: если генератор читает ресурс, его закрытие помещают в `try/finally` — и оно сработает при досрочном выходе из цикла.

## Главная ментальная модель

Главная модель главы: **свой объект становится обходимым, как только у него появляется `Symbol.iterator`, возвращающий свежий итератор**.

Custom iteration — это не магия, а явно заданное правило обхода.

## Пример Automation QA

Собственный тестовый набор может скрывать служебные поля, но отдавать наружу только тесты:

```javascript
const testSuite = {
  name: 'smoke',
  tests: ['login', 'checkout'],
  *[Symbol.iterator]() {
    for (const test of this.tests) {
      yield test;
    }
  },
};

for (const test of testSuite) {
  console.log(test);
}
```

Теперь объект ведет себя как коллекция тестов, хотя внутри хранит и дополнительные данные.

## Распространённые мифы

**Миф: свой iterable — это сложно.**
Метод-генератор с `Symbol.iterator` занимает три строки и делает всю работу.

**Миф: можно создать итератор один раз и возвращать его.**
Тогда второй обход получит исчерпанный итератор и вернёт пустой результат.

**Миф: генератор и ручной итератор дают разный результат.**
Результат одинаков; различается объём кода и контроль над деталями.

**Миф: `*[Symbol.iterator]()` — особый синтаксис протокола.**
Это обычный метод-генератор: звёздочка относится к методу, а не к протоколу.

**Миф: освобождение ресурсов в генераторе невозможно.**
`try/finally` выполнится при досрочном выходе из цикла.

## Частые вопросы

**Что выбрать для своего объекта?**
Генератор, если нет причин управлять объектом итератора вручную.

**Почему второй обход вернул пустой массив?**
`Symbol.iterator` вернул один и тот же итератор вместо нового.

**Как освободить ресурс при `break`?**
В генераторе — через `try/finally`; в ручном варианте — реализовав `return()`.

**Нужно ли возвращать `value` вместе с `done: true`?**
Нет, значение в завершающем шаге необязательно.

**Где `this` внутри метода-генератора?**
Это обычный метод объекта, поэтому `this` указывает на сам объект.

## Распространённые ошибки

### Ошибка 1. Вернуть массив вместо iterator из `Symbol.iterator`

Метод должен возвращать iterator. Если нужно использовать массив, можно вернуть `this.tests[Symbol.iterator]()`.

### Ошибка 2. Потерять `this` внутри `Symbol.iterator`

Если iterator обращается к полям объекта, нужно понимать, откуда берутся данные.

### Ошибка 3. Делать собственную итерацию без причины

Если достаточно обычного массива, не нужно усложнять модель собственным iterable-объектом.

## Краткие итоги

Custom iteration позволяет собственным объектам работать с `for...of`.

Главное:

* объект становится iterable через `Symbol.iterator`;
* `Symbol.iterator` должен вернуть iterator;
* iterator можно написать вручную;
* generator часто делает код короче;
* правило обхода должно быть очевидным для читателя.
