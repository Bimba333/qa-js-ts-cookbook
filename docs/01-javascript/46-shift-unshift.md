## Теория

`unshift()` добавляет один или несколько элементов в начало массива.

В этой главе мы фокусируемся по одному элементу за раз:

```javascript
const requestTasks = ['GET /users', 'GET /orders'];

requestTasks.unshift('POST /login');
```

До выполнения:

```text
индекс:  0              1
значение 'GET /users'   'GET /orders'
```

После выполнения:

```text
индекс:  0              1              2
значение 'POST /login'  'GET /users'   'GET /orders'
```

Важно: исходный массив изменён на месте. Новый массив не создаётся, а прежние
элементы сдвинулись вправо: то, что было под индексом `0`, теперь под `1`.

### Зачем существует `unshift()`

`unshift()` существует, потому что иногда новое значение должно стать первым.

Примеры:

```text
срочный request
приоритетный test step
первая вкладка браузера
приоритетная failure
setup task перед обычными задачами
```

`unshift()` отвечает:

```text
Как добавить новый первый element?
```

### `shift()`

`shift()` удаляет первый элемент из массива и возвращает удалённое значение.

```javascript
const requestTasks = ['POST /login', 'GET /users', 'GET /orders'];

const firstTask = requestTasks.shift();
```

До выполнения:

```text
индекс:  0              1              2
значение 'POST /login'  'GET /users'   'GET /orders'
```

После выполнения:

```text
индекс:  0              1
значение 'GET /users'   'GET /orders'
```

Возвращаемое значение:

```text
"POST /login"
```

Важно: метод возвращает **удалённый элемент**, а не изменённый массив. Сам
массив изменяется на месте, а оставшиеся элементы сдвигаются влево.

### Зачем существует `shift()`

`shift()` существует, потому что иногда первый элемент нужно обработать и удалить.

Примеры:

```text
взять первый собранный request
обработать первый test step
удалить первую вкладку браузера
взять failure с самым высоким приоритетом
забрать первую задачу из простого списка
```

`shift()` отвечает:

```text
Как удалить и получить первый element?
```

### Начало массив

Начало массив — это индекс `0`.

Поскольку массивы упорядочены, изменение начала влияет на позиции других элементов.

Значения не потеряли порядок относительно друг друга. Они перешли на новые индексы.

### Длина как следствие

`unshift()` добавляет новый элемент в начало.

Так как массив теперь содержит на один элемент больше, `length` увеличивается.

`shift()` удаляет первый элемент.

Так как массив теперь содержит на один элемент меньше, `length` уменьшается.

### Отличие от `push()` и `pop()`

Операции в конце:

```text
push(x)  добавляет элемент после последнего — индексы остальных не меняются
pop()    удаляет последний элемент — индексы остальных не меняются
```

Операции в начале:

```text
unshift(x)  добавляет элемент перед первым — все индексы сдвигаются вправо
shift()     удаляет первый элемент — все индексы сдвигаются влево
```

Ключевое отличие: конец массива не имеет соседей справа, поэтому изменение там
никого не задевает. У начала соседи есть всегда, и позиция каждого из них
меняется.

Здесь мы не обсуждаем замеры производительности или оценку сложности. Важная идея главы — смещение индексов.

## Внутренний механизм

Когда JavaScript выполняет:

```javascript
requestTasks.unshift('POST /login');
```

У движка есть:

```text
массив:              requestTasks
новое значение:      "POST /login"
текущий первый индекс: 0
```

Поток действий:

```text
1. освободить позицию 0 — сдвинуть каждый элемент на индекс справа
2. записать новое значение в позицию 0
3. увеличить length на единицу
4. вернуть новую длину
```

Например: `tasks.unshift('setup')` ставит элемент в начало и сдвигает остальные
вправо.

Когда JavaScript выполняет:

```javascript
const task = requestTasks.shift();
```

Движок делает обратное:

```text
1. запомнить значение из позиции 0
2. сдвинуть каждый следующий элемент на индекс влево
3. уменьшить length на единицу
4. вернуть запомненное значение
```

Например: `tasks.shift()` забирает первый элемент и сдвигает остальные влево.

Если массив пустой:

```javascript
const requestTasks = [];
const firstTask = requestTasks.shift();
```

Результат: `firstTask` равен `undefined`, а сам массив остаётся пустым. Удалять
нечего, и это не ошибка — метод просто сообщает, что первого элемента не было.

## Ментальная модель

Передняя дверь поезда: состав пронумерован от головы, и новый вагон цепляют
спереди. Номера всех прежних вагонов после этого увеличиваются на единицу,
хотя сами вагоны никуда не переставляли.

`unshift()` добавляет новый вагон в начало:

```text
[urgent][car A][car B][car C]
```

Интуиция очереди:

Используйте это только как высокоуровневую интуицию. Формальную структуру данных «очередь» мы здесь не разбираем.

Первая страница блокнота: вклеить лист перед первой страницей можно, но тогда
нумерация всех остальных страниц сдвигается.

Ряд сидений: если посадить человека на первое место, все сидящие смещаются на
одно место вправо.

Конвейер: снять изделие с начала ленты — значит сделать первым то, что было
вторым.

Центральная модель: начало массива — это позиция с индексом `0`, и любая
операция с ней меняет индексы всех остальных элементов.

## Частые вопросы

### `unshift()` создаёт новый массив?

Нет.

В модели этой главы массив изменяется на месте, а возвращается новая длина —
число, а не массив.

### `shift()` создаёт новый массив?

Нет.

### Что возвращает `shift()`?

Удаленный первый элемент.

### Что происходит при `shift()` из пустого массив?

массив остается пустым.

### Это очередь?

На высоком уровне удаление из начала похоже на обработку очереди.

Но формальные структуры очередь и двусторонняя очередь не являются темой этой главы.

### Почему индексы меняются?

Потому что индекс `0` — это начало.

Когда появляется новый первый элемент, старые элементы должны сместиться вправо.

Когда первый элемент удаляется, оставшиеся элементы должны сместиться влево.

## Распространённые мифы

### Миф: `shift()` — это то же самое, что `pop()`

Реальность: `shift()` удаляет первый элемент. `pop()` удаляет последний элемент.

### Миф: `unshift()` добавляет элемент в конец

Реальность: `unshift()` добавляет элемент в начало.

### Миф: индексы остаются такими же после `unshift()`

Реальность: существующие элементы смещаются вправо, поэтому их индексы меняются.

### Миф: `shift()` возвращает измененный массив

Реальность: `shift()` возвращает удалённый первый элемент.

### Миф: `shift()` из пустого массив всегда падает

Реальность: он возвращает `undefined`.

---

## Распространённые ошибки

### Ошибка 1. Ожидать, что `shift()` удалит последний элемент

Неправильная модель: будто `shift()` возвращает изменённый массив.

Правильная модель: `shift()` возвращает удалённый первый элемент.

### Ошибка 2. Забыть, что индексы смещаются после `unshift()`

Неправильная модель: будто `unshift()` возвращает новый массив.

Что пропущено:

```text
A сместился с index 0 на index 1
B сместился с index 1 на index 2
```

Правильная модель: `unshift()` изменяет исходный массив и возвращает его новую длину.

### Ошибка 3. Ожидать, что `shift()` вернет массив

Неправильный код:

```javascript
const tasks = ['login', 'users'];
const result = tasks.shift();

console.log(result.length);
```

Что произошло:

`result` — это удалённый первый элемент, а не измененный массив.

Исправленная модель: после операций с началом массива сохранённые ранее индексы указывают уже на другие элементы.

### Ошибка 4. Игнорировать пустой массив

```javascript
const tasks = [];
const firstTask = tasks.shift();
```

`firstTask` равен `undefined`.

Перед использованием удаленного значения код должен учитывать пустую коллекцию.

## Практическое использование

Используйте `unshift()`, когда новое значение должно стать первым:

```text
срочный request
приоритетная test task
setup step перед обычными steps
важная failure перед обычными failures
```

Используйте `shift()`, когда первое значение нужно удалить и обработать:

```text
первый запрос для выполнения
первый собранный шаг теста
первая вкладка браузера в простой модели
первое падение для отчёта
```

Читаемость: `shift()` меняет индексы всех оставшихся элементов, и в коде это
не видно. Если из массива берут первый элемент, имя переменной должно об этом
говорить — иначе читатель решит, что порядок не важен.

### Обработка первого собранный элемент

```javascript
const nextRequest = requestTasks.shift();
```

Теперь:

Оставшиеся запросы смещаются влево.

### вкладки браузера в начале

Если простая модель считает первую вкладку активной, то после `unshift()` активной окажется уже другая — индекс сместился.

### Собранные шаги теста

Если обязательный предусловие обнаружен поздно, `unshift()` может поместить его перед обычными шаги.
