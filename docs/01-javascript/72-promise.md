# Promise

## Связь с предыдущей главой

Предыдущая глава показала обратные вызовы:

```mermaid

    N1["асинхронная операция"]
    N2["результат позже"]
```

Обратный вызов работает, но при росте сценария код становится труднее читать.

Promise появляется как более управляемая модель результата, который станет доступен позже.

## Главный вопрос

> Почему были введены Promise?

Короткий ответ: Promise представляет результат асинхронной операции, который станет доступен позже, и позволяет работать с ним как с отдельным объектом.

## Предварительные требования

Для этой главы нужно понимать:

* что асинхронная операция завершается позже;
* что обратный вызов может получить результат;
* что функция может вернуть объект;
* что ошибки асинхронных операций нужно обрабатывать отдельно.

`async/await`, Promise API, microtasks и Event Loop internals в этой главе не изучаются.

После главы вы будете понимать:

## Мотивация

В модели обратных вызовов продолжение передается внутрь функции:

```javascript
runTest('login smoke', function saveResult(result) {
  console.log(result);
});
```

Promise меняет форму:

```javascript
runTest('login smoke').then(function saveResult(result) {
  console.log(result);
});
```

Теперь функция `runTest()` возвращает объект, который представляет будущий результат операции.

```mermaid
flowchart TD
    N1["runTest()"]
    N2["Promise"]
    N3["результат позже"]
    N1 --> N2
    N2 --> N3
```

## Теория

Promise — это объект, который представляет результат асинхронной операции, доступный не сейчас, а позже.

Promise сам по себе не делает код асинхронным. Асинхронная операция уже запущена другим механизмом. Promise только представляет ее будущий результат и дает удобный способ зарегистрировать код для успешного завершения или ошибки.

Promise — обычный JavaScript-объект. Его можно сохранить в переменную, вернуть из функции или передать в другую функцию так же, как другие объекты JavaScript. Это важно: Promise не является специальной "магической паузой" в коде, он является объектом для работы с результатом, который появится позже.

```mermaid
flowchart TD
    N1["асинхронная операция"]
    N2["Promise"]
    N3["успешный результат"]
    N4["ошибка"]
    N1 --> N2
    N2 --> N3
    N2 --> N4
```

Для успешного результата используется `then()`:

```javascript
operation().then(function handleResult(result) {
  console.log(result);
});
```

Для ошибки используется `catch()`:

```javascript
operation().catch(function handleError(error) {
  console.log(error);
});
```

В этой главе важно не количество методов, а модель:

```mermaid
flowchart TD
    N1["Promise"]
    N2["обещание результата, который появится позже"]
    N1 --> N2
```

### Три состояния и их необратимость

Promise находится в одном из трёх состояний:

| Состояние | Что означает |
| --- | --- |
| pending | результат ещё не известен |
| fulfilled | операция завершилась успешно |
| rejected | операция завершилась ошибкой |

Переход происходит **один раз** и необратим: из pending в одно из двух других. Это и есть гарантия, которой нет у колбэка из предыдущей главы — обработчик не может сработать дважды.

### Конструктор выполняется синхронно

Деталь, которая удивляет и объясняет многие вопросы о порядке:

```javascript
const marks = [];
new Promise((resolve) => {
  marks.push('executor выполнен синхронно');
  resolve();
}).then(() => marks.push('then асинхронно'));
marks.push('после конструктора');

// ['executor выполнен синхронно', 'после конструктора', 'then асинхронно']
```

Функция, переданная в конструктор, вызывается немедленно — прямо во время создания объекта. Асинхронным является только выполнение обработчиков: они попадают в очередь микрозадач, о которой речь в главе 75.

### `then()` возвращает новый Promise

Это свойство делает возможными цепочки:

```javascript
const first = Promise.resolve(1);
const second = first.then((v) => v + 1);

first !== second;   // true — это разные объекты
```

Значение, возвращённое из обработчика, становится результатом нового Promise. Поэтому цепочка читается как последовательность преобразований:

```javascript
Promise.resolve(1)
  .then((v) => v + 1)
  .then((v) => console.log(v));   // 2
```

Если из обработчика вернуть Promise, он **разворачивается**: следующий `then()` получит его результат, а не сам объект. Проверено — возврат `Promise.resolve('развёрнут')` даёт следующему обработчику строку.

### Ошибки идут по цепочке до ближайшего `catch()`

Исключение, брошенное внутри обработчика, не теряется — оно превращает результат в rejected:

```javascript
Promise.resolve()
  .then(() => { throw new Error('из then'); })
  .catch((e) => console.log(e.message));   // 'из then'
```

`catch()` тоже возвращает Promise, поэтому после него цепочка продолжается — и если обработчик вернул значение, следующий `then()` получит его:

```javascript
Promise.reject(new Error('x'))
  .catch(() => 'восстановлено')
  .then((v) => console.log(v));   // 'восстановлено'
```

Это принципиальное отличие от колбэков: одна обработка ошибок на всю цепочку вместо проверки в каждом шаге.

### Promise не отменяет правил выполнения

Важно не приписывать объекту лишнего. Promise не запускает операцию, не ускоряет её и не приостанавливает выполнение кода. Строка с `.then()` выполняется немедленно — она лишь регистрирует обработчик на будущее.

Всё, что говорилось в главе 70, продолжает действовать: результат доступен только внутри продолжения, а синхронный код по-прежнему идёт до конца первым.

## Внутренний механизм

На высоком уровне:

```mermaid
flowchart TD
    N1["function runTest()"]
    N2["создает Promise"]
    N3["запускает асинхронную работу"]
    N4["возвращает Promise сразу"]
    N5["позже Promise получает результат"]
    N1 --> N2
    N2 --> N3
    N3 --> N4
    N4 --> N5
```

Код, переданный в `then()`, не выполняется в момент регистрации. Он будет выполнен после успешного завершения операции.

```mermaid
flowchart TD
    N1["promise.then(handler)"]
    N2["handler зарегистрирован"]
    N3["результат появился позже"]
    N4["handler(result)"]
    N1 --> N2
    N2 --> N3
    N3 --> N4
```

Если операция завершается ошибкой, управление попадает в `catch()`.

Подробные состояния Promise, цепочки Promise и `async/await` будут изучаться в следующих главах. Сейчас достаточно модели результата после завершения операции.

## Главная ментальная модель

Главная модель главы: **Promise — это объект, представляющий результат, которого ещё нет, и место, куда заранее вешают обработчики**.

Для тестового раннера: обещание результата позволяет описать проверку до того, как операция завершилась, и не блокировать выполнение ожиданием.

Асинхронная вспомогательная функция может возвращать Promise:

```javascript

  console.log(`${result.testName}: ${result.status}`);
});
```

Это читается как:

Promise делает отложенный результат явным: функция не прячет продолжение внутри себя, а возвращает объект, с которым можно работать дальше.

## Распространённые мифы

**Миф: Promise делает операцию асинхронной.**
Операцию запускает другой механизм. Promise лишь представляет её будущий результат.

**Миф: функция в конструкторе выполняется позже.**
Она выполняется немедленно. Асинхронны только обработчики.

**Миф: `then()` изменяет исходный Promise.**
Он возвращает новый. Исходный остаётся прежним.

**Миф: после `catch()` цепочка заканчивается.**
`catch()` тоже возвращает Promise, и следующий `then()` получит его результат.

**Миф: вложенный Promise придёт в обработчик как объект.**
Он разворачивается: обработчик получит его результат.

## Частые вопросы

**Может ли обработчик сработать дважды?**
Нет. Состояние меняется один раз и необратимо — в этом преимущество перед колбэком.

**Куда попадёт исключение из `then()`?**
В ближайший `catch()` по цепочке.

**Как вернуть значение из цепочки?**
Вернуть его из обработчика: оно станет результатом следующего Promise.

**Почему код после `.then()` выполняется раньше обработчика?**
`.then()` только регистрирует обработчик. Он выполнится после синхронного кода.

**Чем `catch()` отличается от проверки ошибки в колбэке?**
Он один на всю цепочку, а в колбэках ошибку проверяют на каждом шаге.

## Распространённые ошибки

### Ошибка 1. Думать, что Promise уже содержит готовое значение

Promise представляет значение, которое появится позже. Готового результата в момент создания может еще не быть.

### Ошибка 2. Забывать вернуть Promise из вспомогательной функции

Если вспомогательная функция запускает асинхронную работу, но не возвращает Promise, вызывающий код не сможет дождаться результата.

### Ошибка 3. Обрабатывать только успешный сценарий

Асинхронная операция может завершиться ошибкой. Для этого нужен `catch()`.

## Краткие итоги

Promise решает проблему управления асинхронным результатом.

Главное:

* Promise представляет результат, который станет доступен позже;
* `then()` регистрирует обработчик успешного результата;
* `catch()` регистрирует обработчик ошибки;
* Promise делает асинхронный результат явным;
* это естественное продолжение модели обратных вызовов.
