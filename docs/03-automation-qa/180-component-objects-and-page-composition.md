# Component Objects и композиция страниц

## Связь с предыдущей главой

Page Object отделил сценарий от деталей страницы. Повторяющиеся заголовки, навигация, таблицы и модальные окна могут встречаться на разных страницах, поэтому копирование их Locators создаёт новое дублирование.

## Цель главы

Научиться моделировать независимый UI-компонент через корневой Locator и собирать страницы композицией без наследования.

## Главный вопрос

Как переиспользовать независимые части интерфейса без наследования страниц?

## Мотивация

Одинаковая навигация встречается на нескольких страницах. Базовый класс страницы кажется быстрым решением, но связывает несвязанные страницы общей иерархией. Component Object описывает сам компонент интерфейса, а Page Object включает его через композицию.

## Теория

Component Object представляет ограниченную область DOM с собственной ответственностью. Его корневой Locator задаёт границу поиска, поэтому одинаковые роли и тексты за пределами компонента не влияют на его Locators.

Композиция означает, что Page Object содержит Component Objects. Компоненту не обязательно знать всю `Page`: ему достаточно корневого Locator. Это уменьшает связанность и позволяет использовать компонент на разных страницах.

## Внутренний механизм

Цепочка Locators сохраняет область поиска. Вызов `root.getByRole(...)` ищет элемент внутри корневого Locator, а не во всём документе. Компонент использует те же auto-waiting и web-first assertions, что и любой Locator.

Page Object создаёт `NavigationComponent` из `page.getByRole("navigation")`. Тест взаимодействует с навигацией через страницу, не наследуя общий базовый класс.

## Главная ментальная модель

Страница собирается из объектов-компонентов так же, как интерфейс собирается из независимых областей DOM.

## Практические примеры

Заголовок, боковая панель, таблица данных и модальное окно могут иметь отдельные объекты. Корневой Locator каждого объекта ограничивает селекторы и делает одинаковые компоненты на странице различимыми.

## Automation QA

Component Objects уменьшают дублирование в Page Objects и позволяют команде менять один компонент интерфейса в одном месте. Тест при этом сохраняет язык пользовательского сценария.

## Концептуальные границы и компромиссы

Не каждый `div` заслуживает отдельного класса. Компонент полезен, когда у области есть собственное поведение, устойчивая граница или повторное использование. Слишком мелкая декомпозиция усложняет навигацию по коду.

## Распространённые ошибки

- Передавать компоненту всю `Page`, хотя достаточно корневого Locator.
- Создавать компонент для каждого элемента.
- Использовать наследование Page Objects для общего компонента интерфейса.
- Искать элементы компонента глобально.
- Позволять компоненту управлять несвязанными областями страницы.

## Краткие итоги

- Component Object моделирует независимую область UI.
- Корневой Locator задаёт границу поиска.
- Page Object включает компоненты через композицию.
- Композиция уменьшает связанность по сравнению с наследованием.
- Декомпозиция должна следовать реальным UI-границам.

## Что нужно запомнить

- Компонент владеет только своей областью.
- Цепочка Locators сохраняет границу корневого Locator.
- Повторное использование не требует базового класса страницы.
- Component Object должен иметь осмысленное поведение.
- Чрезмерное дробление ухудшает поддержку.
