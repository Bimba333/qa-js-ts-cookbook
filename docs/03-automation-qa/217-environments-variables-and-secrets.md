# Окружения, переменные и secrets

## Связь с предыдущей главой

Глава 216 связала тестовые файлы с именованными проектами Playwright. Теперь каждому запуску нужны внешние адреса, режимы и чувствительные значения.

## Цель главы

Разделить настройки окружения, секреты и исходный код, сохранив явные обязательные и необязательные значения и безопасную диагностику.

## Главный вопрос

> Как передавать различия окружений и чувствительные данные без hardcode?

## Мотивация

Жёстко заданный адрес или token связывает тест с одной машиной и создаёт риск раскрытия учётных данных. Без явной проверки отсутствующая переменная может незаметно направить запуск в неверное окружение.

## Теория

Переменные окружения являются входом процесса. Они всегда приходят как `string | undefined`, поэтому код обязан отличать обязательные значения от необязательных и не считать наличие строки доказательством её корректности.

Конфигурация проекта описывает режим Playwright, а секрет предоставляет внешняя среда. Секрет нельзя хранить в репозитории, включать в сообщение об ошибке или выводить целиком. Маскирование заменяет всё чувствительное значение безопасным маркером.

Локальное окружение и CI могут передавать значения разными способами, но приложение должно получать один контракт. В примере разрешены только `local` и `preview`. Отсутствующее обязательное значение должно завершать запуск с понятной ошибкой; неявный переход на production недопустим.

## Внутренний механизм

Node.js предоставляет переменные через `process.env`. Загрузчик читает снимок входных значений, проверяет обязательные поля и формирует отдельное представление. Тесты загрузчика передают обычный объект и не меняют глобальный `process.env`.

## Главная ментальная модель

Переменные окружения — недоверенный внешний запрос к конфигурации; секрет — часть запроса, которую нельзя возвращать в диагностике.

## Практический пример

```text
examples/03-automation-qa/chapter-217/01-environment-and-secrets.execution.ts
```

Пример загружает тестовые значения и проверяет, что token доступен рабочему коду, но всегда заменяется на `[REDACTED]` в диагностическом объекте.

## Automation QA

URL тестового API, имя окружения и token имеют разных владельцев. Их нужно передать перед запуском, а не менять между тестами. Логи должны помогать определить окружение без раскрытия учётных данных.

## Компромиссы

Большое число переменных окружения делает запуск гибким, но размывает контракт. Выносить наружу следует только реальные различия окружений, оставляя стабильные значения в коде.

## Распространённые ошибки

- Хранить token в конфигурационном файле репозитория.
- Использовать production как значение по умолчанию.
- Логировать весь `process.env`.
- Менять `process.env` в одном тесте и не восстанавливать его.

## Краткие итоги

- Переменные окружения являются внешними строками.
- Обязательные и необязательные значения обрабатываются явно.
- Секреты не хранятся и не логируются.
- Выбор проекта и передача секретов решают разные задачи.
