# Загрузка и runtime validation конфигурации

## Связь с предыдущей главой

Глава 217 определила внешние источники конфигурации. Их значения остаются недоверенными строками, пока программа не проверит форму и смысл.

## Цель главы

Построить загрузчик, который читает, преобразует и валидирует внешние значения, возвращая типизированный результат или диагностическую ошибку до старта тестов.

## Главный вопрос

> Как завершить запуск сразу, если внешняя конфигурация неполна или некорректна?

## Мотивация

Ошибка `Cannot read properties of undefined` в середине теста скрывает настоящую причину — отсутствующую настройку. Раннее завершение сокращает расстояние между дефектом конфигурации и сообщением о нём.

## Теория

Загрузчик конфигурации читает внешние строки, удаляет незначащие пробелы, разбирает значения и проверяет ограничения. Только после этих шагов появляется `RuntimeConfig`. TypeScript описывает результат загрузчика, но не проверяет `process.env` во время выполнения.

Нормализация удаляет допустимые различия вроде внешних пробелов. Разбор переводит строку в `number`, проверенный URL или ограниченное значение. Runtime validation проверяет обязательность, диапазоны, протоколы и разрешённые окружения. Диагностическая ошибка называет поле и правило, но не раскрывает секрет.

## Внутренний механизм

```mermaid
flowchart LR
    E[Внешние строки] --> N[Удалить внешние пробелы]
    N --> P[Разобрать значения]
    P --> V[Runtime validation]
    V -->|успех| C[Типизированная конфигурация]
    V -->|ошибка| F[Завершить запуск]
```

Загрузчик не должен возвращать частично валидный объект. После успешного вызова остальной код получает readonly-результат, замороженный через `Object.freeze()`, с примитивными полями и не повторяет проверки каждого поля. Это поверхностная, а не глубокая заморозка; в примере вложенных изменяемых значений нет.

## Главная ментальная модель

Загрузчик — пограничный контроль между непроверенной внешней средой и типизированным внутренним кодом.

## Практический пример

```text
examples/03-automation-qa/chapter-218/01-runtime-config-validation.execution.ts
```

Пример подтверждает успешную загрузку замороженного результата, а также отказ при неизвестном окружении, некорректном URL, запрещённом протоколе и отсутствующем token. Никакого неявного перехода на production не происходит. URL возвращается строкой, поэтому загрузчик не передаёт вызывающему коду изменяемый объект `URL`.

## Automation QA

Конфигурацию следует загрузить до начала дорогих операций браузера, API или базы данных. Тогда ошибка запуска не маскируется под дефект продукта и содержит точное имя некорректной настройки.

## Компромиссы

Строгая runtime validation требует описать контракт, но делает запуск воспроизводимым. Чрезмерная проверка внутренних констант лишь усложняет загрузчик; проверять нужно внешнюю границу.

## Распространённые ошибки

- Использовать type assertion вместо runtime validation.
- Преобразовывать `Number(value)` без проверки результата.
- Возвращать объект после первой обнаруженной частичной ошибки.
- Включать secret в текст исключения.

## Краткие итоги

- Внешняя строка не становится безопасной из-за TypeScript-типа.
- Загрузчик нормализует строки, разбирает значения и выполняет runtime validation.
- Успех возвращает полный типизированный результат.
- Некорректный запуск завершается до тестовых действий.
