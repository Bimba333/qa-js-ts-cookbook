# Interface

## Связь с предыдущей главой

Type alias дал имя объектной форме.

Interface решает похожую задачу, но особенно хорошо подходит для описания публичного объектного договора.

## Главный вопрос

> Как описывать объектный контракт, который будут реализовывать разные части проекта?

Короткий ответ: `interface` описывает форму объекта, которую TypeScript проверяет по свойствам и методам.

## Мотивация

В большом проекте разные части кода должны договориться о публичной форме объекта.

Например, reporter должен иметь метод записи сообщения, а helper не должен знать его внутреннюю реализацию.

Interface описывает такой внешний договор.

## Теория

Interface объявляется через `interface`:

```typescript
interface Reporter {
  name: string;
  write(message: string): void;
}
```

Объект подходит под interface, если имеет нужную форму.

```typescript
const consoleReporter: Reporter = {
  name: 'console',
  write(message: string): void {
    console.log(message);
  },
};
```

## Внутренний механизм

Interface существует только на этапе проверки TypeScript.

В runtime остается обычный JavaScript-объект.

TypeScript сравнивает форму объекта с описанным interface.

## Главная ментальная модель

Interface — это публичный договор объекта.

Он говорит: "Мне не важно, как объект устроен внутри, но снаружи у него должны быть эти свойства и методы".

## Automation QA

Interface полезен для helpers и reporting:

```typescript
interface Logger {
  log(message: string): void;
}
```

Любой объект с методом `log` может использоваться там, где ожидается `Logger`.

## Распространённые ошибки

### Ошибка 1. Думать, что interface создает класс

Interface не создает runtime-конструктор.

### Ошибка 2. Описывать детали реализации

Interface должен описывать внешний договор, а не внутренние временные переменные.

### Ошибка 3. Путать method signature и вызов метода

В interface описывается форма метода, а не его выполнение.
