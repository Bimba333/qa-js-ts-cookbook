# keyof Constraints

## Связь с предыдущей главой

Generic constraint позволяет требовать минимальную форму объекта.

Теперь нужно связать два параметра: объект и ключ, который точно существует в этом объекте.

## Главный вопрос

Как разрешить только ключи существующего объекта?

## Мотивация

В JavaScript можно обратиться к любому ключу:

```ts
function readValue(object: object, key: string) {
  // TypeScript не знает, есть ли такой ключ.
}
```

TypeScript может сделать такой доступ безопаснее через `keyof`.

## Теория

### `keyof` превращает форму в список ключей

```ts
type Config = { baseUrl: string; retries: number };
type ConfigKey = keyof Config;   // 'baseUrl' | 'retries'
```

Результат — объединение литеральных типов ключей. Это позволяет говорить о ключах так же строго, как о значениях.

### Связка «объект и его ключ»

Основной приём модуля:

```ts
function pickValue<ObjectType, Key extends keyof ObjectType>(
  object: ObjectType,
  key: Key,
): ObjectType[Key] {
  return object[key];
}
```

Здесь работают две конструкции сразу:

- `Key extends keyof ObjectType` — ключ обязан принадлежать именно этому объекту;
- `ObjectType[Key]` — **индексированный доступ**: тип значения по этому ключу.

Результат точный, а не общий:

```ts
const config = { baseUrl: "https://service.local", retries: 2 };

const retries = pickValue(config, "retries");   // number
const baseUrl = pickValue(config, "baseUrl");   // string
pickValue(config, "nope");                       // ошибка: такого ключа нет
```

Без этой связки пришлось бы объявить ключ как `string`, а результат — как объединение всех типов значений. Точность потерялась бы в обоих местах.

### Индексированный доступ работает и отдельно

`ObjectType[Key]` — самостоятельная конструкция, полезная и вне дженериков:

```ts
type Config = { baseUrl: string; retries: number };

type BaseUrl = Config["baseUrl"];              // string
type AnyValue = Config[keyof Config];          // string | number
```

Последняя запись даёт объединение типов всех значений — частый способ получить «тип любого значения этого объекта».

### `keyof` для индексной сигнатуры

Неочевидный случай:

```ts
type Dict = { [k: string]: number };
type DictKeys = keyof Dict;   // string | number
```

Откуда `number`? Потому что в JavaScript числовой ключ приводится к строке, значит числом тоже можно обратиться. Помнить об этом стоит: результат шире, чем ожидается.

### `keyof` и массивы

У массива ключами считаются не только индексы, но и все его методы:

```ts
type ArrayKeys = keyof string[];   // number | 'length' | 'push' | 'map' | …
```

Поэтому для работы с элементами используют не `keyof`, а индексированный доступ: `string[][number]` даёт тип элемента.

### Практическая ценность

Приём закрывает целый класс ошибок в работе с конфигурациями и тестовыми данными: опечатка в имени ключа становится ошибкой компиляции, а тип результата остаётся точным без ручных утверждений.

Это заметно надёжнее, чем распространённая альтернатива с `key: string` и приведением результата через `as`.

## Внутренний механизм

```mermaid
flowchart TD
    A[ObjectType] --> B[keyof ObjectType]
    B --> C[Key ограничен существующими ключами]
    C --> D[object[key] имеет точный тип]
```

Проверка работает на этапе компиляции. Во время выполнения остается обычный доступ к свойству.

## Главная ментальная модель

`keyof` превращает форму объекта в список разрешенных ключей.

## Практические примеры

```ts
function pickValue<ObjectType, Key extends keyof ObjectType>(
  object: ObjectType,
  key: Key,
): ObjectType[Key] {
  return object[key];
}

const config = {
  baseUrl: "https://service.local",
  retries: 2,
};

const retries = pickValue(config, "retries");
```

## Automation QA

Во вспомогательной функции для конфигурации можно запретить несуществующие ключи:

```ts
const environment = {
  name: "staging",
  baseUrl: "https://staging.example.test",
  retries: 1,
};

const baseUrl = pickValue(environment, "baseUrl");
```

Если указать ключ, которого нет в объекте, TypeScript покажет ошибку.

## Распространённые ошибки

Ошибка — использовать просто `string` для ключа:

```ts
function read(object: { id: string }, key: string) {
  // object[key] небезопасен
}
```

Если ключ связан с объектом, лучше выразить эту связь через `Key extends keyof ObjectType`.

## Распространённые мифы

**Миф: `keyof` возвращает массив ключей.**
Он возвращает объединение литеральных типов ключей, а не значение.

**Миф: `keyof` для словаря даёт только `string`.**
Даёт `string | number`: числовой ключ в JavaScript приводится к строке.

**Миф: `keyof` массива даёт индексы.**
В объединение попадают и все методы массива. Для элемента используют индексированный доступ.

**Миф: достаточно объявить ключ как `string`.**
Тогда теряются и проверка имени, и точность типа результата.

## Частые вопросы

**Что такое `ObjectType[Key]`?**
Индексированный доступ: тип значения по указанному ключу. Работает и без дженериков.

**Как получить тип любого значения объекта?**
`Config[keyof Config]` — объединение типов всех значений.

**Как получить тип элемента массива?**
`Items[number]`, а не через `keyof`.

**Зачем два параметра типа, если объект один?**
Первый описывает объект, второй — конкретный переданный ключ. Их связь и даёт точный результат.

## Краткие итоги

- `keyof` получает union ключей объекта.
- `K extends keyof T` ограничивает ключ существующими свойствами.
- `T[K]` возвращает тип значения по ключу.
- Это связь на этапе компиляции, а не валидация во время выполнения.
- Такой прием полезен для вспомогательных функций конфигурации и безопасного выбора свойств.
