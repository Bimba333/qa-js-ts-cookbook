# Enum

## Связь с предыдущей главой

Мы уже умеем описывать конкретные значения через литеральные типы и сохранять их через `as const`.

Но в TypeScript есть отдельная конструкция для именованных наборов значений — `enum`.

## Главный вопрос

> Когда нужен enum, если есть литеральные типы?

Короткий ответ: `enum` задает именованный набор значений и существует в сгенерированном JavaScript.

## Мотивация

Иногда команде нужен общий список именованных значений: например, статусы отчета или режимы запуска.

Литеральные типы существуют только для проверки.

`enum` отличается тем, что после компиляции остается объект во время выполнения.

## Теория

### Enum порождает код

Это главное отличие enum от всего остального в системе типов.

```typescript
enum TestStatus {
  Passed = 'passed',
  Failed = 'failed',
}
```

После компиляции остаётся настоящий объект: его можно передать, перебрать, напечатать. `interface` и `type` так не умеют — они стираются.

Отсюда и главный вопрос при выборе: **нужен ли объект во время выполнения?** Если нет, enum добавляет код без пользы.

### Числовой enum и обратное отображение

```typescript
enum RetryMode { Off, On }
```

Без явных значений члены нумеруются с нуля. Объект во время выполнения содержит **оба направления**:

```typescript
RetryMode.Off    // 0
RetryMode[0]     // 'Off'
```

Обратное отображение иногда удобно для диагностики, но именно оно делает объект вдвое больше и позволяет случайно получить имя там, где ожидалось значение.

### Строковый enum устроен проще

У строкового enum обратного отображения нет: `Str['passed']` — ошибка. Объект хранит только имена членов и их строковые значения.

Строковые значения к тому же читаемы в логах и отчётах, поэтому для статусов и режимов они предпочтительнее числовых.

### Enum — номинальный тип

Необычное свойство на фоне остального TypeScript: enum проверяется **по имени**, а не по форме.

```typescript
const s: TestStatus = 'passed';   // ошибка, хотя значение совпадает
const n: RetryMode = 5;           // ошибка, хотя это число
```

Строка, равная значению члена, не подходит: нужен именно член enum. Для номинальности это плюс, для совместимости с внешними данными — минус: значение из JSON придётся приводить явно.

### `const enum` и почему его обычно избегают

`const enum` не создаёт объект: компилятор подставляет значения прямо в места использования.

Выглядит привлекательно, но плохо сочетается с раздельной компиляцией файлов — а именно так работают современные сборщики и транспиляторы, включая запуск тестов Playwright. Поэтому в проектах с изолированной компиляцией `const enum` обычно запрещают.

### Альтернатива без кода во время выполнения

Ту же задачу чаще решают объединением литералов:

```typescript
type TestStatus = 'passed' | 'failed';
```

А если нужен ещё и перебираемый список, его строят из значения:

```typescript
const TEST_STATUSES = ['passed', 'failed'] as const;
type TestStatus = typeof TEST_STATUSES[number];
```

Получается и тип, и массив для перебора — без отдельной конструкции языка и без обратных отображений.

### Когда enum всё же оправдан

Когда объект действительно нужен как значение: перебрать члены, построить отображение, передать в стороннюю библиотеку, ожидающую enum. Во всех остальных случаях объединение литералов проще и дешевле.

## Внутренний механизм

TypeScript проверяет, что значение соответствует enum.

После компиляции обычный `enum` остается в JavaScript как объект.

Это важно: enum не является только типом, в отличие от type alias или interface.

У числового enum во время выполнения есть отображение имени в число и обратное отображение числа в имя. У строкового enum обратного отображения нет: объект хранит имена элементов и их строковые значения.

## Главная ментальная модель

Enum — это именованный список значений, который виден и TypeScript, и коду во время выполнения.

Если объект во время выполнения не нужен, литеральные типы часто оказываются проще.


## Распространённые ошибки

### Ошибка 1. Использовать enum для любого набора строк

Если объект во время выполнения не нужен, литеральные типы могут быть проще.

### Ошибка 2. Забывать, что enum остается в JavaScript

Обычный enum не исчезает после компиляции.

### Ошибка 3. Смешивать enum и произвольные строки

Если функция ожидает `TestStatus`, лучше передавать значение enum, а не случайную строку.

## Распространённые мифы

**Миф: enum — это просто удобный синтаксис для набора констант.**
Он порождает объект во время выполнения, в отличие от `type` и `interface`.

**Миф: строка, равная значению члена, подойдёт вместо enum.**
Enum проверяется по имени: нужен именно его член.

**Миф: у любого enum есть обратное отображение.**
Только у числового. У строкового объект хранит одно направление.

**Миф: `const enum` — просто оптимизация без последствий.**
Он плохо сочетается с изолированной компиляцией файлов, поэтому во многих проектах запрещён.

## Частые вопросы

**Что выбрать: enum или объединение литералов?**
Если объект во время выполнения не нужен — объединение. Оно проще, не добавляет кода и легко превращается в список через `as const`.

**Почему значение из JSON не подходит под enum?**
Enum номинален: строка с тем же содержимым не является его членом. Нужна проверка и явное приведение.

**Зачем вообще нужно обратное отображение?**
Для диагностики: по числу получить имя. Но чаще оно только увеличивает объект и создаёт неоднозначность.

**Как перебрать значения объединения литералов?**
Собрать массив через `as const` и вывести тип из него: значения и тип останутся согласованными.
