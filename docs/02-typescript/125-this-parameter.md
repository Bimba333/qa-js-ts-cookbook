# this Parameter

## Связь с предыдущей главой

Мы описали разные сигнатуры вызова функции.

Теперь важно вспомнить, что в JavaScript результат функции может зависеть не только от аргументов, но и от `this`.

## Главный вопрос

> Как TypeScript помогает контролировать this в функциях?

Короткий ответ: специальный this-параметр описывает, каким должен быть контекст вызова функции.

## Мотивация

В JavaScript метод можно отделить от объекта и потерять исходный `this`.

В QA-коде это особенно опасно для объектных helpers и Page Object-подобных структур: метод ожидает состояние объекта, но вызывается как обычная функция.

TypeScript помогает явно описать ожидаемый `this`.

## Теория

this-параметр записывается первым параметром, но не передается как обычный аргумент:

```typescript
type Counter = {
  value: number;
};

function increment(this: Counter, step: number): number {
  return this.value + step;
}
```

Такой параметр существует только для проверки TypeScript.

Во время выполнения `this` определяется обычными правилами JavaScript.

Метод объекта и свободная функция ведут себя по-разному:

```typescript
const counter = {
  value: 1,
  increment(step: number): number {
    return this.value + step;
  },
};
```

## Внутренний механизм

TypeScript не меняет правила привязки `this`.

Он только проверяет, что функция с this-параметром вызывается с подходящим контекстом.

Если функция передается как callback, контекст может потеряться. Поэтому контекст callback нужно описывать явно или избегать зависимости от `this`.

## Главная ментальная модель

this-параметр — это невидимый во время выполнения договор о получателе вызова.

Он говорит TypeScript: "эта функция ожидает, что ее вызовут с таким объектом в роли `this`".

## Automation QA

В объектных helpers лучше не терять контекст:

```typescript
const reportHelper = {
  prefix: '[report]',
  format(message: string): string {
    return `${this.prefix} ${message}`;
  },
};
```

Если метод зависит от `this`, его нельзя бездумно передавать как обычный callback.

## Распространённые ошибки

### Ошибка 1. Думать, что this-параметр передается аргументом

Он нужен только TypeScript и не становится реальным параметром функции.

### Ошибка 2. Ожидать, что TypeScript привяжет `this`

TypeScript проверяет контекст, но не выполняет `bind`.

### Ошибка 3. Передавать метод как callback без учета контекста

Так можно потерять объект, от которого метод зависит.

## Краткие итоги

Главное:

* this-параметр описывает ожидаемый контекст вызова;
* он не является аргументом во время выполнения;
* TypeScript не меняет JavaScript-правила `this`;
* методы и свободные функции могут вести себя по-разному;
* callback может потерять контекст.
