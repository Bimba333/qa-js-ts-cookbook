# Intersection Types

## Связь с предыдущей главой

Union type описывает выбор: значение подходит под один из вариантов.

Intersection type описывает объединение требований: значение должно удовлетворять всем частям сразу.

## Главный вопрос

> Как объединить несколько требований к одному значению?

Короткий ответ: intersection type соединяет несколько типов через `&`, и итоговое значение должно соответствовать каждому из них.

## Мотивация

В QA-проекте отчетная запись может иметь данные теста и общие метаданные.

Не хочется копировать одни и те же свойства в каждый тип.

Intersection позволяет собрать один контракт из нескольких частей.

## Теория

### «И то, и другое»

Intersection требует, чтобы значение удовлетворяло **всем** частям сразу:

```typescript
type TestInfo = { title: string };
type WithDuration = { durationMs: number };

type ReportEntry = TestInfo & WithDuration;

const entry: ReportEntry = { title: 'login', durationMs: 120 };
```

Полезная симметрия с объединением: `|` требует соответствия **любому** варианту, `&` — **каждому**.

Порядок частей значения не имеет: `A & B` и `B & A` — один и тот же тип.

### Конфликт свойств порождает `never`

Если части требуют несовместимые типы одного свойства, компилятор не выбирает «последнее» и не объединяет объекты:

```typescript
type Conflict = { id: string } & { id: number };
```

Тип свойства `id` становится `never` — типом, у которого нет значений. Ошибки в объявлении не будет; она появится при попытке что-нибудь присвоить.

Это существенное отличие от `interface extends`, который сообщает о конфликте сразу в месте объявления. Подробнее сравнение — в главе 113.

### Пересечение функций — это перегрузка

Менее известное, но полезное свойство:

```typescript
type F = ((a: string) => number) & ((a: number) => string);
```

Значение такого типа можно вызвать обоими способами: со строкой — получить число, с числом — строку. Компилятор выберет подходящую сигнатуру по аргументу.

Так описывают функции с разным поведением для разных типов аргументов — альтернатива перегрузкам, которые разбираются в главе 124.

### Пересечение примитивов бессмысленно

`string & number` — тип без значений, то есть `never`. Никакое значение не может быть одновременно строкой и числом.

Исключение — приём с меткой из главы 114: `string & { __brand: 'UserId' }` работает именно потому, что помечающая часть существует только при проверке и не требует настоящего свойства.

### Ничего не происходит во время выполнения

Intersection не вызывает `Object.assign` и не создаёт новый объект. Это требование к значению, а не операция над ним.

Собрать объект по-прежнему нужно самому — например, распространением свойств.

### Когда пересечение, а когда `extends`

Практический ориентир:

| Ситуация | Инструмент |
| --- | --- |
| Публичный объектный договор, который расширяют | `interface extends` |
| Добавить общий блок полей к нескольким типам | `&` |
| Части приходят из разных модулей и не образуют иерархию | `&` |
| Нужна ранняя диагностика конфликта | `interface extends` |

## Внутренний механизм

Intersection type работает только на этапе проверки TypeScript.

Он не вызывает `Object.assign` и не объединяет объекты во время выполнения.

Если две части требуют несовместимые типы одного свойства, итоговое требование может стать невозможным для нормального значения.

Например, если одно требование говорит `id: string`, а другое — `id: number`, TypeScript не выбирает "последнее" свойство и не объединяет объект во время выполнения. Он требует значение, которое одновременно удовлетворяет обоим условиям, а для обычного `string` и `number` такого значения нет.

## Главная ментальная модель

Intersection type — это "и то, и другое".

Значение должно пройти все проверки сразу.


## Распространённые ошибки

### Ошибка 1. Считать `&` JavaScript-оператором AND

В позиции типа `&` означает intersection type.

### Ошибка 2. Ожидать слияние объектов во время выполнения

Intersection не создает новый объект во время выполнения.

### Ошибка 3. Использовать intersection вместо понятного interface extends без причины

Если нужен публичный объектный договор с расширением, interface может быть читабельнее.

## Распространённые мифы

**Миф: `&` в позиции типа — это логическое И из JavaScript.**
Это отдельный оператор системы типов. К значениям он отношения не имеет.

**Миф: пересечение объединяет объекты во время выполнения.**
Оно описывает требование к значению. Объект нужно собрать самому.

**Миф: при конфликте свойств побеждает последнее.**
Тип свойства становится `never`, и создать такое значение невозможно.

**Миф: пересечение и `extends` взаимозаменяемы.**
`extends` сообщает о конфликте в объявлении, пересечение — молчит до использования.

## Частые вопросы

**Почему объект с конфликтом не удаётся создать?**
Свойство получило тип `never`, а значений такого типа не существует.

**Зачем пересекать функции?**
Чтобы описать разное поведение для разных типов аргументов — компилятор выберет подходящую сигнатуру.

**Имеет ли значение порядок частей?**
Нет, `A & B` и `B & A` эквивалентны.

**Когда предпочесть `extends`?**
Когда описывается расширяемый объектный договор и важно раннее обнаружение конфликта.
