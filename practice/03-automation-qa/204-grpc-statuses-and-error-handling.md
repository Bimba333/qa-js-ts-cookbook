# Практика: Статусы gRPC и обработка ошибок

## Задача 1. Концептуальные вопросы

Что содержат `code`, `details` и metadata объекта `ServiceError`? Чем бизнес-отказ отличается от недоступности service?

## Задача 2. Анализ статуса

Распределите случаи: пустой `title`, неизвестный ID, повторяющийся `title`, отсутствующий token, read-only token, истёкший deadline.

## Задача 3. Предскажите результат

Server не запущен, а тест ожидает `NOT_FOUND`. Какой класс отказа фактически наблюдается?

## Задача 4. Поиск ошибки

Проверка использует только `rejects.toBeTruthy()`. Добавьте точную проверку стабильных свойств ошибки.

## Задача 5. Automation QA

Создайте таблицу негативных сценариев с причиной в request, ожидаемым status, правилом проверки `details` и последующей проверкой состояния.

## Задача 6. Мини-проект

Реализуйте локальные `INVALID_ARGUMENT`, `NOT_FOUND` и `ALREADY_EXISTS`, затем проверьте `code` и стабильные `details`.
