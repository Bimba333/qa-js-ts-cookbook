# Практика: Проверка API-ответов и бизнес-правил

## Задача 1. Концептуальные вопросы

Разделите HTTP-контракт, форму ответа и проверку бизнес-правила. Какой вопрос задаёт каждый уровень?

## Задача 2. Анализ проверок

После POST тест проверяет 201, `Location`, тип ID и сохранённый `title`. Распределите проверки по уровням.

## Задача 3. Предскажите результат

API добавил необязательное поле `updatedAt`, а тест сравнивает весь объект через `toEqual`. Будет ли падение означать нарушение проверяемого правила?

## Задача 4. Поиск ошибки

Тест проверяет только `response.ok()` и объявляет создание корректным. Добавьте минимальные точные проверки без снимка всего ответа.

## Задача 5. Automation QA

Сформулируйте диагностические сообщения для неверного кода состояния, `Location` и сохранённого бизнес-значения.

## Задача 6. Мини-проект

Проверьте локальный POST на трёх уровнях: код состояния и заголовок, обязательные поля ответа, связь тела с отправленными данными.
