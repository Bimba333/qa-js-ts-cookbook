# Практика: Transactions, rollback и test isolation

## 1. Граница транзакции

Объясните, почему транзакция принадлежит одному подключению, а не всему тестовому процессу.

## 2. Предскажите результат

Тест выполняет `BEGIN` и `INSERT`, а API читает через другое подключение до `COMMIT`. Может ли API увидеть строку? Укажите, что точный ответ зависит от уровня изоляции, а в обычном `READ COMMITTED` незафиксированная строка не видна.

## 3. Отладка прерванной транзакции

После нарушения ограничения тест продолжает `SELECT` без `ROLLBACK`. Объясните SQLSTATE `25P02` и исправьте поток выполнения.

## 4. Реализация отката

Напишите транзакцию, которая всегда выполняет `ROLLBACK` в `finally`, и проверьте отсутствие строки.

## 5. Граница внешних эффектов

Объясните, почему `ROLLBACK` не отменяет HTTP-запрос, сообщение или запись другого подключения.

## 6. Мини-проект: выбор изоляции

Выберите откат для теста репозитория и уникальные закоммиченные данные для теста API. Обоснуйте разные стратегии.
