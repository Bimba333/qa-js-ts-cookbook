# Практика: Playwright и Playwright Test

## Задача 1. Концептуальные вопросы

Разделите обязанности библиотеки Playwright и Playwright Test. Кто управляет браузером, а кто обнаруживает тесты и формирует результат запуска?

## Задача 2. Классификация

Распределите по владельцам: `Page`, `Locator`, `test()`, built-in fixtures, проверки, отчётность, браузерные действия.

## Задача 3. Предскажите результат

```ts
import { expect, test } from "@playwright/test";

test("статус", async ({ page }) => {
  await page.setContent("<p>Готово</p>");
  await expect(page.getByText("Готово")).toBeVisible();
});
```

Что делает библиотека, что делает тестовый раннер и каким будет результат?

## Задача 4. Debugging

Инженер запускает обычный скрипт с `chromium.launch()` и ожидает автоматический отчёт по тестам. Объясните ошибку модели и предложите минимальное направление исправления.

## Задача 5. Automation QA

Для регрессионного набора нужны единый запуск, timeout, проверки и результаты. Обоснуйте выбор Playwright Test, не утверждая, что прямое использование API библиотеки бесполезно.

## Задача 6. Мини-проект

Напишите минимальный тест локальной страницы с заголовком `Стенд готов`. Используйте `page.setContent()`, `getByRole` и `toBeVisible`. Укажите ожидаемый результат.
