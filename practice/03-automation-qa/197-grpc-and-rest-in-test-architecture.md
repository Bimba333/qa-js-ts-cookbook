# Практика: gRPC и REST в тестовой архитектуре

## Задача 1. Концептуальные вопросы

Чем REST API, ориентированный на ресурсы, отличается от gRPC service, ориентированного на RPC methods? Какие свойства тест должен наблюдать в каждом случае?

## Задача 2. Анализ границы

Команда предлагает универсальный `call(method, payload)`, который возвращает только данные и скрывает HTTP status, gRPC status и metadata. Объясните риск и предложите границы clients.

## Задача 3. Предскажите результат

Тест ожидает HTTP 404 после вызова gRPC `GetTask`. Какой результат фактически должен проверяться, если ресурс отсутствует?

## Задача 4. Поиск ошибки

Тест вызывает публичный демонстрационный gRPC endpoint и зависит от его данных. Перестройте стратегию для детерминированного запуска.

## Задача 5. Automation QA

Для системы с публичным REST API и внутренним gRPC service определите по одному полезному сценарию каждого уровня и один случай оправданного сравнения.

## Задача 6. Мини-проект

Запустите локальный gRPC service, вызовите unary method через сгенерированный client, проверьте response и закройте client и server в `finally`.
