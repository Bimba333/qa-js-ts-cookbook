# Практика: Конфликты данных и параллельные тесты

## 1. Общие строки

Объясните, почему общая изменяемая запись создаёт зависимость от порядка выполнения даже при одном worker.

## 2. Предскажите результат

Два теста одновременно вставляют задачу с одинаковым PRIMARY KEY. Какой результат ожидается и почему повтор не исправляет владение данными?

## 3. Отладка гонки при очистке

Два worker удаляют строки по общему префиксу. Найдите риск и предложите точные идентификаторы.

## 4. Реализация уникального пространства имён

Постройте ID задачи из идентификаторов worker и сценария без общего изменяемого счётчика.

## 5. Детерминированная проверка

Напишите `SELECT id ... ORDER BY id` для двух пространств имён и объясните необходимость упорядочивания.

## 6. Мини-проект: данные для параллельного запуска

Создайте две независимые задачи, проверьте обе и выполните очистку только по принадлежащим сценарию ID.
