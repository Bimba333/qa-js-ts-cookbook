# Практика: Что такое Automation QA Framework

## Задача 1. Концептуальные вопросы

1. Чем фреймворк отличается от изолированного тестового скрипта?
2. Почему инструмент автоматизации браузера не определяет архитектуру проекта?
3. Когда сложный фреймворк может быть лишним?

## Задача 2. Классификация

Команда имеет 12 скриптов. Каждый сам читает URL, создаёт пользователя, выполняет проверку и печатает ошибку. Назовите две ответственности фреймворка, которые уже стоит выделить, и одну абстракцию, которую пока нельзя обосновать.

## Задача 3. Предскажите результат выполнения кода

```ts
type TestContext = { orderId: string };

function run(context: TestContext): void {
  console.log(`Проверка ${context.orderId}`);
}

run({ orderId: "order-42" });
```

Что будет выведено и какую границу представляет `TestContext`?

## Задача 4. Отладка архитектуры

В каждом тесте повторяются URL, токен и запрос очистки данных. Объясните проблему и предложите минимальное изменение без создания универсального фреймворка.

## Задача 5. Automation QA

Для проекта из трёх стабильных smoke-тестов решите, нужны ли отдельный слой отчётности, десять Page Objects и собственный тестовый раннер. Обоснуйте каждое решение.

## Задача 6. Мини-проект

Опишите минимальный фреймворк для пяти сценариев работы с заказами. Укажите тестовый код, конфигурацию, жизненный цикл данных и диагностику. Для каждого элемента назовите ответственность и причину появления.
