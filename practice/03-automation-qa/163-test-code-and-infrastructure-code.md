# Практика: Тестовый и инфраструктурный код

## Задача 1. Концептуальные вопросы

Чем намерение теста отличается от инфраструктурного механизма? Почему устранение любого дублирования не является целью?

## Задача 2. Классификация кода

Распределите обязанности: выбрать ожидаемый статус заказа, загрузить токен, открыть соединение, создать уникальный email, сравнить бизнес-результат, закрыть соединение, сохранить запись журнала.

## Задача 3. Предскажите результат выполнения кода

```ts
const order = { id: "order-42", status: "created" };
console.log(`${order.id}: ${order.status}`);
```

Что будет выведено? Какие части этих данных принадлежат намерению сценария?

## Задача 4. Улучшите читаемость

```ts
await helper.run("admin", "order-42", true);
```

Предложите вызовы, которые сохраняют язык предметной области. Не реализуйте транспортное взаимодействие.

## Задача 5. Automation QA

Два теста повторяют три строки подготовки. Опишите критерии, по которым вы решите оставить повторение или выделить общий компонент.

## Задача 6. Мини-проект

Разделите сценарий отмены заказа на тестовый и инфраструктурный код. Укажите публичные операции, владельцев, диагностические данные и детали, которые не должны попасть в тест.
