# Практика: Жизненный цикл данных в сценариях между слоями

## 1. Entity identity
Объясните, почему один идентификатор должен использоваться в API setup, UI action, проверке и cleanup.

## 2. Выбор слоя
Для проверки HTTP validation error выберите ближайший слой. Объясните, почему UI и database не обязательны.

## 3. Cleanup order
Предскажите порядок удаления parent и child, созданных именно в таком порядке. Объясните обратный порядок cleanup и почему он является правилом этого lifecycle, а не любого ресурса без исключений.

## 4. Failure-safe cleanup
Найдите две ошибки: cleanup регистрируется до успешного create или только после всех assertions. Предложите порядок, при котором failure до create не планирует удаление, а failure после create всё равно запускает cleanup.

## 5. Automation QA-задача
Спроектируйте сценарий API setup → UI action → API verification с одним cleanup owner и точным идентификатором.

## 6. Мини-проект: cross-layer lifecycle
Реализуйте локальные adapters для создания, изменения, чтения и удаления entity. Подтвердите точный cleanup после успешного и упавшего сценария, повторный cleanup и нулевое остаточное состояние без удаления широкого набора данных.
