# Практика: Расследование падения автотеста

## 1. Классификация
Для расхождения статуса перечислите признаки дефекта теста, framework, приложения, окружения, данных и инфраструктуры. Укажите, какие доказательства позволяют различить эти версии.

## 2. Предскажите результат
Тест упал один раз, затем прошёл после повторного запуска без изменений. Что доказал успешный запуск и чего он не доказал?

## 3. Сужение поиска
Составьте минимальный воспроизводимый сценарий с тем же config, project, environment name и seed. Меняйте только одну переменную за шаг.

## 4. Диагностика ложного исправления
Инженер увеличил timeout, ослабил assertion и отключил очистку. Объясните, почему первопричина остаётся неизвестной.

## 5. Automation QA-задача
API и database возвращают `pending`, UI ожидал `completed`. Сформулируйте симптом, доказательства, гипотезу, владельца и способ проверки исправления.

## 6. Мини-проект: карточка расследования
Реализуйте типизированную карточку с симптомом, доказательствами, гипотезой, владельцем, исправлением и проверкой. Запретите гипотезу без доказательств.
