# Практика: Структурированное логирование

## 1. Состав события
Определите level, имя события, идентификатор сценария, timestamp и поля для завершённого API-запроса без чувствительных данных.

## 2. Предскажите результат
Logger записывает `{ token: "secret", status: 401 }`, а маскирование выполняется после сериализации. Где останется секрет?

## 3. Выбор уровня
Распределите по уровням: начало setup, временно недоступный необязательный сервис, необработанная ошибка очистки, подробная структура локального payload.

## 4. Отладка границы logger
Logger перехватывает ошибку, пишет сообщение и возвращает `undefined`. Исправьте границу так, чтобы исходная ошибка сохранилась и оставалась наблюдаемой.

## 5. Automation QA-задача
Создайте безопасное событие запроса и ответа с method, path, status, duration и идентификатором сценария. Не записывайте body целиком.

## 6. Мини-проект: безопасный logger
Реализуйте типизированный logger, единые имена событий и маскирование token, authorization, cookie, password, connection string и storage state. Циклический или слишком большой payload не должен нарушать ограниченную сериализацию JSON. Проверьте `BigInt`, значение не типа `Error` и циклическую цепочку `Error.cause`.
