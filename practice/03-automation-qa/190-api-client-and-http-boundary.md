# Практика: API Client и граница HTTP-слоя

## Задача 1. Концептуальные вопросы

Что должен скрывать API Client и какой результат он не должен скрывать от негативного теста?

## Задача 2. Анализ публичного API

Сравните `post("/tasks", body)` и `createTask(data)`. Какой метод выражает смысл ресурса и когда общий транспортный метод всё же уместен внутри клиента?

## Задача 3. Предскажите результат

Метод `getTask()` всегда выбрасывает ошибку на 404. Как это повлияет на тест отсутствующего ресурса?

## Задача 4. Поиск ошибки

Один `UniversalApiClient` содержит пользователей, задачи, отчёты, повторы и проверки. Разделите ответственности без создания искусственной иерархии.

## Задача 5. Automation QA

Спроектируйте публичные методы `TasksClient` для создания, чтения и удаления. Укажите, где проверяется обязательный транспортный контракт и где остаётся проверка бизнес-правила.

## Задача 6. Мини-проект

Реализуйте небольшой `TasksClient`, которому передаются APIRequestContext и `baseURL`. Создайте задачу, прочитайте её и сохраните доступ к APIResponse для проверки кода состояния.
