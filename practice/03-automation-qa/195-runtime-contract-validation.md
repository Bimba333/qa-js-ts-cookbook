# Практика: Проверка контрактов во время выполнения

## Задача 1. Концептуальные вопросы

Почему interface TypeScript не проверяет JSON во время выполнения? Чем проверка контракта отличается от проверки бизнес-правила?

## Задача 2. Анализ границы

Код использует `await response.json() as Profile`. Объясните, какое предположение осталось непроверенным, и предложите вариант с `unknown`.

## Задача 3. Предскажите результат

Сервер вернул `{ id: 7, active: "yes" }`, а type assertion объявил значение типом `Profile`. Найдёт ли TypeScript ошибку во время теста автоматически?

## Задача 4. Поиск ошибки

Валидатор отклоняет любое новое необязательное поле. Оцените строгость и совместимость контракта с будущими расширениями.

## Задача 5. Automation QA

Опишите диагностику расхождения контракта для неверного типа `active`: какое поле, ожидаемый тип и фактическое значение должны быть видимы?

## Задача 6. Мини-проект

Напишите небольшой type guard для `{ id: string; active: boolean }`, проверьте локальный ответ как `unknown`, затем выполните проверку бизнес-правила.
