# Практика: Структура проекта и границы модулей

## Задача 1. Концептуальные вопросы

Объясните внутреннюю согласованность, связанность, публичный API и внутреннее устройство. Почему дерево папок само по себе не гарантирует архитектуру?

## Задача 2. Сравнение структур

Сравните организацию по слоям и по функциональности для проекта с `orders` и `users`. Назовите по одному преимуществу и риску каждого варианта.

## Задача 3. Предскажите результат выполнения кода

```ts
type Orders = { read(id: string): string };
const orders: Orders = { read: (id) => `${id}: created` };
console.log(orders.read("order-42"));
```

Что будет выведено? Что потребитель знает о внутренней реализации?

## Задача 4. Найдите скрытую связанность

Тесты импортируют внутренний обработчик ответа из API-модуля. Объясните риск и предложите публичную операцию, которая сохранит обработчик внутренним.

## Задача 5. Automation QA

В папке `helpers` находятся загрузчик конфигурации, SQL-запросы, генератор email и форматирование отчёта. Предложите более согласованных владельцев без требования создавать отдельный файл для каждой функции.

## Задача 6. Мини-проект

Выберите организацию по слоям, по функциональности или гибридный вариант для проекта с UI, REST и общей инфраструктурой тестовых данных. Составьте текстовый список модулей, публичных точек входа и разрешённых зависимостей. Обоснуйте компромиссы.
