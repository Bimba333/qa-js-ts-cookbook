# Практика: Принципы тестовой отчётности

## 1. Контракт отчёта
Перечислите идентичность теста, status, duration, steps, сведения о падении, окружение, links и владельца одного теста.

## 2. Предскажите результат
Reporter получает тест без предметных steps и attachments. Сможет ли он восстановить их из вызовов helper?

## 3. Названия steps
Замените шаги `call helper` и `check` на названия, выражающие бизнес-намерение сценария задачи.

## 4. Error details
Оберните ошибку API Client через `cause`, сохранив исходный stack и безопасный контекст.

## 5. Automation QA-задача
Добавьте owner, имя окружения и ссылку на test case без token, connection string и storage state.

## 6. Мини-проект: полезный отчёт
Создайте тест с устойчивой идентичностью, двумя предметными `test.step()`, annotations, `Error.cause` и ограниченным вложением.
