# Практика: Retry policy

## 1. Семантика retry
Объясните значения `testInfo.retry` для первой и повторной попыток при `retries: 1`.

## 2. Retry и repeat
Сравните индекс retry и `repeatEachIndex`; приведите ожидаемое число выполнений одного теста.

## 3. Retry и polling
Выберите механизм для eventual consistency и обоснуйте, почему retry всего теста хуже ограниченного polling конкретного условия.

## 4. Детерминированный дефект
Тест всегда ожидает неверный статус. Объясните результат при трёх retries.

## 5. Automation QA-задача
Сохраните отдельные доказательства первой и retry-попытки без общего изменяемого состояния. Покажите очистку состояния после упавшей попытки.

## 6. Мини-проект: контролируемый retry
Создайте изолированную конфигурацию, где попытка `0` падает, попытка `1` проходит, а основной набор остаётся зелёным. Проверьте exit code с retry и без него.
