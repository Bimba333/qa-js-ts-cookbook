# Практика: Организация test data

## 1. Классификация данных
Распределите справочник статусов, уникальный ID заказа, данные негативного сценария и URL API по категориям главы.

## 2. Предскажите результат
Два теста изменяют один объект в области модуля. Что произойдёт при изменении порядка?

## 3. Диагностика общей сущности
Набор тестов использует одного изменяемого пользователя. Определите владельца и предложите безопасную модель.

## 4. Реализация сценарных данных
Создайте объект задачи с уникальным диагностируемым ID и явным владельцем.

## 5. Персональные данные
Объясните, почему копия production-профиля не является подходящей тестовой заготовкой.

## 6. Мини-проект: каталог данных
Создайте справочник, замороженный через `Object.freeze()`, и Factory сценарных данных. Покажите, какие данные используются совместно, какие создаются заново и почему входные и ожидаемые объекты не должны разделять изменяемые ссылки.
