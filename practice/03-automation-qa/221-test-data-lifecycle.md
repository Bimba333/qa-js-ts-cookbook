# Практика: Жизненный цикл тестовых данных

## 1. Владение жизненным циклом
Объясните, кто регистрирует очистку ресурса и когда это нужно сделать.

## 2. Предскажите результат
Родительская запись с внешним ключом удаляется раньше дочерней. Какая ветка ошибки возникнет?

## 3. Диагностика потерянной ошибки
Проверка и очистка падают, но `catch` сохраняет только ошибку очистки. Что потеряно?

## 4. Реализация стека очистки
Напишите регистрацию асинхронных функций очистки и выполнение в обратном порядке. После ошибки одной функции продолжите остальные и сохраните все ошибки.

## 5. Очистка через API и базу данных
Определите безопасные ключи владения для каждого слоя.

## 6. Мини-проект: безопасный ResourceScope
Создайте родительский и дочерний ресурсы, сразу зарегистрируйте очистку, вызовите контролируемую ошибку и две ошибки очистки. Подтвердите LIFO, сохранение всех ошибок, однократное выполнение callbacks, безопасный повторный `close()` и запрет регистрации после закрытия.
