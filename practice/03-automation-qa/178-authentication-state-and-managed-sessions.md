# Практика: Authentication state и управляемые сессии

## Задача 1. Концептуальные вопросы

Что сохраняет `storageState`, зачем нужен setup project и почему файл состояния следует считать чувствительным артефактом?

## Задача 2. Анализ изоляции

Два теста загружают одно состояние роли администратора в свежие контексты. Какие значения браузерного состояния изолированы после старта и через какое серверное состояние тесты всё ещё могут конфликтовать?

## Задача 3. Предскажите результат

Контекст A и контекст B созданы из одного файла состояния. A изменяет cookie после создания. Какое значение увидит B?

## Задача 4. Поиск ошибки

Тест входа запускается в проекте с заранее заданным `storageState` и сразу попадает на защищённую страницу. Почему проверка неверна и как разделить проекты?

## Задача 5. Automation QA

Опишите стратегию файлов состояния для ролей `operator` и `admin`: имена, источник учётных данных, срок жизни, правила Git и владельца обновления.

## Задача 6. Мини-проект

Создайте setup project, который сохраняет cookie роли QA в локальный файл состояния, и зависимый проект, который проверяет cookie в свежем контексте. Не используйте реальный сервис или учётные данные.
