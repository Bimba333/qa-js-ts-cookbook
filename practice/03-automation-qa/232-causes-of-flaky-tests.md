# Практика: Причины flaky tests

## 1. Классификация результата
Классифицируйте серии `failed`, `failed/failed`, `failed/passed` и `failed/passed/failed` при одном сопоставимом контексте. Для каждой серии укажите, достаточно ли доказательств для следующего шага расследования.

## 2. Предскажите вывод
Браузер один раз не запустился в ограниченном sandbox. Можно ли назвать тест flaky и почему?

## 3. Изменяющееся условие
Для одинаковой конфигурации перечислите доказательства зависимости от времени, общего изменяемого состояния и конфликта данных.

## 4. Диагностика timeout
Объясните, почему тайм-аут не доказывает race condition и какие данные нужны для проверки гипотезы.

## 5. Automation QA-задача
API-тест иногда получает `409` при использовании общей записи. Сформулируйте гипотезу и способ её проверки без случайного поведения.

## 6. Мини-проект: классификатор запусков
Реализуйте типизированный классификатор серии: инфраструктурное падение, недостаточно доказательств, детерминированный успех, детерминированное падение, сигнал нестабильности, подтверждённый нестабильный паттерн.
