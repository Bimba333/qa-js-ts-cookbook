# Практика: HTTP и REST для API-тестирования

## Задача 1. Концептуальные вопросы

Объясните разницу между HTTP и REST. Что является ресурсом и что представляет его JSON-представление?

## Задача 2. Анализ метода

Тест дважды отправляет одинаковый PUT для `/tasks/task-7`. Опишите, какой итог ожидается от идемпотентной операции и что идемпотентность не гарантирует.

## Задача 3. Предскажите результат

Клиент повторяет DELETE уже удалённого ресурса. Обязан ли второй ответ иметь тот же код состояния, чтобы операция оставалась идемпотентной? Обоснуйте ответ.

## Задача 4. Поиск ошибки

Команда считает, что stateless API не хранит задачи между запросами, и не очищает данные. Найдите ошибку в ментальной модели и предложите правило изоляции.

## Задача 5. Automation QA

Для чтения отчёта, создания задачи, полного замещения настроек и удаления ресурса выберите уместные HTTP-методы. Для каждого укажите, какую семантику должен подтвердить контракт.

## Задача 6. Мини-проект

Напишите локальный Playwright API-тест, который дважды отправляет одинаковый PUT для известного ID и подтверждает одно итоговое представление ресурса. Используйте динамический локальный порт и гарантированно закройте сервер.
