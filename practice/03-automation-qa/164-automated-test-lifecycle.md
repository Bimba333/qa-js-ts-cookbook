# Практика: Жизненный цикл автотеста

## Задача 1. Концептуальные вопросы

Расположите этапы: конфигурация, инициализация ресурсов, подготовка данных, сценарий, проверка, сбор диагностических данных, очистка, освобождение ресурсов, отчётность. Почему жизненный цикл шире тела теста?

## Задача 2. Анализ аварийного пути

Проверка упала после создания заказа. Опишите порядок сбора диагностических данных, очистки, освобождения ресурсов и формирования отчёта. Что нельзя потерять при ошибке очистки?

## Задача 3. Предскажите результат выполнения кода

```ts
async function run(): Promise<void> {
  try {
    console.log("scenario");
  } finally {
    console.log("cleanup");
  }
}

await run();
```

Какие строки и в каком порядке появятся?

## Задача 4. Отладка жизненного цикла

Очистка вызывается последней строкой после проверки. Объясните, что произойдёт при падении проверки, и предложите обобщённое исправление без синтаксиса hooks.

## Задача 5. Automation QA

Для UI-сессии, API-клиента, соединения с базой данных и созданного заказа определите владельца, область жизни и правило освобождения ресурса или очистки данных.

## Задача 6. Мини-проект

Опишите жизненный цикл сценария заказа с ошибками подготовки, действия и очистки. Для каждого пути укажите итоговый результат и сохраняемые диагностические данные.
