# Практика: Builders, factories и уникальные данные

## 1. Factory или Builder
Выберите механизм для простого тела запроса и для объекта, собираемого несколькими осмысленными шагами.

## 2. Предскажите результат
Factory каждый раз возвращает один сохранённый объект, затем тест меняет `priority`. Что увидит следующий тест?

## 3. Диагностика скрытого побочного эффекта
Метод `build()` отправляет POST. Объясните нарушение границы.

## 4. Реализация overrides
Напишите Factory валидной задачи с типизированными overrides и новым объектом на каждый вызов.

## 5. Уникальность и seed
Объясните, как seed из имени проекта, индекса повтора и индекса worker вместе с локальной последовательностью предотвращает коллизии и помогает воспроизводимости.

## 6. Мини-проект: фабрика данных запроса
Создайте Factory с валидными значениями по умолчанию, seed из project/repeat/worker, последовательными ID и тремя сценарными вариантами без общего изменяемого результата. Factory не должна выполнять I/O, проверки или очистку.
