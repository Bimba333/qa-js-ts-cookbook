# Практика: APIRequestContext

## Задача 1. Концептуальные вопросы

Кто владеет встроенной fixture `request` и созданным вручную APIRequestContext? Что именно изолирует новый контекст?

## Задача 2. Анализ жизненного цикла

Тест создаёт контекст через `request.newContext()` и передаёт его вспомогательной функции. Укажите владельца `dispose()` и место гарантированного освобождения.

## Задача 3. Предскажите результат

Два APIRequestContext используют разные cookies, но обращаются к одному ID задачи. Будут ли серверные изменения автоматически изолированы?

## Задача 4. Поиск ошибки

Глобальный APIRequestContext создаётся при импорте модуля и никогда не освобождается. Перестройте жизненный цикл без singleton и скрытого ресурса.

## Задача 5. Automation QA

Выберите между встроенной fixture и созданным вручную контекстом для обычного теста, отдельной cookie-сессии и клиента с общими заголовками. Объясните компромиссы.

## Задача 6. Мини-проект

Создайте APIRequestContext с динамическим `baseURL` и тестовым заголовком, выполните относительный GET и освободите контекст и локальный сервер в `finally`.
