# Практика: Инструменты и роли в Automation QA

## Задача 1. Концептуальные вопросы

Разделите понятия: фреймворк, тестовый раннер, система проверок, система CI и приложение под тестированием. Почему один продукт может совмещать роли, но роли всё равно полезно различать?

## Задача 2. Матрица ответственности

Назначьте владельца каждому действию: открыть страницу браузера, сравнить статус, выполнить HTTP-запрос, сохранить отчёт, запустить команду после pull request, реализовать бизнес-правило заказа.

## Задача 3. Предскажите результат выполнения кода

```ts
const roles = ["runner", "assertions", "reporting"];
console.log(roles.join(" -> "));
```

Что будет выведено? Почему порядок в строке не означает, что средство отчётности отвечает за запуск теста?

## Задача 4. Диагностика ответственности

CI запустил тест, проверка получила неверный фактический статус, а отчёт сохранил падение. Кто обнаружил несовпадение, кто организовал запуск и кто только представил результат?

## Задача 5. Automation QA

Составьте матрицу ответственности для автоматизации браузера, API-клиента, доступа к базе данных и тестового окружения. Для каждой роли укажите одну обязанность и одну явную не-обязанность.

## Задача 6. Мини-проект

Для проверки регистрации пользователя выберите минимальный набор ролей. Не выбирайте конкретные библиотеки. Покажите взаимодействие от запуска до результата и объясните, кто владеет каждым шагом.
