# Практика: Негативные API-сценарии и ошибки

## Задача 1. Концептуальные вопросы

Почему ожидаемый 4xx является контролируемым результатом теста, а транспортная ошибка — другой категорией ошибки?

## Задача 2. Анализ кодов

Для отсутствующего token, недостаточных разрешений, неизвестного ID, дублирующегося ресурса и неподдерживаемого типа содержимого выберите ожидаемые коды состояния и объясните договорённость.

## Задача 3. Предскажите результат

POST с пустым `title` вернул 422, но ресурс всё равно появился. Может ли тест считаться успешным после проверки только кода состояния?

## Задача 4. Поиск ошибки

Негативный тест принимает любой код состояния от 400 до 499. Сделайте причину отказа и контракт ошибки однозначными.

## Задача 5. Automation QA

Выберите три негативных сценария создания задачи на основе рисков и укажите проверку отсутствия побочного эффекта.

## Задача 6. Мини-проект

Отправьте локальному API невалидное тело данных, проверьте 422 и стабильный код ошибки, затем подтвердите, что коллекция не изменилась.
