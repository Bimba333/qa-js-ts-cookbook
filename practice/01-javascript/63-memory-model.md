# Практика: Memory Model

## Концептуальные вопросы

1. Зачем программе нужна память во время выполнения?
2. Что в этой модели хранится на Stack?
3. Что в этой модели хранится в Heap?
4. Почему переменную со значением-объектом удобно рисовать как ссылку?
5. Почему Stack/Heap model не нужно считать точным описанием устройства движка?

## Чтение кода

```javascript
function c() {
  const count = 3;
  const user = { name: 'Anna' };

  console.log(count);
  console.log(user.name);
}

function b() {
  c();
}

function a() {
  b();
}

a();
```

Опишите:

* где в этой модели находится Execution Context `c`;
* где находится примитивное значение `3`;
* где находится объект `{ name: 'Anna' }`;
* что хранит переменная `user`.

## Предскажите результат выполнения

```javascript
function c() {
  const user = { name: 'Anna', status: 'created' };
  const sameUser = user;

  sameUser.status = 'active';

  console.log(user.status);
}

c();
```

Сначала запишите вывод без запуска.

## Отладка

Автор думал, что `sameUser` — отдельная копия:

```javascript
const user = { status: 'created' };
const sameUser = user;

sameUser.status = 'active';

console.log(user.status);
```

Объясните ошибку через Heap и ссылку.

## QA-аналогия

В test helper передали объект с тестовыми данными. Второй helper изменил свойство этого объекта.

Почему первый helper позже может увидеть измененные данные?

## Мини-сценарий

Напишите `a() -> b() -> c()`, где `c()`:

* создает примитивное значение `count`;
* создает объект `user`;
* создает вторую переменную, которая ссылается на тот же объект;
* меняет свойство через вторую переменную;
* печатает свойство через первую переменную.

После кода нарисуйте Stack/Heap-диаграмму.
