# Практика. Глава 0. О курсе

## Проверка понимания

Ответьте своими словами.

1. Почему этот курс начинается с JavaScript, а не с TypeScript или Playwright?
2. Что означает принцип "понимание важнее запоминания"?
3. Почему TypeScript не заменяет runtime-проверки API-ответов?
4. Чем отличается знание синтаксиса от понимания механизма?
5. Почему Automation QA Engineer должен понимать Stack, Heap, References и Event Loop?
6. Как связаны директории `docs/`, `examples/`, `practice/` и `solutions/`?
7. Почему решения не следует открывать до самостоятельной попытки выполнить практику?

## Анализ кода

Прочитайте код и объясните, что произойдет.

```javascript
const testUser = {
  email: 'qa@example.com'
};

const userFromHelper = testUser;

userFromHelper.email = 'changed@example.com';

console.log(testUser.email);
```

Ответьте:

1. Что будет выведено в консоль?
2. Почему изменение видно через переменную `testUser`?
3. Как эта ситуация может повлиять на тестовые данные в Automation QA?

## Написание кода

Напишите небольшой JavaScript-фрагмент, который показывает разницу между:

* переназначением переменной;
* изменением объекта, на который указывает переменная.

Используйте осмысленные имена переменных. Пример должен быть минимальным.

## Поиск ошибок

Найдите ошибку в рассуждении.

```text
Если объект описан TypeScript-типом, значит API точно вернет объект такой формы.
Поэтому runtime-проверки в API-тестах не нужны.
```

Объясните:

1. Какая часть рассуждения неверна?
2. Почему TypeScript не гарантирует форму реального JSON во время выполнения?
3. Какие проверки стоит добавить в API-тест?

## QA-задача

Представьте, что в проекте есть flaky-тест.

Тест иногда падает после изменения общего объекта с тестовыми данными. Опишите:

1. Какую JavaScript-тему нужно изучить, чтобы понять причину?
2. Какие вопросы вы зададите при анализе проблемы?
3. Как можно уменьшить риск такой ошибки в тестовом фреймворке?

## Мини-проект

Составьте личный план прохождения курса.

План должен включать:

* как вы будете читать главы;
* где будете запускать примеры;
* как будете выполнять практику;
* когда будете смотреть решения;
* как будете фиксировать ошибки в понимании;
* как будете связывать темы курса со своей текущей или будущей работой в Automation QA.

Формат свободный, но план должен быть конкретным и пригодным для реального использования.
