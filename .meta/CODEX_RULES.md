# CODEX_RULES.md

# Обязательные правила Codex для генерации контента

> Version: 1.0
> Status: Active

---

# 1. Назначение

Этот документ защищает курс от chapter drift, неожиданного расширения scope и самостоятельных архитектурных изменений во время написания глав.

Правила обязательны для всех будущих задач, в которых Codex создает или изменяет:

* главы;
* примеры;
* практику;
* решения;
* навигацию;
* учебные материалы.

---

# 2. ROADMAP.md — источник истины

`.meta/ROADMAP.md` является источником истины для всего образовательного контента.

Перед созданием или изменением любого учебного материала Codex обязан прочитать и проверить задачу по:

```text
.meta/ROADMAP.md
```

Задача должна совпадать с roadmap по следующим пунктам:

* номер главы;
* название главы;
* модуль;
* учебная цель;
* prerequisites;
* разрешенный scope.

---

# 3. Обязательное условие остановки

Если запрос пользователя конфликтует с `.meta/ROADMAP.md`, Codex обязан остановиться.

В этом случае запрещено:

* создавать файлы;
* изменять файлы;
* переименовывать главы;
* переносить темы;
* добавлять отсутствующие главы;
* менять порядок глав;
* менять порядок модулей.

Вместо выполнения задачи Codex должен сообщить:

1. Ожидаемую структуру по roadmap.
2. Запрошенную структуру задачи.
3. Точное расхождение.
4. Возможные варианты решения.

После этого Codex должен дождаться подтверждения перед продолжением.

---

# 4. Защита scope

Перед созданием контента Codex обязан проверить задачу по scope-документу текущего раздела.

Для TypeScript используется:

```text
.meta/TYPESCRIPT_SCOPE.md
```

Для других разделов используются соответствующие scope-документы, если они существуют.

Codex не должен вводить:

* исключенные технологии;
* темы будущих разделов;
* framework-specific материал, если он не относится к текущему разделу;
* дублирование материала из предыдущих разделов.

Если найден scope conflict, Codex обязан остановиться и сообщить о конфликте.

---

# 5. Обязательный workflow создания главы

Перед написанием главы Codex обязан:

1. Прочитать `.meta/ROADMAP.md`.
2. Прочитать scope-документ текущего раздела.
3. Подтвердить, что глава существует в roadmap.
4. Подтвердить цель главы.
5. Подтвердить prerequisites.

Только после этой проверки разрешено создавать:

* `docs`;
* `examples`;
* `practice`;
* `solutions`.

---

# 6. Запрет самостоятельных архитектурных изменений

Codex не имеет права самостоятельно:

* вставлять главы;
* удалять главы;
* объединять главы;
* разделять главы;
* переименовывать главы;
* менять порядок глав;
* менять порядок модулей.

Даже если обнаружена более удачная структура, Codex должен только сообщить об архитектурной проблеме и дождаться одобрения.

---

# 7. Консистентность будущих глав

Каждая новая глава должна сохранять:

* нумерацию roadmap;
* границы модулей;
* терминологию;
* стиль обучения;
* assumptions о знаниях из предыдущих глав.

Глава не должна обучать концепциям, которые назначены будущим главам.

---

# 8. Финальная проверка перед завершением задачи

Перед завершением любой задачи по созданию главы Codex обязан проверить:

* созданная глава существует в roadmap;
* `SUMMARY.md` может быть обновлен корректно;
* prerequisites удовлетворены;
* roadmap drift не появился;
* scope expansion не появился.

Если проверка не проходит, задача не считается завершенной.

---

# 9. Обязательная политика изменений

Все будущие задачи Codex, которые изменяют существующий учебный контент, должны проверяться по:

```text
.meta/CHANGE_POLICY.md
```

Перед редактированием существующих глав, практики, решений, примеров, диаграмм или навигационных материалов Codex обязан:

1. Прочитать `.meta/ROADMAP.md`.
2. Прочитать relevant scope document текущего раздела.
3. Прочитать `.meta/CHANGE_POLICY.md`.
4. Определить, является ли раздел frozen.
5. Проверить, разрешено ли requested change без architecture review.

Frozen sections cannot be structurally changed without explicit approval.

Если изменение нарушает `.meta/CHANGE_POLICY.md`, Codex обязан остановиться, не изменять файлы и сообщить:

* affected section;
* requested change;
* policy conflict;
* possible resolutions.

После этого Codex должен дождаться подтверждения перед продолжением.
