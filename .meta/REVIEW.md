# REVIEW

## Общие замечания

### Высокий приоритет

* Добавить во все главы раздел «Частые вопросы», если тема вызывает типичные вопросы у читателя.
* В каждую практику добавить минимум одно задание типа «Предскажите результат выполнения кода» (без предварительного запуска).

### Средний приоритет

* В фундаментальных главах использовать один сквозной пример, который постепенно разбирается по мере объяснения новых концепций, вместо большого количества независимых небольших примеров.

* В фундаментальных главах, где объясняется внутренний механизм языка, явно связывать текущую главу со следующей и показывать, какое место новая тема занимает в общей модели выполнения JavaScript.
* Добавить единый стиль информационных блоков:

  * Важно
  * Типичная ошибка
  * Полезно знать
* Использовать эти блоки только там, где они действительно усиливают объяснение, не превращая главу в набор предупреждений.
* Добавить блок «Миф → Реальность» в главы, где существуют распространенные заблуждения.
* Там, где это уместно, добавлять небольшую историческую timeline, чтобы показать развитие технологии и сформировать исторический контекст.
* Добавить в конце некоторых крупных разделов чек-лист готовности к следующему разделу.

### Низкий приоритет

* После завершения каждого крупного раздела проводить единое редакторское ревью:

  * привести главы к единому стилю;
  * убрать возможные повторения;
  * проверить достаточность ASCII-схем;
  * проверить последовательность введения терминов;
  * убедиться, что требования `STYLE_GUIDE.md` соблюдены во всех главах.
