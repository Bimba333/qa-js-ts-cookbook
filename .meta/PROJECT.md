# PROJECT.md

# JavaScript & TypeScript for Automation QA

> Версия: 1.0
> Статус: Active
> Документ-владелец: Repository Architecture

---

# 1. Назначение проекта

Данный репозиторий представляет собой полноценную образовательную программу по JavaScript, TypeScript и Automation QA.

Это не набор заметок.

Это не конспект.

Это не краткое руководство.

Это инженерный учебник, который объединяет:

* фундаментальную теорию;
* практические задания;
* реальные задачи из Automation QA;
* проекты;
* примеры кода;
* решения;
* архитектурные рекомендации.

Основная цель проекта — сформировать глубокое понимание языка и научить применять его в промышленной автоматизации тестирования.

---

# 2. Миссия проекта

Создать лучший русскоязычный открытый курс по JavaScript и TypeScript для Automation QA.

Под "лучший" понимается не объем материала, а его качество.

После прохождения курса читатель должен понимать язык настолько хорошо, чтобы самостоятельно:

* читать чужой код;
* проектировать собственные решения;
* писать качественные автотесты;
* проектировать архитектуру тестового фреймворка;
* понимать ошибки, а не искать готовые решения.

---

# 3. Целевая аудитория

Основная аудитория:

* Junior Automation QA
* Middle Automation QA
* Manual QA, переходящий в автоматизацию
* Backend QA
* SDET

Также курс должен быть полезен:

* начинающим JavaScript-разработчикам;
* инженерам, желающим изучить TypeScript;
* разработчикам автотестов на Playwright.

---

# 4. Исходный уровень читателя

Предполагается, что читатель:

* умеет писать простые автотесты;
* запускал JavaScript-код;
* видел TypeScript;
* умеет пользоваться терминалом;
* умеет пользоваться VS Code.

Не предполагается глубокое понимание языка.

---

# 5. Конечный уровень

После завершения курса читатель должен:

## JavaScript

Понимать:

* Runtime
* Engine
* Execution Context
* Scope
* Hoisting
* TDZ
* Stack
* Heap
* References
* Closures
* this
* Prototype Chain
* Event Loop
* Promises
* Async/Await
* Memory Management

Не просто знать определения.

А понимать внутренний механизм работы.

---

## TypeScript

Уметь использовать:

* Type Inference
* Interfaces
* Type Aliases
* Generics
* Utility Types
* Conditional Types
* Mapped Types
* Narrowing
* Type Guards
* Declaration Files

Понимать ограничения TypeScript.

Понимать, что происходит после компиляции.

---

## Automation QA

Уметь проектировать:

* Playwright Framework
* API Layer
* gRPC Layer
* Database Layer
* Helpers
* Fixtures
* Assertions
* Reporting
* Configuration
* Test Data Builders

# 6. Главная философия

Главная идея курса:

> Понимание важнее запоминания.

Каждая тема должна отвечать на вопросы:

* Что это?
* Почему это существует?
* Как это работает?
* Почему работает именно так?
* Где это применяется?
* Какие ошибки встречаются чаще всего?

---

# 7. Принципы обучения

Проект строится на следующих принципах.

## Принцип 1

Сначала механизм.

Потом синтаксис.

---

## Принцип 2

Каждая новая тема строится только на уже изученных знаниях.

---

## Принцип 3

Никакой магии.

Если используется новый механизм, он должен быть объяснен.

---

## Принцип 4

Все примеры должны запускаться.

Если пример содержит ошибку, она должна быть намеренной и подробно разобранной.

---

## Принцип 5

Теория всегда сопровождается практикой.

---

## Принцип 6

Каждая тема должна быть связана с Automation QA.

---

# 8. Структура курса

Курс состоит из пяти крупных частей.

## Часть I

Введение.

Сюда входят:

* устройство курса;
* рабочее окружение;
* Git;
* Node.js;
* VS Code;
* терминал;
* структура проекта.

---

## Часть II

JavaScript.

Полное изучение языка.

От переменных до Event Loop.

---

## Часть III

TypeScript.

Полное изучение системы типов.

От базовых типов до сложных generic-конструкций.

---

## Часть IV

Automation QA.

Применение языка в реальных проектах.

Playwright.

REST.

gRPC.

Database.

Framework Architecture.

---

## Часть V

Финальный проект.

Разработка собственного automation framework.

---

# 9. Практика

Практика является обязательной частью курса.

Каждая глава должна содержать:

* вопросы на понимание;
* задачи на анализ кода;
* задачи на написание кода;
* задачи на поиск ошибок;
* задачи уровня Automation QA;
* мини-проект.

Практика должна формировать инженерное мышление.
