# Сервис прогресса

Хранит прогресс читателя по задачам книги и позволяет переносить его между
устройствами. Отдельный сервис, а не часть учебного стенда: стенд — цель для
тестов, а это инфраструктура самой книги.

## Запуск

```bash
npm run platform:up      # поднять сервис и базу
npm run platform:smoke   # проверить контракт целиком
npm run platform:down    # остановить
```

Сервис слушает `http://127.0.0.1:4320`, база — на порту `55433`.

## Контракт

| Маршрут | Назначение |
| --- | --- |
| `GET /health/ready` | Готовность сервиса и базы |
| `POST /api/v1/auth/register` | Регистрация: `{ email, password }` → `201 { token, user }` |
| `POST /api/v1/auth/login` | Вход: `{ email, password }` → `200 { token, user }` |
| `POST /api/v1/auth/logout` | Завершение сессии по токену → `204` |
| `GET /api/v1/progress` | Снимок прогресса учётной записи |
| `PUT /api/v1/progress` | Приём снимка: `{ tasks }` → сохранённый результат |

Токен передаётся заголовком `Authorization: Bearer <токен>`.

## Правило слияния

Снимок с устройства **дополняет** сохранённый, а не заменяет его:

- решённая задача не возвращается в состояние «попытка»;
- число попыток и использованных подсказок только растёт.

Иначе устройство с устаревшим снимком откатывало бы прогресс, сделанный на
другом. Это же правило применяется на стороне книги при переносе снимка
файлом и при работе с внешним хранилищем — результат одинаков.

## Хранение

- Пароль хранится как `scrypt` с индивидуальной солью; сравнение постоянно по
  времени.
- В таблице сессий лежит **хеш** токена, а не сам токен: утечка дампа не даёт
  войти.
- Прогресс хранится одной записью `jsonb` на учётную запись.

## Внешнее хранилище вместо своего сервиса

Книга работает с этим сервисом через четыре операции: регистрация, вход,
чтение снимка, запись снимка. Тот же контракт реализован поверх Supabase
(`.vitepress/theme/composables/progress-sync.js`), поэтому выбор хранилища —
это настройка на странице «Прогресс», а не изменение книги.

Для Supabase нужна таблица:

```sql
create table progress (
  user_id uuid primary key references auth.users(id) on delete cascade default auth.uid(),
  tasks jsonb not null default '{}'::jsonb,
  updated_at timestamptz not null default now()
);

alter table progress enable row level security;

create policy "читатель видит только свой прогресс"
  on progress for all
  using (auth.uid() = user_id)
  with check (auth.uid() = user_id);
```

Важное отличие: в этом варианте слияние снимков выполняет книга — своего кода
на стороне Supabase нет. Правило слияния то же самое, но проверить его можно
только на реальном проекте: в составе репозитория этот путь не проверяется.

## Границы

Сервис учебный. В нём нет подтверждения адреса, восстановления пароля,
ограничения частоты запросов и удаления учётной записи. Прежде чем открывать
его наружу, эти вещи нужно добавить.
