# Сервис прогресса

Хранит прогресс читателя по задачам книги и позволяет переносить его между
устройствами. Отдельный сервис, а не часть учебного стенда: стенд — цель для
тестов, а это инфраструктура самой книги.

## Запуск

```bash
npm run platform:up      # поднять сервис и базу
npm run platform:smoke   # проверить контракт целиком
npm run platform:down    # остановить
```

Сервис слушает `http://127.0.0.1:4320`, база — на порту `55433`.

## Контракт

| Маршрут | Назначение |
| --- | --- |
| `GET /health/ready` | Готовность сервиса и базы |
| `POST /api/v1/auth/register` | Регистрация: `{ email, password }` → `201 { token, user }` |
| `POST /api/v1/auth/login` | Вход: `{ email, password }` → `200 { token, user }` |
| `POST /api/v1/auth/logout` | Завершение сессии по токену → `204` |
| `GET /api/v1/progress` | Снимок прогресса учётной записи |
| `PUT /api/v1/progress` | Приём снимка: `{ tasks }` → сохранённый результат |

Токен передаётся заголовком `Authorization: Bearer <токен>`.

## Правило слияния

Снимок с устройства **дополняет** сохранённый, а не заменяет его:

- решённая задача не возвращается в состояние «попытка»;
- число попыток и использованных подсказок только растёт.

Иначе устройство с устаревшим снимком откатывало бы прогресс, сделанный на
другом. Это же правило применяется на стороне книги при переносе снимка
файлом и при работе с внешним хранилищем — результат одинаков.

## Хранение

- Пароль хранится как `scrypt` с индивидуальной солью; сравнение постоянно по
  времени.
- В таблице сессий лежит **хеш** токена, а не сам токен: утечка дампа не даёт
  войти.
- Прогресс хранится одной записью `jsonb` на учётную запись.

## Внешнее хранилище вместо своего сервиса

Книга работает с этим сервисом через четыре операции: регистрация, вход,
чтение снимка, запись снимка. Тот же контракт реализован поверх Supabase
(`.vitepress/theme/composables/progress-sync.js`), поэтому выбор хранилища —
это настройка на странице «Прогресс», а не изменение книги.

Для Supabase нужна таблица:

```sql
create table progress (
  user_id uuid primary key references auth.users(id) on delete cascade default auth.uid(),
  tasks jsonb not null default '{}'::jsonb,
  updated_at timestamptz not null default now()
);

alter table progress enable row level security;

create policy "читатель видит только свой прогресс"
  on progress for all
  using (auth.uid() = user_id)
  with check (auth.uid() = user_id);
```

Важное отличие: в этом варианте слияние снимков выполняет книга — своего кода
на стороне Supabase нет. Правило слияния то же самое, но проверить его можно
только на реальном проекте: в составе репозитория этот путь не проверяется.

## Границы

Сервис учебный. В нём нет подтверждения адреса, восстановления пароля,
ограничения частоты запросов и удаления учётной записи. Прежде чем открывать
его наружу, эти вещи нужно добавить.

## Подписка и доступ к главам

Добавлено 2026-09-28 вместе с уровнями доступа книги (`book.access.mjs`).

**Модель:** три состояния читателя — гость (бесплатные главы, прогресс не
сохраняется), вошедший (бесплатные главы, прогресс сохраняется), подписчик
(вся книга).

**Контракт сервиса пополнился пятой операцией:**

```
GET  /api/v1/entitlement            → { subscribed, plan, validUntil }
POST /api/v1/entitlement/dev-grant  → то же; выдаёт подписку БЕЗ оплаты
```

`subscribed` вычисляется на сервере сравнением `valid_until` с текущим
временем, а не хранится полем: срок мог истечь между записью и чтением.

**`dev-grant` выключен по умолчанию** и включается переменной
`PLATFORM_ALLOW_DEV_GRANT=1`. С ним подписку может выдать себе любой вошедший
читатель — это заглушка вместо платёжного провайдера для локальной работы.
В рабочей среде маршрут обязан отвечать 404.

**Supabase:** тот же контракт поверх таблицы `subscriptions` с политикой RLS
«читать только свою строку»:

```sql
create table public.subscriptions (
  user_id uuid primary key references auth.users(id) on delete cascade,
  plan text not null,
  valid_until timestamptz not null,
  updated_at timestamptz not null default now()
);

alter table public.subscriptions enable row level security;

create policy "read own subscription" on public.subscriptions
  for select using (auth.uid() = user_id);
```

Слабость этого варианта, записанная честно: срок сравнивает **клиент**, потому
что своего кода на стороне Supabase нет. Для платного доступа это означает, что
Supabase годится как хранилище прогресса, но решение о доступе должен принимать
сервис, который отдаёт содержимое.

## Чего разграничение доступа НЕ делает сейчас

Книга собирается как статический сайт: текст платной главы лежит в сборке и
доступен в исходнике страницы. Замок в интерфейсе (`ChapterAccess.vue`) —
честная граница для читателя, но не защита.

Настоящее разграничение требует, чтобы платные главы **не попадали в
статическую сборку**, а приходили от сервиса после проверки права доступа.
Порядок работ, когда будет выбран хостинг:

1. режим сборки, исключающий платные главы (`srcExclude` из `book.access.mjs`);
2. страница-читалка с динамическим маршрутом вместо исключённых глав;
3. маршрут сервиса, отдающий содержимое главы по идентификатору и токену;
4. проверка, что в статической сборке платного текста не осталось.

Пункт 4 обязателен: без него первые три создают видимость защиты.
