# Решения. Глава 24. Function Declaration

## Концептуальные вопросы

### 1. Зачем существуют функции

Ответ:

Функции существуют, чтобы давать имена переиспользуемым алгоритмам.

Объяснение:

Если одна и та же проверка появляется во многих тестах, функция позволяет описать ее один раз и вызывать много раз.

Распространённая ошибка:

Думать, что функции нужны только для сокращения количества строк.

Связь с Automation QA:

Helpers - это функции с переиспользуемым тестовым поведением.

### 2. Дублирование кода

Ответ:

Дублирование кода - это повторяющаяся логика, скопированная в нескольких местах.

Объяснение:

Одна и та же проверка в десяти тестах означает десять мест для обновления.

Распространённая ошибка:

Соглашаться на дублирование только потому, что скопировать код сначала проще.

Связь с Automation QA:

Дублированные assertions со временем начинают проверять разные вещи.

### 3. Опасность дублированной проверки

Ответ:

Она опасна, потому что правило может измениться в одной копии, но не измениться в другой.

Объяснение:

Тесты случайно начинают проверять разные вещи.

Распространённая ошибка:

Обновить только ту копию, где тест упал.

Связь с Automation QA:

Regression suite becomes unreliable.

### 4. Переиспользуемое поведение

Ответ:

Переиспользуемое поведение - это алгоритм, который можно запускать из разных мест.

Объяснение:

Подготовка, очистка и валидация часто повторяются.

Распространённая ошибка:

Переиспользовать код через copy/paste вместо функции.

Связь с Automation QA:

Общие helpers уменьшают дублирование тестового кода.

### 5. Именование алгоритма

Ответ:

Это означает дать осмысленное имя последовательности действий.

Объяснение:

`validateUserResponse` говорит, что делает алгоритм.

Распространённая ошибка:

Использовать расплывчатые имена вроде `doStuff`.

Связь с Automation QA:

Хорошие имена helper-функций делают тесты читаемыми.

### 6. Function declaration

Ответ:

Function declaration создает именованную функцию.

Объяснение:

Синтаксис начинается с `function`, затем идут имя, круглые скобки и тело.

Распространённая ошибка:

Ожидать, что объявление выполнит тело функции.

Связь с Automation QA:

Объявление helper не выполняет setup.

### 7. Тело функции

Ответ:

Тело функции - это код внутри `{ ... }`.

Объяснение:

Оно содержит переиспользуемый алгоритм.

Распространённая ошибка:

Помещать несвязанные действия в одно тело.

Связь с Automation QA:

Helper body should be focused.

### 8. Вызов функции

Ответ:

Вызов функции - это обращение к функции по имени с круглыми скобками.

Объяснение:

`setupTestData()` просит JavaScript выполнить тело функции.

Распространённая ошибка:

Написать имя функции, но фактически не вызвать ее.

Связь с Automation QA:

Helper must be called to perform setup.

### 9. Выполнение объявления

Ответ:

Нет. Объявление не выполняет тело функции.

Объяснение:

Тело ожидает вызова.

Распространённая ошибка:

Ожидать вывод от объявленной, но не вызванной функции.

Связь с Automation QA:

Объявленный cleanup helper ничего не очистит, пока его не вызовут.

### 10. Когда выполняется тело

Ответ:

Тело выполняется, когда функция вызвана.

Объяснение:

Каждый вызов запускает выполнение тела.

Распространённая ошибка:

Путать объявление и вызов.

Связь с Automation QA:

Переиспользуемые assertions выполняются только при вызове.

### 11. Многократные вызовы

Ответ:

Одно объявление можно вызвать много раз.

Объяснение:

Каждый вызов снова выполняет одно и то же тело.

Распространённая ошибка:

Думать, что функцию можно использовать только один раз.

Связь с Automation QA:

Одна и та же проверка может выполняться во многих тестах.

### 12. Читаемость

Ответ:

Функции заменяют низкоуровневые повторяющиеся шаги осмысленными именами.

Объяснение:

`validateUserProfile()` читать проще, чем много повторяющихся строк.

Распространённая ошибка:

Прятать поведение за расплывчатыми именами.

Связь с Automation QA:

Тесты читаются как сценарии.

### 13. Поддерживаемость

Ответ:

Функции централизуют поведение.

Объяснение:

Изменение одного тела функции влияет на все места вызова.

Распространённая ошибка:

Дублировать код и обновлять только одну копию.

Связь с Automation QA:

Framework helpers снижают стоимость поддержки.

## Найдите дублированный код

### Задача 1

Ответ:

Дублированная логика: проверка статуса.

Возможное имя функции:

```text
validateSuccessfulStatus
```

Объяснение:

Оба блока сравнивают статус с `200` и выбрасывают одну и ту же ошибку.

Распространённая ошибка:

Назвать функцию `check`, не объяснив, что именно проверяется.

Связь с Automation QA:

Переиспользуемая проверка статуса.

### Задача 2

Ответ:

Дублированная логика: сценарий профиля пользователя.

Возможное имя функции:

```text
validateUserProfileFlow
```

или разделить на:

```text
createUser
openProfilePage
validateProfile
```

Объяснение:

Если каждое действие переиспользуется отдельно, отдельные функции могут быть лучше.

Распространённая ошибка:

Создать одну огромную функцию для несвязанных шагов.

Связь с Automation QA:

Helpers для setup, page-действий и assertions.

### Задача 1

Ответ:

Распространённая ошибка:

Ожидать, что объявление запустит тело.

Setup helper был объявлен, но не использован.

Тело: `console.log('Create user')`.

Объяснение:

Вызов запускает выполнение.

Пропустить строку вызова.

Setup выполняется.

Вывод:


Объяснение:

Выполняется только прямой `console.log`.

Распространённая ошибка:

Думать, что cleanup выполняется, потому что он объявлен.

Связь с Automation QA:

Cleanup helper нужно вызвать явно.

## Задачи на отладку

Ответ:

Потому что `validateResponse()` ни разу не вызвана.

Исправление:

```javascript
function validateResponse() {
  console.log('Validation runs');
}

validateResponse();
console.log('Test finished');
```

Объяснение:

Объявление - это не выполнение.

Распространённая ошибка:

Забыть вызов.

Связь с Automation QA:

Тест пропустил validation helper.

### Задача 2

Лучше:

```javascript
function validateResponseStatus() {
  console.log('Validate response status');

```

Объяснение:

Имя функции должно описывать переиспользуемый алгоритм.

Распространённая ошибка:

Использовать расплывчатые имена helper-функций.

Связь с Automation QA:

Читаемые test helpers.

### Задача 3

Ответ:

Она объединяет несколько разных алгоритмов.

Возможное разделение:


Объяснение:

Сфокусированные функции легче переиспользовать и поддерживать.

Распространённая ошибка:

Создать один огромный helper.

Связь с Automation QA:

Framework helpers должны иметь понятные обязанности.

## Мини-проект

Возможное решение:

```javascript
function setupTestData() {
  console.log('Create test user');
}

function openUserProfile() {
  console.log('Open user profile');
}

function validateUserProfile() {
  console.log('Validate user profile');
}

function cleanupTestData() {
  console.log('Delete test user');
}

setupTestData();
openUserProfile();
validateUserProfile();
validateUserProfile();
cleanupTestData();
```

Отчет:

```text
Имя функции         | Переиспользуемый алгоритм | Вызвана? | Сколько раз | QA-смысл
------------------- | ------------------------- | -------- | ----------- | -----------------------
setupTestData       | создать тестовые данные   | да       | 1           | setup helper
openUserProfile     | открыть профиль           | да       | 1           | navigation helper
validateUserProfile | проверить профиль         | да       | 2           | reusable assertion
cleanupTestData     | удалить тестовые данные   | да       | 1           | cleanup helper
```

Объяснение:

Каждая функция называет одно переиспользуемое действие. Проверка вызывается дважды, чтобы показать повторный вызов.

Распространённая ошибка:

Поместить все действия в одну расплывчатую функцию `runTest`.

Связь с Automation QA:

Это отражает базовую структуру test helpers.
