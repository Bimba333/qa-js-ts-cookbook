# Решения: Frames

## Задача 1. Концептуальные вопросы
### Ответ
`Frame` представляет контекст просмотра и его жизненный цикл; `FrameLocator` задаёт границу Locator для действий внутри iframe. Основная Page работает с другим документом.
### Объяснение
Каждый frame имеет собственное DOM-дерево.
### Типичная ошибка
Считать iframe обычным container.
### Связь с Automation QA
Правильный контекст устраняет ложные ошибки поиска элементов.

## Задача 2. Анализ контекста
### Ответ
Кнопку оплаты ищут через `page.frameLocator(...).getByRole(...)`. Статус заказа ищут через Locator основной `page`.
### Объяснение
Каждый элемент адресуется от владельца документа.
### Типичная ошибка
Продолжить все проверки через FrameLocator.
### Связь с Automation QA
Явные границы упрощают диагностику встроенных компонентов.

## Задача 3. Предскажите результат
### Ответ
Locator основной Page не найдёт кнопку, и `click()` завершится по тайм-ауту, если такой элемент не появится в основном документе.
### Объяснение
Playwright не пересекает границу iframe автоматически.
### Типичная ошибка
Увеличивать тайм-аут вместо выбора frame.
### Связь с Automation QA
Проблема контекста не является проблемой скорости.

## Задача 4. Поиск ошибки
### Ответ
Индекс зависит от порядка frames. Нужно найти iframe по устойчивому атрибуту или accessible name и использовать `FrameLocator`; для `Frame` можно выбрать по URL или name, если они стабильны.
### Объяснение
Позиция не выражает идентичность.
### Типичная ошибка
Закрепить другой индекс.
### Связь с Automation QA
Динамические сторонние frames меняют порядок.

## Задача 5. Automation QA
### Ответ
Сначала статус страницы проверяется через Locator от `page`. Frame отчёта выбирается по заголовку, а заголовок документа ожидается с помощью web-first assertion внутри `FrameLocator`.
### Объяснение
Каждое наблюдаемое условие имеет свою границу.
### Типичная ошибка
Добавить фиксированную задержку после загрузки основной Page.
### Связь с Automation QA
Ожидания по наблюдаемому условию устойчивы к разной скорости встроенного отчёта.

## Задача 6. Мини-проект
### Ответ
```ts
import { expect, test } from "@playwright/test";

test("работает внутри iframe", async ({ page }) => {
  await page.setContent(`
    <iframe title="Профиль" srcdoc="
      <label>Имя <input></label>
      <button>Сохранить</button>
      <script>document.querySelector('button').onclick=()=>document.body.dataset.saved='yes'<\/script>
    "></iframe>
  `);
  const frame = page.frameLocator('iframe[title="Профиль"]');
  await frame.getByLabel("Имя").fill("QA");
  await frame.getByRole("button", { name: "Сохранить" }).click();
  await expect(frame.locator("body")).toHaveAttribute("data-saved", "yes");
});
```
### Объяснение
Все операции во внутреннем DOM сохраняют границу frame.
### Типичная ошибка
Проверять атрибут через `page.locator("body")`.
### Связь с Automation QA
Шаблон применим к платёжным и другим встроенным формам.
