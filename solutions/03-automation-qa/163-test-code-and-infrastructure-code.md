# Решения: Тестовый и инфраструктурный код

## Задача 1. Концептуальные вопросы

### Ответ

Намерение теста определяет бизнес-поведение и ожидаемый результат. Инфраструктура обеспечивает техническое выполнение. Стремление к нулевому дублированию может создать дорогую и неясную абстракцию.

### Объяснение

Общая реализация нужна при общей ответственности и причине изменения.

### Типичная ошибка

Измерять качество минимальным числом строк.

### Связь с Automation QA

Читаемый сценарий важнее формальной краткости.

## Задача 2. Классификация кода

### Ответ

Тестовый код: ожидаемый статус и бизнес-сравнение. Инфраструктурный код: токен, открытие и закрытие соединения, уникальный email и журналирование. Конкретные тестовые данные связывают оба уровня, но владелец должен быть явным.

### Объяснение

Граница определяется причиной изменения.

### Типичная ошибка

Считать любые данные исключительно инфраструктурой.

### Связь с Automation QA

Ожидаемый статус должен быть виден читателю теста.

## Задача 3. Предскажите результат выполнения кода

### Ответ

`order-42: created`. Идентификатор и ожидаемое бизнес-состояние важны для намерения сценария.

### Объяснение

Данные показывают проверяемую сущность и состояние.

### Типичная ошибка

Скрывать их внутри универсального вспомогательного компонента.

### Связь с Automation QA

Бизнес-идентификаторы полезны и в диагностике.

## Задача 4. Улучшите читаемость

### Ответ

```ts
const order = await orders.createFor("admin");
await orders.cancel(order.id);
await orderChecks.expectStatus(order.id, "cancelled");
```

### Объяснение

Операции сохраняют язык предметной области, не раскрывая детали транспорта.

### Типичная ошибка

Заменять один неясный вспомогательный компонент несколькими техническими компонентами.

### Связь с Automation QA

Из сценария видно поведение заказа.

## Задача 5. Automation QA

### Ответ

Оставить повторение можно, если оно локально и может развиваться по-разному. Выделить компонент стоит, если есть общий владелец, одинаковое поведение, несколько потребителей и единая причина изменения.

### Объяснение

Количество строк — только сигнал, не решение.

### Типичная ошибка

Абстрагировать после первого совпадения.

### Связь с Automation QA

Это снижает риск появления вспомогательного компонента с множеством режимов.

## Задача 6. Мини-проект

### Ответ

Один допустимый вариант: тестовый код выбирает пользователя, отменяет заказ и ожидает `cancelled`. Инфраструктура получает токен, создаёт клиент, подготавливает заказ, регистрирует очистку и журналирование. Публичные операции: `createOrder`, `cancelOrder`, `readOrderStatus`.

### Объяснение

Детали HTTP и учётные данные остаются внутренними, а бизнес-поток виден.

### Типичная ошибка

Прятать проверку в подготовке данных.

### Связь с Automation QA

Падение можно связать с конкретным бизнес-шагом.
