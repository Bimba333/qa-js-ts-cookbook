# Решения: Что такое Automation QA Framework

## Задача 1. Концептуальные вопросы

### Ответ

Фреймворк объединяет правила, границы и переиспользуемую инфраструктуру, а изолированный скрипт решает одну проверку. Библиотека предоставляет техническую возможность, но не принимает архитектурные решения. Маленькому стабильному проекту сложный фреймворк может стоить дороже поддерживаемых им тестов.

### Объяснение

Размер решения должен следовать подтверждённой сложности.

### Типичная ошибка

Считать количество слоёв признаком качества.

### Связь с Automation QA

Три smoke-теста могут обходиться минимальными границами конфигурации и диагностики.

## Задача 2. Классификация

### Ответ

Стоит выделить конфигурацию и жизненный цикл тестовых данных. Нельзя обосновать, например, архитектуру плагинов без нескольких реальных вариантов расширения.

### Объяснение

Первые две обязанности уже повторяются и имеют общую причину изменения.

### Типичная ошибка

Выделять общий слой только из-за похожих имён файлов.

### Связь с Automation QA

Единые значения окружения и очистка данных уменьшают реальные риски.

## Задача 3. Предскажите результат выполнения кода

### Ответ

Вывод: `Проверка order-42`. `TestContext` задаёт публичный контракт входных данных сценария.

### Объяснение

Функция получает необходимые данные, не выбирая их источник.

### Типичная ошибка

Помещать загрузку окружения внутрь каждого сценария.

### Связь с Automation QA

Так локальный контекст и контекст CI могут создаваться отдельно.

## Задача 4. Отладка архитектуры

### Ответ

Создать один поставщик конфигурации и один клиент данных с операцией очистки, затем передавать их сценариям через явный контекст.

### Объяснение

Это устраняет подтверждённое дублирование без универсального слоя.

### Типичная ошибка

Сразу создавать сложную иерархию вспомогательных компонентов.

### Связь с Automation QA

Токен и очистка данных меняются централизованно.

## Задача 5. Automation QA

### Ответ

Отдельный слой отчётности и собственный тестовый раннер не обоснованы. Десять Page Objects для трёх сценариев также избыточны; достаточно абстракций для реально используемых страниц.

### Объяснение

Готовые возможности и небольшой объём проекта уменьшают цену собственной инфраструктуры.

### Типичная ошибка

Проектировать на воображаемый будущий масштаб.

### Связь с Automation QA

Минимальная архитектура быстрее диагностируется и изменяется.

## Задача 6. Мини-проект

### Ответ

Один допустимый вариант: тестовый код описывает создание и проверку заказа; конфигурация выдаёт URL окружения; механизм жизненного цикла создаёт уникальный заказ и регистрирует очистку; диагностика сохраняет идентификатор заказа и этап падения.

### Объяснение

Каждая граница решает существующую повторяемую задачу.

### Типичная ошибка

Скрыть бизнес-действие внутри общего `runTest()`.

### Связь с Automation QA

Пять сценариев используют одинаковые окружение, правила владения данными и сбора диагностических данных.
