# Решения: Transactions, rollback и test isolation

## 1. Граница транзакции
### Ответ
`BEGIN`, операторы и завершение транзакции выполняются через одно подключение.
### Объяснение
PostgreSQL хранит состояние транзакции в серверном сеансе.
### Типичная ошибка
Вызвать `BEGIN` через пул, а `INSERT` — через другое выделенное подключение.
### Связь с Automation QA
Вспомогательная функция транзакции должна принимать конкретный клиент.

## 2. Предскажите результат
### Ответ
При уровне изоляции `READ COMMITTED` подключение API не увидит незакоммиченную строку другого подключения.
### Объяснение
Видимость для другого подключения наступает после `COMMIT`.
### Типичная ошибка
Использовать незакоммиченные исходные данные для сквозного теста.
### Связь с Automation QA
Сценарий API требует уникальных закоммиченных данных и очистки.

## 3. Отладка прерванной транзакции
### Ответ
После ошибки ограничения нужно выполнить `ROLLBACK`, затем начать новую транзакцию или продолжить вне неё.
### Объяснение
Неудачный оператор переводит транзакцию в прерванное состояние; последующие команды получают SQLSTATE `25P02` до отката.
### Типичная ошибка
Повторять `SELECT` до тайм-аута.
### Связь с Automation QA
Обработка ошибок отделяет ожидаемое нарушение ограничения от инфраструктурной ошибки.

## 4. Реализация отката
### Ответ
```ts
await client.query("BEGIN");
try {
  await client.query("INSERT INTO tasks (id, title, priority) VALUES ($1, $2, $3)", [id, title, "high"]);
} finally {
  await client.query("ROLLBACK");
}
const result = await client.query("SELECT id FROM tasks WHERE id = $1", [id]);
expect(result.rows).toEqual([]);
```
### Объяснение
Откат выполняется независимо от результата тела теста.
### Типичная ошибка
Выполнять `COMMIT` при очистке по умолчанию.
### Связь с Automation QA
Тест репозитория не оставляет данные.

## 5. Граница внешних эффектов
### Ответ
Откат отменяет только изменения этой транзакции базы данных. HTTP-вызов, сообщение или другое закоммиченное подключение имеют собственный жизненный цикл.
### Объяснение
У них нет общей атомарной границы.
### Типичная ошибка
Считать транзакцию распределённым откатом.
### Связь с Automation QA
Межслойная очистка проектируется отдельно.

## 6. Мини-проект: выбор изоляции
### Ответ
Тест репозитория выполняется на одном клиенте внутри транзакции и откатывается. Тест API создаёт уникальную закоммиченную строку, вызывает API и удаляет точный ID в `finally`.
### Объяснение
Приложение использует отдельное подключение и должно видеть исходные данные.
### Типичная ошибка
Применять транзакцию на тест без учёта внешнего процесса.
### Связь с Automation QA
Стратегия изоляции следует границе теста.
