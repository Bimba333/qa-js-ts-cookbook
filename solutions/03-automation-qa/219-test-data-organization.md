# Решения: Организация test data

## 1. Классификация данных
### Ответ
Статусы — статический справочник; ID заказа — динамические данные; невалидная сумма — сценарные данные; URL API — конфигурация окружения.
### Объяснение
Категория определяется изменяемостью и владельцем.
### Типичная ошибка
Называть всё тестовой заготовкой.
### Связь с Automation QA
Разные категории получают разный жизненный цикл.

## 2. Предскажите результат
### Ответ
Второй тест увидит изменение первого, поэтому результат зависит от порядка.
### Объяснение
Объект модуля используется совместно внутри одного worker-процесса.
### Типичная ошибка
Считать `const` или `readonly` глубокой неизменяемостью во время выполнения.
### Связь с Automation QA
Статический справочник замораживается, а сценарные объекты создаются заново.

## 3. Диагностика общей сущности
### Ответ
У общей изменяемой записи нет одного владельца; каждый сценарий должен создать собственного пользователя или работать с неизменяемой справочной учётной записью.
### Объяснение
Один тест не может безопасно очищать ресурс другого.
### Типичная ошибка
Исправлять конфликт порядком выполнения.
### Связь с Automation QA
Явный владелец обеспечивает независимый запуск.

## 4. Реализация сценарных данных
### Ответ
```ts
const task = {
  id: `${testInfo.project.name}-r${testInfo.repeatEachIndex}-w${testInfo.workerIndex}-task-1`,
  owner: `scenario-${testInfo.title}`,
  title: "Проверить отчёт",
};
```
### Объяснение
ID содержит имя проекта, индексы повтора и worker, поэтому источник данных виден в диагностике.
### Типичная ошибка
Использовать общий счётчик между worker или полагаться только на порядок проектов.
### Связь с Automation QA
Очистка использует точный `task.id`.

## 5. Персональные данные
### Ответ
Production-профиль раскрывает персональные данные и может изменяться независимо от теста; нужна синтетическая тестовая заготовка.
### Объяснение
Тестовые данные должны быть разрешёнными и воспроизводимыми.
### Типичная ошибка
Обезличить только имя, оставив email или token.
### Связь с Automation QA
Отчёты не содержат реальные данные пользователя.

## 6. Мини-проект: каталог данных
### Ответ
Статусы хранятся в `Object.freeze()`, а Factory создаёт новую задачу с уникальным ID; владелец регистрирует очистку только этой задачи. Входные и ожидаемые объекты создаются независимо.
### Объяснение
Разделяется лишь неизменяемый справочник.
### Типичная ошибка
Хранить созданные задачи в общем массиве области модуля.
### Связь с Automation QA
Каталог остаётся безопасным при повторном запуске.
