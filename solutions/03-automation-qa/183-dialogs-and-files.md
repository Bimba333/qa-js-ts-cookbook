# Решения: Диалоги и работа с файлами

## Задача 1. Концептуальные вопросы
### Ответ
Dialog и download приходят как события браузера, поэтому ожидание или обработчик устанавливаются до вызывающего действия. Репозиторий владеет безопасным файлом для upload, а тест или fixture — временным download и его удалением.
### Объяснение
DOM не содержит готовый элемент для этих взаимодействий.
### Типичная ошибка
Оставить владение файлами неявным.
### Связь с Automation QA
Явный жизненный цикл предотвращает блокировки и мусор в CI.

## Задача 2. Анализ взаимодействия
### Ответ
Для alert: `page.once("dialog")` до click. Для file input: `setInputFiles()`. Для download: `page.waitForEvent("download")` до click.
### Объяснение
Только upload через существующий input не требует отдельного события браузера.
### Типичная ошибка
Использовать `fill()` для file input.
### Связь с Automation QA
API соответствует фактическому взаимодействию с браузером.

## Задача 3. Предскажите результат
### Ответ
Без обработчика Playwright автоматически отклонит `confirm`, и действие продолжится. Если обработчик зарегистрирован, но не вызывает `accept()` или `dismiss()`, вызвавшее dialog действие не завершится. DOM Locator не управляет dialog уровня браузера.
### Объяснение
Dialog существует вне дерева документа.
### Типичная ошибка
Искать кнопку alert через role Locator.
### Связь с Automation QA
Зарегистрированный, но незавершённый обработчик dialog выглядит как случайный тайм-аут.

## Задача 4. Поиск ошибки
### Ответ
Общее имя файла создаёт состояния гонки и устаревшие данные. Нужно использовать `test.info().outputPath()` или уникальную временную директорию и удалять файл в `finally`.
### Объяснение
Каждый тест должен владеть своим путём к артефакту.
### Типичная ошибка
Отключить параллельное выполнение вместо исправления владения.
### Связь с Automation QA
Изолированный каталог результатов работает локально и в CI.

## Задача 5. Automation QA
### Ответ
До клика создаётся Promise ожидания download. После события проверяется предложенное имя, файл сохраняется в уникальный каталог результатов, содержимое проверяется, а `finally` удаляет его.
### Объяснение
Факт события недостаточен для проверки отчёта.
### Типичная ошибка
Проверять только расширение.
### Связь с Automation QA
Содержимое является наблюдаемым бизнес-результатом.

## Задача 6. Мини-проект
### Ответ
```ts
import { readFile, rm } from "node:fs/promises";
import { expect, test } from "@playwright/test";

test("загружает и скачивает файл", async ({ page }) => {
  await page.setContent(`
    <input aria-label="Файл" type="file">
    <a download="result.txt" href="data:text/plain;charset=utf-8,%D0%B3%D0%BE%D1%82%D0%BE%D0%B2%D0%BE">Скачать</a>
  `);
  await page.getByLabel("Файл").setInputFiles({
    name: "input.txt", mimeType: "text/plain", buffer: Buffer.from("QA"),
  });
  const downloadPromise = page.waitForEvent("download");
  await page.getByRole("link", { name: "Скачать" }).click();
  const download = await downloadPromise;
  const path = test.info().outputPath(download.suggestedFilename());
  try {
    await download.saveAs(path);
    expect(await readFile(path, "utf8")).toBe("готово");
  } finally {
    await rm(path, { force: true });
  }
});
```
### Объяснение
Буфер upload детерминирован, путь download изолирован каталогом результатов теста.
### Типичная ошибка
Использовать личный абсолютный путь.
### Связь с Automation QA
Пример переносим между машиной разработчика и CI.
