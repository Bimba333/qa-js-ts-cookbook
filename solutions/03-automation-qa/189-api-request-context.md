# Решения: APIRequestContext

## Задача 1. Концептуальные вопросы
### Ответ
Встроенный `request` принадлежит Playwright Test. Контекст из `newContext()` принадлежит создавшему его коду. Новый контекст изолирует клиентские cookies и настройки, но не серверные данные.
### Объяснение
Владение созданием определяет освобождение.
### Типичная ошибка
Закрывать fixture или оставлять вручную созданный контекст открытым.
### Связь с Automation QA
Явный жизненный цикл предотвращает общее состояние HTTP-клиента.

## Задача 2. Анализ жизненного цикла
### Ответ
Владелец — тест или fixture, вызвавшие `newContext()`. Владелец должен вызвать `dispose()` в `finally` после завершения всех потребителей.
### Объяснение
Вспомогательная функция-потребитель не должна закрывать чужой ресурс.
### Типичная ошибка
Переносить `dispose()` внутрь первой вспомогательной функции.
### Связь с Automation QA
Несколько операций могут безопасно использовать одну управляемую сессию.

## Задача 3. Предскажите результат
### Ответ
Нет. Cookies изолированы, но оба клиента изменяют один серверный ресурс с тем же ID.
### Объяснение
Состояние клиента и состояние сервера имеют разные границы.
### Типичная ошибка
Считать новый контекст новой базой данных.
### Связь с Automation QA
Для данных нужны unique IDs или очистка.

## Задача 4. Поиск ошибки
### Ответ
Контекст создаётся в test-scoped fixture или внутри теста, передаётся потребителям и освобождается после `use()` либо в `finally`.
### Объяснение
Module import не предоставляет управляемый async жизненный цикл.
### Типичная ошибка
Добавлять глобальный afterAll к singleton.
### Связь с Automation QA
Владение на уровне теста сохраняет независимость набора тестов.

## Задача 5. Automation QA
### Ответ
Обычный тест использует встроенную fixture. Отдельная cookie-сессия и специальные общие заголовки оправдывают созданный вручную контекст. Цена — явное создание и вызов `dispose()`.
### Объяснение
Дополнительная сессия нужна только для отдельной границы состояния.
### Типичная ошибка
Создавать контекст для каждого запроса.
### Связь с Automation QA
Минимальный жизненный цикл уменьшает стоимость и риск утечек.

## Задача 6. Мини-проект
### Ответ
```ts
import { expect, request as factory, test } from "@playwright/test";
import { startLocalApi } from "./support/local-api.js";

test("управляет request context", async () => {
  const api = await startLocalApi();
  try {
    const context = await factory.newContext({
      baseURL: api.baseURL,
      extraHTTPHeaders: { "x-test-role": "qa" },
    });
    try {
      const response = await context.get("/inspect");
      expect(await response.json()).toMatchObject({ testRole: "qa" });
    } finally {
      await context.dispose();
    }
  } finally {
    await api.close();
  }
});
```
### Объяснение
Контекст и сервер имеют независимые и явно управляемые жизненные циклы.
### Типичная ошибка
Закрыть сервер раньше APIRequestContext.
### Связь с Automation QA
Сценарий переносим и не оставляет фоновых ресурсов.
