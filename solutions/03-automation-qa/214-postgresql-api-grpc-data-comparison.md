# Решения: Сверка данных PostgreSQL с API и gRPC

## 1. Каноническая модель
### Ответ
Оба слоя преобразуются к общей форме с одинаковыми именами, типами, допустимостью `null` и представлением времени.
### Объяснение
Это отделяет различия представления от расхождения бизнес-данных.
### Типичная ошибка
Сравнивать исходную строку базы данных с исходным объектом JSON или protobuf.
### Связь с Automation QA
Падение показывает реальное расхождение данных.

## 2. Предскажите результат
### Ответ
Строгое сравнение завершится ошибкой, потому что строка и число различаются.
### Объяснение
`pg` сохраняет точность `numeric`, возвращая строковое представление.
### Типичная ошибка
Использовать `==`.
### Связь с Automation QA
Правило преобразования должно быть явным и проверяемым.

## 3. Отладка сравнения времени
### Ответ
Обе стороны приводятся к UTC ISO: `new Date(value).toISOString()`.
### Объяснение
Смещение часового пояса становится частью нормализации.
### Типичная ошибка
Удалять суффикс `Z` строковой операцией.
### Связь с Automation QA
Сравнение не зависит от часового пояса машины, запускающей тесты.

## 4. Реализация преобразования
### Ответ
```ts
const mapped = {
  id: row.id,
  ownerId: row.owner_id,
  estimatedHours: row.estimated_hours === null ? null : Number(row.estimated_hours),
  createdAt: row.created_at.toISOString(),
  description: row.description,
};
```
### Объяснение
Каждое изменение представления видно в одном месте.
### Типичная ошибка
Использовать небезопасное приведение к транспортному типу.
### Связь с Automation QA
Преобразование делает диагностику предсказуемой.

## 5. Выбор бизнес-полей
### Ответ
Сравниваются стабильный ID, заголовок, статус или приоритет и поля контракта. Внутренняя последовательность, столбцы аудита и служебные признаки хранения исключаются, если у теста нет специальной цели.
### Объяснение
Проверка должна соответствовать цели теста.
### Типичная ошибка
Копировать `SELECT *` в snapshot.
### Связь с Automation QA
Тест не ломается при безопасном рефакторинге схемы.

## 6. Мини-проект: межслойная диагностика
### Ответ
Сначала модели связываются по ID, затем преобразование строит канонические объекты; сообщение о расхождении перечисляет поле, значение базы данных и транспортное значение.
### Объяснение
Различия по полям быстрее локализуют ошибку, чем общий результат `false`.
### Типичная ошибка
Сравнивать сущности с разными ID.
### Связь с Automation QA
Диагностика сохраняет контекст межслойного падения.
