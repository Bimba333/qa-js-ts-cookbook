# Решения: Hooks и жизненный цикл теста

## Задача 1. Концептуальные вопросы
### Ответ
`beforeAll` и `afterAll` обрамляют группу тестов; `beforeEach` и `afterEach` обрамляют каждый тест в области объявления.
### Объяснение
Scope определяет применимые hooks.
### Типичная ошибка
Считать hooks глобальными всегда.
### Связь с Automation QA
Область управляет подготовкой и очисткой.

## Задача 2. Порядок выполнения
### Ответ
При обычном успешном выполнении двух тестов в одном worker: `beforeAll`, `beforeEach`, test 1, `afterEach`, `beforeEach`, test 2, `afterEach`, `afterAll`.
### Объяснение
Hooks уровня теста повторяются для каждого тела теста. После перезапуска worker hooks уровня группы могут выполниться снова.
### Типичная ошибка
Запускать `beforeAll` перед каждым тестом.
### Связь с Automation QA
Порядок объясняет владельца состояния.

## Задача 3. Предскажите результат
### Ответ
При ошибке в `beforeEach` тело теста не выполняется, но применимый `afterEach` всё равно запускается. Ошибка в `afterEach` делает жизненный цикл неуспешным, потому что очистка не завершена корректно.
### Объяснение
Подготовка и очистка являются частью результата.
### Типичная ошибка
Игнорировать ошибки очистки.
### Связь с Automation QA
Незакрытый ресурс влияет на следующие сценарии.

## Задача 4. Debugging
### Ответ
Тесты изменяют общий заказ и зависят от предыдущих изменений. Каждый тест должен получать собственный заказ или независимое состояние.
### Объяснение
Стоимость подготовки не оправдывает общее изменяемое состояние.
### Типичная ошибка
Зафиксировать порядок тестов.
### Связь с Automation QA
Независимые данные допускают параллельное выполнение.

## Задача 5. Automation QA
### Ответ
В hook допустима одинаковая техническая подготовка страницы или очистка. Выбор роли пользователя, создание конкретного заказа и важные предусловия лучше видеть в теле теста.
### Объяснение
Сценарий должен сохранять бизнес-смысл.
### Типичная ошибка
Спрятать весь Arrange далеко от теста.
### Связь с Automation QA
Ошибку легче связать с условием сценария.

## Задача 6. Мини-проект
### Ответ
```ts
test.describe("lifecycle", () => {
  test.beforeEach(async ({ page }) => {
    await page.setContent(`<ol aria-label="События"><li>beforeEach</li></ol>`);
  });
  test.afterEach(async ({ page }) => {
    await page.getByRole("list").evaluate((list) => {
      const item = document.createElement("li");
      item.textContent = "afterEach";
      list.append(item);
    });
    await expect(page.getByRole("listitem")).toHaveText(["beforeEach", "test", "afterEach"]);
  });
  test("сценарий", async ({ page }) => {
    await page.getByRole("list").evaluate((list) => {
      const item = document.createElement("li");
      item.textContent = "test";
      list.append(item);
    });
    await expect(page.getByRole("listitem")).toHaveText(["beforeEach", "test"]);
  });
});
```
### Объяснение
Проверка фиксирует test-scoped последовательность без общего изменяемого массива. Порядок all-hooks рассматривается отдельно как порядок успешного выполнения внутри worker.
### Типичная ошибка
Хранить порядок hooks в общем изменяемом массиве между тестами.
### Связь с Automation QA
Пример делает порядок наблюдаемым.
