# Решения: Parallel execution

## 1. Уровни параллелизма
### Ответ
По умолчанию файлы распределяются между workers; `fullyParallel` разрешает параллельное выполнение отдельных тестов; parallel describe ограничивает режим группой; workers задают доступное число процессов.
### Объяснение
Режим выполнения и доступное число процессов — разные настройки.
### Типичная ошибка
Считать `workers: 4` режимом параллельного выполнения тестов внутри файла.
### Связь с Automation QA
Число выполнений рассчитывается отдельно от числа workers.

## 2. Предскажите конфликт
### Ответ
Тесты могут перезаписать или удалить один файл, поэтому результат будет зависеть от расписания.
### Объяснение
У фиксированного пути нет единственного владельца.
### Типичная ошибка
Добавить произвольную задержку.
### Связь с Automation QA
Для каждого теста используется `testInfo.outputPath()`.

## 3. Последовательная группа
### Ответ
Serial mode уместен для одного неделимого рабочего процесса; для обычных тестов он скрывает зависимость и связывает результаты группы: после падения следующие тесты пропускаются, а при retry группа повторяется вместе.
### Объяснение
Независимые проверки должны создавать собственные данные.
### Типичная ошибка
Обернуть весь набор в serial mode.
### Связь с Automation QA
Последовательная граница применяется узко и явно.

## 4. Независимость тестов
### Ответ
Каждый тест создаёт необходимые данные, проверяет их и очищает в собственном жизненном цикле.
### Объяснение
Второй тест больше не читает состояние первого.
### Типичная ошибка
Перенести общее состояние в переменную модуля.
### Связь с Automation QA
Выбор тестов и retries не меняют корректность.

## 5. Automation QA-задача
### Ответ
Идентификаторы включают идентификатор выполнения, файлы создаются через `outputPath`, а очистка удаляет только собственные идентификаторы и файлы.
### Объяснение
Параллельное расписание не создаёт конфликтов владения.
### Типичная ошибка
Удалять все записи по общему префиксу.
### Связь с Automation QA
Очистка API-сценария не затрагивает соседний тест.

## 6. Мини-проект: безопасный параллельный набор
### Ответ
Конфигурация использует точный `testMatch` и `fullyParallel`; два теста имеют независимые ресурсы. Запуски `--workers=1` и `--workers=2` завершаются успешно.
### Объяснение
Число workers меняет скорость, но не результат.
### Типичная ошибка
Проверить только одно значение workers.
### Связь с Automation QA
Так подтверждается изоляция ресурсов.
