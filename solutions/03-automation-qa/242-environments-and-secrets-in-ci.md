# Решения: Environments и secrets в CI

## 1. Variable и secret
### Ответ
`API_BASE_URL` хранится как variable, если адрес не секретен; `API_TOKEN` хранится как secret.
### Объяснение
Variable описывает окружение, а token предоставляет credential.
### Типичная ошибка
Хранить оба значения прямо в YAML.
### Связь с Automation QA
Тестовый код получает единый runtime-контракт, но не отвечает за хранение значений.

## 2. Граница fork
### Ответ
Непроверенный код из fork не должен получать repository secrets. Для такого события запускают проверки без credentials или пропускают только явно зависимый job.
### Объяснение
Отсутствие secret является границей безопасности, а не случайной ошибкой.
### Типичная ошибка
Переключаться на `pull_request_target` без анализа угроз.
### Связь с Automation QA
Набор тестов без секретов остаётся доступным для внешнего pull request.

## 3. Masking и permissions
### Ответ
Masking скрывает известное значение в журнале. Permissions ограничивают доступ workflow к ресурсам. Скрытое значение всё ещё может быть использовано чрезмерно привилегированным job.
### Объяснение
Отображение и авторизация — разные механизмы.
### Типичная ошибка
Считать masked token безопасным при `write-all`.
### Связь с Automation QA
Тестовый job получает только необходимые права и credentials.

## 4. Проверка runtime-конфигурации
### Ответ
```bash
set -euo pipefail
require_non_blank() {
  local value="${!1-}"
  test -n "${value//[[:space:]]/}"
}
require_non_blank API_BASE_URL
require_non_blank API_TOKEN
```
### Объяснение
Функция отклоняет отсутствующее, пустое и состоящее только из пробелов значение, ничего не выводит и сохраняет ненулевой код завершения.
### Типичная ошибка
Использовать `echo "$API_TOKEN"` для проверки.
### Связь с Automation QA
Неполная конфигурация останавливается до сетевого сценария.

## 5. Automation QA-задача
### Ответ
Используйте environment secret в `qa-preview`, если credential требует ручного подтверждения и ограниченной области environment.
### Объяснение
Настроенные правила защиты добавляют управляемую границу доступа.
### Типичная ошибка
Использовать production environment для учебных тестов.
### Связь с Automation QA
Credentials тестового environment отделены от production.

## 6. Мини-проект: защищённый контракт environment
### Ответ
Fixture главы 242 задаёт `environment: qa-preview`, `vars.API_BASE_URL`, `secrets.API_TOKEN`, `contents: read` и раннюю проверку пустых и пробельных значений. Значения доступны только шагу проверки.
### Объяснение
YAML содержит только имена secret, но не значения.
### Типичная ошибка
Коммитить вымышленный token, похожий на реальный credential.
### Связь с Automation QA
Статический fixture проверяет контракт без доступа к GitHub secrets.
