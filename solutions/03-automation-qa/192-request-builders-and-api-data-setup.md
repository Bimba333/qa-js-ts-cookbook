# Решения: Request Builders и подготовка данных через API

## Задача 1. Концептуальные вопросы
### Ответ
Валидные значения по умолчанию дают минимальное рабочее тело данных, переопределения выражают отличие сценария, а независимый `build()` не позволяет одному тесту изменить данные другого.
### Объяснение
Builder управляет созданием значения, но не HTTP-вызовом и не жизненным циклом ресурса.
### Типичная ошибка
Прятать обязательные для сценария значения среди случайных значений по умолчанию.
### Связь с Automation QA
Тест показывает только значимое отклонение от валидного случая.

## Задача 2. Анализ данных
### Ответ
Общая изменяемая ссылка создаёт зависимость от порядка. `build()` должен возвращать новый объект, например `{ ...this.values }`, а вложенные изменяемые поля также должны копироваться.
### Объяснение
Независимость результата важнее fluent syntax.
### Типичная ошибка
Копировать только верхний уровень тела данных с общим вложенным массивом.
### Связь с Automation QA
Изолированные данные безопаснее при параллельном выполнении.

## Задача 3. Предскажите результат
### Ответ
При падении проверки выполнение не дойдёт до обычной очистки, и ресурс останется на сервере. Удаление следует размещать в `finally` или в завершающей части fixture с сохранённым ID.
### Объяснение
Очистка должна выполняться и после неуспешного основного сценария.
### Типичная ошибка
Регистрировать очистку до того, как известен назначенный сервером ID.
### Связь с Automation QA
Гарантированная очистка уменьшает загрязнение окружения.

## Задача 4. Поиск ошибки
### Ответ
Builder только формирует тело данных. API Client отправляет POST и возвращает модель ответа. Тест или fixture сохраняет ID и владеет очисткой; глобальное разделяемое состояние не используется.
### Объяснение
У этих операций разные причины изменения и разные жизненные циклы.
### Типичная ошибка
Называть вспомогательный объект с внутренним состоянием builder-ом.
### Связь с Automation QA
Явное владение данными упрощает диагностику и повторный запуск.

## Задача 5. Automation QA
### Ответ
Уникальность можно строить из индекса worker, идентификатора теста и случайного суффикса. Очистка использует ID ответа, потому что `title` может повторяться, нормализоваться или изменяться.
### Объяснение
Назначенный сервером идентификатор является устойчивой связью между подготовкой и очисткой.
### Типичная ошибка
Удалять первый ресурс, найденный по title.
### Связь с Automation QA
ID предотвращает удаление данных соседнего теста.

## Задача 6. Мини-проект
### Ответ
```ts
import { expect, test } from "@playwright/test";
import { startLocalApi } from "./support/local-api.js";

class TaskBuilder {
  private title = "Новая задача";
  withTitle(title: string) { this.title = title; return this; }
  build() { return { title: this.title }; }
}

test("создаёт и удаляет данные", async ({ request }) => {
  const api = await startLocalApi();
  let taskId: string | undefined;
  try {
    const payload = new TaskBuilder().withTitle("api-task").build();
    const response = await request.post(`${api.baseURL}/tasks`, { data: payload });
    expect(response.status()).toBe(201);
    const location = response.headers().location;
    expect(location).toMatch(/^\/tasks\/task-\d+$/);
    if (location === undefined) throw new Error("Ответ создания не содержит Location");
    taskId = location.slice("/tasks/".length);
  } finally {
    if (taskId) await request.delete(`${api.baseURL}/tasks/${taskId}`);
    await api.close();
  }
});
```
### Объяснение
Построение тела данных, HTTP-операция и очистка имеют отдельных владельцев.
### Типичная ошибка
Удалять ресурс только после проверки.
### Связь с Automation QA
Шаблон остаётся устойчивым при падении теста.
