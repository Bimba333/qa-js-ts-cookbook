# Решения: Workers и shared resources

## 1. Worker и project
### Ответ
Worker — процесс выполнения; project — конфигурация, тесты которой распределяются между workers.
### Объяснение
Один project может использовать несколько workers.
### Типичная ошибка
Называть project отдельным процессом.
### Связь с Automation QA
Число процессов и набор конфигураций масштабируются независимо.

## 2. Замена worker
### Ответ
Локальное состояние процесса теряется; новый worker создаёт fixtures заново. После падения меняется `workerIndex`, а `parallelIndex` сохраняет слот параллельного выполнения.
### Объяснение
На состоянии модуля нельзя строить координацию всего набора.
### Типичная ошибка
Ожидать сохранения счётчика после падения.
### Связь с Automation QA
Владение внешним ресурсом восстанавливается по сохранённому идентификатору выполнения.

## 3. Общая учётная запись
### Ответ
Выделите учётную запись по `parallelIndex` или через аренду из пула; очистка освобождает только полученную аренду.
### Объяснение
Явный владелец предотвращает удаление ресурса соседнего теста.
### Типичная ошибка
Использовать одну учётную запись для всех workers.
### Связь с Automation QA
Ограниченный ресурс координируется явно.

## 4. Идентификаторы worker
### Ответ
`workerIndex` различает созданные процессы, `parallelIndex` — слоты параллельного выполнения. Конкретные значения относятся только к текущему запуску.
### Объяснение
Индексы помогают именовать ресурсы, но не являются постоянными бизнес-идентификаторами.
### Типичная ошибка
Сохранять `workerIndex` как глобального владельца навсегда.
### Связь с Automation QA
Идентификатор ресурса также включает project и полный логический идентификатор теста.

## 5. Automation QA-задача
### Ответ
Каждый тест создаёт уникальный идентификатор записи и удаляет только свою запись; затем набор проходит с двумя workers.
### Объяснение
Устраняется общий ключ, а не параллельное выполнение.
### Типичная ошибка
Поставить `workers: 1`.
### Связь с Automation QA
Правильность сохраняется при масштабировании.

## 6. Мини-проект: идентификатор владельца ресурса
### Ответ
Идентификатор объединяет project, shard, индексы parallel, worker, repeat и retry, ограниченное название и короткий хеш полного `titlePath`; запрещённые для имени файла символы заменяются.
### Объяснение
Полный `titlePath` различает одинаковые короткие названия в разных группах, а хеш сохраняет ограниченную длину.
### Типичная ошибка
Включать абсолютный путь или секрет.
### Связь с Automation QA
Очистка использует сохранённый идентификатор конкретной попытки и удаляет только её ресурс.
