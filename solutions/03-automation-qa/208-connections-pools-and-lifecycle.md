# Решения: Connections, pools и lifecycle

## 1. Подключение и пул
### Ответ
Отдельный `Client` закрывается через `client.end()`. `Pool` завершается через `pool.end()`. Полученный `PoolClient` сначала возвращается через `release()`.
### Объяснение
Пул владеет подключениями, а вызывающий код временно владеет выделенным подключением.
### Типичная ошибка
Вызывать `end()` у выделенного клиента.
### Связь с Automation QA
Явное владение предотвращает зависание набора тестов.

## 2. Предскажите результат
### Ответ
Пул может исчерпать подключения, а открытые ресурсы удержат процесс Node.js.
### Объяснение
Ни выделенное подключение, ни жизненный цикл пула не завершены.
### Типичная ошибка
Считать окончание тестовой функции автоматическим закрытием ресурсов.
### Связь с Automation QA
Утечка проявляется как тайм-аут или незавершающийся запуск тестов.

## 3. Отладка очистки
### Ответ
Сначала `client.release()`, затем `await pool.end()`.
### Объяснение
Владелец пула завершает его после возврата выделенного ресурса.
### Типичная ошибка
Закрывать родительский ресурс раньше возврата дочернего.
### Связь с Automation QA
Порядок очистки остаётся одинаковым при успехе и ошибке.

## 4. Реализация жизненного цикла
### Ответ
```ts
const pool = new Pool(config);
let client: PoolClient | undefined;
try {
  client = await pool.connect();
  await client.query("SELECT 1");
} finally {
  client?.release();
  await pool.end();
}
```
### Объяснение
`finally` выполняется и после отклонённого запроса.
### Типичная ошибка
Создавать пул внутри `try`, но терять ссылку для его завершения.
### Связь с Automation QA
Fixture применяет тот же жизненный цикл вокруг `use()`.

## 5. Область теста или worker
### Ответ
Тест, изменяющий состояние, выигрывает от клиента или схемы в области теста. Набор тестов только для чтения может использовать пул в области worker при доказанной изоляции.
### Объяснение
Область выбирается по владению и стоимости подключений.
### Типичная ошибка
Предписывать один общий пул для всех тестов.
### Связь с Automation QA
Fixture worker обязана завершить пул после worker.

## 6. Мини-проект: fixture пула
### Ответ
```ts
const test = base.extend<{ db: PoolClient }>({
  db: async ({}, use) => {
    const pool = new Pool(config);
    let client: PoolClient | undefined;
    try {
      client = await pool.connect();
      await use(client);
    } finally {
      try {
        client?.release();
      } finally {
        await pool.end();
      }
    }
  },
});
```
### Объяснение
Fixture владеет пулом и выделенным подключением, а тест — только временем использования. Пул завершается и при ошибке получения подключения.
### Типичная ошибка
Передавать пул без определённого владельца завершения.
### Связь с Automation QA
Жизненный цикл не зависит от результата проверок.
