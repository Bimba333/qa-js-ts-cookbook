# Решения: Нормализация и проверки между слоями

## 1. Каноническая модель
### Ответ
Подходят стабильный ID, бизнес-статус, сумма или часы, нормализованная дата и состояние owner, если этими полями владеет выбранное сравнение. Модель остаётся локальной этому сравнению.
### Объяснение
Технические поля транспорта и хранилища остаются в adapters источников.
### Типичная ошибка
Копировать объединение всех DTO.
### Связь с Automation QA
Сравнение отвечает одному бизнес-вопросу.

## 2. Предскажите результат
### Ответ
Строгое сравнение различит строку и число, несмотря на одинаковое числовое значение.
### Объяснение
Слои используют разные представления во время выполнения.
### Типичная ошибка
Применять нестрогое равенство.
### Связь с Automation QA
Оба значения преобразуются в проверенное число.

## 3. Диагностика опасной нормализации
### Ответ
Некорректное внешнее значение превращается в допустимый `0`, создавая ложноположительный результат.
### Объяснение
Adapter должен отклонить `NaN`, а не изобретать бизнес-значение.
### Типичная ошибка
Использовать `Number(value) || 0`.
### Связь с Automation QA
Контрактное расхождение остаётся видимым.

## 4. Реализация преобразования
### Ответ
```ts
type OwnerState =
  | { kind: "missing" }
  | { kind: "null" }
  | { kind: "value"; value: string };

const hours = Number(row.estimated_hours);
const date = new Date(row.due_at);
if (!Number.isFinite(hours) || Number.isNaN(date.getTime())) throw new Error("Invalid task row");
let owner: OwnerState;
if (!Object.prototype.hasOwnProperty.call(row, "owner")) owner = { kind: "missing" };
else if (row.owner === null) owner = { kind: "null" };
else if (typeof row.owner === "string") owner = { kind: "value", value: row.owner };
else throw new Error("Invalid owner");
return { id: row.id, hours, dueAt: date.toISOString(), owner };
```
### Объяснение
Преобразование проверяет число и дату и сохраняет различие между отсутствующим значением, `null` и строковым значением, включая пустую строку.
### Типичная ошибка
Использовать type assertion для строки базы данных.
### Связь с Automation QA
Каноническая модель содержит поля, проверенные во время выполнения.

## 5. Владение полями
### Ответ
Техническая колонка не входит в контракт API и может измениться без изменения бизнес-поведения.
### Объяснение
Сравниваются поля, необходимые для выбранного бизнес-вопроса.
### Типичная ошибка
Требовать равенства всех метаданных хранилища.
### Связь с Automation QA
Тест не становится копией схемы базы данных.

## 6. Мини-проект: сравнение между слоями
### Ответ
Adapters API и PostgreSQL отдельно валидируют вход, явно преобразуют собственные коды статуса, числа, даты и состояние owner и возвращают `CanonicalTask`, после чего выполняется `toEqual`.
### Объяснение
Различия преобразований изолированы до предметного сравнения.
### Типичная ошибка
Нормализовать порядок или `null` без контрактного основания.
### Связь с Automation QA
Ложноположительные результаты предотвращаются явными правилами каждого adapter.
