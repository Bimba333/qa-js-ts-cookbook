# Решения: Конфигурация Playwright и execution projects

## 1. Граница конфигурации
### Ответ
`testDir` задаёт каталог поиска, `testMatch` отбирает в нём файлы, `projects` создаёт варианты запуска, `use` задаёт параметры выполнения, а reporter представляет результат. Проекты не гарантируют изоляцию тестовых данных.
### Объяснение
Обнаружение тестов предшествует умножению найденных тестов по выбранным проектам.
### Типичная ошибка
Считать reporter источником поведения теста или проект средством автоматической изоляции.
### Связь с Automation QA
Явные границы позволяют воспроизвести конкретный профиль.

## 2. Предскажите результат
### Ответ
Будет четыре выполнения: два файла умножаются на два проекта.
### Объяснение
Один найденный тест запускается отдельно в каждом выбранном проекте.
### Типичная ошибка
Называть это повторным обнаружением тестов.
### Связь с Automation QA
Стоимость набора проектов должна быть осознанной.

## 3. Диагностика обнаружения тестов
### Ответ
Широкий glob захватит замороженные и служебные `.ts`; нужен список `chapter-216/**/*.execution.ts` … `chapter-224/**/*.execution.ts`.
### Объяснение
Точный шаблон задаёт границу модуля.
### Типичная ошибка
Использовать один общий `**/*.ts`.
### Связь с Automation QA
Изолированная конфигурация не меняет результаты других модулей.

## 4. Выбор проекта
### Ответ
```bash
npx playwright test --config=playwright.execution.config.ts --project=local-chromium
```
### Объяснение
`--config` выбирает конфигурацию, `--project` — один её вариант.
### Типичная ошибка
Передавать имя файла вместо имени проекта.
### Связь с Automation QA
Команда воспроизводит один профиль выполнения.

## 5. Браузер и окружение
### Ответ
`chromium` определяет браузерный движок, `preview` — целевое окружение. Ни одно из значений не обозначает worker.
### Объяснение
Оси можно комбинировать, но они решают разные задачи.
### Типичная ошибка
Считать браузер названием окружения или проект worker-процессом.
### Связь с Automation QA
Имя `preview-chromium` делает обе настройки наблюдаемыми.

## 6. Мини-проект: профили выполнения
### Ответ
Конфигурация использует точный `testMatch`, общий `reporter: "line"`, отдельный `outputDir` и проекты `local-chromium`/`preview-chromium` с тестовыми `baseURL`; обнаружение проверяется командой с `--list`.
### Объяснение
Оба проекта применяются к одному набору файлов и создают ожидаемое удвоение.
### Типичная ошибка
Использовать production URL или общий каталог результатов замороженного модуля.
### Связь с Automation QA
Профили запуска остаются воспроизводимыми и изолированными.
