# Решения: Диагностический поток Framework

## 1. Политика доказательств
### Ответ
Сохраняются title и case ID, project, имя окружения, seed, идентификатор сценария, исходный `Error` и артефакт, отвечающий на вопрос о падении.
### Объяснение
Набор поддерживает воспроизведение и проверку гипотезы.
### Типичная ошибка
Сохранять все доступные данные без ограничения.
### Связь с Automation QA
Политика делает диагностику повторяемой.

## 2. Предскажите результат
### Ответ
Ошибка hook может стать последней и затруднить чтение исходного падения assertion.
### Объяснение
Диагностический код должен сохранять исходное падение даже при собственной ошибке.
### Типичная ошибка
Выполнять рискованный сетевой запрос в hook.
### Связь с Automation QA
Hook прикладывает уже доступный безопасный контекст.

## 3. Связывание данных
### Ответ
Один идентификатор помещается в структурированное событие, JSON-вложение и metadata отчёта; секрет хранится только как `[REDACTED]`.
### Объяснение
Связь не требует раскрытия credentials.
### Типичная ошибка
Использовать token как идентификатор сценария.
### Связь с Automation QA
События разных слоёв объединяются в расследовании.

## 4. Граница хранения
### Ответ
Временный output принадлежит запуску теста и очищается runner; результаты reporter принадлежат адаптеру; опубликованный отчёт и срок его хранения принадлежат границе хранилища или release-процесса.
### Объяснение
Разные стадии имеют разных владельцев.
### Типичная ошибка
Удалять report data из test body.
### Связь с Automation QA
Жизненный цикл артефакта остаётся контролируемым.

## 5. Automation QA-задача
### Ответ
Диагностика достаточна, если сохраняет условия воспроизведения, исходную ошибку и доказательства для проверки конкретной гипотезы без данных production.
### Объяснение
Объём данных сам по себе не является критерием.
### Типичная ошибка
Считать наличие trace завершённым расследованием.
### Связь с Automation QA
Доказательства оцениваются по вопросам, на которые отвечают.

## 6. Мини-проект: диагностический поток
### Ответ
Успешный набор тестов использует предметные steps, безопасный logger, ограниченное описание cause и attachments; значение не типа `Error` получает явное описание, а циклическая cause — маркер. Набор с контролируемым падением через failure hook копирует вложение с контекстом, удаляет временный исходный файл и сохраняет настроенные артефакты UI с exit `1`.
### Объяснение
Негативный путь изолирован, основной набор тестов остаётся зелёным.
### Типичная ошибка
Включить retry, чтобы контролируемое падение исчезало.
### Связь с Automation QA
Поток готов к отдельной технической проверке без окончательной сборки framework.
