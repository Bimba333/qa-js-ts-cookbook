# Решения: Жизненный цикл тестовых данных

## 1. Владение жизненным циклом
### Ответ
Код, успешно создавший ресурс, сразу регистрирует очистку в `ResourceScope` текущего сценария.
### Объяснение
Между созданием и регистрацией не остаётся промежутка, в котором ошибка оставит ресурс без очистки.
### Типичная ошибка
Регистрировать всё после завершения подготовки.
### Связь с Automation QA
Каждый тест удаляет только собственные данные.

## 2. Предскажите результат
### Ответ
Удаление родительской записи получит ошибку внешнего ключа, а без продолжения очистки дочерняя и родительская записи останутся в системе.
### Объяснение
Зависимости удаляются в обратном порядке создания.
### Типичная ошибка
Полагаться на cascade без явного контракта.
### Связь с Automation QA
Стек очистки выполняется в порядке LIFO.

## 3. Диагностика потерянной ошибки
### Ответ
Потеряна основная ошибка проверки; её и ошибки очистки следует сохранить в `AggregateError`.
### Объяснение
Ошибка очистки не отменяет исходную причину падения.
### Типичная ошибка
Выбрасывать последнюю ошибку.
### Связь с Automation QA
Отчёт показывает дефект и проблему восстановления среды.

## 4. Реализация стека очистки
### Ответ
```ts
const cleanups: Array<() => Promise<void>> = [];
cleanups.push(deleteParent);
cleanups.push(deleteChild);
const cleanupErrors: unknown[] = [];
for (const cleanup of cleanups.reverse()) {
  try {
    await cleanup();
  } catch (error) {
    cleanupErrors.push(error);
  }
}
if (cleanupErrors.length > 0) {
  throw new AggregateError(cleanupErrors, "Очистка завершилась с ошибками");
}
```
### Объяснение
Обратный порядок удаляет дочерний ресурс до родительского, а отдельная ошибка не пропускает оставшиеся callbacks.
### Типичная ошибка
Использовать `forEach(async ...)` без ожидания.
### Связь с Automation QA
Процесс Node.js не завершается до окончания очистки.

## 5. Очистка через API и базу данных
### Ответ
Очистка через API использует ID созданного ресурса, а очистка базы данных — точный первичный ключ или принадлежащую сценарию схему.
### Объяснение
Широкие условия удаления нарушают владение данными.
### Типичная ошибка
Удалять все записи с общим префиксом.
### Связь с Automation QA
Параллельные сценарии не очищают соседние данные.

## 6. Мини-проект: безопасный ResourceScope
### Ответ
Родительский и дочерний ресурсы регистрируют очистку сразу. Контролируемая основная ошибка сохраняется, LIFO-очистка продолжает работу после двух ошибок, а `AggregateError` содержит основную ошибку и обе ошибки очистки. Повторный `close()` не вызывает callbacks снова, а регистрация после закрытия отклоняется.
### Объяснение
Жизненный цикл управляет успешной и ошибочной ветками одинаково.
### Типичная ошибка
Прерывать очистку после первой ошибки или повторно выполнять callbacks при втором `close()`.
### Связь с Automation QA
Система возвращается в контролируемое состояние с полной диагностикой.
