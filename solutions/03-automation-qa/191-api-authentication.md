# Решения: Аутентификация API

## Задача 1. Концептуальные вопросы
### Ответ
Аутентификация подтверждает, кто выполняет запрос, а авторизация определяет, разрешено ли этому субъекту действие. API key обычно передаёт идентификатор клиента, bearer token — предъявляемое подтверждение доступа с заданными правами и сроком действия.
### Объяснение
Одинаковый HTTP-заголовок не делает механизмы взаимозаменяемыми: их выдача, срок жизни и модель прав различаются.
### Типичная ошибка
Считать наличие учётных данных гарантией доступа к любому маршруту.
### Связь с Automation QA
Тесты отдельно проверяют отсутствие подтверждённой личности и недостаточные разрешения.

## Задача 2. Анализ доступа
### Ответ
`401 Unauthorized` означает, что сервер не смог подтвердить личность: token отсутствует или недействителен. `403 Forbidden` означает, что личность известна, но её роли недостаточно для операции.
### Объяснение
Ответы описывают разные границы контракта доступа.
### Типичная ошибка
Ожидать `401` при любом отказе доступа.
### Связь с Automation QA
Раздельные сценарии точнее локализуют дефект аутентификации или авторизации.

## Задача 3. Предскажите результат
### Ответ
Часть тестов может пройти, а более поздние получить `401`; параллельные workers могут увидеть ошибку в разное время. Новый APIRequestContext скопирует переданный token, но не получит новый token без явного процесса аутентификации.
### Объяснение
Жизненный цикл контекста и жизненный цикл учётных данных являются разными процессами.
### Типичная ошибка
Пытаться исправить истёкший token пересозданием контекста с тем же заголовком.
### Связь с Automation QA
Token получают или обновляют в контролируемой fixture с известным сроком жизни.

## Задача 4. Поиск ошибки
### Ответ
Секрет передаётся через защищённую переменную окружения, проверяется при запуске и никогда не попадает в исходный код, URL, сообщения проверки или вложения. Диагностика может показывать тип учётных данных и код состояния, но должна маскировать значение.
### Объяснение
Удобство расследования не отменяет границу хранения секретов.
### Типичная ошибка
Маскировать token только в `console.log`, оставляя его в дампе запроса.
### Связь с Automation QA
Одинаковая политика нужна при локальном запуске и в отчётах.

## Задача 5. Automation QA
### Ответ
Позитивный сценарий использует token минимально достаточной роли и ожидает `200`. Запрос без учётных данных ожидает `401` и стабильный код ошибки. Token роли QA на административном маршруте ожидает `403`, а защищённое состояние не должно измениться.
### Объяснение
Негативные проверки подтверждают не только отказ, но и его причину и отсутствие эффекта.
### Типичная ошибка
Проверять административный маршрут только привилегированным token.
### Связь с Automation QA
Матрица ролей становится частью регрессионного набора тестов доступа.

## Задача 6. Мини-проект
### Ответ
```ts
import { expect, test } from "@playwright/test";
import { startLocalApi } from "./support/local-api.js";

test("проверяет аутентификацию и авторизацию", async ({ request }) => {
  const api = await startLocalApi();
  try {
    const session = await request.post(`${api.baseURL}/sessions`, {
      data: { username: "qa", password: "local-secret" },
    });
    expect(session.status()).toBe(200);
    const body: unknown = await session.json();
    if (
      typeof body !== "object"
      || body === null
      || !("token" in body)
      || typeof body.token !== "string"
    ) {
      throw new Error("Ответ сессии не содержит token");
    }

    const profile = await request.get(`${api.baseURL}/profile`, {
      headers: { authorization: `Bearer ${body.token}` },
    });
    expect(profile.status()).toBe(200);
    expect((await request.get(`${api.baseURL}/profile`)).status()).toBe(401);

    const admin = await request.get(`${api.baseURL}/admin`, {
      headers: { authorization: `Bearer ${body.token}` },
    });
    expect(admin.status()).toBe(403);
  } finally {
    await api.close();
  }
});
```
### Объяснение
Token остаётся только в памяти теста и не выводится в сообщения.
### Типичная ошибка
Добавлять token в название шага теста или вложение.
### Связь с Automation QA
Локальный API воспроизводимо разделяет `200`, `401` и `403`.
