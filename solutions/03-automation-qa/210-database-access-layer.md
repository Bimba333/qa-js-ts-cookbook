# Решения: Database Access Layer

## 1. Назначение слоя
### Ответ
DAL централизует SQL и преобразование строк схемы, предоставляя предметные операции. `execute()` оставляет сценарий зависимым от SQL.
### Объяснение
Абстракция полезна, когда выражает устойчивую ответственность.
### Типичная ошибка
Создать универсальный репозиторий с одним обобщённым методом.
### Связь с Automation QA
Тест остаётся читаемым без потери семантики базы данных.

## 2. Предскажите результат
### Ответ
`"2.50" !== 2.5`, поэтому строгое сравнение завершится ошибкой.
### Объяснение
PostgreSQL часто возвращает `numeric` как строку для сохранения точности.
### Типичная ошибка
Использовать нестрогое равенство.
### Связь с Automation QA
Преобразование должно явно определять допустимый переход к числу.

## 3. Отладка преобразования
### Ответ
```ts
const description = row.description; // string | null
```
### Объяснение
`null` сохраняется, пока прикладной контракт явно не определит другое представление.
### Типичная ошибка
Удалять свойство через spread только ради совпадения объектов.
### Связь с Automation QA
Несовпадение `null` и отсутствующего свойства часто указывает на реальное различие контрактов.

## 4. Реализация метода репозитория
### Ответ
```ts
async findTask(id: string): Promise<TaskRecord | undefined> {
  const result = await this.client.query<TaskRow>(
    "SELECT id, title, estimated_hours FROM tasks WHERE id = $1",
    [id],
  );
  const row = result.rows[0];
  return row === undefined ? undefined : {
    id: row.id,
    title: row.title,
    estimatedHours: row.estimated_hours === null ? null : Number(row.estimated_hours),
  };
}
```
### Объяснение
Запрос параметризован, отсутствие строки явно, преобразование централизовано.
### Типичная ошибка
Использовать `as TaskRecord` без преобразования.
### Связь с Automation QA
Тест получает удобную прикладную модель.

## 5. Граница проверок
### Ответ
Репозиторий возвращает факты из базы данных; тестовый сценарий решает, какой результат ожидается.
### Объяснение
Проверка зависит от цели конкретного теста.
### Типичная ошибка
Встроить `expect(row).toBeDefined()` в `findTask`.
### Связь с Automation QA
Один метод может использоваться и в положительном, и в отрицательном сценарии.

## 6. Мини-проект: TasksRepository
### Ответ
Репозиторий принимает клиент с методом запросов в конструкторе; методы используют `$1...$n`, возвращают преобразованные строки и `rowCount`, но не создают подключение и транзакцию.
### Объяснение
Внешний владелец может передать обычный или транзакционный клиент.
### Типичная ошибка
Открывать новый пул внутри каждого метода.
### Связь с Automation QA
Жизненный цикл и откат остаются видимыми в коде fixture и теста.
