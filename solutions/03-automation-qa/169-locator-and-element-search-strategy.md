# Решения: Locator и стратегия поиска элементов

## Задача 1. Концептуальные вопросы
### Ответ
`Locator` хранит запрос, а не зафиксированный узел; DOM разрешается при действии или проверке.
### Объяснение
После re-render запрос обращается к актуальному состоянию.
### Типичная ошибка
Считать `Locator` снимком элемента.
### Связь с Automation QA
Динамический UI реже ломает корректный `Locator`.

## Задача 2. Выбор стратегии
### Ответ
Кнопка: `getByRole`; email: `getByLabel`; строка: role/listitem с `filter`; canvas без семантики: согласованный test id.
### Объяснение
Выбор использует самый значимый доступный контракт.
### Типичная ошибка
Объявить test id обязательным везде.
### Связь с Automation QA
Стратегии балансируют доступность и устойчивость.

## Задача 3. Предскажите результат
### Ответ
Действие завершится strictness error из-за двух совпадений.
### Объяснение
Click требует однозначной цели.
### Типичная ошибка
Без анализа добавить `.first()`.
### Связь с Automation QA
Ошибка обнаруживает неясное намерение теста.

## Задача 4. Debugging
### Ответ
```ts
const order = page.getByRole("listitem").filter({ hasText: "order-42" });
await order.getByRole("button", { name: "Открыть" }).click();
```
### Объяснение
Locator выражает строку заказа и действие внутри неё.
### Типичная ошибка
Сохранить `nth(3)` без контракта порядка.
### Связь с Automation QA
Изменение расположения строк не ломает поиск.

## Задача 5. Automation QA
### Ответ
Role проверяет пользовательскую семантику, но имя меняется при локализации. Test id стабилен к тексту, но не доказывает доступность.
### Объяснение
Оба контракта имеют цену.
### Типичная ошибка
Называть один вариант универсальным.
### Связь с Automation QA
Команда выбирает `Locator` с учётом рисков интерфейса.

## Задача 6. Мини-проект
### Ответ
```ts
await page.setContent(`<ul><li>order-41 <button>Открыть</button></li><li>order-42 <button>Открыть</button></li><li>order-43 <button>Открыть</button></li></ul>`);
const order = page.getByRole("listitem").filter({ hasText: "order-42" });
await expect(order).toHaveCount(1);
await expect(order.getByRole("button", { name: "Открыть" })).toBeVisible();
```
### Объяснение
Filtering связывает кнопку с нужной строкой.
### Типичная ошибка
Искать все кнопки и выбирать вторую.
### Связь с Automation QA
Код сохраняет бизнес-идентификатор заказа.
