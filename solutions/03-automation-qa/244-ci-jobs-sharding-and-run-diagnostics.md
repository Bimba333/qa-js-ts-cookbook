# Решения: CI jobs, sharding и диагностика запусков

## 1. Matrix и shard
### Ответ
Matrix `shard: [1, 2]` создаёт два GitHub Actions jobs, каждый со своим runner. Каждый job передаёт в Playwright свой shard с нумерацией от единицы. Playwright project выбирает конфигурацию запуска, а workers выполняют тесты внутри job.
### Объяснение
Matrix создаёт отдельные окружения выполнения, а sharding выбирает части набора тестов.
### Типичная ошибка
Считать matrix двумя Playwright workers или projects.
### Связь с Automation QA
Подготовка повторяется в каждом job, а тесты распределяются явно.

## 2. Покрытие
### Ответ
Shard `1/2` выполняет 2 теста, shard `2/2` — ещё 2; общее количество уникальных тестов равно 4, дубликатов и пропусков нет.
### Объяснение
Проверяется объединение идентификаторов тестов, а не только сумма количеств.
### Типичная ошибка
Считать `2 + 2` достаточным без проверки пересечений.
### Связь с Automation QA
Регрессионное покрытие не теряется при ускорении.

## 3. Идентификаторы artifacts
### Ответ
Имя `stability-shard-$&#123;&#123; matrix.shard &#125;&#125;-of-2` принадлежит одному matrix job.
### Объяснение
Идентификатор shard делает принадлежность результата явной.
### Типичная ошибка
Использовать одно имя `stability-results` для всех jobs.
### Связь с Automation QA
Диагностические материалы каждого сегмента можно расследовать отдельно.

## 4. Fail-fast
### Ответ
`strategy.fail-fast: false` не отменяет состояние failed одного job, но позволяет второму shard завершиться и сохранить диагностические материалы.
### Объяснение
Это политика выполнения matrix, а не ослабление assertions.
### Типичная ошибка
Путать fail-fast с `continue-on-error`.
### Связь с Automation QA
Команда получает полную картину распределённого запуска.

## 5. Automation QA-задача
### Ответ
Сравните commit, событие запуска, environment, project, shard, данные worker, идентификаторы тестовых данных и внешние зависимости. Затем воспроизведите только изменившееся условие.
### Объяснение
Контекст падения только в CI направляет расследование, но не называет первопричину автоматически.
### Типичная ошибка
Сразу заводить дефект продукта по одному падению запуска по расписанию.
### Связь с Automation QA
Классификация сохраняет границы глав 232 и 225.

## 6. Мини-проект: sharded pipeline
### Ответ
Fixture главы 244 задаёт ограниченную matrix `[1, 2]`, `fail-fast: false`, команды `--shard=1/2` и `--shard=2/2` через выражение matrix и уникальные artifacts. Объединение отчёта не реализуется простым объединением каталогов.
### Объяснение
Два независимых jobs дают полное покрытие и сохраняют принадлежность результатов.
### Типичная ошибка
Добавлять объединение без проверки формата reporter.
### Связь с Automation QA
Pipeline масштабируется без изменения утверждённой семантики sharding.
