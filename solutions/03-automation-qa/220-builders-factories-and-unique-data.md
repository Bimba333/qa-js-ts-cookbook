# Решения: Builders, factories и уникальные данные

## 1. Factory или Builder
### Ответ
Для простого тела запроса достаточно Factory; для последовательных предметных шагов подходит Builder.
### Объяснение
Сложность API должна соответствовать сложности создания.
### Типичная ошибка
Создавать fluent Builder для трёх полей.
### Связь с Automation QA
Тест показывает только важные overrides.

## 2. Предскажите результат
### Ответ
Следующий тест получит изменённый `priority`, потому что оба вызова ссылаются на один объект.
### Объяснение
Сохранённый изменяемый результат нарушает независимость.
### Типичная ошибка
Копировать только верхний уровень при вложенном изменении.
### Связь с Automation QA
Factory возвращает новую структуру при каждом вызове.

## 3. Диагностика скрытого побочного эффекта
### Ответ
`build()` должен создать значение, а POST принадлежит подготовке через API или API Client.
### Объяснение
Иначе создание объекта неожиданно владеет сетевым запросом и очисткой.
### Типичная ошибка
Смешивать Factory и service client.
### Связь с Automation QA
Ошибка ясно относится к созданию данных или транспорту.

## 4. Реализация overrides
### Ответ
```ts
interface Task { id: string; title: string; priority: "low" | "high" }
function createTaskFactory(seed: string) {
  let sequence = 0;
  return (overrides: Partial<Task> = {}): Task => {
    sequence += 1;
    return { id: `${seed}-${sequence}`, title: "Проверить отчёт", priority: "low", ...overrides };
  };
}
```
### Объяснение
Каждый вызов создаёт новый объект, overrides видимы, а seed и локальная последовательность дают воспроизводимый ID. Объект overrides вызывающего кода не изменяется.
### Типичная ошибка
Разрешать неизвестные поля через `Record<string, unknown>`.
### Связь с Automation QA
Тело запроса остаётся типизированным.

## 5. Уникальность и seed
### Ответ
Seed включает имя проекта, индекс повтора и индекс worker, а локальная последовательность различает вызовы одной Factory.
### Объяснение
Такая структура предотвращает коллизии между проектами и повторами и оставляет диагностический контекст.
### Типичная ошибка
Использовать timestamp или `Math.random()` как единственную гарантию.
### Связь с Automation QA
Падение можно повторить с тем же seed.

## 6. Мини-проект: фабрика данных запроса
### Ответ
Локальная Factory хранит последовательность, создаёт новый валидный объект и принимает типизированные overrides для обычного, срочного и негативного вариантов. Seed строится из project/repeat/worker. Factory не выполняет I/O, проверки или очистку.
### Объяснение
Варианты отличаются только полями, важными сценарию.
### Типичная ошибка
Изменять объект по умолчанию между вызовами.
### Связь с Automation QA
Все три тела запроса воспроизводимы и независимы.
