# Решения: Timeouts и границы ожидания

## Задача 1. Концептуальные вопросы
### Ответ
Test timeout включает тело теста, подготовку fixture и `beforeEach`; `afterEach` и освобождение fixture получают отдельный бюджет того же значения, а `beforeAll` и `afterAll` имеют собственные границы. Expect timeout ограничивает проверку, action timeout — действие, navigation timeout — переход. Retry запускает новую попытку после ошибки.
### Объяснение
Граница и повтор — разные механизмы.
### Типичная ошибка
Увеличивать retry вместо исправления wait condition.
### Связь с Automation QA
Правильная классификация улучшает диагностику.

## Задача 2. Анализ границ
### Ответ
Test timeout в одну секунду может завершить выполнение раньше expect timeout.
### Объяснение
Во время тела теста test timeout охватывает выполняемую проверку, поэтому может завершиться раньше её собственной границы.
### Типичная ошибка
Считать expect timeout гарантированным временем.
### Связь с Automation QA
Сообщение об ошибке нужно читать вместе с областью timeout.

## Задача 3. Предскажите результат
### Ответ
Assertion проходит примерно после обновления статуса, потому что 80 мс находятся внутри границы 500 мс.
### Объяснение
Timeout — максимум, а не обязательная задержка.
### Типичная ошибка
Ожидать, что тест всегда ждёт 500 мс.
### Связь с Automation QA
Успешное состояние завершает ожидание сразу.

## Задача 4. Debugging
### Ответ
Проверить `Locator`, фактическое состояние UI, правильность условия, ошибки приложения и сети, затем измерить нормальную длительность. Изменять только релевантную границу.
### Объяснение
Число не устраняет первопричину.
### Типичная ошибка
Начинать с глобальной настройки.
### Связь с Automation QA
Расследование сохраняет полезный сигнал ошибки.

## Задача 5. Automation QA
### Ответ
Локальный UI-отклик ожидается быстро; формирование отчёта может быть отдельной длительной операцией. Их вариативность и бизнес-ограничения различаются.
### Объяснение
Граница относится к классу операции.
### Типичная ошибка
Использовать один максимум для всего.
### Связь с Automation QA
Разные boundaries помогают обнаруживать деградацию.

## Задача 6. Мини-проект
### Ответ
```ts
await page.setContent(`<p aria-label="Статус">Старт</p><script>setTimeout(() => document.querySelector('p').textContent='Готово', 80)</script>`);
await expect(page.getByLabel("Статус")).toHaveText("Готово", { timeout: 500 });
```
Граница должна превышать подтверждённую нормальную вариативность с разумным запасом.
### Объяснение
Локальная настройка документирует особенность проверки.
### Типичная ошибка
Представлять 500 мс универсальным правилом.
### Связь с Automation QA
Выбор подтверждается поведением тестовой среды.
