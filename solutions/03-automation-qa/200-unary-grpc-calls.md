# Решения: Unary gRPC-вызовы

## Задача 1. Концептуальные вопросы
### Ответ
Unary call отправляет один request и завершается response либо ошибкой. `ClientUnaryCall` принадлежит одному вызову, а channel client используется несколькими calls до `close()`.
### Объяснение
Завершение call и закрытие channel являются разными событиями.
### Типичная ошибка
Закрывать channel после первого RPC method независимо от границы ответственности владельца.
### Связь с Automation QA
Разделение предотвращает состояние гонки и лишние подключения.

## Задача 2. Анализ обёртки Promise
### Ответ
При `error !== null` обёртка должна вызвать `reject(error)` и выйти. Только определённый response приводит к `resolve(response)`.
### Объяснение
У unary call две взаимоисключающие ветви результата.
### Типичная ошибка
Выполнить `resolve` после `reject` в том же callback.
### Связь с Automation QA
`ServiceError` остаётся доступным негативной проверке.

## Задача 3. Предскажите результат
### Ответ
Тест может завершиться до callback; проверка не войдёт в жизненный цикл раннера, и ошибка станет потерянной либо поздней.
### Объяснение
Раннер ожидает возвращённый Promise.
### Типичная ошибка
Считать, что Playwright Test автоматически отслеживает любой callback.
### Связь с Automation QA
`await` исключает ложноположительное завершение.

## Задача 4. Поиск ошибки
### Ответ
Нужно вернуть Promise, который завершается callback RPC, и дождаться его через `await`. `waitForTimeout()` удаляется.
### Объяснение
Сигнал завершения точнее временной догадки.
### Типичная ошибка
Увеличивать задержку при редких падениях.
### Связь с Automation QA
Сценарий становится быстрее и детерминированнее.

## Задача 5. Automation QA
### Ответ
Тест создаёт request, ожидает create response, сохраняет ID, вызывает get, сравнивает messages и закрывает client/server в `finally`.
### Объяснение
Каждый call имеет наблюдаемый результат, а ресурсы — владельца.
### Типичная ошибка
Связать calls через неуникальный title вместо ID.
### Связь с Automation QA
Последовательность подходит для подготовки и проверки данных.

## Задача 6. Мини-проект
### Ответ
```ts
const callUnary = <T>(start: (callback: (error: ServiceError | null, value?: T) => void) => ClientUnaryCall) =>
  new Promise<T>((resolve, reject) => {
    start((error, value) => {
      if (error !== null) return reject(error);
      if (value === undefined) return reject(new Error("Response отсутствует"));
      resolve(value);
    });
  });
```
### Объяснение
Адаптер сохраняет ошибку и запрещает неопределённый успешный результат.
### Типичная ошибка
Использовать `value!` без проверки.
### Связь с Automation QA
Обобщённый адаптер повторно используется без потери деталей протокола.
