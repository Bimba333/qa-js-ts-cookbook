# Решения: Расследование падения автотеста

## 1. Классификация
### Ответ
Дефект теста подтверждается ошибочным ожиданием или сценарием; дефект framework — общей тестовой инфраструктурой; дефект приложения — воспроизводимым нарушением продукта; проблемы окружения и данных — конфигурацией окружения или состоянием данных; инфраструктурная проблема — runner, сетью либо недоступным внешним сервисом.
### Объяснение
Классификацию подтверждают stack, данные запроса и ответа, состояние database, config и повторение в тех же условиях.
### Типичная ошибка
Назвать владельца только по месту последнего assertion.
### Связь с Automation QA
Доказательства помогают направить дефект правильной команде.

## 2. Предскажите результат
### Ответ
Доказан один успешный запуск; причина первого падения и стабильность исправления не доказаны.
### Объяснение
Условия могли измениться между запусками.
### Типичная ошибка
Закрыть расследование после одного повторного запуска.
### Связь с Automation QA
Сохраняются project, seed и доказательства обоих запусков.

## 3. Сужение поиска
### Ответ
Оставить только шаги, необходимые для падения, запустить тот же файл с тем же config и `--project`, сохранить имя окружения и seed, затем по одному проверять данные, транспорт и состояние приложения.
### Объяснение
Одна изменяемая переменная позволяет связать результат с гипотезой.
### Типичная ошибка
Одновременно менять timeout, данные и project.
### Связь с Automation QA
Выбор файла и `--project` создают минимальное воспроизведение.

## 4. Диагностика ложного исправления
### Ответ
Timeout лишь отложил падение, слабый assertion перестал замечать расхождение, а отключённая очистка оставила общее состояние.
### Объяснение
Ни одно изменение не проверило механизм возникновения `pending`.
### Типичная ошибка
Считать зелёный статус доказательством найденной первопричины.
### Связь с Automation QA
Исправление не должно уменьшать наблюдаемость дефекта.

## 5. Automation QA-задача
### Ответ
Симптом: UI не получил `completed`. Доказательства: API и database также возвращают `pending`. Гипотеза: приложение не завершило обработку. Владелец уточняется по доказательствам API и database. Проверка: после исправления оба слоя и UI согласованно показывают `completed`.
### Объяснение
Два источника backend уменьшают вероятность дефекта только в UI assertion.
### Типичная ошибка
Обвинить UI по месту падения.
### Связь с Automation QA
Доказательства из нескольких слоёв отделяют симптом от владельца.

## 6. Мини-проект: карточка расследования
### Ответ
Используйте readonly-поля `symptom`, `evidence`, `hypothesis`, `owner`, `correction`, `verification`; constructor или factory отклоняет пустой массив `evidence`.
### Объяснение
Структура не позволяет смешать наблюдение и вывод.
### Типичная ошибка
Сохранить только свободный текст.
### Связь с Automation QA
Карточка делает ход рассуждения проверяемым при triage.
