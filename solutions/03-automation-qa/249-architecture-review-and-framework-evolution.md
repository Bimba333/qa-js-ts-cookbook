# Решения: Architecture review и эволюция Framework

## 1. Evidence
### Ответ
Наблюдаемые сигналы: изменение API client требует правок 20 tests; import graph содержит цикл; global state пересекает workers; разные helpers читают config самостоятельно. Предпочтение: автору больше нравится factory, чем constructor.
### Объяснение
Первое наблюдаемо и имеет maintenance cost, второе само по себе не доказывает дефект.
### Типичная ошибка
Выдавать вкус команды за обязательный architecture rule.
### Связь с Automation QA
Review опирается на фактическую область влияния изменения.

## 2. Coupling и cohesion
### Ответ
UI tests должны зависеть от user-facing page contracts, а не transport details. Их массовая правка при смене API обычно указывает на лишний coupling, если пользовательский контракт не изменился.
### Объяснение
Изменение пересекло границу без изменения цели UI tests.
### Типичная ошибка
Считать любое повторное использование хорошей связью.
### Связь с Automation QA
Public boundaries ограничивают стоимость migration.

## 3. Предскажите решение
### Ответ
Первым устраняется high-severity cycle, потому что он нарушает dependency direction и блокирует изолированное изменение.
### Объяснение
Severity ранжирует подтверждённые риски до косметического дублирования.
### Типичная ошибка
Начать с самого простого rename и оставить цикл.
### Связь с Automation QA
Fixture и service снова можно проверять независимо.

## 4. Speculative abstraction
### Ответ
DI container пока не решает подтверждённую проблему. Оставьте явный constructor или factory и вернитесь к решению при подтверждённой потребности в другом способе сборки зависимостей.
### Объяснение
Новая абстракция также имеет стоимость поддержки.
### Типичная ошибка
Измерять зрелость framework числом patterns.
### Связь с Automation QA
Composition остаётся читаемой для команды тестирования.

## 5. Automation QA-задача
### Ответ
Checklist проверяет: изменяемое состояние теста не находится в worker scope; resource имеет одного владельца; cleanup точный; исходный `cause` сохранён; имена artifacts включают shard; transports скрыты за публичными границами. Каждый пункт сопровождается наблюдаемым сигналом и владельцем решения.
### Объяснение
Каждый пункт связан с наблюдаемым failure mode.
### Типичная ошибка
Использовать контрольный список без evidence и владельца исправления.
### Связь с Automation QA
Review охватывает execution, data и diagnostics contracts.

## 6. Мини-проект: review decision
### Ответ
Отсортируйте неизменяемую копию signals по severity и стабильному имени без зависимости от locale. Верните первый signal и его evidence; для пустого массива верните решение сохранить архитектуру.
### Объяснение
Детерминированный выбор не изобретает refactoring без входного сигнала.
### Типичная ошибка
Всегда возвращать заранее выбранный pattern.
### Связь с Automation QA
Следующий engineering task обоснован фактической стоимостью framework.
