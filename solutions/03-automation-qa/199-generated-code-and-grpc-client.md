# Решения: Сгенерированный код и создание gRPC Client

## Задача 1. Концептуальные вопросы
### Ответ
Генератор создаёт объявления TypeScript, loader создаёт описание package во время выполнения, сгенерированный client предоставляет RPC methods, а channel соединяет client с endpoint. Client закрывает его создатель.
### Объяснение
У каждого элемента отдельная роль во время статической проверки или выполнения.
### Типичная ошибка
Считать loader заменой управления жизненным циклом ресурсов.
### Связь с Automation QA
Явные роли упрощают устройство fixture.

## Задача 2. Анализ генерации
### Ответ
Нужно зафиксировать версии пакетов, параметры, входной `.proto` и один script `grpc:generate`. После генерации diff должен содержать только ожидаемые файлы модуля.
### Объяснение
Параметры влияют на представление enum, значения по умолчанию и imports.
### Типичная ошибка
Документировать только название инструмента без параметров.
### Связь с Automation QA
CI и локальный запуск получают одинаковые типы.

## Задача 3. Предскажите результат
### Ответ
Открытый channel может удерживать процесс или оставить ресурс до завершения среды выполнения. Тест должен вызвать `client.close()`.
### Объяснение
Завершение call не закрывает channel.
### Типичная ошибка
Считать unary response автоматическим освобождением client.
### Связь с Automation QA
Закрытие channel предотвращает ошибки из-за незавершённых ресурсов.

## Задача 4. Поиск ошибки
### Ответ
Сгенерированный файл восстанавливается генератором. Бизнес-helper переносится в написанный вручную `TasksGrpcClient`, который получает сгенерированный client через constructor.
### Объяснение
Повторная генерация не должна уничтожать бизнес-код.
### Типичная ошибка
Защищать директорию сгенерированного кода от повторной генерации ради ручных изменений.
### Связь с Automation QA
Разделение упрощает обновление `.proto`.

## Задача 5. Automation QA
### Ответ
Configuration предоставляет endpoint. Fixture создаёт сгенерированный client и закрывает его. Обёртка выражает операции ресурса, а тест хранит проверки и ожидаемые status.
### Объяснение
Fixture предоставляет доступ к ресурсу, но не передаёт обёртке ответственность за его закрытие.
### Типичная ошибка
Создавать client внутри каждого метода обёртки.
### Связь с Automation QA
Схема поддерживает изоляцию без singleton.

## Задача 6. Мини-проект
### Ответ
```ts
const server = await startLocalGrpcServer();
const client = createTaskServiceClient(server.endpoint);
try {
  await new Promise<void>((resolve, reject) =>
    client.waitForReady(Date.now() + 1_000, (error) =>
      error === undefined ? resolve() : reject(error)));
  const task = await callUnary<Task__Output>((callback) =>
    client.createTask({ title: "Generated" }, callback));
  expect(task.id).toBe("task-1");
} finally {
  client.close();
  await server.close();
}
```
### Объяснение
Сгенерированный метод используется после подтверждения готовности и внутри явного жизненного цикла.
### Типичная ошибка
Не ограничить ожидание готовности client.
### Связь с Automation QA
Решение полностью локально и воспроизводимо.
