# Решения: Структура HTTP-запроса

## Задача 1. Концептуальные вопросы
### Ответ
URL адресует маршрут, параметр пути выбирает конкретный ресурс, строка запроса уточняет обращение, заголовки передают метаданные, тип содержимого описывает тело, а тело содержит данные операции.
### Объяснение
Разделение локализует ошибку сообщения.
### Типичная ошибка
Смешивать строку запроса и тело как взаимозаменяемые части сообщения.
### Связь с Automation QA
Точная диагностика показывает, какая часть контракта запроса нарушена.

## Задача 2. Анализ запроса
### Ответ
`/tasks` выбирает коллекцию, `source=qa` уточняет запрос, заголовок задаёт тестовую роль, JSON-тело передаёт данные создания.
### Объяснение
Каждая часть имеет отдельную ответственность.
### Типичная ошибка
Помещать role и title в один query string.
### Связь с Automation QA
Так тест остаётся читаемым и близким к контракту API.

## Задача 3. Предскажите результат
### Ответ
Сервер может вернуть 415, 400 или другой документированный код состояния. Без контракта нельзя утверждать точный ответ, но тип содержимого не соответствует фактическому JSON.
### Объяснение
HTTP определяет формат поля, а маршрут определяет реакцию.
### Типичная ошибка
Всегда ожидать 400.
### Связь с Automation QA
Негативный тест должен фиксировать реальную договорённость сервиса.

## Задача 4. Поиск ошибки
### Ответ
Нужно передать `params: { title }`. APIRequestContext закодирует пробел и `&` как часть значения.
### Объяснение
Строковая конкатенация может изменить структуру query.
### Типичная ошибка
Заменить только пробел вручную.
### Связь с Automation QA
Структурный API защищает тестовые данные с особыми символами.

## Задача 5. Automation QA
### Ответ
Используйте `params: { status, owner }` и заголовок вроде `x-test-role`. Учётные данные должны передаваться в защищённом заголовке аутентификации, а не в URL.
### Объяснение
Строка запроса описывает фильтр, заголовок — служебный контекст.
### Типичная ошибка
Записывать token в query для удобства.
### Связь с Automation QA
URL часто попадает в журналы доступа и отчёты.

## Задача 6. Мини-проект
### Ответ
```ts
import { expect, test } from "@playwright/test";
import { startLocalApi } from "./support/local-api.js";

test("разбирает request", async ({ request }) => {
  const api = await startLocalApi();
  try {
    const response = await request.post(`${api.baseURL}/inspect`, {
      params: { source: "qa api" },
      headers: { "x-test-role": "auditor" },
      data: { title: "Задача" },
    });
    expect(await response.json()).toMatchObject({
      query: { source: "qa api" },
      testRole: "auditor",
      body: { title: "Задача" },
    });
  } finally {
    await api.close();
  }
});
```
### Объяснение
Playwright кодирует params и сериализует data как JSON.
### Типичная ошибка
Вызывать `JSON.stringify()` и задавать несовместимый заголовок.
### Связь с Automation QA
Пример проверяет состав запроса без внешней сети.
