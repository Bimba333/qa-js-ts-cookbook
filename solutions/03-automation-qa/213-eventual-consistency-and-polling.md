# Решения: Eventual consistency и polling

## 1. Ожидание по условию
### Ответ
Polling завершается сразу при выполнении условия и ограничивается предельным сроком.
### Объяснение
Фиксированное время не связано с фактической готовностью строки.
### Типичная ошибка
Заменять проверку длинной паузой.
### Связь с Automation QA
Ожидание по условию быстрее и даёт больше диагностической информации.

## 2. Предскажите результат
### Ответ
После 50 ms `SELECT`, вероятно, вернёт пустой результат. Увеличенная пауза остаётся зависимой от нагрузки.
### Объяснение
Время появления строки не гарантировано одной константой.
### Типичная ошибка
Удваивать паузу после каждого нестабильного падения.
### Связь с Automation QA
Ограниченный polling ждёт наблюдаемый бизнес-факт.

## 3. Отладка бесконечного polling
### Ответ
Цикл хранит абсолютный предельный срок, ждёт заданный интервал и при тайм-ауте выбрасывает ошибку с последним наблюдаемым значением.
### Объяснение
Эти границы предотвращают бесконечный цикл и перегрузку базы данных.
### Типичная ошибка
Проверять только количество попыток без диагностики.
### Связь с Automation QA
Сообщение о тайм-ауте показывает последнее состояние базы данных.

## 4. Реализация polling
### Ответ
```ts
const row = await pollUntil({
  read: async () => (await client.query<TaskRow>(
    "SELECT id, title FROM tasks WHERE id = $1", [id],
  )).rows[0],
  isReady: (value) => value?.title === expectedTitle,
  deadlineMs: 1_000,
  intervalMs: 25,
  describeLastValue: (value) => JSON.stringify(value ?? null),
});
```
### Объяснение
Условие привязано к стабильному ID и ожидаемому бизнес-значению. Последняя прочитанная строка сохраняется для диагностики тайм-аута.
### Типичная ошибка
Возвращать любую первую строку таблицы.
### Связь с Automation QA
Проверяется нужная сущность, а не случайное количество строк.

## 5. Ошибка подключения
### Ответ
Ошибку подключения нужно немедленно распространить: это инфраструктурная ошибка, а не отсутствие бизнес-данных.
### Объяснение
Повтор условия запроса не исправляет учётные данные или недоступный сервер.
### Типичная ошибка
Перехватывать все ошибки и возвращать `undefined`.
### Связь с Automation QA
Отчёт различает недоступную базу данных и тайм-аут сохранения.

## 6. Мини-проект: отложенное сохранение
### Ответ
Источник данных возвращает Promise, polling ждёт строку, а `finally` дожидается источника и закрывает клиент или пул. Таймер имеет короткую управляемую задержку и не остаётся после теста.
### Объяснение
Оба асинхронных жизненных цикла завершаются явно.
### Типичная ошибка
Запустить источник и не дождаться возможного отклонения Promise.
### Связь с Automation QA
Тест не оставляет фоновую работу после завершения.
