# Решения: Network interception и mocking

## Задача 1. Концептуальные вопросы
### Ответ
События наблюдают сетевой обмен, а перехват route управляет запросом. UI-тест с mock доказывает реакцию UI на заданный ответ, но не доступность и корректность реального backend.
### Объяснение
Mock заменяет границу интеграции.
### Типичная ошибка
Называть тест с mock сквозной проверкой.
### Связь с Automation QA
Нужны отдельные сценарии с реальной интеграцией.

## Задача 2. Анализ route
### Ответ
Пустой список — `fulfill()`, добавление заголовка — `continue()` или `fallback()` при цепочке обработчиков, запрет аналитики — `abort()`.
### Объяснение
Каждый метод выражает отдельную судьбу запроса.
### Типичная ошибка
Использовать `fulfill()` для изменения одного заголовка.
### Связь с Automation QA
Точное намерение делает network setup читаемым.

## Задача 3. Предскажите результат
### Ответ
Запрос останется приостановленным, а UI, ожидающий ответ, может завершиться по тайм-ауту.
### Объяснение
Обработчик route обязан явно продолжить или завершить запрос.
### Типичная ошибка
Считать возврат из callback автоматическим вызовом `continue()`.
### Связь с Automation QA
Незавершённый route выглядит как медленный backend.

## Задача 4. Поиск ошибки
### Ответ
Маска перехватывает документы, скрипты и стили. Нужно ограничить URL и при необходимости HTTP-метод, а остальные запросы передать через `fallback()` или не перехватывать.
### Объяснение
Граница перехвата должна соответствовать цели теста.
### Типичная ошибка
Добавить исключения по одному ресурсу.
### Связь с Automation QA
Узкая маска route уменьшает ложные падения.

## Задача 5. Automation QA
### Ответ
Route для точного URL профиля возвращает 503. UI-тест вызывает загрузку и проверяет видимое сообщение «Профиль временно недоступен». Тест не доказывает, что реальный сервис действительно возвращает этот контракт.
### Объяснение
Подготовка и наблюдаемый результат связаны одним состоянием.
### Типичная ошибка
Проверять только статус внутри обработчика.
### Связь с Automation QA
Сценарий детерминированно воспроизводит редкое состояние ошибки.

## Задача 6. Мини-проект
### Ответ
```ts
import { expect, test } from "@playwright/test";

test("показывает mock profile", async ({ page }) => {
  await page.route("https://book.test/profile", (route) => route.fulfill({
    status: 200,
    contentType: "application/json",
    body: '{"name":"QA"}',
  }));
  await page.setContent('<button>Загрузить</button><p role="status"></p>');
  await page.getByRole("button").evaluate((button) => {
    button.addEventListener("click", async () => {
      const profile = await fetch("https://book.test/profile").then((r) => r.json());
      const status = document.querySelector('[role="status"]');
      if (status instanceof HTMLElement) status.textContent = profile.name;
    });
  });
  await page.getByRole("button").click();
  await expect(page.getByRole("status")).toHaveText("QA");
});
```
### Объяснение
Точный URL полностью обрабатывается через `fulfill()` до обращения во внешнюю сеть.
### Типичная ошибка
Оставить часть запросов реальному домену.
### Связь с Automation QA
Контролируемый ответ делает состояние UI воспроизводимым.
