# Решения: Playwright и Playwright Test

## Задача 1. Концептуальные вопросы
### Ответ
Playwright управляет браузером; Playwright Test обнаруживает и запускает тесты, предоставляет окружение и формирует результат.
### Объяснение
Библиотека выполняет браузерные операции, тестовый раннер управляет жизненным циклом запуска.
### Типичная ошибка
Считать их одним компонентом.
### Связь с Automation QA
Граница показывает владельца browser behavior и test execution.

## Задача 2. Классификация
### Ответ
`Page`, `Locator`, браузерные действия — Playwright. `test()`, built-in fixtures, проверки и отчётность — Playwright Test.
### Объяснение
Fixtures могут передавать объекты библиотеки, но их жизненный цикл организует тестовый раннер.
### Типичная ошибка
Отнести `Page` к тестовому раннеру только потому, что он её выдаёт.
### Связь с Automation QA
Классификация помогает определить слой, в котором произошла ошибка.

## Задача 3. Предскажите результат
### Ответ
Библиотека создаёт содержимое страницы и ищет элемент; тестовый раннер выполняет тест и проверку. Тест проходит.
### Объяснение
Заголовок существует и видим.
### Типичная ошибка
Приписать обнаружение тестов объекту `page`.
### Связь с Automation QA
Один результат объединяет браузерное действие и проверку.

## Задача 4. Debugging
### Ответ
Прямой script не является тестовым набором. Для автоматического test report сценарий нужно объявить через `test()` и запускать Playwright Test.
### Объяснение
Библиотека не обязана выполнять обязанности тестового раннера.
### Типичная ошибка
Добавлять собственный отчёт, не определив потребность в особом тестовом раннере.
### Связь с Automation QA
Стандартный тестовый раннер уменьшает объём инфраструктурного кода.

## Задача 5. Automation QA
### Ответ
Playwright Test подходит из-за единого обнаружения, выполнения, fixtures, проверок, timeout и результатов. Прямое использование API остаётся полезным для специальных браузерных утилит.
### Объяснение
Выбор следует из типа задачи.
### Типичная ошибка
Объявлять один способ универсальным.
### Связь с Automation QA
Регрессия требует управляемого набора тестов.

## Задача 6. Мини-проект
### Ответ
```ts
import { expect, test } from "@playwright/test";

test("стенд готов", async ({ page }) => {
  await page.setContent("<h1>Стенд готов</h1>");
  await expect(page.getByRole("heading", { name: "Стенд готов" })).toBeVisible();
});
```
Тест проходит.
### Объяснение
Тестовый раннер предоставляет `page`, а web-first assertion проверяет локальный DOM.
### Типичная ошибка
Использовать внешний сайт.
### Связь с Automation QA
Пример является минимальной детерминированной UI-проверкой.
