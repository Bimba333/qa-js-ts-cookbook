# Решения: Page Object

## Задача 1. Концептуальные вопросы
### Ответ
Page Object владеет Locator и способом выполнить пользовательские действия. Тестовый сценарий владеет бизнес-намерением и ключевыми проверками результата.
### Объяснение
Граница отделяет изменение реализации UI от смысла проверки.
### Типичная ошибка
Перенести весь тест в Page Object.
### Связь с Automation QA
Тест остаётся читаемым как сценарий, а селекторы меняются локально.

## Задача 2. Анализ API
### Ответ
`loginAs(email)` лучше выражает намерение. `clickSubmit()` допустим, если именно низкоуровневое состояние кнопки является предметом теста или это внутренний вспомогательный метод.
### Объяснение
Уровень абстракции выбирается по языку потребителя.
### Типичная ошибка
Создать обёртку для каждого действия Playwright без новой семантики.
### Связь с Automation QA
Пользовательские методы уменьшают технический шум.

## Задача 3. Предскажите результат
### Ответ
Да. Locator лениво разрешает актуальный DOM в момент следующего действия.
### Объяснение
Он хранит стратегию поиска, а не старую ссылку на DOM-элемент.
### Типичная ошибка
Кэшировать DOM-элемент после первого рендеринга.
### Связь с Automation QA
Locator устойчивее к повторному рендерингу современных интерфейсов.

## Задача 4. Поиск ошибки
### Ответ
Класс объединяет несвязанные страницы и причины изменения. Его следует разделить по устойчивым границам страниц, а повторяющиеся компоненты вынести в Component Object, если они действительно общие.
### Объяснение
Граница следует ответственности, а не одному общему объекту браузера.
### Типичная ошибка
Заменить чрезмерно крупный объект множеством искусственных микроклассов.
### Связь с Automation QA
Локальные изменения уменьшают область влияния рефакторинга UI.

## Задача 5. Automation QA
### Ответ
Публичный API может содержать `openOrder(id)` и `createOrder(data)`. Селекторы, заполнение отдельных полей и промежуточная навигация остаются внутренними деталями. Проверка бизнес-результата остаётся в теле теста.
### Объяснение
API отражает действия пользователя, не DOM-команды.
### Типичная ошибка
Возвращать все внутренние Locator только ради проверок.
### Связь с Automation QA
Тесты говорят на языке заказов, а не селекторов.

## Задача 6. Мини-проект
### Ответ
```ts
import { expect, type Locator, type Page, test } from "@playwright/test";

class ProfilePage {
  readonly nameInput: Locator;
  readonly saveButton: Locator;

  constructor(private readonly page: Page) {
    this.nameInput = page.getByLabel("Имя");
    this.saveButton = page.getByRole("button", { name: "Сохранить" });
  }

  async open(): Promise<void> {
    await this.page.setContent(`
      <label>Имя <input></label><button>Сохранить</button><p role="status"></p>
      <script>document.querySelector("button").onclick=()=>
        document.querySelector('[role="status"]').textContent="Сохранено"</script>
    `);
  }

  async changeName(name: string): Promise<void> {
    await this.nameInput.fill(name);
    await this.saveButton.click();
  }
}

test("изменяет имя", async ({ page }) => {
  const profile = new ProfilePage(page);
  await profile.open();
  await profile.changeName("Vlad");
  await expect(page.getByRole("status")).toHaveText("Сохранено");
});
```
### Объяснение
Page Object выполняет взаимодействие, а тест проверяет бизнес-результат.
### Типичная ошибка
Скрыть проверку «Сохранено» внутри `changeName()` без необходимости.
### Связь с Automation QA
Изменение формы локализуется в одном объекте.
