# Решения: Protocol Buffers: сервисы и сообщения

## Задача 1. Концептуальные вопросы
### Ответ
`package` задаёт пространство имён, `service` группирует RPC methods, `rpc` связывает request и response, message описывает поля, а номер поля идентифицирует его в бинарном представлении. Тип TypeScript существует только во время статической проверки.
### Объяснение
Совместимость protobuf определяется `.proto`, а не названием интерфейса TypeScript.
### Типичная ошибка
Считать сгенерированный тип средством проверки схемы во время выполнения.
### Связь с Automation QA
QA-инженер читает исходный контракт до подготовки данных и проверок.

## Задача 2. Анализ совместимости
### Ответ
Номер 8 нельзя повторно использовать: старый декодер может прочитать `archived` как `legacy_id`. Нужно добавить `reserved 8;` и назначить новому полю новый номер.
### Объяснение
Номер поля является частью бинарного protobuf-контракта.
### Типичная ошибка
Удалить строку и считать номер свободным.
### Связь с Automation QA
Проверка контракта предотвращает дефекты при одновременной работе разных версий.

## Задача 3. Предскажите результат
### Ответ
Старый client пропустит неизвестное поле 9 и продолжит читать известные поля. Новый client сможет определить присутствие `optional`-поля.
### Объяснение
Добавление нового поля с новым номером обычно совместимо.
### Типичная ошибка
Объявлять любое расширение нарушением совместимости.
### Связь с Automation QA
Тесты совместимости должны учитывать разные версии участников обмена.

## Задача 4. Поиск ошибки
### Ответ
Нужно изменить `.proto` и снова выполнить генерацию. Ручная правка сгенерированного `Task.ts` не меняет сериализатор, контракт server и следующий результат генерации.
### Объяснение
Сгенерированный файл является производным артефактом.
### Типичная ошибка
Исправлять симптом только в одной рабочей копии client.
### Связь с Automation QA
Воспроизводимая генерация сохраняет единый контракт команды.

## Задача 5. Automation QA
### Ответ
Проверяются новый уникальный номер, `reserved` для удаления, совместимость при смене типа и совместимый либо нарушающий совместимость характер нового RPC method. Затем генерация повторяется и проверяются сценарии со старым и новым client.
### Объяснение
Каждый вид изменения имеет отдельный риск.
### Типичная ошибка
Ограничиться успешной компиляцией новой версии.
### Связь с Automation QA
Контрольный список делает проверку контракта повторяемой.

## Задача 6. Мини-проект
### Ответ
```proto
syntax = "proto3";
package qa.reports.v1;
service ReportService {
  rpc GetReport(GetReportRequest) returns (Report);
}
message GetReportRequest { string id = 1; }
message Report {
  reserved 3;
  string id = 1;
  string status = 2;
  optional string summary = 4;
}
```
### Объяснение
Номера 1, 2 и 4 сохраняют идентичность полей, а 3 защищён от повторного использования.
### Типичная ошибка
Перенумеровать fields для визуального порядка.
### Связь с Automation QA
Контракт пригоден для генерации и проверки совместимости разных версий.
