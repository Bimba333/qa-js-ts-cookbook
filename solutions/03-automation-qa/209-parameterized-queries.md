# Решения: Parameterized queries

## 1. Текст SQL и значения
### Ответ
Плейсхолдеры отделяют значения от грамматики SQL, но PostgreSQL не принимает идентификатор таблицы или столбца через `$1`.
### Объяснение
Динамический идентификатор меняет структуру запроса и требует отказа от динамики либо строгого списка разрешённых значений.
### Типичная ошибка
Пытаться выполнить `SELECT * FROM $1`.
### Связь с Automation QA
Вспомогательные функции тестов должны явно ограничивать операции со схемой.

## 2. Предскажите результат
### Ответ
Конкатенация нарушит строковый литерал на апострофе или изменит SQL. Параметризованный запрос передаст заголовок как одно значение.
### Объяснение
Драйвер кодирует параметр отдельно.
### Типичная ошибка
Экранировать один символ вручную.
### Связь с Automation QA
Реальные тестовые данные часто содержат знаки препинания и Unicode.

## 3. Отладка NULL
### Ответ
```sql
SELECT id FROM tasks WHERE description IS NULL;
```
### Объяснение
`NULL` означает неизвестность; сравнение через `=` не возвращает true.
### Типичная ошибка
Использовать `= NULL` или `!= NULL`.
### Связь с Automation QA
Допустимость `NULL` должна проверяться семантикой SQL, а не догадкой JavaScript.

## 4. Реализация INSERT RETURNING
### Ответ
```ts
const result = await client.query<{ id: string; description: string | null }>(
  "INSERT INTO tasks (id, title, priority, description) VALUES ($1, $2, $3, $4) RETURNING id, description",
  [id, title, "low", null],
);
expect(result.rowCount).toBe(1);
expect(result.rows[0]).toEqual({ id, description: null });
```
### Объяснение
Изменение данных и возвращённая строка проверяются отдельно.
### Типичная ошибка
Считать успешно выполненный запрос доказательством изменения ровно одной строки.
### Связь с Automation QA
`rowCount` помогает обнаружить слишком широкое изменение или отсутствие изменений.

## 5. Детерминированный SELECT
### Ответ
```sql
SELECT id FROM tasks WHERE priority = $1 ORDER BY id;
```
### Объяснение
Без `ORDER BY` PostgreSQL не гарантирует порядок строк.
### Типичная ошибка
Полагаться на порядок вставки.
### Связь с Automation QA
Детерминированное упорядочивание предотвращает нестабильные проверки массивов.

## 6. Мини-проект: безопасная функция запросов
### Ответ
```ts
const findTask = async (client: Client, id: string) => {
  const result = await client.query<{ id: string; title: string }>(
    "SELECT id, title FROM tasks WHERE id = $1",
    [id],
  );
  return result.rows[0];
};
```
### Объяснение
Функция имеет узкую цель и естественно возвращает `undefined`.
### Типичная ошибка
Возвращать первый элемент через небезопасное утверждение о ненулевом значении.
### Связь с Automation QA
Отсутствие строки остаётся наблюдаемым результатом.
