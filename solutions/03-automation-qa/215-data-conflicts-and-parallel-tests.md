# Решения: Конфликты данных и параллельные тесты

## 1. Общие строки
### Ответ
Даже один worker может встретить устаревшее изменение от предыдущего неудачного запуска или зависеть от порядка тестов.
### Объяснение
Состояние базы данных живёт дольше тестовой функции.
### Типичная ошибка
Считать последовательный запуск автоматической изоляцией.
### Связь с Automation QA
Независимый тест проходит отдельно и после повторного запуска.

## 2. Предскажите результат
### Ответ
Один `INSERT` пройдёт, другой получит нарушение `UNIQUE` или первичного ключа с SQLSTATE `23505`. Повтор не определяет владельца ID.
### Объяснение
Конфликт детерминирован ограничением целостности.
### Типичная ошибка
Добавлять повтор вместо уникального пространства имён.
### Связь с Automation QA
Каждый сценарий получает собственный идентификатор.

## 3. Отладка гонки при очистке
### Ответ
Каждый worker хранит точные ID созданных строк и удаляет их только через `WHERE id = $1`.
### Объяснение
Общий префикс может захватить данные соседнего worker.
### Типичная ошибка
Выполнять `DELETE WHERE id LIKE 'test-%'`.
### Связь с Automation QA
Владение очисткой остаётся локальным.

## 4. Реализация уникального пространства имён
### Ответ
```ts
const taskId = `w${testInfo.workerIndex}-${crypto.randomUUID()}`;
```
### Объяснение
Идентификатор worker помогает диагностике, а UUID устраняет общий изменяемый счётчик.
### Типичная ошибка
Использовать глобальный счётчик процесса для параллельных worker.
### Связь с Automation QA
Идентификатор остаётся уникальным и читаемым.

## 5. Детерминированная проверка
### Ответ
```ts
const result = await client.query<{ id: string }>(
  "SELECT id FROM tasks WHERE id = ANY($1::text[]) ORDER BY id",
  [[firstId, secondId]],
);
```
### Объяснение
`ORDER BY` определяет порядок массива независимо от плана запроса.
### Типичная ошибка
Сравнивать строки в порядке вставки.
### Связь с Automation QA
Проверка стабильна при повторном и параллельном выполнении.

## 6. Мини-проект: данные для параллельного запуска
### Ответ
Создаются два уникальных ID, оба передаются параметрами, проверяются через упорядоченный `SELECT`, затем каждый удаляется точным `DELETE` в `finally`.
### Объяснение
Создание, проверка и очистка используют один набор принадлежащих сценарию данных.
### Типичная ошибка
Очищать «последние две строки».
### Связь с Automation QA
Сценарий не зависит от общего состояния или порядка worker.
