# Решения: Архитектурные слои и поток зависимостей

## Задача 1. Концептуальные вопросы

### Ответ

Публичную границу образуют разрешённые потребителям операции. Цикл делает порядок владения и инициализации неясным. Ненужный слой добавляет стоимость без решаемой задачи.

### Объяснение

Архитектура оценивается по ответственности и зависимостям.

### Типичная ошибка

Считать каждую директорию отдельным архитектурным слоем.

### Связь с Automation QA

Небольшой проект только с API не обязан иметь UI-слой.

## Задача 2. Чтение потока зависимостей

### Ответ

Цикла нет. Слой тестовых сценариев оркестрирует подготовку через API и проверку через базу данных.

### Объяснение

Оба клиента зависят от конфигурации, но не друг от друга.

### Типичная ошибка

Помещать проверку через базу данных внутрь API-клиента.

### Связь с Automation QA

Сценарий сохраняет видимым намерение, объединяющее несколько слоёв.

## Задача 3. Предскажите результат выполнения кода

### Ответ

Вывод: `created`. Публичная граница — тип `Reader` и его операция `read()`.

### Объяснение

Потребитель не знает способ получения статуса.

### Типичная ошибка

Экспортировать внутреннюю модель ответа транспорта.

### Связь с Automation QA

Клиент можно изменить без переписывания намерения теста.

## Задача 4. Найдите нарушение

### Ответ

Есть циклическая зависимость. Тестовые данные нужно передавать UI-модулю через параметр публичного метода или отдельный поставщик тестовых данных, используемый слоем тестовых сценариев.

### Объяснение

Инфраструктура не должна импортировать тесты.

### Типичная ошибка

Использовать файл теста как хранилище общих данных.

### Связь с Automation QA

Явный владелец позднее упростит параллельное выполнение.

## Задача 5. Automation QA

### Ответ

Тесты зависят от API-клиента и слоя доступа к базе данных; оба зависят от конфигурации и диагностики. Конфигурация не зависит от клиентов, клиенты не зависят от тестов, API и слой базы данных не импортируют друг друга.

### Объяснение

Оркестрация остаётся на уровне тестовых сценариев.

### Типичная ошибка

Создавать взаимные импорты ради совместного использования кода.

### Связь с Automation QA

Сценарий с несколькими слоями остаётся читаемым, а реализации слоёв — заменяемыми.

## Задача 6. Мини-проект

### Ответ

Один допустимый минимум: тесты, API-клиент, слой доступа к базе данных, конфигурация, тестовые данные и диагностика. Точка сборки зависимостей создаёт конфигурацию, затем диагностику и клиенты, после чего передаёт публичные API исполнителю сценария.

### Объяснение

UI и gRPC отсутствуют, потому что проект их не использует.

### Типичная ошибка

Создавать пустые слои по шаблону.

### Связь с Automation QA

Структура соответствует реальному техническому объёму проекта.
