# Решения: API Client и граница HTTP-слоя

## Задача 1. Концептуальные вопросы
### Ответ
API Client скрывает URL, HTTP-метод и повторяющуюся сериализацию. Он не должен безусловно скрывать код состояния, тело ошибки и заголовки, нужные негативному тесту.
### Объяснение
Абстракция сохраняет наблюдаемый контракт.
### Типичная ошибка
Преобразовывать любой не-2xx в одинаковое исключение.
### Связь с Automation QA
Тест может проверять как успех, так и контролируемый отказ.

## Задача 2. Анализ публичного API
### Ответ
`createTask(data)` выражает операцию ресурса. Общий `post()` уместен как закрытая транспортная вспомогательная функция внутри клиента, но не как язык сценария.
### Объяснение
Публичный API должен передавать намерение.
### Типичная ошибка
Переименовать метод запроса без добавления новой семантики.
### Связь с Automation QA
Тест читается на языке тестируемой системы.

## Задача 3. Предскажите результат
### Ответ
Тест не сможет проверить код состояния и контракт ошибки 404, если клиент заранее заменит ответ исключением без подробностей.
### Объяснение
Негативный результат является частью контракта API.
### Типичная ошибка
Ограничивать клиент только позитивным сценарием.
### Связь с Automation QA
Метод ресурса должен поддерживать целевые негативные сценарии.

## Задача 4. Поиск ошибки
### Ответ
Разделите клиенты ресурсов по устойчивым областям. Политика повторов и транспортная политика остаются отдельной общей границей только при реальной необходимости; проверки остаются в тесте или целевом валидаторе.
### Объяснение
Причины изменения должны быть локальными.
### Типичная ошибка
Заменить один перегруженный объект сотней классов по одному маршруту.
### Связь с Automation QA
Граница ресурса уменьшает область изменений API.

## Задача 5. Automation QA
### Ответ
`create(data)` может гарантировать 201 и вернуть модель; `get(id)` возвращает APIResponse для 200/404; `delete(id)` возвращает код состояния или ответ. Бизнес-значения проверяет тест.
### Объяснение
У каждого метода есть минимальная понятная гарантия.
### Типичная ошибка
Скрывать ошибку очистки полностью.
### Связь с Automation QA
Клиент уменьшает HTTP-шум без потери диагностики.

## Задача 6. Мини-проект
### Ответ
```ts
import { expect, type APIRequestContext, test } from "@playwright/test";
import { startLocalApi } from "../../examples/03-automation-qa/support/local-api.js";

class TasksClient {
  constructor(private request: APIRequestContext, private baseURL: string) {}
  create(title: string) {
    return this.request.post(`${this.baseURL}/tasks`, { data: { title } });
  }
  get(id: string) {
    return this.request.get(`${this.baseURL}/tasks/${id}`);
  }
}

test("использует клиент ресурса", async ({ request }) => {
  const api = await startLocalApi();
  try {
    const client = new TasksClient(request, api.baseURL);
    const created = await client.create("API Client");
    expect(created.status()).toBe(201);
    const location = created.headers().location;
    expect(location).toMatch(/^\/tasks\/task-\d+$/);
    if (location === undefined) throw new Error("Ответ создания не содержит Location");
    const id = location.slice("/tasks/".length);
    expect((await client.get(id)).status()).toBe(200);
  } finally {
    await api.close();
  }
});
```
### Объяснение
Клиент получает контекст, но не становится владельцем его жизненного цикла.
### Типичная ошибка
Создавать контекст внутри constructor.
### Связь с Automation QA
Публичные методы сохраняют намерение операции и наблюдаемость HTTP-результата.
