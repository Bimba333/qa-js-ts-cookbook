# Решения: Вкладки, окна и popups

## Задача 1. Концептуальные вопросы
### Ответ
Popup — самостоятельная `Page`, frame — документ внутри Page. Событие `page` подходит для любого нового окна BrowserContext, `popup` — для окна, открытого конкретной исходной Page.
### Объяснение
Источник события определяет точность ожидания.
### Типичная ошибка
Работать с popup как с FrameLocator.
### Связь с Automation QA
Явный opener уменьшает риск выбрать не то окно.

## Задача 2. Анализ синхронизации
### Ответ
Создать Promise ожидания события, выполнить действие, дождаться Promise, дождаться нужного состояния UI новой Page, проверить его и закрыть Page в `finally`.
### Объяснение
Ожидание события должно существовать до действия, которое его вызывает.
### Типичная ошибка
Ждать событие после действия.
### Связь с Automation QA
Порядок устраняет состояние гонки.

## Задача 3. Предскажите результат
### Ответ
Popup может появиться до регистрации обработчика, и ожидание завершится по тайм-ауту.
### Объяснение
Событие браузера не хранится для будущего подписчика как очередь теста.
### Типичная ошибка
Считать медленный UI гарантией успеть подписаться.
### Связь с Automation QA
Состояние гонки может проявляться только при быстрых запусках в CI или на быстрых машинах.

## Задача 4. Поиск ошибки
### Ответ
Последняя Page может принадлежать другому действию. Нужно создать `page.waitForEvent("popup")` перед конкретным вызывающим действием и использовать полученное значение.
### Объяснение
Событие связывает причину и результат.
### Типичная ошибка
Добавить задержку перед чтением `context.pages()`.
### Связь с Automation QA
Несколько окон требуют явной идентификации, а не выбора по позиции.

## Задача 5. Automation QA
### Ответ
Исходная Page запускает предпросмотр, Promise события возвращает popup, проверки выполняются в нём, а `finally` закрывает popup. Исходной Page продолжает владеть fixture.
### Объяснение
Cleanup применяется только к вручную полученному дополнительному ресурсу.
### Типичная ошибка
Закрыть BrowserContext и уничтожить обе Page.
### Связь с Automation QA
Предпросмотр не влияет на следующие шаги исходного сценария.

## Задача 6. Мини-проект
### Ответ
```ts
import { expect, test } from "@playwright/test";

test("проверяет popup", async ({ page }) => {
  await page.setContent(`<button onclick="window.open('about:blank')">Preview</button>`);
  const popupPromise = page.waitForEvent("popup");
  await page.getByRole("button", { name: "Preview" }).click();
  const popup = await popupPromise;
  try {
    await popup.setContent("<h1>Preview</h1>");
    await expect(popup.getByRole("heading")).toHaveText("Preview");
    expect(popup.context()).toBe(page.context());
  } finally {
    await popup.close();
  }
});
```
### Объяснение
Promise создан до клика, а для popup явно задано освобождение ресурса.
### Типичная ошибка
Искать heading в исходной page.
### Связь с Automation QA
Тот же порядок применяется к предпросмотру отчётов.
