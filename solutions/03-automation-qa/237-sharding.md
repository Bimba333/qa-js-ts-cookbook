# Решения: Sharding

## 1. Идентификатор shard
### Ответ
`1/3` означает первый shard из трёх; номер находится в диапазоне от 1 до общего количества, а общее количество положительно.
### Объяснение
Команда выбирает подмножество обнаруженных тестов.
### Типичная ошибка
Использовать номер 0.
### Связь с Automation QA
Команда запуска сохраняет идентификатор shard.

## 2. Независимость shards
### Ответ
Shards запускаются независимо и не гарантируют порядок или общее состояние процесса.
### Объяснение
Подготовка каждого теста должна быть самодостаточной.
### Типичная ошибка
Создать данные только в shard 1.
### Связь с Automation QA
Каждая часть может быть перезапущена отдельно.

## 3. Баланс распределения
### Ответ
Сравните число и длительность тестов каждого локального shard; измените группировку при устойчивом перекосе.
### Объяснение
Баланс оценивается по наблюдаемой длительности, а не только по количеству тестов.
### Типичная ошибка
Ожидать равное время от равного числа файлов.
### Связь с Automation QA
Длинные сценарии влияют на общее время запуска.

## 4. Общий ресурс
### Ответ
Добавьте пространство имён shard к имени файла или аренде учётной записи и удаляйте только ресурс этого пространства.
### Объяснение
Независимые процессы не координируют фиксированное имя автоматически.
### Типичная ошибка
Использовать общий `results.json`.
### Связь с Automation QA
Внешние лимиты остаются отдельной границей ресурсов.

## 5. Automation QA-задача
### Ответ
Каждый shard сохраняет отдельный фрагмент результата; объединение сохраняет статусы всех частей и завершается падением при падении любого shard.
### Объяснение
Объединение меняет представление, но не переписывает итоговый статус.
### Типичная ошибка
Сохранять только результат последнего shard.
### Связь с Automation QA
Падение одной части не теряется.

## 6. Мини-проект: два локальных shard
### Ответ
Выполните одну конфигурацию с `--shard=1/2` и `--shard=2/2`. Каждый shard получает два теста; вместе они покрывают четыре уникальных теста без пересечений и пропусков.
### Объяснение
Тесты не зависят от соседней части, а остаточное состояние после обеих команд отсутствует.
### Типичная ошибка
Создать общий временный файл.
### Связь с Automation QA
Локальная проверка предшествует реализации CI.
