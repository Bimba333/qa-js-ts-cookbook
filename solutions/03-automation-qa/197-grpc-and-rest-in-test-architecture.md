# Решения: gRPC и REST в тестовой архитектуре

## Задача 1. Концептуальные вопросы
### Ответ
REST-тест обращается к ресурсу через HTTP method и URL и наблюдает HTTP response. gRPC-тест вызывает RPC method service и наблюдает protobuf response, metadata либо gRPC status.
### Объяснение
Оба транспорта могут выражать одну бизнес-операцию, но предоставляют разную диагностику протокола.
### Типичная ошибка
Переносить HTTP-проверки в gRPC без изменения модели.
### Связь с Automation QA
Точная граница протокола делает падение теста диагностируемым.

## Задача 2. Анализ границы
### Ответ
Нужно сохранить отдельные REST и gRPC clients. Общая бизнес-функция может координировать их, но HTTP status, gRPC status, metadata и deadline остаются доступны сценарию.
### Объяснение
Универсальный `call()` стирает важные различия контрактов.
### Типичная ошибка
Считать одинаковые данные запроса доказательством одинакового транспорта.
### Связь с Automation QA
Отдельные clients протоколов поддерживают позитивные и негативные проверки.

## Задача 3. Предскажите результат
### Ответ
Тест должен получить ServiceError с `code: status.NOT_FOUND`, а не HTTP 404.
### Объяснение
Native gRPC использует собственную модель завершения RPC.
### Типичная ошибка
Механически сопоставлять каждый gRPC status HTTP-коду.
### Связь с Automation QA
Правильный status отличает ожидаемый отказ от транспортной ошибки.

## Задача 4. Поиск ошибки
### Ответ
Публичный endpoint заменяется локальным gRPC server на `127.0.0.1` с динамическим портом и отдельным состоянием для каждого экземпляра. Тест создаёт и закрывает client и server в `finally`.
### Объяснение
Тест получает полный контроль над данными и жизненным циклом ресурсов.
### Типичная ошибка
Считать доступный демонстрационный service стабильной test fixture.
### Связь с Automation QA
Локальная граница устраняет зависимость от публичной сети и порядка тестов.

## Задача 5. Automation QA
### Ответ
REST-сценарий проверяет создание публичного ресурса по HTTP-контракту. gRPC-сценарий проверяет внутренний командный RPC method и status. Сравнение полезно, если оба интерфейса должны показывать один созданный бизнес-объект.
### Объяснение
Сравнивается бизнес-факт, а не техническое равенство протоколов.
### Типичная ошибка
Дублировать каждый сценарий на обоих транспортах без риска или требования.
### Связь с Automation QA
Контекстный выбор уменьшает стоимость поддержки.

## Задача 6. Мини-проект
### Ответ
```ts
const server = await startLocalGrpcServer();
const client = createTaskServiceClient(server.endpoint);
try {
  const task = await callUnary<Task__Output>((callback) =>
    client.createTask({ title: "Local RPC" }, callback));
  expect(task.title).toBe("Local RPC");
} finally {
  client.close();
  await server.close();
}
```
### Объяснение
Call, channel и server имеют явные границы завершения.
### Типичная ошибка
Закрывать server до client.
### Связь с Automation QA
Шаблон подходит детерминированным локальным интеграционным тестам.
