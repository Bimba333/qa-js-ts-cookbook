# Решения: Изоляция UI-тестов и состояние браузера

## Задача 1. Концептуальные вопросы
### Ответ
Браузерное состояние включает cookies и storage; серверное состояние хранится внешней системой. Свежий контекст изолирует только браузерную сессию.
### Объяснение
Границы хранения различаются.
### Типичная ошибка
Считать контекст транзакцией серверной части.
### Связь с Automation QA
Для данных нужны уникальность и очистка.

## Задача 2. Анализ зависимости
### Ответ
Второй тест не владеет prerequisite и падает отдельно. Подготовку пользователя нужно выполнять для этого теста или через управляемый будущий механизм без зависимости от соседнего test result.
### Объяснение
Тесты не являются шагами одного сценария.
### Типичная ошибка
Закрепить порядок запуска.
### Связь с Automation QA
Независимость позволяет фильтрацию и повторный запуск.

## Задача 3. Предскажите результат
### Ответ
Контекст B не увидит cookie и `localStorage` контекста A.
### Объяснение
Browser общий, session boundaries разные.
### Типичная ошибка
Считать общий процесс общим профилем.
### Связь с Automation QA
Авторизация не протекает между тестами.

## Задача 4. Debugging
### Ответ
Оба теста изменяют один серверный ресурс. Нужны уникальные идентификаторы заказов или контролируемое разделение данных и очистка владельцем.
### Объяснение
Браузерная изоляция не защищает общую серверную часть.
### Типичная ошибка
Добавить retries.
### Связь с Automation QA
Data collision является источником flaky behavior.

## Задача 5. Automation QA
### Ответ
Тест должен проходить отдельно, при любом порядке и одновременно с другими тестами без изменения результата.
### Объяснение
Три режима обнаруживают разные виды скрытой связи.
### Типичная ошибка
Проверять только полную последовательную группу тестов.
### Связь с Automation QA
Условия приближены к CI.

## Задача 6. Мини-проект
### Ответ
```ts
test("изолирует состояние", async ({ browser }) => {
  const a = await browser.newContext();
  const b = await browser.newContext();
  const storagePageUrl = new URL("./storage-page.html", import.meta.url).href;
  try {
    const pageA = await a.newPage();
    const pageB = await b.newPage();
    await pageA.goto(storagePageUrl);
    await pageB.goto(storagePageUrl);
    await pageA.evaluate(() => sessionStorage.setItem("user", "qa"));
    expect(await pageA.evaluate(() => sessionStorage.getItem("user"))).toBe("qa");
    expect(await pageB.evaluate(() => sessionStorage.getItem("user"))).toBeNull();
  } finally {
    await a.close();
    await b.close();
  }
});
```
Локальный `storage-page.html` лежит рядом со spec-файлом и не загружает внешние ресурсы. Пример не обращается к серверной части и потому ничего не доказывает о её данных. `data:` URL использовать нельзя: Chromium отключает Web Storage для такого origin.
### Объяснение
Проверяется только граница браузерного состояния.
### Типичная ошибка
Обобщать результат на server state.
### Связь с Automation QA
Разные уровни требуют разных стратегий изоляции.
