# Решения: CI fundamentals для Automation QA

## 1. CI, доставка и развёртывание
### Ответ
CI выполняет заданные проверки интегрируемого изменения. Непрерывная доставка поддерживает готовность изменения к выпуску, а непрерывное развёртывание автоматически переносит прошедшее изменение в целевое окружение. Пока эти механизмы не описаны отдельно, CI сам не доставляет и не развёртывает продукт; зелёный результат покрывает только запущенные проверки.
### Объяснение
Pipeline даёт ограниченный инженерный сигнал, а не доказательство отсутствия всех дефектов.
### Типичная ошибка
Называть любой GitHub Actions workflow pipeline развёртывания.
### Связь с Automation QA
Команда понимает границу покрытия автоматизированного набора.

## 2. Чистый runner
### Ответ
Скрыты незаявленный пакет и исполняемый файл браузера из старого cache. Оба требования нужно выразить командами установки.
### Объяснение
Чистый runner начинает без локального состояния машины разработчика.
### Типичная ошибка
Копировать cache вместо восстановления контракта установки.
### Связь с Automation QA
Запуск браузера становится воспроизводимым этапом, а не свойством машины.

## 3. `npm ci`
### Ответ
`npm ci` использует существующий lockfile без его обновления и завершается ошибкой при расхождении с manifest. `npm install` может пересчитать и изменить граф зависимостей.
### Объяснение
В CI lockfile является проверяемым входом запуска.
### Типичная ошибка
Исправлять расхождение автоматическим изменением lockfile на runner.
### Связь с Automation QA
Все jobs получают одинаковые версии тестовых зависимостей.

## 4. Exit code и timeout
### Ответ
Pipeline завершится на втором этапе с кодом `2`; третий обязательный этап не запускается. Timeout сообщает о превышении границы времени, но не доказывает race condition или flaky test.
### Объяснение
Первый ненулевой код завершения сохраняет распространение ошибки.
### Типичная ошибка
Преобразовать ненулевой код завершения в ноль ради продолжения.
### Связь с Automation QA
Причина расследуется по диагностическим материалам этапа, а не по одному статусу.

## 5. Automation QA-задача
### Ответ
Порядок: checkout, настройка Node.js, `npm ci`, проверки типов и документации, установка браузера, браузерные тесты. Каждый обязательный этап должен успешно завершиться до следующего.
### Объяснение
Недорогие проверки останавливают заведомо непригодный запуск раньше дорогой подготовки окружения.
### Типичная ошибка
Устанавливать браузер до проверки компиляции.
### Связь с Automation QA
Pipeline быстрее возвращает точный сигнал автору изменения.

## 6. Мини-проект: CI-контракт
### Ответ
Зафиксируйте Node.js 22, `npm ci`, `npm run docs:ts:smoke`, выбранную команду Playwright, timeout job 20 минут и каталоги диагностических материалов. Подготовка принадлежит job, результаты тестов — команде тестов, artifacts — шагу загрузки.
### Объяснение
У каждого результата есть явный источник и владелец.
### Типичная ошибка
Полагаться на неописанное состояние runner.
### Связь с Automation QA
Контракт можно повторить локально по тем же командам.
