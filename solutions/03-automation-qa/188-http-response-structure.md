# Решения: Структура HTTP-ответа

## Задача 1. Концептуальные вопросы
### Ответ
Код состояния классифицирует результат, заголовки описывают сообщение, а тело переносит данные или ошибку. При транспортной ошибке пригодного HTTP-ответа нет; ошибка приложения приходит в HTTP-ответе.
### Объяснение
4xx и 5xx являются HTTP-ответами, доступными для проверки.
### Типичная ошибка
Называть 500 сетевой ошибкой клиента.
### Связь с Automation QA
Разделение ускоряет поиск причины падения.

## Задача 2. Анализ ответа
### Ответ
201 и `Location` относятся к HTTP-контракту. Форма JSON и совпадение title относятся к данным и бизнес-результату.
### Объяснение
Идентификатор из тела связывает заголовок с созданным ресурсом.
### Типичная ошибка
Проверять только тело и игнорировать 201.
### Связь с Automation QA
Тест видит нарушение на точном уровне.

## Задача 3. Предскажите результат
### Ответ
Чтение JSON из пустого тела завершится ошибкой разбора. Следует проверить 204 и отсутствие обязательного тела без вызова `json()`.
### Объяснение
Метод чтения должен соответствовать формату ответа.
### Типичная ошибка
Вызывать `json()` для каждого ответа.
### Связь с Automation QA
Корректное чтение предотвращает ложные ошибки разбора.

## Задача 4. Поиск ошибки
### Ответ
Нужно ожидать `status() === 202`, тип содержимого JSON и валидный `jobId`. `ok()` принимает и другие 2xx.
### Объяснение
У конкретной операции есть точный контракт.
### Типичная ошибка
Считать все коды успешных ответов взаимозаменяемыми.
### Связь с Automation QA
Тест обнаружит синхронную обработку вместо согласованной очереди.

## Задача 5. Automation QA
### Ответ
200 подходит для успешного чтения, 201 — создания, 202 — принятой фоновой операции, 204 — успеха без тела. Конкретный маршрут может использовать другую документированную договорённость.
### Объяснение
Коды связываются со смыслом сценария, а не запоминаются изолированно.
### Типичная ошибка
Требовать 200 для DELETE без чтения контракта.
### Связь с Automation QA
Сценарии становятся точными и объяснимыми.

## Задача 6. Мини-проект
### Ответ
```ts
import { expect, test } from "@playwright/test";
import { startLocalApi } from "../../examples/03-automation-qa/support/local-api.js";

test("проверяет accepted response", async ({ request }) => {
  const api = await startLocalApi();
  try {
    const response = await request.get(`${api.baseURL}/responses/accepted`);
    expect(response.status()).toBe(202);
    expect(response.headers()["content-type"]).toContain("application/json");
    expect(response.headers()["x-request-id"]).toBe("request-1");
    expect(await response.json()).toEqual({ status: "queued", jobId: "job-1" });
  } finally {
    await api.close();
  }
});
```
### Объяснение
Каждая проверка относится к отдельной части ответа.
### Типичная ошибка
Сравнивать все заголовки ответа.
### Связь с Automation QA
Проверка остаётся устойчивой к несущественным метаданным.
