# Решения: Error Handling in Asynchronous Code

## Концептуальные вопросы

### 1. Что такое rejected Promise?

Ответ: Promise, завершившийся ошибкой.

Объяснение: такой результат нужно обработать через `catch()` или `try/catch` с `await`.

Типичная ошибка: считать rejected Promise обычным синхронным исключением.

Связь с Automation QA: падение загрузки отчета должно стать ошибкой запуска.

### 2. Как `catch()` связан с ошибкой Promise?

Ответ: `catch()` регистрирует обработчик rejected Promise.

Объяснение: ошибка передается в функцию внутри `catch()`.

На что обратить внимание: не добавлять `catch()` к асинхронному потоку.

Связь с Automation QA: ошибка login должна попадать в отчет или лог.

### 3. Как `try/catch` работает с `await`?

Ответ: если awaited Promise отклоняется, управление переходит в `catch`.

Объяснение: `await` превращает rejected Promise в ошибку внутри `async`-функции.

Важно помнить: забыть `await` внутри `try`.

Связь с Automation QA: ошибка загрузки отчета может быть поймана в одном месте.

### 4. Что значит распространение ошибки наружу?

Ответ: если ошибка не обработана внутри `async`-функции, функция возвращает rejected Promise.

Объяснение: внешний код может обработать ошибку через `catch()`.

Типичная ошибка: думать, что ошибка исчезает сама.

Связь с Automation QA: ошибка вспомогательной функции может быть обработана на уровне раннера.

### 5. Почему очистка ресурсов важна при асинхронных ошибках?

Ответ: ресурсы нужно освобождать даже при неуспешном сценарии.

Объяснение: ошибка не должна оставлять открытые сессии или временные данные.

Типичная ошибка: выполнять очистку ресурсов только после успеха.

Связь с Automation QA: browser context, данные и отчеты требуют очистки.

## Чтение кода

Ответ: ошибки из `executeTest()` и `uploadReport(result)` попадут в `catch`, если они возвращают rejected Promise.

Объяснение: оба вызова ожидаются через `await`.

Типичная ошибка: считать, что `catch` ловит только первую строку.

Связь с Automation QA: один обработчик может закрыть ошибку теста или отчета.

## Предскажите результат выполнения

Ответ:

```text
upload failed
```

Объяснение: `await Promise.reject(...)` переводит выполнение в `catch`.

На что обратить внимание: ожидать `success`.

Связь с Automation QA: неуспешная загрузка отчета должна быть видна.

## Отладка

Ответ: нужно использовать `await uploadReport()` внутри `async`-функции или `uploadReport().catch(...)`.

Объяснение: без `await` `try/catch` не обрабатывает rejected Promise как синхронную ошибку.

Типичная ошибка: обернуть Promise-вызов в `try/catch` и не ожидать его.

Связь с Automation QA: ошибки асинхронных вспомогательных функций должны ожидаться явно.

## Задание Automation QA

Ответ:

```javascript
async function runFramework() {
  try {
    const result = await executeTest();
    await uploadReport(result);
  } catch (error) {
    console.log(`framework error: ${error}`);
  } finally {
    await cleanup();
  }
}
```

Объяснение: `try/catch` обрабатывает ошибку, `finally` выполняет очистку ресурсов.

Типичная ошибка: забыть `await cleanup()`.

Связь с Automation QA: очистка ресурсов должна завершиться до окончания запуска.

## Мини-проект

Ответ: поток должен ловить ошибку, при ошибке вызвать `captureScreenshot()`, затем выполнить `cleanup()`.

Объяснение: диагностические действия часто зависят от ошибки, очистка ресурсов нужна всегда.

Важно помнить: потерять исходную ошибку после скриншота.

Связь с Automation QA: скриншот и очистка ресурсов — типичный сценарий после падения теста.
