# Решения: Parallel Asynchronous Operations

## Концептуальные вопросы

### 1. Когда асинхронные операции стоит запускать вместе?

Ответ: когда они независимы и не используют результаты друг друга.

Объяснение: независимые операции можно начать до ожидания общего результата.

Типичная ошибка: запускать все подряд последовательно без необходимости.

Связь с Automation QA: логи и скриншот можно собирать одновременно.

### 2. Чем `Promise.all()` отличается от `Promise.allSettled()`?

Ответ: `Promise.all()` требует успеха всех Promise, `Promise.allSettled()` возвращает итоги всех.

Объяснение: `allSettled()` полезен, когда важна полная картина.

На что обратить внимание: использовать `all()` для диагностических задач, где нужны все результаты.

Связь с Automation QA: результаты уведомлений в разные каналы лучше собирать через `allSettled()`.

### 3. Чем `Promise.race()` отличается от `Promise.any()`?

Ответ: `race()` берет первый завершившийся Promise, `any()` берет первый успешный.

Объяснение: ошибка может завершить `race()`, но не обязательно завершит `any()`.

Типичная ошибка: считать эти методы одинаковыми.

Связь с Automation QA: health check и выбор первого успешного endpoint — разные задачи.

### 4. Почему `Promise.all()` не делает JavaScript-код параллельным внутри Call Stack?

Ответ: он координирует Promise, а не создает несколько Call Stack.

Объяснение: асинхронные операции уже запущены, а JavaScript-обработчики выполняются по обычным правилам.

Важно помнить: объяснять `Promise.all()` как многопоточность.

Связь с Automation QA: операции ожидания можно начать вместе, но обработка результатов остается JavaScript-кодом.

### 5. Какие операции в Automation QA можно запускать вместе после теста?

Ответ: сбор логов, скриншот, trace, независимые уведомления, загрузки в разные места.

Объяснение: они часто не зависят друг от друга.

Типичная ошибка: параллелить шаги, где один результат нужен следующему.

Связь с Automation QA: загрузка отчета должна ждать артефакты, если отчет строится из них.

## Чтение кода

Ответ: `collectLogs()` и `captureScreenshot()` можно запускать вместе, если скриншот не зависит от логов.

Объяснение: `Promise.all()` дождется обоих результатов.

Типичная ошибка: использовать последовательные `await` для независимых операций.

Связь с Automation QA: так ускоряется сбор артефактов после теста.

## Предскажите результат выполнения

Ответ:

```text
[ 'logs', 'screenshot' ]
```

Объяснение: оба Promise успешны, `Promise.all()` возвращает массив результатов.

На что обратить внимание: ожидать два отдельных вывода.

Связь с Automation QA: результаты артефактов удобно передать дальше одним массивом.

## Отладка

Ответ: можно заменить на `const [logs, screenshot] = await Promise.all([collectLogs(), captureScreenshot()]);`.

Объяснение: если операции независимы, их можно запустить вместе.

Типичная ошибка: ускорять зависимые шаги таким способом.

Связь с Automation QA: сбор артефактов обычно независим.

## Задание Automation QA

Ответ:

```text
логи + скриншот                 -> Promise.all()
итог всех загрузок              -> Promise.allSettled()
самый быстрый health check      -> Promise.race()
первый успешный endpoint        -> Promise.any()
```

Объяснение: выбор метода зависит от нужной стратегии ожидания.

Типичная ошибка: использовать `Promise.all()` для всех случаев.

Связь с Automation QA: разные инфраструктурные задачи требуют разных стратегий.

## Мини-проект

Ответ: `finishTestRun()` должен использовать `Promise.all()` для логов и скриншота, затем загрузить отчет, затем `Promise.allSettled()` для уведомлений.

Объяснение: сбор артефактов независим, загрузка отчета зависит от артефактов, уведомления независимы между собой.

Важно помнить: запускать загрузку отчета до готовности артефактов.

Связь с Automation QA: это практическая модель завершения тестового запуска.
