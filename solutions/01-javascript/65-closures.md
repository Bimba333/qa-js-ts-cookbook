# Решения: Closures

## Концептуальные вопросы

### 1. Что сохраняет Closure?

Ответ: доступ к лексическому окружению, где функция была создана.

Почему так происходит: внутренняя функция может читать переменные внешней функции даже позже.

Распространённая ошибка: думать, что Closure хранит только одно значение.

Связь с Automation QA: logger может помнить configuration.

### 2. Почему Closure не является копией значений?

Ответ: функция сохраняет доступ к окружению, а не отдельный снимок.

Что происходит внутри: если в окружении есть изменяемое состояние, функция работает с этим состоянием.

Распространённая ошибка: ожидать независимые копии всех данных.

Связь с Automation QA: reporter может накапливать результаты в одном массиве.

### 3. Почему функция может читать переменную после завершения внешней функции?

Ответ: потому что созданная функция продолжает иметь доступ к лексическому окружению внешней функции.

На что обратить внимание: внешняя функция завершилась, но нужное окружение остается доступным для внутренней функции.

Распространённая ошибка: считать, что все локальные данные всегда исчезают сразу.

Связь с Automation QA: helper может помнить `baseUrl`.

### 4. Чем Closure полезен для хранения конфигурации?

Ответ: он позволяет создать функцию с заранее сохраненными настройками.

Почему так происходит: configuration передается один раз, а используется много раз.

Распространённая ошибка: хранить все настройки в глобальных переменных.

Связь с Automation QA: разные окружения могут создавать разные вспомогательные функции.

### 5. Когда лучше передать значение параметром, а не использовать Closure?

Ответ: когда значение меняется от вызова к вызову.

На что обратить внимание: Closure хорош для стабильного состояния, а параметры — для текущих данных вызова.

Распространённая ошибка: прятать слишком много данных в Closure.

Связь с Automation QA: `testName` лучше передавать параметром, а `environment` можно сохранить.

## Задание Automation QA

Ответ:

```javascript
function createUrlBuilder(configuration) {
  return function buildUrl(path) {
    return `${configuration.baseUrl}${path}`;
  };
}
```

Что происходит внутри: `buildUrl` помнит `configuration`.

Распространённая ошибка: передавать `baseUrl` в каждый вызов вручную.

Связь с Automation QA: вспомогательные функции API часто строят URL из общей конфигурации.

## Мини-проект

Ответ:

```javascript
function createFrameworkLogger(configuration) {
  return function log(message) {
    console.log(`[${configuration.environment}] ${message}`);
  };
}

const log = createFrameworkLogger({ environment: 'staging' });

log('start test');
log('finish test');
```

На что обратить внимание: Closure появляется между `createFrameworkLogger` и возвращенной функцией `log`.

Распространённая ошибка: делать `environment` глобальной переменной.

Связь с Automation QA: такой logger легко создать для разных окружений.
