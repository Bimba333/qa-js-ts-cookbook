# Решения: Callback

## Концептуальные вопросы

### 1. Что такое обратный вызов?

Ответ: функция, переданная другому коду для будущего вызова.

Объяснение: она описывает, что сделать после завершения операции.

Распространённая ошибка: путать функцию и результат ее выполнения.

Связь с Automation QA: обратный вызов может сохранить результат теста.

### 2. Почему обратный вызов передают как функцию, а не как готовое значение?

Ответ: потому что значение появится позже.

Объяснение: переданная функция будет вызвана, когда результат станет доступен.

Распространённая ошибка: вызвать функцию сразу и передать `undefined`.

Связь с Automation QA: обработчик отчета нужен после генерации отчета.

### 3. Как результат асинхронной операции попадает в обратный вызов?

Ответ: код, который завершает операцию, вызывает обратный вызов с результатом в аргументе.

Объяснение: `callback(result)` передает данные в функцию продолжения.

Распространённая ошибка: искать результат сразу после запуска операции.

Связь с Automation QA: результат теста передается в функцию сохранения.

### 4. Зачем в обратный вызов иногда передают ошибку?

Ответ: чтобы вызывающий код мог обработать неуспешное завершение.

Объяснение: асинхронная операция может завершиться не только результатом, но и ошибкой.

Распространённая ошибка: обрабатывать только успешный сценарий.

Связь с Automation QA: генерация отчета может не выполниться.

### 5. Почему вложенные обратные вызовы могут усложнять код?

Ответ: каждый следующий шаг оказывается внутри предыдущей функции.

Объяснение: чем больше шагов, тем глубже вложенность и сложнее обработка ошибок.

Распространённая ошибка: строить длинные цепочки вложенных функций без структуры.

Связь с Automation QA: подготовка окружения, запуск теста и отчет могут стать трудночитаемыми.

## Чтение кода

Ответ: `printReport` является обратным вызовом. Она вызывается внутри `finishReport()` после задержки.

Объяснение: `createReport()` принимает функцию и вызывает ее позже с готовым отчетом.

Распространённая ошибка: считать, что `printReport` выполняется в момент передачи.

Связь с Automation QA: отчет печатается только после готовности.

## Предскажите результат выполнения

Ответ:

```text
test started
runner continues
passed
```

Объяснение: `callback('passed')` вызывается позже.

Распространённая ошибка: ожидать `passed` до `runner continues`.

Связь с Automation QA: раннер продолжает текущую работу, а статус приходит позже.

## Отладка

Ответ:

```javascript
runTest(function printResult(status) {
  console.log(`test finished: ${status}`);
});
```

Объяснение: нужно передать функцию, а не результат вызова `console.log()`.

Распространённая ошибка: писать `runTest(console.log(...))`.

Связь с Automation QA: обработчик результата должен быть вызван после завершения теста.

## Задание Automation QA

Ответ:

```javascript
function runTest(testName, callback) {
  setTimeout(function finishTest() {
    callback({ testName, status: 'passed' });
  }, 100);
}

runTest('login smoke', function printResult(result) {
  console.log(`${result.testName}: ${result.status}`);
});
```

Объяснение: результат передается в обратный вызов после завершения теста.

Распространённая ошибка: вернуть результат из `runTest()` синхронно.

Связь с Automation QA: это модель отложенного результата теста.

## Мини-проект

Ответ:

```javascript
function prepareEnvironment(callback) {
  setTimeout(function finishPreparation() {
    callback({ environment: 'staging' });
  }, 100);
}

function runTest(configuration, callback) {
  setTimeout(function finishTest() {
    callback({
      testName: 'login smoke',
      status: 'passed',
      environment: configuration.environment,
    });
  }, 100);
}

function createReport(result, callback) {
  setTimeout(function finishReport() {
    callback(`${result.environment}: ${result.testName}: ${result.status}`);
  }, 100);
}

prepareEnvironment(function onEnvironmentReady(configuration) {
  runTest(configuration, function onTestFinished(result) {
    createReport(result, function onReportReady(report) {
      console.log(report);
    });
  });
});
```

Объяснение: каждый шаг продолжает следующий через обратный вызов.

Распространённая ошибка: читать `result` до вызова обратного вызова.

Связь с Automation QA: это рабочая, но уже вложенная модель асинхронного тестового потока.
