# Решения: Microtasks

## Концептуальные вопросы

### 1. Что такое Microtasks?

Ответ: задачи с высоким приоритетом, выполняемые после текущего синхронного кода.

Объяснение: они выполняются до macrotasks.

Частое заблуждение: считать Microtasks параллельным выполнением.

Связь с Automation QA: сохранение результата может выполниться раньше таймера отчета.

### 2. Почему обработчик Promise выполняется раньше таймера?

Ответ: обработчик Promise попадает в microtask queue, а таймер — в macrotask queue.

Объяснение: после текущего кода Microtasks имеют приоритет.

Распространённая ошибка: смотреть только на порядок строк в файле.

Связь с Automation QA: уведомление о завершении может появиться раньше загрузки отчета.

### 3. Когда выполняется `queueMicrotask()`?

Ответ: после завершения текущего синхронного кода и до macrotasks.

Объяснение: `queueMicrotask()` явно добавляет задачу в microtask queue.

Типичная ошибка: считать ее таймером.

Связь с Automation QA: короткое сохранение статуса можно запланировать как microtask.

### 4. Почему Microtasks не прерывают текущий синхронный код?

Ответ: текущий Call Stack должен завершиться.

Объяснение: Microtasks выполняются после текущего синхронного блока.

Распространённая ошибка: ожидать выполнение microtask между двумя обычными строками.

Связь с Automation QA: текущий шаг раннера завершится перед сохранением результата.

### 5. Как Microtasks могут влиять на порядок операций в тестовом фреймворке?

Ответ: они могут выполниться раньше таймеров и похожих задач.

Объяснение: это меняет порядок логов по сравнению с простым чтением сверху вниз.

Частое заблуждение: считать все отложенные задачи равными.

Связь с Automation QA: microtask сохранения результата может идти до macrotask генерации отчета.

## Чтение кода

Ответ:

```text
start
finish
save result
```

Объяснение: Promise-обработчик выполняется после текущего кода.

Распространённая ошибка: ожидать `save result` перед `finish`.

Связь с Automation QA: сохранение результата не прерывает текущий синхронный блок.

## Предскажите результат выполнения

Ответ:

```text
A
D
C
B
```

Объяснение: синхронные `A` и `D` идут первыми, microtask `C` идет перед таймером `B`.

Распространённая ошибка: ожидать `A B C D`.

Связь с Automation QA: результат может сохраниться до генерации отчета.

## Отладка

Ответ: ожидание неверное, потому что Promise-обработчик является microtask.

Объяснение: после текущего кода Microtasks выполняются раньше таймеров.

Типичная ошибка: считать, что более ранняя строка всегда выполняется раньше.

Связь с Automation QA: уведомление о завершении может идти перед загрузкой отчета.

## Задание Automation QA

Ответ:

```javascript
console.log('test: executed');

queueMicrotask(function saveResult() {
  console.log('result: saved');
});

setTimeout(function generateReport() {
  console.log('report: generated');
}, 0);
```

Объяснение: сначала синхронный код, затем microtask, затем macrotask.

Распространённая ошибка: ожидать отчет до сохранения результата.

Связь с Automation QA: порядок помогает сохранять результат до отчета.

## Мини-проект

Ответ:

```text
executeTests()
отметить запуск завершенным через Promise
save final status через queueMicrotask()
загрузить отчет через setTimeout()
```

Объяснение: синхронный код идет первым, затем Microtasks, затем Macrotasks.

Распространённая ошибка: не различать Promise-обработчик и таймер.

Связь с Automation QA: это модель порядка завершения тестового запуска.
