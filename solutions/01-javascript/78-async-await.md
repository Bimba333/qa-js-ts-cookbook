# Решения: async и await

## Концептуальные вопросы

### 1. Что возвращает `async`-функция?

Ответ: Promise.

Объяснение: даже обычное возвращаемое значение будет обернуто в Promise.

Типичная ошибка: ожидать обычное значение напрямую.

Связь с Automation QA: `runFramework()` можно ожидать как Promise результата запуска.

### 2. Что делает `await`?

Ответ: ожидает завершения Promise внутри `async`-функции и возвращает успешный результат.

Объяснение: выполнение текущей `async`-функции продолжится после результата.

На что обратить внимание: думать, что `await` блокирует весь JavaScript.

Связь с Automation QA: тестовые шаги можно читать последовательно.

### 3. Почему `await` не делает весь JavaScript синхронным?

Ответ: он приостанавливает только текущую `async`-функцию.

Объяснение: асинхронная модель с Promise и Event Loop остается той же.

Важно помнить: считать `await` магической синхронизацией всего процесса.

Связь с Automation QA: другие отложенные задачи могут продолжать ожидать своей очереди.

### 4. Что будет в переменной, если забыть `await`?

Ответ: Promise, а не готовый результат.

Объяснение: асинхронная функция возвращает Promise.

Типичная ошибка: читать поле результата у Promise.

Связь с Automation QA: `result.status` не сработает, если `result` на самом деле Promise.

### 5. Почему `async/await` удобен для тестовых сценариев?

Ответ: тестовые шаги читаются как последовательный сценарий.

Объяснение: код становится ближе к реальному порядку действий пользователя или раннера.

Типичная ошибка: использовать `await` без понимания зависимости между шагами.

Связь с Automation QA: сценарии login -> выполнить тесты -> отчет становятся понятнее.

## Чтение кода

Ответ: сначала ожидается `login()`, затем `executeTest(session)`, затем возвращается результат.

Объяснение: каждый `await` ждет Promise перед переходом к следующей строке внутри функции.

На что обратить внимание: думать, что оба шага стартуют одновременно.

Связь с Automation QA: тест нельзя выполнить до получения session.

## Предскажите результат выполнения

Ответ:

```text
passed
```

Объяснение: `getResult()` возвращает Promise со значением `passed`.

Типичная ошибка: думать, что `async` возвращает строку напрямую.

Связь с Automation QA: результат асинхронной вспомогательной функции читается через Promise или `await`.

## Отладка

Ответ: нужно написать `const result = await executeTest();`.

Объяснение: без `await` в `result` находится Promise.

Типичная ошибка: обращаться к `result.status` до завершения Promise.

Связь с Automation QA: статус теста доступен только после завершения асинхронного шага.

## Задание Automation QA

Ответ:

```javascript
async function runFlow() {
  const configuration = await prepareEnvironment();
  const session = await login(configuration);
  const result = await executeTests(session);
  return generateReport(result);
}
```

Объяснение: каждый шаг зависит от предыдущего.

Типичная ошибка: запускать зависимые шаги параллельно.

Связь с Automation QA: login нужен до выполнения тестов.

## Мини-проект

Ответ: `runFramework()` должен последовательно вызвать `prepareEnvironment`, `login`, `executeTest`, `generateReport` и вернуть статус отчета.

Объяснение: `async/await` делает поток похожим на сценарий.

Важно помнить: забыть `return` перед итоговым статусом.

Связь с Automation QA: такой вид удобен для основного сценария тестового запуска.
