# Решения: this

## Концептуальные вопросы

### 1. От чего зависит значение `this`?

Ответ: от формы вызова функции.

Почему так происходит: для обычного `object.method()` значением `this` становится объект перед точкой.

Распространённая ошибка: думать, что `this` определяется местом объявления функции.

Связь с Automation QA: метод reporter может работать правильно только при правильной форме вызова.

### 2. Что будет `this` при вызове `object.method()`?

Ответ: `this` будет указывать на `object`.

Что происходит внутри: объект перед точкой становится объектом выполнения для обычного вызова метода.

Распространённая ошибка: искать `this` в лексическом окружении.

Связь с Automation QA: `Reporter.report()` использует `Reporter` как `this`.

### 3. Почему метод может потерять контекст?

Ответ: если отделить метод от объекта.

Почему так происходит: при `const report = Reporter.report` объект перед точкой исчезает.

Распространённая ошибка: считать, что функция навсегда помнит объект, из которого была взята.

Связь с Automation QA: метод reporter может сломаться при передаче как обратный вызов.

### 4. Чем `this` отличается от Closure?

Ответ: Closure связан с местом создания функции, а `this` — с формой вызова.

Что происходит внутри: функция может одновременно использовать Closure и `this`, но это разные механизмы.

Распространённая ошибка: объяснять `this` через внешние переменные.

Связь с Automation QA: configuration можно сохранить через Closure, а имя reporter читать через `this`.

### 5. Почему методы Reporter часто используют `this`?

Ответ: потому что reporter хранит собственные поля и методы работают с этими полями.

На что обратить внимание: `this.environment` или `this.name` позволяют методу читать данные своего объекта.

Распространённая ошибка: передавать все поля параметрами, хотя они принадлежат объекту.

Связь с Automation QA: reporter object может хранить имя отчета, окружение и формат вывода.

## Чтение кода

Ответ: `this` указывает на `Reporter`.

Почему так происходит: вызов имеет форму `Reporter.report('login')`.

Распространённая ошибка: думать, что `this` указывает на функцию `report`.

Связь с Automation QA: обычный вызов метода reporter сохраняет объект выполнения.

## Предскажите результат выполнения

Ответ:

```text
[api] request started
```

Что происходит внутри: при `Logger.log(...)` значением `this` становится `Logger`.

Распространённая ошибка: ожидать `undefined` вместо `api`.

Связь с Automation QA: метод logger может использовать `this.prefix`.

## Отладка

Ответ: метод `report` отделен от объекта `Reporter`, поэтому `this` больше не указывает на `Reporter`.

Почему возникает ошибка: вызов `report('login')` не имеет объекта перед точкой.

Распространённая ошибка: считать, что `const report = Reporter.report` сохраняет объект выполнения.

Связь с Automation QA: передача методов как обратных вызовов часто приводит к потере `this`.

## Задание Automation QA

Ответ:

```javascript
const Logger = {
  prefix: 'api',
  log(message) {
    console.log(`[${this.prefix}] ${message}`);
  },
};

Logger.log('request started');
```

На что обратить внимание: `this.prefix` читает поле объекта `Logger`.

Распространённая ошибка: вызвать отделенный `log` без объекта.

Связь с Automation QA: logger object может хранить формат логов.

## Мини-проект

Ответ:

```javascript
'use strict';

const Reporter = {
  environment: 'staging',
  report(testName, status) {
    console.log(`${this.environment}: ${testName} -> ${status}`);
  },
};

Reporter.report('login smoke', 'passed');

const report = Reporter.report;

try {
  report('login smoke', 'passed');
} catch (error) {
  console.log(error.name);
}
```

На что обратить внимание: обычный вызов сохраняет `this`, отделенный вызов теряет объект выполнения.

Распространённая ошибка: ожидать одинаковое поведение в обоих вызовах.

Связь с Automation QA: методы reporter нельзя передавать без учета `this`.
