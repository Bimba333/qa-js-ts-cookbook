# Решения: Promise API

## Концептуальные вопросы

### 1. Для чего используется `then()`?

Ответ: для обработки успешного результата Promise.

Объяснение: функция внутри `then()` получает значение, с которым Promise завершился успешно.

Типичная ошибка: использовать `then()` как универсальное место для любых исходов.

Связь с Automation QA: успешный результат теста можно передать в генерацию отчета.

### 2. Для чего используется `catch()`?

Ответ: для обработки ошибки Promise.

Объяснение: если Promise завершается ошибкой, управление попадает в `catch()`.

На что обратить внимание: забыть обработку ошибки в тестовом потоке.

Связь с Automation QA: ошибка загрузки отчета должна быть видна в логах.

### 3. Почему `finally()` удобно применять для очистки ресурсов?

Ответ: он выполняется после завершения Promise независимо от успеха или ошибки.

Объяснение: очистка ресурсов нужна в обоих случаях.

Типичная ошибка: выполнять очистку ресурсов только в успешном сценарии.

Связь с Automation QA: сессию нужно закрывать даже при падении теста.

### 4. Почему важно возвращать Promise из шага внутри `then()`?

Ответ: чтобы цепочка дождалась следующей асинхронной операции.

Объяснение: без `return` следующий шаг может начаться без результата.

Важно помнить: запустить асинхронный шаг внутри `then()` и не вернуть его.

Связь с Automation QA: загрузка отчета должна дождаться генерации отчета.

### 5. Как Promise API помогает структурировать тестовый поток?

Ответ: он разделяет успешный путь, ошибку и завершающие действия.

Объяснение: `then()`, `catch()` и `finally()` имеют разные роли.

Типичная ошибка: смешивать всю логику в одном обработчике.

Связь с Automation QA: код раннера становится легче читать и отлаживать.

## Чтение кода

Ответ: `then()` генерирует отчет, `catch()` обрабатывает ошибку, `finally()` выполняет очистку ресурсов.

Объяснение: каждый метод описывает отдельную ветку поведения Promise.

Типичная ошибка: считать `finally()` местом для обработки результата.

Связь с Automation QA: очистка ресурсов должна выполняться независимо от результата теста.

## Предскажите результат выполнения

Ответ:

```text
test passed
cleanup
```

Объяснение: Promise успешен, поэтому сначала выполняется `then()`, затем `finally()`.

На что обратить внимание: ожидать `cleanup` перед результатом.

Связь с Automation QA: сначала обрабатывается результат, затем чистятся ресурсы.

## Отладка

Ответ: `finally()` не предназначен для получения результата.

Объяснение: результат нужно обрабатывать в `then()`, а `finally()` использовать для завершающего действия.

Типичная ошибка: писать бизнес-логику обработки результата внутри `finally()`.

Связь с Automation QA: очистка ресурсов не должна зависеть от данных отчета.

## Задание Automation QA

Ответ:

```javascript
executeTest()
  .then(function generateReport(result) {
    return generateReportFile(result);
  })
  .then(function uploadReport(report) {
    return uploadReportFile(report);
  })
  .catch(function handleError(error) {
    console.log(`error: ${error}`);
  })
  .finally(function cleanup() {
    console.log('cleanup finished');
  });
```

Объяснение: каждый шаг возвращает следующий Promise.

Важно помнить: не вернуть Promise из `generateReport`.

Связь с Automation QA: цепочка сохраняет правильный порядок отчета и загрузки.

## Мини-проект

Ответ: поток строится как цепочка `prepareEnvironment().then(login).then(executeTest).then(generateReport).finally(cleanup)`.

Объяснение: каждый следующий шаг получает результат предыдущего.

Типичная ошибка: смешать очистку ресурсов с обработкой результата.

Связь с Automation QA: это базовая структура Promise-based раннера.
