# Решения: Web APIs

## Концептуальные вопросы

### 1. Чем JavaScript отличается от среды выполнения?

Ответ: JavaScript — язык и выполняемый код, а среда выполнения предоставляет дополнительные API.

Объяснение: `setTimeout()` и `console` доступны благодаря среде выполнения.

Распространённая ошибка: считать все доступные функции частью языка.

Связь с Automation QA: тестовые инструменты часто дают собственные API поверх языка.

### 2. Почему `setTimeout()` не является синтаксисом языка JavaScript?

Ответ: это функция API среды выполнения.

Объяснение: JavaScript-код вызывает ее, но ожидание таймера выполняет среда выполнения.

Типичная ошибка: смешивать API и синтаксис.

Связь с Automation QA: ожидания часто реализуются через API фреймворка.

### 3. Что делает среда выполнения, когда JavaScript вызывает `setTimeout()`?

Ответ: принимает таймер, отслеживает задержку и позже передает готовую задачу в очередь.

Объяснение: текущий JavaScript-код не блокируется ожиданием таймера.

Распространённая ошибка: думать, что JavaScript сам ждет внутри Call Stack.

Связь с Automation QA: ожидание загрузки отчета может быть делегировано среде выполнения.

### 4. Почему тело обратного вызова все равно выполняется как JavaScript-код?

Ответ: среда выполнения планирует задачу, но сама функция выполняется позже в Call Stack.

Объяснение: обратный вызов возвращается в обычную модель выполнения JavaScript.

Частое заблуждение: считать, что API среды выполнения выполняет тело функции отдельно от JavaScript.

Связь с Automation QA: обратный вызов загрузки отчета все равно имеет обычный порядок выполнения.

### 5. Какие API среды выполнения часто встречаются в Automation QA?

Ответ: `console`, таймеры, сетевые API, файловые API Node.js и API тестового фреймворка.

Объяснение: они расширяют возможности JavaScript-кода.

Распространённая ошибка: ожидать одинаковый набор API в браузере и Node.js.

Связь с Automation QA: Playwright и Node.js дают API для тестовых задач.

## Чтение кода

Ответ: `console.log()` и вызов `setTimeout()` выполняются JavaScript-кодом. Ожидание задержки выполняет среда выполнения.

Объяснение: обратный вызов `uploadReport` вернется в выполнение позже.

Распространённая ошибка: считать, что JavaScript заблокирован на 100 ms.

Связь с Automation QA: загрузка отчета может быть запланирована без блокировки текущего кода.

## Предскажите результат выполнения

Ответ:

```text
start
finish
environment ready
```

Объяснение: таймер откладывает выполнение функции.

Распространённая ошибка: ожидать `environment ready` перед `finish`.

Связь с Automation QA: готовность окружения может прийти позже текущей синхронной части.

## Отладка

Ответ: `setTimeout()` не выполняет JavaScript-код параллельно.

Объяснение: среда выполнения отслеживает таймер, а обратный вызов позже попадет в Call Stack.

Типичная ошибка: использовать слово "параллельно" для выполнения обратного вызова.

Связь с Automation QA: порядок логов остается предсказуемым.

## Задание Automation QA

Ответ:

```javascript
function uploadReportLater(reportName) {
  setTimeout(function uploadReport() {
    console.log(`${reportName}: uploaded`);
  }, 100);
}

uploadReportLater('smoke-report');
console.log('runner continues');
```

Объяснение: JavaScript вызывает API, а среда выполнения отслеживает задержку.

Распространённая ошибка: возвращать результат загрузки синхронно.

Связь с Automation QA: загрузка отчета часто является отложенной операцией.

## Мини-проект

Ответ:

```javascript
console.log('report: created');

setTimeout(function uploadReport() {
  console.log('report: uploaded');
}, 100);

console.log('runner: continues');
```

Объяснение: создание отчета синхронное, загрузка запланирована через API среды выполнения.

Распространённая ошибка: ожидать загрузку до `runner: continues`.

Связь с Automation QA: раннер может продолжать работу после планирования загрузки.
