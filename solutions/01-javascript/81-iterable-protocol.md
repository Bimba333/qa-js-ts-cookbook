# Решения: Iterable Protocol

## Концептуальные вопросы

### 1. Почему `for...of` работает с массивом?

Ответ: массив является iterable.

Объяснение: у массива есть `Symbol.iterator`, поэтому JavaScript знает, как начать обход.

Типичная ошибка: думать, что `for...of` работает только из-за квадратных скобок.

Связь с Automation QA: массив тест-кейсов можно напрямую обходить в раннере.

### 2. Что делает `Symbol.iterator`?

Ответ: он задает точку начала итерации.

Объяснение: `for...of` ищет этот метод, чтобы получить механизм обхода.

Типичная ошибка: считать `Symbol.iterator` обычным именем свойства.

Связь с Automation QA: коллекция тестов должна иметь понятное правило обхода.

### 3. Почему обычный объект не обходится через `for...of` напрямую?

Ответ: у обычного объекта нет встроенного правила `Symbol.iterator` для `for...of`.

Объяснение: JavaScript не должен угадывать, какие свойства и в каком порядке обходить.

Типичная ошибка: ожидать, что любой объект автоматически iterable.

Связь с Automation QA: объект конфигурации лучше обходить явно через нужную структуру данных.

### 4. Чем iterable отличается от массива?

Ответ: iterable — это объект с правилом итерации, а массив — один из встроенных iterable-объектов.

Объяснение: строка, Map и Set тоже iterable, хотя они не являются массивами.

Типичная ошибка: приравнивать iterable к Array.

Связь с Automation QA: тестовые данные могут храниться в разных iterable-коллекциях.

### 5. Какие встроенные значения являются iterable?

Ответ: Array, String, Map и Set.

Объяснение: у них уже есть `Symbol.iterator`.

Типичная ошибка: забыть, что строка тоже iterable.

Связь с Automation QA: строки идентификаторов и Set приоритетов можно обходить через `for...of`.

## Задание Automation QA

Ответ:

```javascript

  { id: 'T-1', title: 'login works' },
  { id: 'T-2', title: 'checkout works' },
  { id: 'T-3', title: 'report works' },

  console.log(`${testCase.id}: ${testCase.title}`);
}
```

Типичная ошибка: обходить индексы, когда нужны сами тест-кейсы.
