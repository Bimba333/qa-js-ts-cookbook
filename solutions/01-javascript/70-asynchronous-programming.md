# Решения: Asynchronous Programming

## Концептуальные вопросы

### 1. Почему некоторые операции завершаются позже?

Ответ: потому что они зависят от среды выполнения JavaScript или внешнего процесса и не могут вернуть результат сразу.

Объяснение: запуск операции и готовность результата происходят в разные моменты.

Распространённая ошибка: считать, что запуск равен завершению.

Связь с Automation QA: генерация отчета или подготовка окружения может занять время.

### 2. Чем отличается запуск операции от получения результата?

Ответ: запуск начинается сейчас, результат появляется позже.

Объяснение: код после запуска продолжает выполняться.

Распространённая ошибка: читать результат сразу после планирования.

Связь с Automation QA: статус отчета нельзя считать готовым сразу после старта генерации.

### 3. Почему нельзя читать результат сразу после планирования отложенной операции?

Ответ: потому что отложенная операция еще не завершилась.

Объяснение: синхронная строка после планирования выполняется раньше результата.

Распространённая ошибка: использовать переменную так, будто она уже обновлена.

Связь с Automation QA: результат теста может быть еще неизвестен.

### 4. Зачем среда выполнения участвует в асинхронных операциях?

Ответ: среда выполнения предоставляет API для задач, которые завершаются позже.

Объяснение: `setTimeout()` — пример такого API для отложенного выполнения.

Распространённая ошибка: объяснять асинхронность только самим JavaScript Engine.

Связь с Automation QA: многие ожидания происходят через возможности среды выполнения и инструментов.

### 5. Какие задачи Automation QA часто завершаются не сразу?

Ответ: подготовка окружения, ожидание результата теста, генерация отчета, запись логов, внешние проверки.

Объяснение: такие задачи зависят от времени или внешней системы.

Распространённая ошибка: проектировать их как обычные синхронные функции.

Связь с Automation QA: именно поэтому тестовые фреймворки активно используют асинхронность.

## Чтение кода

Ответ:

```text
before
after
report ready
```

Объяснение: `setTimeout()` планирует выполнение функции позже.

Распространённая ошибка: ожидать, что `report ready` появится до `after`.

Связь с Automation QA: отчет может быть готов позже, чем завершится текущий синхронный участок.

## Предскажите результат выполнения

Ответ:

```text
not ready
ready
```

Объяснение: первый `console.log(status)` выполняется до отложенной функции.

Распространённая ошибка: думать, что `status` уже стал `ready`.

Связь с Automation QA: статус операции нельзя читать слишком рано.

## Отладка

Ответ: `console.log()` выполняется до `finishTest()`.

Объяснение: значение `result` изменится позже, но синхронный вывод уже произошел.

Распространённая ошибка: считать, что `setTimeout()` блокирует выполнение.

Связь с Automation QA: проверка результата должна выполняться после завершения операции.

## Задание Automation QA

Ответ:

```javascript
console.log('test executed');

setTimeout(function generateReport() {
  console.log('report generated');
}, 100);

console.log('runner continues');
```

Объяснение: генерация отчета запланирована, а текущий код идет дальше.

Распространённая ошибка: ожидать отчет до `runner continues`.

Связь с Automation QA: это модель отложенной отчетности.

## Мини-проект

Ответ:

```javascript
function startEnvironmentPreparation() {
  console.log('environment preparation started');

  setTimeout(function finishPreparation() {
    console.log('environment ready');
  }, 100);
}

startEnvironmentPreparation();
console.log('runner continues');
```

Объяснение: функция запускает подготовку, но готовность наступает позже.

Распространённая ошибка: возвращать из функции значение, которого еще нет.

Связь с Automation QA: подготовка окружения часто требует продолжения после готовности.
