# Решения: Generators

## Концептуальные вопросы

### 1. Что создает `function*`?

Ответ: функцию-генератор.

Объяснение: при вызове она возвращает объект-генератор (generator object), который работает как iterator.

Типичная ошибка: считать `function*` обычной функцией с другим синтаксисом.

Связь с Automation QA: генератор может выдавать шаги отчета по одному.

### 2. Когда начинает выполняться тело функции-генератора?

Ответ: при первом `next()` или при начале обхода через `for...of`.

Объяснение: сам вызов функции-генератора только создает генератор.

Типичная ошибка: ожидать выполнение тела сразу при вызове функции.

Связь с Automation QA: подготовка значений может начаться только при реальном обходе.

### 3. Что делает `yield`?

Ответ: выдает значение наружу и приостанавливает генератор.

Объяснение: следующий `next()` продолжит выполнение после этого `yield`.

Типичная ошибка: путать `yield` с окончательным `return`.

Связь с Automation QA: отчетные записи можно отдавать последовательно.

### 4. Почему генератор упрощает создание iterator?

Ответ: он берет на себя создание `next()`, `value` и `done`.

Объяснение: разработчик описывает только последовательность `yield`.

Типичная ошибка: вручную писать сложный iterator там, где достаточно генератора.

Связь с Automation QA: генератор делает обход тестовых данных проще и читабельнее.

### 5. Почему обычный генератор не является асинхронным механизмом?

Ответ: он выдает значения синхронно.

Объяснение: `yield` приостанавливает генератор, но не запускает асинхронную операцию сам по себе.

Типичная ошибка: считать любой генератор заменой Promise.

Связь с Automation QA: обычный генератор подходит для синхронной выдачи шагов или данных.

## Чтение кода

Ответ: первый `next()` вернет `prepare`, второй — `run`.

Объяснение: генератор выполняется до ближайшего `yield` и затем ставится на паузу.

Типичная ошибка: ожидать, что все `yield` выполнятся сразу.

Связь с Automation QA: шаги запуска можно получать по одному.

## Предскажите результат выполнения

Ответ:

```text
logs
screenshot
```

Объяснение: `for...of` вызывает генератор до завершения.

Типичная ошибка: ожидать объекты `{ value, done }` внутри `for...of`.

Связь с Automation QA: `for...of` скрывает детали `next()` при обработке артефактов.

## Отладка

Объяснение: вызов `getTestName()` не возвращает строку из `yield`; нужно вызвать `next()` или использовать `for...of`.

Типичная ошибка: ожидать значение `yield` напрямую из вызова функции-генератора.

Связь с Automation QA: генератор нужно обходить, чтобы получить тестовые данные.

## Задание Automation QA

Ответ:

```javascript
function* reportEntries() {
  yield 'collect logs';
  yield 'capture screenshot';
  yield 'upload report';
}

for (const entry of reportEntries()) {
  console.log(entry);
}
```

Объяснение: каждый `yield` выдает одну отчетную запись.

Типичная ошибка: использовать `return` вместо нескольких `yield`.

Связь с Automation QA: так можно описать последовательность отчетных действий.

## Мини-проект

Ответ:

```javascript
function* failedTestArtifacts(testId) {
  yield { testId, type: 'log' };
  yield { testId, type: 'screenshot' };
  yield { testId, type: 'trace' };
}

for (const artifact of failedTestArtifacts('T-1')) {
  console.log(`${artifact.testId} -> ${artifact.type}`);
}
```

Объяснение: генератор сохраняет контекст `testId` и выдает связанные артефакты.

Типичная ошибка: собрать все артефакты в массив без необходимости, если нужна последовательная выдача.

Связь с Automation QA: после падения теста артефакты часто обрабатываются один за другим.
