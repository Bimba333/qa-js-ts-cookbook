# Решения: Macrotasks

## Концептуальные вопросы

### 1. Что такое Macrotasks?

Ответ: отложенные задачи вроде таймеров, которые выполняются после текущего кода и Microtasks.

Объяснение: `setTimeout()` и `setInterval()` планируют macrotasks.

Частое заблуждение: считать macrotask немедленным выполнением.

Связь с Automation QA: загрузка отчета через таймер является macrotask.

### 2. Почему `setTimeout(..., 0)` не выполняется сразу?

Ответ: задача попадает в macrotask queue и ждет своей очереди.

Объяснение: текущий Call Stack и Microtasks имеют приоритет.

Типичная ошибка: понимать `0` как выполнение в той же строке.

Связь с Automation QA: таймер уведомления не прерывает текущий тестовый код.

### 3. Чем macrotask отличается от microtask?

Ответ: Microtasks выполняются раньше macrotasks после текущего кода.

Объяснение: это разные очереди с разным приоритетом.

Частое заблуждение: считать все очереди одинаковыми.

Связь с Automation QA: сохранение результата может идти раньше загрузки отчета.

### 4. Как `setInterval()` связан с macrotasks?

Ответ: каждый запуск обратного вызова из `setInterval()` планируется как отдельная отложенная задача.

Объяснение: интервал не делает код параллельным, он повторно планирует выполнение.

Распространённая ошибка: забыть остановить интервал через `clearInterval()`.

Связь с Automation QA: повторная загрузка отчета может работать по интервалу.

### 5. Почему знание macrotasks помогает читать логи тестового раннера?

Ответ: оно объясняет, почему таймерные логи идут после синхронных и microtask-логов.

Объяснение: порядок зависит от очередей.

Типичная ошибка: считать порядок случайным.

Связь с Automation QA: это помогает отлаживать уведомления и загрузку отчетов.

## Чтение кода

Ответ:

```text
start
finish
save result
upload report
```

Объяснение: синхронный код идет первым, Promise-обработчик как microtask идет перед таймером.

Распространённая ошибка: ожидать загрузку отчета перед сохранением результата.

Связь с Automation QA: результат сохраняется до загрузки отчета.

## Предскажите результат выполнения

Ответ:

```text
A
E
C
B
D
```

Объяснение: `A` и `E` синхронные, `C` — microtask, `B` и `D` — macrotasks.

Распространённая ошибка: ожидать `A B C D E`.

Связь с Automation QA: таймеры идут после Promise-обработчиков.

## Отладка

Ответ: таймеры не выполняются раньше Promise-обработчиков только потому, что написаны выше.

Объяснение: Promise-обработчик попадает в microtask queue, а таймер — в macrotask queue.

Распространённая ошибка: игнорировать приоритет очередей.

Связь с Automation QA: порядок загрузки отчета и сохранения результата зависит от типа задачи.

## Задание Automation QA

Ответ:

```javascript
console.log('tests: executed');

Promise.resolve().then(function markRunFinished() {
  console.log('run: finished');
});

setTimeout(function uploadReport() {
  console.log('report: uploaded');
}, 0);

setTimeout(function notifyDashboard() {
  console.log('dashboard: notified');
}, 0);
```

Объяснение: синхронный лог идет первым, затем microtask, затем macrotasks.

Распространённая ошибка: ожидать загрузку отчета перед `run: finished`.

Связь с Automation QA: так выглядит типичный порядок завершения запуска.

## Мини-проект

Ответ:

```text
prepare environment
execute test
сохранить результат через microtask
сгенерировать отчет через macrotask
уведомить панель мониторинга через macrotask
```

Объяснение: Call Stack завершается, затем выполняются Microtasks, затем Macrotasks через Event Loop.

Распространённая ошибка: считать, что асинхронные задачи выполняются в случайном порядке.

Связь с Automation QA: модель помогает стабильно предсказывать порядок отчетности и уведомлений.
