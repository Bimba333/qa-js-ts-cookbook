# Решения: Custom Iteration

## Концептуальные вопросы

### 1. Что нужно добавить объекту, чтобы он стал iterable?

Ответ: метод `Symbol.iterator`.

Объяснение: `for...of` ищет этот метод, чтобы начать обход.

Типичная ошибка: добавить обычный метод `iterator` вместо `Symbol.iterator`.

Связь с Automation QA: объект тестового набора может сам описывать обход своих тестов.

### 2. Что должен вернуть метод `Symbol.iterator`?

Ответ: iterator.

Объяснение: iterator должен уметь возвращать результаты через `next()`.

Типичная ошибка: вернуть массив вместо iterator.

Связь с Automation QA: если внутри есть массив тестов, можно вернуть его iterator.

### 3. Чем ручной iterator отличается от iterator на основе generator?

Ответ: ручной iterator явно описывает `next()`, generator делает это автоматически.

Объяснение: оба подхода дают JavaScript механизм получения значений.

Типичная ошибка: считать generator другим протоколом итерации.

Связь с Automation QA: generator обычно делает собственный тестовый набор проще.

### 4. Когда собственная итерация полезна?

Ответ: когда объект хранит служебные данные, но должен обходиться как коллекция.

Объяснение: можно скрыть метаданные и отдавать только нужные элементы.

Типичная ошибка: делать собственный iterable-объект для обычного массива без дополнительной пользы.

Связь с Automation QA: тестовый набор может иметь `name`, `owner`, `tests`, но обходить только `tests`.

### 5. Почему не стоит делать собственный iterable-объект без необходимости?

Ответ: это усложняет объект.

Объяснение: если массив решает задачу, дополнительный протокол может ухудшить читаемость.

Типичная ошибка: добавлять `Symbol.iterator` ради синтаксиса, а не ради модели данных.

Связь с Automation QA: тестовый код должен быть предсказуемым для команды.

## Чтение кода

Ответ:

```text
login
checkout
```

Объяснение: `Symbol.iterator` реализован через generator и выдает элементы `this.tests`.

Типичная ошибка: думать, что `for...of` обойдет поля `tests` и `name`.

Связь с Automation QA: тестовый набор отдает наружу только тест-кейсы.

## Предскажите результат выполнения

Ответ:

```text
report
```

Объяснение: метод `Symbol.iterator` возвращает iterator внутреннего массива `tests`.

Типичная ошибка: ожидать вывод всего объекта тестового набора.

Связь с Automation QA: объект-обертка может использовать итерацию внутренней коллекции.

## Отладка

Ответ: `Symbol.iterator` возвращает массив, а должен вернуть iterator.

Объяснение: корректно было бы вернуть `this.tests[Symbol.iterator]()`.

Типичная ошибка: путать iterable-массив и iterator, который из него получается.

Связь с Automation QA: собственный тестовый набор должен возвращать рабочий механизм обхода, а не просто данные.

## Задание Automation QA

Ответ:

```javascript
const testSuite = {
  name: 'smoke',
  owner: 'qa-team',
  tests: ['login', 'checkout'],
  *[Symbol.iterator]() {
    for (const test of this.tests) {
      yield test;
    }
  },
};

for (const test of testSuite) {
  console.log(test);
}
```

Объяснение: generator внутри `Symbol.iterator` выдает только элементы `tests`.

Типичная ошибка: использовать стрелочную функцию и потерять ожидаемый `this`.

Связь с Automation QA: так тестовый набор может быть объектом с метаданными и одновременно коллекцией тестов.

## Мини-проект

Ответ:

```javascript
const report = {
  name: 'nightly run',
  logs: ['browser.log', 'api.log'],
  screenshots: ['failure.png'],
  *[Symbol.iterator]() {
    for (const log of this.logs) {
      yield log;
    }

    for (const screenshot of this.screenshots) {
      yield screenshot;
    }
  },
};

for (const entry of report) {
  console.log(entry);
}
```

Объяснение: собственная итерация задает порядок: сначала логи, затем скриншоты.

Типичная ошибка: смешать все поля объекта без явного правила порядка.

Связь с Automation QA: отчет может хранить разные типы артефактов, но отдавать их единым обходом.
