# Решения: Synchronous Execution

## Концептуальные вопросы

### 1. Что означает синхронное выполнение?

Ответ: текущая инструкция должна завершиться до начала следующей.

Объяснение: JavaScript выполняет синхронный код последовательно.

Распространённая ошибка: думать, что JavaScript сам пропускает долгую строку.

Связь с Automation QA: шаги простого тестового раннера выполняются в заданном порядке.

### 2. Почему следующая инструкция ждет завершения текущей?

Ответ: потому что в синхронной модели один шаг выполняется полностью перед следующим.

Объяснение: если текущая строка вызывает функцию, сначала выполняется тело функции.

Распространённая ошибка: ожидать параллельного выполнения обычных строк.

Связь с Automation QA: отчет не создается раньше завершения синхронного теста.

### 3. Что происходит, когда синхронная строка вызывает функцию?

Ответ: создается Function Execution Context, выполняется тело функции, затем управление возвращается к следующей строке.

Объяснение: это обычная работа Call Stack.

Распространённая ошибка: считать, что функция только регистрируется, но не выполняется.

Связь с Automation QA: вспомогательная функция завершает работу до перехода к следующей вспомогательной функции.

### 4. Почему синхронный код удобно читать сверху вниз?

Ответ: порядок чтения обычно совпадает с порядком выполнения.

Объяснение: следующая строка не начинается раньше текущей.

Распространённая ошибка: искать скрытый порядок там, где его нет.

Связь с Automation QA: простой smoke-flow легко читать как список шагов.

### 5. В чем ограничение синхронной модели для Automation QA?

Ответ: долгие операции блокируют дальнейшее выполнение.

Объяснение: если подготовка окружения занимает время, синхронный код ждет.

Распространённая ошибка: использовать синхронное мышление для операций, которые завершатся позже.

Связь с Automation QA: ожидание отчета или внешней системы требует другой модели.


Объяснение: функции вызываются последовательно.

Распространённая ошибка: думать, что объявления функций выполняются до `console.log`.

Связь с Automation QA: шаги раннера идут в заданном порядке.

## Предскажите результат выполнения

Ответ:

```text
before report
report created
after report
```

Объяснение: `createReport()` выполняется полностью перед следующей строкой.

Распространённая ошибка: ожидать `after report` раньше тела функции.

Связь с Automation QA: синхронное создание отчета блокирует следующий шаг.

## Отладка

Ответ: `runSlowStep()` выполняет синхронную работу и не возвращает управление до завершения цикла.

Объяснение: `console.log('next step')` находится после вызова функции.

Распространённая ошибка: считать, что цикл сам выполняется "в фоне".

Связь с Automation QA: тяжелая синхронная подготовка может задержать весь запуск.

## Задание Automation QA

Ответ:

```javascript
function readConfiguration() {
  console.log('configuration read');
  return { environment: 'staging' };
}

function prepareEnvironment(configuration) {
  console.log(`${configuration.environment}: environment prepared`);
}

function runTest(configuration) {
  console.log(`${configuration.environment}: test executed`);
  return { testName: 'login smoke', status: 'passed' };
}

function createReport(result) {
  console.log(`${result.testName}: ${result.status}`);
}

const configuration = readConfiguration();
prepareEnvironment(configuration);
const result = runTest(configuration);
createReport(result);
```

Объяснение: каждый шаг получает данные от предыдущего.

Распространённая ошибка: вызвать `createReport()` до получения `result`.

Связь с Automation QA: это базовая форма последовательного тестового потока.

## Мини-проект

Ответ:

```javascript
function createRunner(configuration) {
  return {
    run(testName) {
      console.log(`environment: ${configuration.environment}`);
      const result = { testName, status: 'passed' };
      console.log(`${result.testName}: ${result.status}`);
      return result;
    },
  };
}

const runner = createRunner({ environment: 'staging' });
runner.run('login smoke');
```

Объяснение: поток синхронный, поэтому результат доступен сразу после вызова `run()`.

Распространённая ошибка: добавлять асинхронные ожидания там, где все данные уже готовы.

Связь с Automation QA: такая модель подходит для локальной валидации и подготовки данных.
