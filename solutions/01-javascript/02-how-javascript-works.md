# Решения. Глава 5. Как выполняется JavaScript

## Проверка понимания

### 1. Что происходит после `node app.js`

Ответ:

Node.js находит файл, читает source code и передает его в JavaScript Engine. Engine выполняет lexical analysis, parsing, строит AST, подготавливает код и только затем начинает execution.

Объяснение:

Файл не выполняется сразу как текст. Сначала engine должен понять, что это корректная программа.

Распространённая ошибка:

Думать, что Node.js сразу выполняет первую строку файла.

Связь с Automation QA:

Если тест не стартовал из-за syntax error, сценарий еще не начал выполняться.

### 2. Source code

Ответ:

Source code — исходный текст программы.

Объяснение:

Для человека это код. Для engine сначала это поток символов, который нужно разобрать.

Распространённая ошибка:

Считать, что engine сразу "понимает смысл" кода без промежуточных этапов.

### 3. Lexical analysis

Ответ:

Lexical analysis разбивает source code на tokens.

Объяснение:

Engine группирует символы в значимые элементы: имена, строки, скобки, операторы.

Распространённая ошибка:

Путать lexical analysis с execution.

### 4. Parsing

Ответ:

Parsing проверяет, образуют ли tokens корректную структуру программы.

Объяснение:

Tokens могут быть распознаны, но расположены неправильно. Parser проверяет грамматику.

Распространённая ошибка:

Думать, что если tokens распознаны, программа уже может выполняться.

### 5. AST

Ответ:

AST — древовидное внутреннее представление структуры программы.

Объяснение:

Engine работает не только с текстом. Дерево показывает связи между частями программы.

Распространённая ошибка:

Представлять AST как просто отформатированный исходный код.

### 6. Syntax error до execution

Ответ:

Syntax error возникает до execution, потому что parser не может построить корректный AST.

Объяснение:

Если структура программы нарушена, engine не может перейти к подготовке и выполнению.

Связь с Automation QA:

Syntax error в тестовом файле означает, что тестовый сценарий не начал выполняться.

### 7. Interpretation и compilation

Ответ:

Interpretation выполняет программу ближе к промежуточному представлению шаг за шагом. Compilation преобразует код в более исполняемую форму заранее или во время работы.

Объяснение:

Современные engines совмещают подходы: могут быстро начать выполнение и оптимизировать часто используемый код.

Распространённая ошибка:

Говорить, что JavaScript "только интерпретируется" и compilation к нему не относится.

### 8. Preparation for execution

Ответ:

Preparation for execution — этап, на котором engine уже разобрал код и готовит его к запуску.

Объяснение:

На этом этапе программа еще не обязательно выполняет пользовательские действия.

### 9. Runtime interaction

Ответ:

Runtime interaction — обращение выполняемого кода к возможностям окружения, например к `console`.

Объяснение:

Engine выполняет JavaScript, но вывод в терминал обеспечивает runtime API.

Связь с Automation QA:

В Playwright runtime interaction может означать взаимодействие с браузером через API инструмента.

### 10. Зачем QA-инженеру понимать этап ошибки

Ответ:

Чтобы отличать ошибку загрузки файла, syntax error, runtime error и ошибку тестовой проверки.

Объяснение:

Разные этапы требуют разных действий. Syntax error не исправляется ожиданием элемента на странице.

## Чтение кода

Код:

```javascript
console.log('Program started');
console.log('Program finished');
```

Ответ:

До вывода первой строки файл проходит чтение source code, lexical analysis, parsing, построение AST и preparation for execution.

Execution начинается после успешной подготовки.

Для наблюдаемого результата используется runtime API `console`.

Объяснение:

Обе строки выводятся только если parser смог разобрать весь файл.

Распространённая ошибка:

Думать, что первая строка выводится до проверки синтаксиса второй строки.

Связь с Automation QA:

Если ниже в тестовом файле syntax error, верхняя часть теста тоже не выполнится.

## Предскажите результат. Задание 1

Файл:

```text
examples/01-javascript/chapter-02/01-valid-program.js
```

Ожидаемый вывод:

```text
Program started
Program finished
```

Объяснение:

Файл синтаксически корректен. Engine строит AST, подготавливает код, начинается execution, затем два обращения к `console.log` выводят две строки.

Распространённая ошибка:

Пропустить этап подготовки и объяснить результат только "Node.js прочитал строки".

## Предскажите результат. Задание 2

Файл:

```text
examples/01-javascript/chapter-02/02-syntax-error.js
```

Ответ:

Первая строка не будет выведена.

Engine остановится на parsing / AST construction stage.

Execution не начинается, потому что parser не может построить корректную структуру программы из-за незакрытой скобки.

Распространённая ошибка:

Ожидать, что первая строка выполнится, потому что она находится выше ошибки.

Связь с Automation QA:

То же применимо к тестовым файлам: syntax error внизу файла может остановить весь файл до выполнения первого теста.

## Поиск syntax error

Код:

```javascript
console.log('Before');
console.log('After'
```

Ответ:

Пропущена закрывающая скобка `)`.

Parser не может построить корректный AST, потому что вызов не завершен.

Проблемная строка:

```javascript
console.log('After'
```

Объяснение:

Открывающая скобка есть, но закрывающей нет. Структура выражения неполная.

Распространённая ошибка:

Искать проблему в строке выше, потому что она выполнялась бы первой.

## Объясните поведение engine

Код:

```javascript
console.log('QA');
```

Ответ:

1. Source code: engine получает текст `console.log('QA');`.
2. Lexical analysis: текст разбивается на tokens.
3. Parsing: parser проверяет грамматику.
4. AST: строится дерево вызова `console.log`.
5. Preparation: engine готовит код к выполнению.
6. Execution: начинается выполнение инструкции.
7. Runtime interaction: `console` выводит текст в терминал.

Объяснение:

Вывод появляется только на последнем этапе. До этого engine анализирует и подготавливает программу.

Распространённая ошибка:

Считать `console.log` частью parsing stage.

Связь с Automation QA:

Полезно отделять "тест не разобрался" от "тест начал выполняться и вывел лог".

## Задачи на отладку

### Задача 1

Ошибка:

```text
SyntaxError: missing ) after argument list
```

Ответ:

Это ошибка до execution.

Ее обнаружил parser.

Сначала нужно проверять структуру кода: скобки, кавычки, запятые, закрытие выражения.

Объяснение:

Parser не смог построить AST. Runtime API еще не выполнялись.

Распространённая ошибка:

Перезапускать тест или менять ожидания Playwright, когда проблема в синтаксисе.

### Задача 2

Ответ:

Браузер мог не открыться, потому что тестовый файл не прошел parsing.

Запуск остановился до execution тестового сценария.

Это не ошибка locator или assertion, потому что они относятся к уже выполняющемуся тесту.

Объяснение:

Если engine не построил AST, Playwright не получает корректный исполняемый тест.

Связь с Automation QA:

В CI это выглядит как "тесты не стартовали", а не как "тесты упали по проверке".

## QA-задачи

### Задача 1

Чек-лист:

```text
1. Файл найден?
2. Команда запуска указывает правильный путь?
3. Есть ли SyntaxError?
4. Если SyntaxError есть, проверить структуру кода.
5. Если syntax корректен, начался ли execution?
6. Если execution начался, какая runtime error появилась?
7. Если браузер открылся, проверять взаимодействие с Playwright.
8. Если проверка упала, анализировать assertion.
```

Объяснение:

Checklist идет по pipeline от запуска файла к тестовой логике.

Распространённая ошибка:

Начинать диагностику с браузера, когда файл еще не разобран parser.

### Задача 2

Ответ:

`SyntaxError` в CI означает, что код не прошел parsing. Падение assertion означает, что тест уже выполнялся и проверка получила неожиданный результат.

Объяснение:

Это разные этапы pipeline. Для `SyntaxError` нужно исправлять структуру кода. Для assertion нужно анализировать фактический и ожидаемый результат.

Связь с Automation QA:

Такое различение помогает правильно классифицировать падения в отчете.

## Мини-проект

Первый файл:

```text
playground/pipeline-valid.js
```

Код:

```javascript
console.log('Pipeline started');
console.log('Pipeline finished');
```

Ожидаемый результат:

```text
Pipeline started
Pipeline finished
```

Engine проходит все этапы и доходит до execution.

Второй файл:

```text
playground/pipeline-syntax-error.js
```

Код:

```javascript
console.log('This will not be printed');
console.log('Broken'
```

Ожидаемый результат:

```text
SyntaxError
```

Первая строка не будет выведена, потому что parser не сможет построить AST для файла.

Объяснение:

В первом файле pipeline доходит до runtime interaction. Во втором файле pipeline останавливается на parsing stage.

Распространённая ошибка:

Ожидать частичного выполнения файла с syntax error.

Связь с Automation QA:

Это модель для диагностики тестового файла: syntax error блокирует весь файл до начала тестового сценария.

## Возможные улучшения

После выполнения практики можно:

* нарисовать собственную схему `source code → tokens → AST → execution`;
* сохранить пример syntax error и объяснение в личных заметках;
* сравнить syntax error и runtime error на двух отдельных файлах;
* использовать pipeline как checklist при разборе падений тестов.
