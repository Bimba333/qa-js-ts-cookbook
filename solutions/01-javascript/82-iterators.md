# Решения: Iterators

## Концептуальные вопросы

### 1. Что возвращает метод `next()`?

Ответ: объект с полями `value` и `done`.

Объяснение: `value` содержит текущее значение, а `done` показывает, завершен ли обход.

Типичная ошибка: ожидать, что `next()` вернет само значение напрямую.

Связь с Automation QA: iterator позволяет выдавать тест-кейсы по одному.

### 2. Для чего нужен `done`?

Ответ: чтобы показать, закончилась ли итерация.

Объяснение: `done: true` означает, что новых значений больше нет.

Типичная ошибка: продолжать читать `value` после завершения.

Связь с Automation QA: раннер должен понимать, когда список тестов закончился.

### 3. Что находится в `value`?

Ответ: текущее значение итерации.

Объяснение: пока `done: false`, `value` содержит очередной элемент.

Типичная ошибка: считать `value` надежным после `done: true`.

Связь с Automation QA: это может быть тест-кейс, лог или артефакт.

### 4. Чем iterator отличается от iterable?

Ответ: iterable умеет начать обход, iterator выдает значения.

Объяснение: iterable дает iterator через `Symbol.iterator`.

Типичная ошибка: смешивать эти роли.

Связь с Automation QA: тестовый набор может быть iterable, а процесс выдачи тестов выполняет iterator.

### 5. Почему `for...of` может остановить обход?

Ответ: потому что iterator возвращает `done: true`.

Объяснение: это сигнал, что значений больше нет.

Типичная ошибка: думать, что цикл заранее знает длину любой коллекции.

Связь с Automation QA: обход может завершиться без знания внутренней структуры коллекции.

## Чтение кода

Ответ:

```text
{ value: 'login', done: false }
{ value: 'checkout', done: false }
{ value: undefined, done: true }
```

Объяснение: первые два вызова возвращают элементы, третий сообщает о завершении.

Типичная ошибка: ожидать ошибку на третьем `next()`.

Связь с Automation QA: завершение списка тестов — нормальное состояние, а не сбой.

## Предскажите результат выполнения

Ответ:

```text
false
true
```

Объяснение: первый вызов получает `logs`, второй завершает итерацию.

Типичная ошибка: ожидать `false` два раза.

Связь с Automation QA: один артефакт выдается один раз.

## Отладка

Ответ: второй вызов `next()` возвращает `done: true`, а `value` становится `undefined`.

Объяснение: у `undefined` нельзя вызвать `toUpperCase()`.

Типичная ошибка: не проверять `done` перед использованием `value`.

Связь с Automation QA: обработчик отчетных записей не должен читать несуществующий элемент.

## Задание Automation QA

Ответ:

```javascript
const testCases = ['login', 'checkout'];
const iterator = testCases[Symbol.iterator]();

console.log(iterator.next());
console.log(iterator.next());
console.log(iterator.next());
```

Объяснение: iterator вручную показывает тот же процесс, который обычно скрыт внутри `for...of`.

Типичная ошибка: создать iterator, но ожидать, что он сам начнет обход.

Связь с Automation QA: это модель последовательной выдачи тестов раннеру.

## Мини-проект

Ответ:

```javascript
function runIterator(iterator) {
  let result = iterator.next();

  while (!result.done) {
    console.log(result.value);
    result = iterator.next();
  }
}

runIterator(['logs', 'screenshot'][Symbol.iterator]());
```

Объяснение: функция использует `done` как условие остановки.

Типичная ошибка: вызывать `next()` дважды за одну итерацию и пропускать значения.

Связь с Automation QA: такой механизм похож на обработку очереди артефактов.
