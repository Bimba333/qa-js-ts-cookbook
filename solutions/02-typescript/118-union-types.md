# Решения: Union Types

## Концептуальные вопросы

### 1. Что описывает union type?

Ответ: несколько допустимых вариантов значения.

Объяснение: значение может соответствовать одному из перечисленных типов.

Типичная ошибка: думать, что нужны все варианты одновременно.

Связь с Automation QA: статус может быть passed или failed.

### 2. Почему union не является массивом типов?

Ответ: union описывает одно значение, а не коллекцию.

Объяснение: `A | B` означает "A или B".

Типичная ошибка: воспринимать union как список элементов во время выполнения.

Связь с Automation QA: результат проверки имеет один текущий статус.

### 3. Почему union не создает значение во время выполнения?

Ответ: это TypeScript-тип, который исчезает после компиляции.

Объяснение: JavaScript не получает объект union.

Типичная ошибка: искать union во время выполнения.

Связь с Automation QA: внешний ответ все равно нужно проверять.

### 4. Чем `string | undefined` отличается от optional property?

Ответ: union описывает значение, optional property описывает возможность отсутствия свойства.

Объяснение: эти идеи связаны, но применяются в разных местах.

Типичная ошибка: считать их полностью одинаковыми.

Связь с Automation QA: поле ответа может отсутствовать, а переменная может быть `undefined`.

### 5. Где union types полезны в QA-коде?

Ответ: в статусах, состояниях результата и вариантах API-ответа.

Объяснение: такие данные часто имеют несколько разрешенных форм.

Типичная ошибка: использовать общий `string` вместо ограниченного набора.

Связь с Automation QA: helper не должен возвращать случайный статус.

Объяснение: `'skipped'` не входит в union.

Типичная ошибка: считать любую строку допустимой.

Связь с Automation QA: набор статусов должен быть согласован.

## Задание на отладку

Ответ:

```typescript
type Id = string | number;

const id: Id = 'T-1';
```

Объяснение: `Id` разрешает строку или число, но не boolean.

Типичная ошибка: добавлять значение не из union.

Связь с Automation QA: идентификатор может прийти в разных форматах.

## Задание Automation QA

Ответ:

```typescript
type CheckResult = 'passed' | 'failed';
```

Объяснение: union ограничивает результат двумя статусами.

Типичная ошибка: использовать `string`.

Связь с Automation QA: проверка возвращает один из известных статусов.

## Мини-проект

Ответ:

```typescript
type ApiResult =
  | { status: 'success'; statusCode: number }
  | { status: 'error'; message: string };

const result: ApiResult = {
  status: 'success',
  statusCode: 200,
};

console.log(result);
```

Объяснение: общий `status` отличает один вариант от другого.

Типичная ошибка: смешать поля success и error без ясного статуса.

Связь с Automation QA: API helper может вернуть успешный или ошибочный результат.
