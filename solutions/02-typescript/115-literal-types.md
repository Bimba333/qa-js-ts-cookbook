# Решения: Literal Types

## Концептуальные вопросы

### 1. Чем `string` отличается от `'passed'`?

Ответ: `string` разрешает любую строку, а `'passed'` разрешает только конкретное значение.

Объяснение: литеральный тип уже обычного примитивного типа.

Типичная ошибка: считать `'passed'` просто примером строки, а не отдельным типом.

Связь с Automation QA: статус теста можно ограничить конкретным значением.

### 2. Почему литеральный тип работает только на этапе проверки?

Ответ: TypeScript-типы исчезают после компиляции.

Объяснение: во время выполнения остается обычное JavaScript-значение.

Типичная ошибка: ожидать защиту во время выполнения от неверной строки.

Связь с Automation QA: внешние API-данные все равно нужно проверять во время выполнения.

### 3. Где литеральные типы полезны в QA-коде?

Ответ: в статусах, окружениях и режимах запуска.

Объяснение: там часто есть небольшой набор точных значений.

Типичная ошибка: использовать свободный `string`, когда набор значений известен.

Связь с Automation QA: `staging` и `production` лучше описывать явно.

### 4. Почему литеральный тип не валидирует внешний JSON?

Ответ: TypeScript не проверяет данные, которые приходят во время выполнения.

Объяснение: типы помогают при написании кода, но не заменяют проверки во время выполнения.

Типичная ошибка: доверять ответу API только из-за TypeScript-типа.

Связь с Automation QA: assertions остаются обязательными.

### 5. Когда литеральный тип может быть слишком узким?

Ответ: когда допустимо много разных значений.

Объяснение: если можно передать любую строку, конкретный литеральный тип ограничит код без пользы.

Типичная ошибка: фиксировать значение там, где нужна гибкость.

Связь с Automation QA: название теста обычно должно быть `string`, а не один literal.

## Задание на отладку

Ответ:

```typescript
const retryCount: 3 = 3;
```

Объяснение: литеральный тип `3` разрешает только число `3`.

Типичная ошибка: путать `number` и конкретное число.

Связь с Automation QA: иногда фиксированное число retries является частью договора.

## Задание Automation QA

Ответ:

```typescript
const testStatus: 'passed' = 'passed';
```

Объяснение: переменная принимает только один конкретный статус.

Типичная ошибка: написать `string`, если нужен точный статус.

Связь с Automation QA: это защищает от случайных значений.

## Мини-проект

Ответ:

```typescript
function printEnvironment(environment: 'staging'): void {
  console.log(environment);
}

printEnvironment('staging');
```

Объяснение: параметр принимает только значение `'staging'`.

Типичная ошибка: передать `'production'`.

Связь с Automation QA: helper может быть ограничен конкретным окружением.
