# Решения: as const

## Концептуальные вопросы

### 1. Что делает `as const` с литеральными типами?

Ответ: сохраняет максимально точные литеральные типы.

Объяснение: TypeScript не расширяет значение до общего `string` или `number`.

Типичная ошибка: думать, что `as const` меняет значение во время выполнения.

Связь с Automation QA: список окружений можно сохранить как точные значения.

### 2. Чем `const` отличается от `as const`?

Ответ: `const` относится к переменной, `as const` — к типу значения.

Объяснение: `const` запрещает переназначить переменную, а `as const` сохраняет точные типы внутри значения.

Типичная ошибка: ожидать от `const` readonly-свойства объекта.

Связь с Automation QA: объект конфигурации может требовать `as const`.

### 3. Почему `as const` не является заморозкой во время выполнения?

Ответ: это подсказка TypeScript, а не JavaScript-вызов.

Объяснение: `as const` исчезает после компиляции.

Типичная ошибка: считать его аналогом `Object.freeze`.

Связь с Automation QA: защита во время выполнения требует отдельного механизма.

### 4. Что происходит с объектными свойствами после `as const`?

Ответ: TypeScript видит их как readonly.

Объяснение: переназначение свойства станет ошибкой проверки.

Типичная ошибка: пытаться менять такие свойства в коде.

Связь с Automation QA: стабильные настройки окружения лучше не менять случайно.

### 5. Где `as const` полезен в QA-проекте?

Ответ: в константах окружений, статусов и режимов запуска.

Объяснение: эти значения обычно фиксированы.

Типичная ошибка: применять `as const` к данным, которые должны меняться.

Связь с Automation QA: статусы отчетов часто являются стабильным набором.

## Задание на отладку

Ответ:

```typescript
const statuses = ['passed', 'failed'] as const;

console.log(statuses[0]);
```

Объяснение: readonly tuple нельзя изменять через `push`.

Типичная ошибка: обращаться с readonly tuple как с обычным массивом.

Связь с Automation QA: порядок статусов может быть стабильным.

## Мини-проект

Ответ:

```typescript
const defaultConfig = {
  environment: 'staging',
  retries: 2,
} as const;

console.log(defaultConfig.environment);
```

Объяснение: свойства получают точные readonly-типы.

Типичная ошибка: пытаться потом менять `defaultConfig.retries`.

Связь с Automation QA: default config обычно должен быть стабильным.
