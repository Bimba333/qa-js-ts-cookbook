# Решения: Index Signatures

## Концептуальные вопросы

### 1. Что описывает index signature?

Ответ: правило для ключей и значений объекта-словаря.

Объяснение: ключи могут быть заранее неизвестны, но значения должны иметь ожидаемый тип.

Типичная ошибка: использовать index signature для объекта с известными свойствами.

Связь с Automation QA: headers часто работают как словарь.

### 2. Когда index signature лучше обычного object type?

Ответ: когда набор ключей заранее неизвестен.

Объяснение: например, metadata может содержать разные ключи в разных сценариях.

Типичная ошибка: описывать динамический словарь множеством случайных optional-свойств.

Связь с Automation QA: request metadata часто расширяется.

### 3. Почему значения словаря должны иметь один тип?

Ответ: так TypeScript может проверять все обращения по одному правилу.

Объяснение: если значение header должно быть строкой, число нарушает договор.

Типичная ошибка: смешивать строки и числа без явной причины.

Связь с Automation QA: HTTP headers ожидают строковые значения.

### 4. Чем string index signature отличается от number index signature?

Ответ: первая описывает строковые ключи, вторая — числовой индекс.

Объяснение: выбор зависит от способа обращения к значениям.

Типичная ошибка: использовать number index signature для обычных текстовых ключей.

Связь с Automation QA: status code map может использовать числовой индекс.

### 5. Где index signatures полезны в QA-коде?

Ответ: в headers, metadata и словарях статусов.

Объяснение: там ключи могут быть заранее неизвестны или многочисленны.

Типичная ошибка: использовать `any` для всего словаря.

Связь с Automation QA: typed словарь защищает request builders.

## Чтение кода

Ответ: значения должны быть строками.

Объяснение: `{ [key: string]: string }` означает строковый ключ и строковое значение.

Типичная ошибка: положить число в значение header.

Связь с Automation QA: headers должны быть строковыми.

## Предскажите результат проверки

Ответ: код согласован.

Объяснение: числовые ключи указывают на строковые значения.

Типичная ошибка: думать, что числовой индекс запрещает строковые значения.

Связь с Automation QA: status code map может возвращать описание статуса.

## Задание на отладку

Ответ:

```typescript
const headers: { [key: string]: string } = {
  accept: 'application/json',
  retries: '2',
};
```

Объяснение: значение `retries` должно быть строкой.

Типичная ошибка: смешивать числовую настройку и строковый header.

Связь с Automation QA: request builder должен собирать headers в ожидаемой форме.

## Задание Automation QA

Ответ:

```typescript
const metadata: { [key: string]: string } = {
  suite: 'smoke',
  owner: 'qa',
};
```

Объяснение: ключи заранее неизвестны, но все значения строковые.

Типичная ошибка: использовать `any` вместо конкретного типа значений.

Связь с Automation QA: metadata остается гибкой, но проверяемой.

## Мини-проект

Ответ:

```typescript
function printHeaders(headers: { [key: string]: string }): void {
  for (const key in headers) {
    console.log(`${key}: ${headers[key]}`);
  }
}

printHeaders({ accept: 'application/json' });
```

Объяснение: функция принимает строковый словарь и выводит пары.

Типичная ошибка: ожидать известный фиксированный набор ключей.

Связь с Automation QA: helper может печатать любые headers.
