# Решения: Function Types

## Концептуальные вопросы

### 1. Что описывает тип параметра функции?

Ответ: какие значения можно передать в функцию.

Объяснение: TypeScript проверяет аргументы вызова по типам параметров.

Типичная ошибка: думать, что параметр проверяется во время выполнения.

Связь с Automation QA: helper не должен принимать статус неправильного типа.

### 2. Когда явный возвращаемый тип полезнее вывода типа?

Ответ: когда функция является публичным договором для других частей проекта.

Объяснение: явный возвращаемый тип делает ожидаемый результат видимым.

Типичная ошибка: ставить явный возвращаемый тип везде без пользы.

Связь с Automation QA: публичные helpers лучше описывать явно.

### 3. Что описывает function type expression?

Ответ: сигнатуру вызываемого значения.

Объяснение: `(value: string) => string` описывает функцию, которая принимает строку и возвращает строку.

Типичная ошибка: считать тип функции реализацией функции.

Связь с Automation QA: форматтеры и обработчики удобно описывать через тип функции.

### 4. Почему тип функции не создает функцию во время выполнения?

Ответ: это TypeScript-тип, который исчезает после компиляции.

Объяснение: реализацию нужно написать отдельно.

Типичная ошибка: ожидать функцию во время выполнения от type alias.

Связь с Automation QA: тип helper не заменяет сам helper.

### 5. Где типы функций полезны в QA helpers?

Ответ: в форматтерах, обработчиках, валидаторах результата и общих helper API.

Объяснение: такие функции часто передаются и переиспользуются.

Типичная ошибка: использовать `any` вместо точной сигнатуры.

Связь с Automation QA: типизированный helper проще безопасно менять.

## Задание на отладку

Ответ:

```typescript
function getRetryCount(): number {
  return 2;
}
```

Объяснение: функция с возвращаемым типом `number` должна возвращать число.

Типичная ошибка: вернуть строку, которая выглядит как число.

Связь с Automation QA: retry count используется как число в логике повторов.

## Задание Automation QA

Ответ:

```typescript
type StatusFormatter = (status: 'passed' | 'failed') => string;
```

Объяснение: тип функции описывает параметр и возвращаемое значение.

Типичная ошибка: написать `string` для статуса и потерять ограничение.

Связь с Automation QA: отчетные статусы должны быть ограничены.

## Мини-проект

Ответ:

```typescript
function formatReportStatus(status: 'passed' | 'failed'): string {
  return `report status: ${status}`;
}

console.log(formatReportStatus('passed'));
```

Объяснение: функция принимает только допустимый статус и возвращает строку.

Типичная ошибка: вернуть объект вместо строки.

Связь с Automation QA: такой formatter можно использовать в отчете.
