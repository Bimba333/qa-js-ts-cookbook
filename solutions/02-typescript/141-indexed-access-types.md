# Решения: Indexed Access Types

## Концептуальные вопросы

### Ответ

`Type[Key]` извлекает тип свойства из типа. Он не читает свойство во время выполнения. Тип элемента массива можно получить через `ArrayType[number]`.

### Объяснение

Это операция системы типов.

### Типичная ошибка

Считать `Type[Key]` обращением к объекту во время выполнения.

### Связь с Automation QA

Так можно переиспользовать тип `body`, `payload` или элемента списка.

## Чтение кода

### Ответ

`Body` получает тип:

```ts
{
  id: string;
  email: string;
}
```

### Объяснение

`ApiResponse["body"]` выбирает тип свойства `body`.

### Типичная ошибка

Копировать вложенный тип вручную.

### Связь с Automation QA

Response body можно связать с общим response contract.

## Предскажите результат проверки

### Ответ

TypeScript покажет ошибку, потому что ключ `"email"` отсутствует в `User`.

### Объяснение

Indexed access type требует допустимый ключ.

### Типичная ошибка

Думать, что несуществующий ключ даст `unknown`.

### Связь с Automation QA

Так типы ловят ошибочные поля API-моделей.

## Анализ типа

### Ответ

`ApiResponse["status" | "body"]` дает union типов свойств `status` и `body`.

### Объяснение

Union ключей превращается в union типов выбранных свойств.

### Типичная ошибка

Ожидать объект с двумя свойствами.

### Связь с Automation QA

Это полезно для обобщенных вспомогательных типов, но требует аккуратности.

## Задание на отладку

### Ответ

```ts
type Tests = Array<{
  title: string;
  status: "passed" | "failed";
}>;

type Test = Tests[number];
```

### Объяснение

`Tests` — массив, поэтому тип элемента извлекается через `number`.

### Типичная ошибка

Обращаться к свойству элемента прямо на типе массива.

### Связь с Automation QA

Так можно получить тип одного теста из suite model.

## Задание Automation QA

### Ответ

```ts
type CreateUserResponse = {
  status: 201;
  body: {
    id: string;
    email: string;
  };
};

type CreatedUser = CreateUserResponse["body"];
```

### Объяснение

Тип пользователя извлекается из response type.

### Типичная ошибка

Создать второй независимый тип пользователя и забыть его обновить.

### Связь с Automation QA

API response и test assertions используют один источник типа.

## Мини-проект

### Ответ

```ts
type Suite = {
  tests: Array<{
    title: string;
    status: "passed" | "failed";
  }>;
};

type SuiteTest = Suite["tests"][number];
```

### Объяснение

Сначала выбирается свойство `tests`, затем элемент массива.

### Типичная ошибка

Путать тип массива и тип элемента.

### Связь с Automation QA

Так удобно описывать элементы test report.
