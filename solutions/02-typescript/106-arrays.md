# Решения: Arrays

## Концептуальные вопросы

### 1. Как записать массив строк через `T[]`?

Ответ:

```typescript
const suites: string[] = ['smoke', 'regression'];
```

Объяснение: `string[]` означает массив строк.

Типичная ошибка: смешивать строки и числа в одном массиве без намерения.

Связь с Automation QA: названия suites удобно хранить как `string[]`.

### 2. Как записать массив чисел через `Array<T>`?

Ответ:

```typescript
const statusCodes: Array<number> = [200, 201, 204];
```

Объяснение: `Array<number>` означает массив чисел.

Типичная ошибка: считать `T[]` и `Array<T>` разными идеями.

Связь с Automation QA: status codes часто проверяются списком чисел.

### 3. Что проверяет TypeScript при добавлении элемента в массив?

Ответ: соответствие элемента типу массива.

Объяснение: в `number[]` нельзя безопасно добавить строку.

Типичная ошибка: ожидать, что TypeScript исправит значение.

Связь с Automation QA: коллекции тестовых данных должны оставаться однородными.

### 4. Для чего нужен `ReadonlyArray`?

Ответ: чтобы описать массив, который не должен изменяться через этот TypeScript-договор.

Объяснение: TypeScript запретит методы изменения на уровне проверки.

Типичная ошибка: считать `ReadonlyArray` runtime-заморозкой.

Связь с Automation QA: readonly список окружений защищает общую конфигурацию.

### 5. Почему `ReadonlyArray` не является runtime-заморозкой массива?

Ответ: TypeScript-типы исчезают после компиляции.

Объяснение: runtime остается JavaScript.

Типичная ошибка: ожидать защиты после компиляции.

Связь с Automation QA: TypeScript помогает при разработке, а runtime discipline все равно важна.

## Чтение кода

Ответ: ожидаются числа.

```typescript
const statusCodes: number[] = [200, 201, 204];
```

Объяснение: `number[]` описывает массив числовых элементов.

Типичная ошибка: добавить строку `'200'`.

Связь с Automation QA: HTTP status codes должны быть числами.

## Предскажите результат проверки

Ответ: код согласован.

```typescript
const suites: string[] = ['smoke', 'regression'];
suites.push('api');
```

Объяснение: добавляется строка в массив строк.

Типичная ошибка: считать любой `push` ошибкой.

Связь с Automation QA: список suites может пополняться строковыми названиями.

## Задание на отладку

Ответ:

```typescript
const retries: number[] = [1, 2, 3];
retries.push(4);
```

Объяснение: массив ожидает числа, поэтому строка `'4'` не подходит.

Типичная ошибка: смешивать строковое и числовое представление настройки.

Связь с Automation QA: retries должны оставаться числовыми.

## Задание Automation QA

Ответ:

```typescript
const environments: string[] = ['local', 'staging', 'production'];
const allowedStatusCodes: Array<number> = [200, 201, 204];
const suiteNames: ReadonlyArray<string> = ['smoke', 'regression'];
```

Объяснение: каждый массив описывает тип своих элементов.

Типичная ошибка: использовать один слишком общий массив для разных видов данных.

Связь с Automation QA: типизированные коллекции упрощают работу helpers и отчетов.

## Мини-проект

Ответ:

```typescript
function printSuites(suites: string[]): void {
  for (const suite of suites) {
    console.log(`suite: ${suite}`);
  }
}

printSuites(['smoke', 'api', 'regression']);
```

Объяснение: функция принимает массив строк и ничего не возвращает.

Типичная ошибка: принимать `any[]` вместо конкретного массива строк.

Связь с Automation QA: такой helper может печатать список suites перед запуском.
