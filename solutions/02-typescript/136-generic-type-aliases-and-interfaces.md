# Решения: Generic Type Aliases and Interfaces

## Концептуальные вопросы

### Ответ

Type alias может иметь параметр типа, чтобы описывать одну форму с разными внутренними типами. Обобщённый interface делает параметризуемым объектный контракт. Неиспользуемый параметр типа не создает связи и усложняет тип.

### Объяснение

Параметр типа должен участвовать в структуре типа.

### Типичная ошибка

Создать generic только ради внешнего вида.

### Связь с Automation QA

API responses часто имеют одинаковую оболочку и разный body.

## Чтение кода

### Ответ

`Data` определяет тип поля `body`.

### Объяснение

`ApiResponse<User>` и `ApiResponse<Order>` используют одну форму, но разный body.

### Типичная ошибка

Типизировать `body` как `unknown`, хотя тип уже известен.

### Связь с Automation QA

Так API client сохраняет тип ответа.

## Предскажите результат проверки

### Ответ

Да, TypeScript знает, что `result.data.id` имеет тип `string`.

### Объяснение

`Data` передан как `{ id: string }`.

### Типичная ошибка

Забыть передать аргумент типа.

### Связь с Automation QA

Test result может хранить строго типизированные данные.

## Анализ типа

### Ответ

`Value` нигде не используется, поэтому `Box<Value>` не сохраняет никакой связи.

### Объяснение

Неиспользуемый параметр типа не влияет на структуру типа.

### Типичная ошибка

Делать generic без причины.

### Связь с Automation QA

Слишком абстрактные типы усложняют поддержку.

## Задание на отладку

### Ответ

```ts
type Page<Item> = {
  items: Item[];
  total: number;
};
```

### Объяснение

`Item` определяет тип элементов страницы.

### Типичная ошибка

Типизировать `items` как `unknown[]`.

### Связь с Automation QA

Постраничные API responses часто имеют такую форму.

## Задание Automation QA

### Ответ

```ts
type ApiResponse<Data> = {
  status: number;
  body: Data;
};

type UserBody = {
  id: string;
  email: string;
};

type UserResponse = ApiResponse<UserBody>;
```

### Объяснение

Оболочка ответа переиспользуется для разных body.

### Типичная ошибка

Создавать отдельную оболочку для каждого endpoint.

### Связь с Automation QA

API clients становятся более согласованными.

## Мини-проект

### Ответ

```ts
interface TestDataBuilder<Data> {
  build(): Data;
}

const userBuilder: TestDataBuilder<{ id: string; role: string }> = {
  build() {
    return { id: "u-1", role: "admin" };
  },
};
```

### Объяснение

`Data` задает тип результата `build()`.

### Типичная ошибка

Возвращать объект, который не соответствует `Data`.

### Связь с Automation QA

Так можно типизировать builders для test data.
