# Решения: Type Alias

## Концептуальные вопросы

### 1. Что делает `type`?

Ответ: создает имя для типа.

Объяснение: type alias позволяет переиспользовать договор в разных местах.

Типичная ошибка: думать, что `type` создает runtime-значение.

Связь с Automation QA: повторяющиеся формы тестовых данных удобно называть.

### 2. Существует ли type alias в runtime?

Ответ: нет.

Объяснение: TypeScript удаляет типы при компиляции.

Типичная ошибка: пытаться обратиться к alias как к переменной.

Связь с Automation QA: alias помогает до запуска, но не валидирует runtime-данные.

### 3. Когда alias улучшает читаемость?

Ответ: когда тип повторяется или имя объясняет назначение данных.

Объяснение: `TestUser` читается лучше, чем длинная inline-форма в каждом месте.

Типичная ошибка: выносить слишком простые типы без пользы.

Связь с Automation QA: данные запроса и тестовые данные часто повторяются.

### 4. Почему плохое имя alias ухудшает код?

Ответ: оно скрывает смысл договора.

Объяснение: `Data` не объясняет, какие данные ожидаются.

Типичная ошибка: использовать слишком общие имена.

Связь с Automation QA: понятные имена типов помогают читать framework code.

### 5. Где type alias полезен в QA-проекте?

Ответ: в тестовых данных, данных API-запроса и конфигурации.

Объяснение: эти формы часто переиспользуются.

Типичная ошибка: копировать одинаковые inline-типы.

Связь с Automation QA: alias снижает риск расхождения договоров.

Связь с Automation QA: такой тип подходит для тестовых данных.

## Задание на отладку

Ответ:

```typescript
type TestUser = {
  email: string;
  active: boolean;
};

const user: TestUser = {
  email: 'qa@example.test',
  active: true,
};
```

Объяснение: `active` должен быть boolean, а не строкой.

Типичная ошибка: писать `'yes'` вместо `true`.

Связь с Automation QA: test user должен иметь предсказуемую форму.

## Задание Automation QA

Ответ:

```typescript
type ApiPayload = {
  endpoint: string;
  method: string;
  body: string;
};
```

Объяснение: alias дает имя форме данных API-запроса.

Типичная ошибка: использовать слишком общее имя вроде `Data`.

Связь с Automation QA: API helpers могут принимать один понятный договор.

## Мини-проект

Ответ:

```typescript
type TestRun = {
  id: string;
  suiteName: string;
  passed: boolean;
};

function printTestRun(run: TestRun): void {
  console.log(`${run.id}: ${run.suiteName}, passed=${run.passed}`);
}

printTestRun({ id: 'RUN-1', suiteName: 'smoke', passed: true });
```

Объяснение: функция принимает именованный договор `TestRun`.

Типичная ошибка: повторять форму прямо в каждом параметре.

Связь с Automation QA: test run metadata часто используется в нескольких helpers.
