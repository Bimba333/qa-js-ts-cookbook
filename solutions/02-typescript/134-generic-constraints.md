# Решения: Generic Constraints

## Концептуальные вопросы

### Ответ

`extends` в generic constraint задает требование к форме типа. Это не наследование во время выполнения. Constraint не проверяет внешние данные во время выполнения.

### Объяснение

TypeScript разрешает использовать только свойства, которые гарантированы constraint.

### Типичная ошибка

Считать constraint валидацией во время выполнения.

### Связь с Automation QA

Тестовые сущности можно ограничивать минимальными полями.

## Чтение кода

### Ответ

TypeScript разрешает `entity.id`, потому что `Entity` ограничен формой `{ id: string }`.

### Объяснение

Любой допустимый `Entity` обязан иметь строковый `id`.

### Типичная ошибка

Думать, что `Entity` становится ровно `{ id: string }`; дополнительные поля сохраняются.

### Связь с Automation QA

Так вспомогательная функция принимает разные сущности, но требует общий id.

## Предскажите результат проверки

### Ответ

TypeScript покажет ошибку: объект не содержит `id`.

### Объяснение

Аргумент не соответствует constraint.

### Типичная ошибка

Добавить assertion вместо исправления данных.

### Связь с Automation QA

Так компилятор ловит несогласованные test entities.

## Анализ типа

### Ответ

`object` гарантирует только то, что значение является объектом. Поле `id` оно не гарантирует.

### Объяснение

Нужен constraint `{ id: string }`.

### Типичная ошибка

Использовать слишком широкий constraint.

### Связь с Automation QA

Широкий constraint не защищает вспомогательные функции от неверных сущностей.

## Задание на отладку

### Ответ

```ts
function printLength<Value extends { length: number }>(value: Value): number {
  return value.length;
}
```

### Объяснение

Constraint гарантирует наличие `length`.

### Типичная ошибка

Использовать `any`, чтобы прочитать `length`.

### Связь с Automation QA

Так можно работать с коллекциями или строковыми labels.

## Задание Automation QA

### Ответ

```ts
function markEntity<Entity extends { id: string }>(entity: Entity) {
  return {
    entity,
    marker: `test-${entity.id}`,
  };
}
```

### Объяснение

Функция сохраняет тип `Entity` и требует `id`.

### Типичная ошибка

Возвращать только `{ id: string }` и терять дополнительные поля.

### Связь с Automation QA

Marker помогает связывать test data с отчетом.

## Мини-проект

### Ответ

```ts
function reportEntity<Entity extends { id: string; status: string }>(entity: Entity): string {
  return `${entity.id}: ${entity.status}`;
}
```

### Объяснение

Constraint требует два поля, которые реально используются.

### Типичная ошибка

Требовать больше полей, чем нужно функции.

### Связь с Automation QA

Отчет получает общий формат для разных test entities.
