# Решения: Function Overloads

## Концептуальные вопросы

### 1. Что описывают сигнатуры перегрузки?

Ответ: публичные варианты вызова функции.

Объяснение: вызывающий код видит сигнатуры перегрузки.

Типичная ошибка: считать сигнатуру реализации основным публичным договором.

Связь с Automation QA: helper можно вызвать разными корректными способами.

### 2. Почему сигнатура реализации не является отдельной функцией во время выполнения?

Ответ: в JavaScript остается одна реализация.

Объяснение: перегрузки существуют для проверки TypeScript.

Типичная ошибка: думать, что TypeScript создаст несколько функций.

Связь с Automation QA: helper должен сам обработать все варианты внутри одной реализации.

### 3. Когда union проще перегрузки?

Ответ: когда результат не зависит от конкретной формы входа.

Объяснение: если функция всегда возвращает один тип, union часто читабельнее.

Типичная ошибка: использовать перегрузку ради перегрузки.

Связь с Automation QA: простые formatter helpers часто достаточно описать union.

### 4. Почему реализация должна быть совместима со всеми сигнатурами перегрузки?

Ответ: она должна обработать каждый публично заявленный вызов.

Объяснение: иначе одна из сигнатур обещает поведение, которого реализация не поддерживает.

Типичная ошибка: сделать сигнатуру реализации слишком узкой.

Связь с Automation QA: helper API не должен обещать неподдерживаемый вызов.

### 5. Где перегрузки могут быть полезны в helper API?

Ответ: когда helper принимает разные формы входа с понятными публичными сигнатурами.

Объяснение: перегрузки документируют варианты вызова.

Типичная ошибка: использовать перегрузку для простого одного варианта.

Связь с Automation QA: поиск отчета по id или title может быть перегружен.

## Чтение кода

Ответ: допустимы вызовы с `number` и со `string`.

Объяснение: это две сигнатуры перегрузки. Вызов с `number` возвращает `TestById`, а вызов со `string` возвращает `TestByTitle`.

Типичная ошибка: думать, что можно передать boolean из-за сигнатуры реализации с union.

Связь с Automation QA: тест можно искать по id или title и сохранить точный тип результата.

## Предскажите результат проверки

Ответ: TypeScript покажет ошибку.

Объяснение: ни одна сигнатура перегрузки не принимает `boolean`.

Типичная ошибка: считать сигнатуру реализации публичной.

Связь с Automation QA: helper не должен принимать неподдерживаемый идентификатор.

## Анализ типа

Ответ: union проще, потому что функция всегда возвращает `string` независимо от входа.

Объяснение: перегрузка не добавляет новой связи между входом и выходом.

Типичная ошибка: усложнять API без пользы.

Связь с Automation QA: простой formatter лучше держать простым.

## Задание на отладку

Ответ:

```typescript
function normalize(value: string): string;
function normalize(value: number): number;
function normalize(value: string | number): string | number {
  return value;
}
```

Объяснение: реализация должна возвращать тип, совместимый с сигнатурами перегрузки.

Типичная ошибка: вернуть boolean, которого нет среди заявленных результатов.

Связь с Automation QA: helper должен выполнять публичный договор.

## Задание Automation QA

Ответ:

```typescript
type ConfigValue = 'baseUrl' | 'retries';

function readConfig(name: 'baseUrl'): string;
function readConfig(name: 'retries'): number;
function readConfig(name: ConfigValue): string | number {
  return name === 'baseUrl' ? 'https://service.local' : 2;
}
```

Объяснение: перегрузки связывают конкретный ключ настройки с конкретным типом результата.

Типичная ошибка: вернуть общий `string | number` для любого ключа без точных сигнатур перегрузки.

Связь с Automation QA: конфигурационные helpers должны возвращать ожидаемый тип значения.

## Мини-проект

Ответ:

```typescript
type ReportById = {
  source: 'id';
  id: number;
};

type ReportByTitle = {
  source: 'title';
  title: string;
};

function findReport(id: number): ReportById;
function findReport(title: string): ReportByTitle;
function findReport(value: number | string): ReportById | ReportByTitle {
  if (typeof value === 'number') {
    return { source: 'id', id: value };
  }

  return { source: 'title', title: value };
}

const byId = findReport(10);
const byTitle = findReport('smoke');

console.log(byId.id);
console.log(byTitle.title);
```

Объяснение: функция имеет две сигнатуры перегрузки и одну реализацию, а результат зависит от формы входа.

Типичная ошибка: создать две реализации с одинаковым именем.

Связь с Automation QA: отчет можно найти разными способами и получить точную форму результата.
