# Решения: Optional, Default and Rest Parameters

## Концептуальные вопросы

### 1. Что означает `?` у параметра функции?

Ответ: аргумент можно не передавать.

Объяснение: TypeScript учитывает возможность отсутствия значения.

Типичная ошибка: считать необязательный параметр обычным обязательным параметром.

Связь с Automation QA: prefix для имени теста может быть необязательным.

### 2. Когда срабатывает параметр со значением по умолчанию?

Ответ: когда аргумент не передан или явно передан `undefined`.

Объяснение: это поведение во время выполнения JavaScript.

Типичная ошибка: думать, что default value работает только при полном отсутствии аргумента.

Связь с Automation QA: retries могут иметь значение по умолчанию.

### 3. Что получает функция через rest-параметр?

Ответ: массив значений.

Объяснение: оставшиеся аргументы собираются в массив внутри функции.

Типичная ошибка: путать rest-параметр со spread при вызове.

Связь с Automation QA: список тегов удобно собрать через rest-параметр.

### 4. Почему обязательный параметр после необязательного параметра создает проблему?

Ответ: вызов становится неоднозначным.

Объяснение: если первый параметр можно пропустить, непонятно, как передать следующий обязательный параметр позиционно.

Типичная ошибка: ставить необязательный параметр перед обязательным.

Связь с Automation QA: helper API должен быть очевидным для вызывающего кода.

### 5. Чем rest-параметр отличается от spread при вызове?

Ответ: rest собирает аргументы в функции, spread распаковывает значения при вызове.

Объяснение: это противоположные направления работы с набором значений.

Типичная ошибка: называть любой `...` rest-параметр.

Связь с Automation QA: helper может принимать теги через rest, а вызывающий код может передать массив через spread.

Объяснение: `name` обязателен, `prefix` можно пропустить.

Типичная ошибка: пропустить обязательный `name`.

Связь с Automation QA: имя теста обязательно, prefix может быть дополнительным.

Объяснение: TypeScript выводит тип из значения по умолчанию `2`.

Типичная ошибка: считать параметр неявным `any`.

Связь с Automation QA: число повторов остается числом даже без явной аннотации.

## Задание на отладку

Ответ:

```typescript
function buildTitle(name: string, prefix?: string): string {
  return prefix ? `${prefix}: ${name}` : name;
}
```

Объяснение: обязательный параметр должен идти до необязательного параметра.

Типичная ошибка: ставить необязательный параметр первым.

Связь с Automation QA: helper проще вызывать, когда обязательные данные идут первыми.

## Задание Automation QA

Ответ:

```typescript
function testTitle(name: string, prefix?: string): string {
  return prefix ? `${prefix}: ${name}` : name;
}
```

Объяснение: `name` обязателен, `prefix` необязателен.

Типичная ошибка: сделать оба параметра optional.

Связь с Automation QA: тест без имени не имеет смысла.

## Мини-проект

Ответ:

```typescript
function buildTags(...tags: string[]): string[] {
  return tags;
}

console.log(buildTags('smoke', 'api'));
```

Объяснение: rest-параметр собирает все строковые теги в массив.

Типичная ошибка: указать `string` вместо `string[]`.

Связь с Automation QA: набор тегов часто передается как список строк.
