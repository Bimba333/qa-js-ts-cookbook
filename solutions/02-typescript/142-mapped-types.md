# Решения: Mapped Types

## Концептуальные вопросы

### Ответ

Mapped type строит новый тип, проходя по union ключей. Он не создает объект во время выполнения. `keyof` обычно дает список ключей, по которым mapped type проходит.

### Объяснение

Mapped type работает только во время проверки TypeScript.

### Типичная ошибка

Ждать преобразование данных во время выполнения.

### Связь с Automation QA

Так можно строить типы ошибок формы, drafts и readonly-моделей.

## Чтение кода

### Ответ

`LoginFlags` получает форму:

```ts
{
  email: boolean;
  password: boolean;
}
```

### Объяснение

Каждый ключ `LoginForm` получает значение типа `boolean`.

### Типичная ошибка

Думать, что значения формы сохранят исходные типы.

### Связь с Automation QA

Так удобно описывать состояние валидации полей.

## Предскажите результат проверки

### Ответ

TypeScript покажет ошибку: `id` должен быть `string`.

### Объяснение

`Copy<User>` сохраняет типы исходных свойств через `Type[Key]`.

### Типичная ошибка

Считать копию через mapped type ослаблением контракта.

### Связь с Automation QA

Копия типа должна сохранять строгую форму test data.

## Анализ типа

### Ответ

`[Key in keyof Type]` означает: для каждого ключа из `keyof Type` создай свойство в новом типе.

### Объяснение

`Key` — временное имя ключа внутри mapped type.

### Типичная ошибка

Использовать объектный тип вместо union ключей после `in`.

### Связь с Automation QA

Это основа для типизации форм и report maps.

## Задание на отладку

### Ответ

```ts
type Errors<Form> = {
  [Key in keyof Form]: string[];
};
```

### Объяснение

Mapped type должен проходить по union ключей.

### Типичная ошибка

Писать `[Key in Form]`, хотя `Form` сам является объектным типом.

### Связь с Automation QA

Так создается словарь ошибок для каждого поля формы.

## Задание Automation QA

### Ответ

```ts
type FieldErrors<Form> = {
  [Field in keyof Form]: string[];
};
```

### Объяснение

Каждое поле формы получает список сообщений.

### Типичная ошибка

Типизировать ошибки как обычный словарь со строковыми ключами и потерять конкретные поля формы.

### Связь с Automation QA

Ошибки формы остаются синхронизированы с моделью формы.

## Мини-проект

### Ответ

```ts
type ReadonlyCopy<Type> = {
  readonly [Key in keyof Type]: Type[Key];
};

type RequiredCopy<Type> = {
  [Key in keyof Type]-?: Type[Key];
};
```

### Объяснение

Первый тип добавляет `readonly`, второй убирает optional modifier.

### Типичная ошибка

Считать эти modifiers защитой во время выполнения.

### Связь с Automation QA

Так можно описывать неизменяемые config-модели и обязательные normalized-модели.
