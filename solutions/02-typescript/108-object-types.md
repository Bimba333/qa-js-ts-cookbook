# Решения: Object Types

## Концептуальные вопросы

### 1. Что описывает object type?

Ответ: форму объекта: имена свойств и типы их значений.

Объяснение: TypeScript проверяет, что объект соответствует этой форме.

Типичная ошибка: описывать объект слишком общим типом.

Связь с Automation QA: краткое описание ответа и тестовые данные должны иметь понятную форму.

### 2. Почему `object` слишком широкий тип для большинства задач?

Ответ: он не описывает конкретные свойства.

Объяснение: TypeScript знает, что это объект, но не знает, есть ли у него `statusCode` или `name`.

Типичная ошибка: использовать `object`, когда нужен договор свойств.

Связь с Automation QA: helper не сможет безопасно читать нужные поля.

### 3. Почему обязательное свойство нельзя пропустить?

Ответ: оно является частью формы, которую требует object type.

Объяснение: если object type требует `name`, объект без `name` не соответствует договору.

Типичная ошибка: пропускать обязательное свойство.

Связь с Automation QA: тестовые данные без обязательного поля могут сломать сценарий.

### 4. Почему object type не валидирует данные в runtime?

Ответ: типы исчезают после компиляции.

Объяснение: TypeScript проверяет исходный код, но не проверяет внешние данные во время выполнения.

Типичная ошибка: доверять API response только из-за TypeScript-типа.

Связь с Automation QA: runtime assertions все равно нужны.

### 5. Где object types полезны в QA-коде?

Ответ: в конфигурации, объектах ответа, тестовых данных и кратких отчетных объектах.

Объяснение: эти данные часто передаются между helpers.

Типичная ошибка: передавать неописанные объекты.

Связь с Automation QA: object types делают границы helpers понятнее.

## Задание на отладку

Ответ:

```typescript
const user: { id: number; name: string } = {
  id: 1,
  name: 'Anna',
};
```

Объяснение: `id` должен быть числом, а не строкой.

Типичная ошибка: считать строку `'1'` тем же самым, что число `1`.

Связь с Automation QA: идентификаторы и счетчики должны иметь предсказуемый тип.

## Задание Automation QA

Ответ:

```typescript
const response: { statusCode: number; statusText: string; durationMs: number } = {
  statusCode: 200,
  statusText: 'OK',
  durationMs: 120,
};
```

Объяснение: object type описывает все обязательные свойства response summary.

Типичная ошибка: не указать `durationMs`.

Связь с Automation QA: такие summaries полезны для отчетов.

## Мини-проект

Ответ:

```typescript
function printResponseSummary(
  response: { statusCode: number; statusText: string; durationMs: number },
): void {
  console.log(`${response.statusCode} ${response.statusText} (${response.durationMs}ms)`);
}

printResponseSummary({ statusCode: 200, statusText: 'OK', durationMs: 120 });
```

Объяснение: функция принимает объект строго описанной формы.

Типичная ошибка: передать объект без одного из обязательных свойств.

Связь с Automation QA: helper получает понятный договор входных данных.
