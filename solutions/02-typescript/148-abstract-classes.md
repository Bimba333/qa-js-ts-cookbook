# Решения: Abstract Classes

## Концептуальные вопросы

### Ответ

Абстрактный класс нельзя создавать напрямую, потому что он может содержать абстрактные члены без реализации. Конкретный наследник обязан реализовать эти члены. Абстрактный класс не валидирует данные во время выполнения.

### Объяснение

`abstract` — это проверка TypeScript. Она помогает описать базовый контракт и общую реализацию.

### Типичная ошибка

Использовать `abstract class` как валидатор во время выполнения.

### Связь с Automation QA

Абстрактный базовый класс подходит для общих моделей страниц или генераторов отчетов.

## Чтение кода

### Ответ

`UsersScreen` наследует метод `openUrl()` и реализует абстрактное свойство `route`. Так как свой конструктор не объявлен, используется стандартный конструктор наследника, который передает аргументы в `BaseScreen`.

### Объяснение

Базовый класс содержит готовую реализацию `openUrl()`, а наследник обязан указать route.

### Типичная ошибка

Забыть реализовать абстрактный член класса в конкретном наследнике.

### Связь с Automation QA

Так можно описать общую модель экранов приложения.

## Предскажите результат проверки

### Ответ

TypeScript покажет ошибку.

```ts
abstract class Writer {
  abstract write(value: string): string;
}

// Ошибка: abstract class нельзя создать напрямую.
const writer = new Writer();
```

### Объяснение

У `Writer` есть абстрактный метод без реализации.

### Типичная ошибка

Считать `abstract class` обычным классом.

### Связь с Automation QA

Базовый writer задает общий контракт, а конкретный writer реализует формат.

## Анализ типа

### Ответ

Конкретный наследник обязан реализовать абстрактные члены класса, потому что иначе экземпляр класса имел бы объявленный контракт без реального метода или свойства.

### Объяснение

TypeScript не разрешает создавать конкретный класс с незаполненными абстрактными членами.

### Типичная ошибка

Оставить наследника пустым и ожидать, что абстрактный метод появится автоматически.

### Связь с Automation QA

Каждая конкретная страница должна указать свой route.

## Задание на отладку

### Ответ

```ts
abstract class ReportWriter {
  abstract writeBody(items: string[]): string;
}

class JsonReportWriter extends ReportWriter {
  writeBody(items: string[]): string {
    return JSON.stringify(items);
  }
}
```

### Объяснение

Наследник реализует абстрактный метод `writeBody`.

### Типичная ошибка

Изменить сигнатуру метода в наследнике.

### Связь с Automation QA

Разные генераторы отчетов могут иметь общий контракт и разную реализацию.

## Задание Automation QA

### Ответ

```ts
abstract class BasePageModel {
  constructor(protected readonly baseUrl: string) {}

  abstract route: string;

  getUrl(): string {
    return `${this.baseUrl}${this.route}`;
  }
}

class DashboardPageModel extends BasePageModel {
  route = "/dashboard";
}
```

### Объяснение

Базовый класс хранит общую логику, конкретный класс задает конкретный route.

### Типичная ошибка

Делать `route` обычным свойством базового класса со случайным значением по умолчанию.

### Связь с Automation QA

Так можно моделировать URL страниц без подключения тестового фреймворка.

## Мини-проект

### Ответ

```ts
abstract class ResultFormatter {
  formatTitle(title: string): string {
    return `Result: ${title}`;
  }

  abstract formatItems(items: string[]): string;
}

class TextResultFormatter extends ResultFormatter {
  formatItems(items: string[]): string {
    return items.join("\n");
  }
}
```

### Объяснение

`formatTitle` реализован один раз, а `formatItems` зависит от конкретного формата.

### Типичная ошибка

Делать все методы абстрактными и терять пользу общей реализации.

### Связь с Automation QA

Так можно строить разные форматы отчета с общей логикой заголовка.
