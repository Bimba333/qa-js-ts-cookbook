# Решения: Async Function Types

## Концептуальные вопросы

### 1. Какой тип возвращает асинхронная функция?

Ответ: `Promise`.

Объяснение: асинхронная функция всегда возвращает Promise во время выполнения.

Типичная ошибка: считать, что асинхронная функция возвращает обычное значение напрямую.

Связь с Automation QA: подготовка окружения часто возвращает Promise.

### 2. Почему явный тип результата асинхронной функции записывается как `Promise<T>`?

Ответ: потому что `T` находится внутри Promise.

Объяснение: успешное значение появится позже, после выполнения асинхронной операции.

Типичная ошибка: написать `string` вместо `Promise<string>`.

Связь с Automation QA: API helper возвращает Promise с результатом.

### 3. Что происходит с обычным значением, возвращенным из асинхронной функции?

Ответ: оно превращается в fulfilled Promise.

Объяснение: это поведение во время выполнения JavaScript async-функций.

Типичная ошибка: вручную создавать лишний Promise без необходимости.

Связь с Automation QA: асинхронный setup helper может вернуть объект, но вызывающий код получит Promise.

### 4. Что происходит с ошибкой, выброшенной внутри асинхронной функции?

Ответ: она превращается в rejected Promise.

Объяснение: ошибку нужно обработать через `catch` или `try/catch` вокруг `await`.

Типичная ошибка: ожидать синхронный throw снаружи Promise.

Связь с Automation QA: ошибка setup должна быть обработана вызывающим кодом.

### 5. Обрабатывает ли TypeScript rejected Promise автоматически?

Ответ: нет.

Объяснение: TypeScript описывает типы, но не добавляет обработку ошибок.

Типичная ошибка: думать, что `Promise<T>` защищает от rejection.

Связь с Automation QA: тестовая инфраструктура должна сама обрабатывать сбои.

## Чтение кода

Объяснение: асинхронная функция всегда возвращает Promise, а успешное значение имеет тип `'passed'`.

Типичная ошибка: считать результатом саму строку.

Связь с Automation QA: статус может прийти асинхронно.

## Задание на отладку

Ответ:

```typescript
async function loadRetries(): Promise<number> {
  return 2;
}
```

Объяснение: `Promise<number>` требует, чтобы успешное значение было числом.

Типичная ошибка: вернуть строку `'2'`.

Связь с Automation QA: количество повторов должно быть числом.

## Задание Automation QA

Ответ:

```typescript
async function prepareEnvironment(): Promise<'ready'> {
  return 'ready';
}
```

Объяснение: асинхронная функция возвращает Promise со значением `'ready'`.

Типичная ошибка: указать возвращаемый тип `'ready'` без `Promise`.

Связь с Automation QA: подготовка окружения обычно асинхронна.

## Мини-проект

Ответ:

```typescript
type SetupResult = {
  status: 'ready';
  retries: number;
};

async function loadSetupResult(): Promise<SetupResult> {
  return {
    status: 'ready',
    retries: 2,
  };
}
```

Объяснение: функция возвращает Promise с объектом `SetupResult`.

Типичная ошибка: вернуть объект неправильной формы.

Связь с Automation QA: setup helper возвращает структурированный результат подготовки.
