# Решения: Compiler Options for Real Projects

## Концептуальные вопросы

### Ответ

`target` описывает уровень сгенерированного JavaScript. `module` описывает формат модулей в сгенерированном JavaScript. `lib` сообщает TypeScript, какие стандартные API доступны по типам, но не добавляет API во время выполнения.

### Объяснение

Параметры компилятора задают правила проекта для проверки и генерации.

### Типичная ошибка

Считать compiler option runtime-полифиллом.

### Связь с Automation QA

Единые параметры компилятора помогают всей команде проверять проект одинаково.

## Чтение кода

### Ответ

Фрагмент задает `target: "ES2022"`, формат модулей `ES2022` и режим проверки без генерации файлов через `noEmit`.

### Объяснение

Так TypeScript может использоваться как инструмент проверки без генерации файлов.

### Типичная ошибка

Думать, что `noEmit` отключает проверку.

### Связь с Automation QA

Это удобно для проверки типов перед запуском тестов.

## Предскажите результат проверки

### Ответ

TypeScript покажет ошибку: в объекте нет обязательного свойства `noEmit`.

### Объяснение

Модель типа требует оба свойства.

### Типичная ошибка

Считать частичный config полным объектом.

### Связь с Automation QA

Конфигурации должны быть полными, если от них зависит запуск проекта.

## Анализ типа

### Ответ

Строгие параметры ловят больше ошибок, но требуют явно описывать спорные места вместо обходов.

### Объяснение

Команда должна понимать, какую проблему решает каждая строгая опция.

### Типичная ошибка

Включить строгую опцию и затем массово обходить ошибки.

### Связь с Automation QA

Это особенно важно для test data и response models.

## Задание на отладку

### Ответ

```ts
type CompilerOptionsModel = {
  target: "ES2020" | "ES2022";
  module: "ES2020" | "ES2022";
  noEmit: boolean;
};

const options: CompilerOptionsModel = {
  target: "ES2022",
  module: "ES2022",
  noEmit: true,
};
```

### Объяснение

`module` должен соответствовать разрешенным literal values.

### Типичная ошибка

Подставлять строку из другого проекта без проверки модели.

### Связь с Automation QA

Явная модель не дает случайно смешивать несовместимые профили.

## Задание Automation QA

### Ответ

`noEmit` полезен, когда TypeScript используется для проверки типов, а запуск тестов выполняет другой инструмент. Тогда команда получает compile-time проверку без генерации лишних файлов.

### Объяснение

`noEmit` не отключает type checking.

### Типичная ошибка

Думать, что если файлы не генерируются, TypeScript ничего не делает.

### Связь с Automation QA

Это подходит для pre-check перед запуском тестового набора.

## Мини-проект

### Ответ

```ts
type ProjectCompilerProfile = {
  target: "ES2022";
  module: "ES2022";
  strict: boolean;
  noEmit: boolean;
  incremental: boolean;
};

const profile: ProjectCompilerProfile = {
  target: "ES2022",
  module: "ES2022",
  strict: true,
  noEmit: true,
  incremental: true,
};
```

### Объяснение

Профиль описывает правила проверки большого проекта.

### Типичная ошибка

Хранить такие решения только в голове команды.

### Связь с Automation QA

Явный профиль помогает согласовать проверки между локальной разработкой и командной работой.
