# Решения: void и never

## Концептуальные вопросы

### 1. Что означает `void` в типе функции?

Ответ: функция не возвращает полезное значение.

Объяснение: функция может выполнять действие, например логировать, но результат не используется.

Типичная ошибка: ждать возвращаемое значение от `void`-функции.

Связь с Automation QA: logging helpers часто имеют результат `void`.

### 2. Когда функция может иметь тип результата `never`?

Ответ: когда обычный результат невозможен.

Объяснение: например, функция всегда бросает ошибку.

Типичная ошибка: ставить `never` обычной функции.

Связь с Automation QA: failure helpers могут иметь тип `never`.

### 3. Почему `throw` связан с `never`?

Ответ: после `throw` функция не возвращает обычный результат.

Объяснение: выполнение прерывается ошибкой.

Типичная ошибка: считать ошибку обычным возвращаемым значением.

Связь с Automation QA: assertion failure останавливает текущий сценарий.

### 4. Чем намерение `void` отличается от значения `undefined`?

Ответ: `void` описывает отсутствие полезного результата функции, а `undefined` является значением JavaScript.

Объяснение: `void` говорит о договоре функции.

Типичная ошибка: использовать эти понятия как полные синонимы.

Связь с Automation QA: helper может ничего не возвращать, но это не значит, что его результат нужно анализировать.

### 5. Где `void` и `never` полезны в QA helpers?

Ответ: `void` полезен для logging, `never` — для helpers, которые бросают ошибку.

Объяснение: тип результата показывает поведение функции.

Типичная ошибка: не описывать результат функции-действия.

Связь с Automation QA: это делает поток выполнения понятнее.

## Чтение кода

Ответ: функции подходит `void`.

```typescript
function logStep(name: string): void {
  console.log(name);
}
```

Объяснение: функция выполняет действие и не возвращает полезный результат.

Типичная ошибка: пытаться использовать результат `logStep`.

Связь с Automation QA: step logging обычно является действием.

## Предскажите результат проверки

Ответ: проблема в том, что `writeLog` возвращает `void`, а код ожидает `string`.

```typescript
function writeLog(message: string): void {
  console.log(message);
}

const result: string = writeLog('started');
```

Объяснение: `void`-результат нельзя использовать как строку.

Типичная ошибка: считать, что `console.log` возвращает текст.

Связь с Automation QA: логирование не должно становиться источником данных для проверки.

## Задание на отладку

Ответ:

```typescript
function fail(message: string): never {
  throw new Error(message);
}
```

Объяснение: функция всегда бросает ошибку и не возвращает обычный результат.

Типичная ошибка: указывать `void`, когда функция всегда прерывает выполнение.

Связь с Automation QA: failure helper обычно завершает сценарий ошибкой.

## Задание Automation QA

Ответ:

```typescript
function logStep(stepName: string): void {
  console.log(`step: ${stepName}`);
}

function stopRun(reason: string): never {
  throw new Error(reason);
}
```

Объяснение: один helper выполняет действие, второй прерывает обычный поток выполнения.

Типичная ошибка: смешивать logging и failure в одной функции.

Связь с Automation QA: понятный поток выполнения упрощает отладку тестов.

## Мини-проект

Ответ:

```typescript
function missingConfig(name: string): never {
  throw new Error(`Missing config: ${name}`);
}

function requireConfigValue(name: string, value: string): string {
  if (value.length === 0) {
    missingConfig(name);
  }

  return value;
}

console.log(requireConfigValue('BASE_URL', 'https://api.example.test'));
```

Объяснение: `missingConfig` не возвращает обычный результат, а `requireConfigValue` возвращает строку только после проверки.

Типичная ошибка: возвращать пустую строку вместо явной ошибки конфигурации.

Связь с Automation QA: config helper должен рано показывать неверную настройку.
