# Решения: Default Generic Parameters

## Концептуальные вопросы

### Ответ

Параметр типа по умолчанию используется, когда аргумент типа не указан. Inference выводит тип из значения, а default применяется как запасной вариант. `unknown` безопаснее `any`, потому что требует проверки перед использованием.

### Объяснение

Default улучшает удобство API, но не должен отключать проверку.

### Типичная ошибка

Использовать `any` как default.

### Связь с Automation QA

Raw API responses лучше держать как `unknown`.

## Чтение кода

### Ответ

`body` получает тип `unknown`.

### Объяснение

`ApiResponse` использован без аргумента типа, поэтому применяется default `unknown`.

### Типичная ошибка

Ожидать, что TypeScript сам узнает форму внешних данных.

### Связь с Automation QA

Внешний ответ требует проверки перед использованием.

## Предскажите результат проверки

### Ответ

TypeScript покажет ошибку: `entity` должен содержать `id`.

### Объяснение

Default `{ id: string }` тоже обязан соблюдаться.

### Типичная ошибка

Думать, что default отменяет constraint.

### Связь с Automation QA

Даже удобный default должен сохранять строгий контракт.

## Анализ типа

### Ответ

Параметр типа по умолчанию существует только на этапе проверки TypeScript.

### Объяснение

После компиляции JavaScript не получает новых веток выполнения из-за default.

### Типичная ошибка

Считать generic defaults логикой времени выполнения.

### Связь с Automation QA

Поведение helper во время выполнения остается тем же.

## Задание на отладку

### Ответ

```ts
type ApiResponse<Data = unknown> = {
  body: Data;
};
```

### Объяснение

`unknown` сохраняет необходимость проверки перед использованием.

### Типичная ошибка

Оставить `any` и потерять проверку.

### Связь с Automation QA

Непроверенные внешние ответы безопаснее начинать с `unknown`.

## Задание Automation QA

### Ответ

```ts
type HelperResult<Data = unknown> = {
  ok: boolean;
  data: Data;
};
```

### Объяснение

Если `Data` не указан, результат остается безопасно неизвестным.

### Типичная ошибка

Использовать слишком широкий default.

### Связь с Automation QA

Так helper может описывать typed и raw результаты.

## Мини-проект

### Ответ

```ts
type EntityBox<Entity extends { id: string } = { id: string }> = {
  entity: Entity;
};

const defaultBox: EntityBox = {
  entity: { id: "base" },
};

const userBox: EntityBox<{ id: string; role: string }> = {
  entity: { id: "u-1", role: "admin" },
};
```

### Объяснение

Первый пример использует default, второй передает явный аргумент типа.

### Типичная ошибка

Передать аргумент типа, который не соответствует constraint.

### Связь с Automation QA

Так можно делать удобные generic wrappers для test entities.
