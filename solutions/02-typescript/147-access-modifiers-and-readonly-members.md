# Решения: Access Modifiers and readonly Members

## Концептуальные вопросы

### Ответ

`public` означает доступ снаружи и используется по умолчанию. `private` доступен только внутри класса. `protected` доступен внутри класса и его наследников. `readonly` запрещает переназначение свойства, но не замораживает вложенные объекты.

### Объяснение

Эти правила проверяются TypeScript до запуска.

### Типичная ошибка

Считать `readonly` аналогом глубокой заморозки во время выполнения.

### Связь с Automation QA

Модификаторы доступа помогают отделять публичные действия helper от внутренних деталей.

## Чтение кода

### Ответ

Снаружи доступны `addStep()` и `getCount()`. Поле `steps` недоступно напрямую, потому что оно `private`.

### Объяснение

`private` ограничивает доступ к члену класса на этапе проверки типов.

### Типичная ошибка

Пытаться читать или менять `logger.steps` снаружи.

### Связь с Automation QA

Так логгер может контролировать, как добавляются шаги.

## Предскажите результат проверки

### Ответ

TypeScript покажет ошибку.

```ts
class Config {
  constructor(public readonly baseUrl: string) {}
}

const config = new Config("https://app.test");

// Ошибка: readonly property нельзя переназначить.
config.baseUrl = "https://other.test";
```

### Объяснение

Параметр-свойство создает публичное readonly-свойство `baseUrl`.

### Типичная ошибка

Думать, что `readonly` запрещает только изменение внутри класса.

### Связь с Automation QA

Базовый URL окружения не должен случайно меняться после создания config object.

## Анализ типа

### Ответ

Конструктор создает `public readonly id` и `private status`.

### Объяснение

Модификаторы на параметрах конструктора превращают параметры в свойства экземпляра.

### Типичная ошибка

Считать параметр-свойство обычным параметром, который исчезает после конструктора.

### Связь с Automation QA

Так можно компактно создавать модели запусков тестов.

## Задание на отладку

### Ответ

```ts
class Logger {
  private steps: string[] = [];

  add(step: string): void {
    this.steps.push(step);
  }

  getSteps(): readonly string[] {
    return this.steps;
  }
}
```

### Объяснение

`steps` скрыт от прямого изменения. Публичный метод возвращает readonly-представление массива.

### Типичная ошибка

Оставить внутренний массив публичным.

### Связь с Automation QA

Логгер должен контролировать порядок и формат добавления шагов.

## Задание Automation QA

### Ответ

```ts
class LoginActions {
  constructor(private readonly baseUrl: string) {}

  getLoginUrl(): string {
    return `${this.baseUrl}/login`;
  }
}
```

### Объяснение

`baseUrl` создается через параметр-свойство и доступен только внутри класса.

### Типичная ошибка

Сделать `baseUrl` публичным и позволить тестам менять его напрямую.

### Связь с Automation QA

Так объект действий держит конфигурационную деталь внутри себя.

## Мини-проект

### Ответ

```ts
class RunState {
  constructor(
    public readonly id: string,
    private status: "created" | "finished",
  ) {}

  finish(): void {
    this.status = "finished";
  }

  getStatus(): "created" | "finished" {
    return this.status;
  }
}
```

### Объяснение

`id` нельзя переназначить, а `status` меняется только через метод класса.

### Типичная ошибка

Делать `status` публичным и терять контроль над состоянием.

### Связь с Automation QA

Так можно хранить состояние запуска тестов без случайных внешних изменений.
