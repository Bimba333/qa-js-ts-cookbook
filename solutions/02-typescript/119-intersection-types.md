# Решения: Intersection Types

## Концептуальные вопросы

### 1. Что описывает intersection type?

Ответ: объединение требований нескольких типов.

Объяснение: значение должно соответствовать всем частям сразу.

Типичная ошибка: считать intersection выбором между вариантами.

Связь с Automation QA: отчетная запись может иметь данные теста и метаданные.

### 2. Чем intersection отличается от union?

Ответ: union означает "или", intersection означает "и".

Объяснение: `A | B` требует один из вариантов, `A & B` требует оба набора свойств.

Типичная ошибка: использовать `&`, когда нужен выбор вариантов.

Связь с Automation QA: статус результата — union, добавка метаданных — intersection.

### 3. Почему intersection не объединяет объекты во время выполнения?

Ответ: это TypeScript-операция над типами.

Объяснение: она не вызывает JavaScript-код и не создает новый объект.

Типичная ошибка: ожидать поведение `Object.assign`.

Связь с Automation QA: данные нужно собрать во время выполнения отдельно.

### 4. Что должен иметь объект, если его тип `A & B`?

Ответ: все требования из `A` и все требования из `B`.

Объяснение: отсутствие свойства из любой части нарушает контракт.

Типичная ошибка: указать только свойства одной части.

Связь с Automation QA: отчет должен иметь и title, и duration.

### 5. Где intersection types полезны в QA-коде?

Ответ: в отчетных объектах, метаданных и комбинированных моделях.

Объяснение: общие части можно переиспользовать без копирования.

Типичная ошибка: создавать один большой повторяющийся тип.

Связь с Automation QA: метаданные часто добавляются к разным результатам.

Объяснение: `ReportEntry` объединяет требования `TestInfo` и `WithDuration`.

Связь с Automation QA: отчетная запись содержит название и длительность.

Объяснение: объект не содержит обязательное свойство `title`.

Типичная ошибка: думать, что достаточно одной части intersection.

Связь с Automation QA: неполная запись отчета ломает ожидания helper.

## Задание на отладку

Ответ:

```typescript
type WithOwner = { owner: string };
type WithSuite = { suite: string };

const metadata: WithOwner & WithSuite = {
  owner: 'qa',
  suite: 'smoke',
};
```

Объяснение: объект должен удовлетворять обоим типам.

Типичная ошибка: указать только `owner`.

Связь с Automation QA: метаданные должны быть полными.

## Задание Automation QA

Ответ:

```typescript
type TestInfo = {
  title: string;
};

type WithDuration = {
  durationMs: number;
};

type ReportEntry = TestInfo & WithDuration;
```

Объяснение: `ReportEntry` собирает оба требования.

Типичная ошибка: скопировать свойства вручную и получить дублирование.

Связь с Automation QA: отчетные модели проще поддерживать частями.

## Мини-проект

Ответ:

```typescript
type TestResult = {
  title: string;
  status: 'passed';
};

type Metadata = {
  owner: string;
  suite: string;
};

type ResultWithMetadata = TestResult & Metadata;

const result: ResultWithMetadata = {
  title: 'login',
  status: 'passed',
  owner: 'qa',
  suite: 'smoke',
};

console.log(result);
```

Объяснение: итоговый тип содержит свойства результата и метаданные.

Типичная ошибка: ожидать, что intersection сам создаст объект во время выполнения.

Связь с Automation QA: результат и метаданные часто объединяются в отчетах.
