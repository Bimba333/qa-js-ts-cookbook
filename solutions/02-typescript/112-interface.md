# Решения: Interface

## Концептуальные вопросы

### 1. Что описывает interface?

Ответ: объектный договор.

Объяснение: interface описывает свойства и методы, которые должен иметь объект.

Типичная ошибка: считать interface классом.

Связь с Automation QA: interface полезен для договоров logger или reporter.

### 2. Существует ли interface в runtime?

Ответ: нет.

Объяснение: interface используется TypeScript-компилятором и исчезает после компиляции.

Типичная ошибка: ожидать runtime-проверку interface.

Связь с Automation QA: внешние данные все равно нужно проверять отдельно.

### 3. Что такое method signature?

Ответ: описание имени метода, параметров и результата.

Объяснение: interface описывает, как метод должен выглядеть.

Типичная ошибка: писать реализацию вместо описания договора.

Связь с Automation QA: reporter может требовать метод `write`.

### 4. Как interface помогает описывать публичный договор?

Ответ: он показывает, что объект обязан предоставить снаружи.

Объяснение: внутреннее устройство объекта не важно, важна внешняя форма.

Типичная ошибка: включать в interface детали реализации.

Связь с Automation QA: helpers должны зависеть от публичного API.

### 5. Где interface полезен в QA-коде?

Ответ: для reporters, loggers, helpers и объектных договоров поведения.

Объяснение: interface хорошо описывает ожидания к объекту.

Типичная ошибка: оставлять такие договоры неявными.

Связь с Automation QA: это упрощает замену реализации.

## Чтение кода

Ответ: interface требует `name: string` и метод `write(message: string): void`.

Объяснение: объект должен иметь оба элемента.

Типичная ошибка: забыть метод `write`.

Связь с Automation QA: reporter должен уметь записывать сообщение.

## Предскажите результат проверки

Ответ: код согласован.

Объяснение: объект имеет метод `log` с ожидаемой сигнатурой.

Типичная ошибка: менять тип параметра метода.

Связь с Automation QA: договор logger выполнен.

## Задание на отладку

Ответ:

```typescript
interface Logger {
  log(message: string): void;
}

const logger: Logger = {
  log(message: string): void {
    console.log(message);
  },
};
```

Объяснение: interface требует метод `log`, а не свойство `name`.

Типичная ошибка: дать объекту похожее, но не совместимое свойство.

Связь с Automation QA: helper ожидает конкретный метод.

## Задание Automation QA

Ответ:

```typescript
interface Reporter {
  write(message: string): void;
}
```

Объяснение: interface описывает публичный метод reporter.

Типичная ошибка: добавлять в interface внутренние поля реализации.

Связь с Automation QA: разные reporters могут иметь один договор.

## Мини-проект

Ответ:

```typescript
interface StepLogger {
  log(message: string): void;
}

function runStep(logger: StepLogger): void {
  logger.log('open checkout page');
}

runStep(console);
```

Объяснение: функция зависит от договора `StepLogger`, а не от конкретной реализации.

Типичная ошибка: привязывать helper к одному конкретному объекту.

Связь с Automation QA: это упрощает замену logger.
