# Решения: Callback Types

## Концептуальные вопросы

### 1. Что описывает тип callback?

Ответ: сигнатуру функции, которую передают в другую функцию.

Объяснение: тип callback описывает параметры и результат callback.

Типичная ошибка: описывать callback через `Function`.

Связь с Automation QA: обработчики результатов должны принимать ожидаемые данные.

### 2. Почему callback не выполняется на этапе проверки?

Ответ: TypeScript проверяет типы, но не запускает код.

Объяснение: callback выполнится только во время выполнения, когда его вызовет JavaScript-код.

Типичная ошибка: ожидать от TypeScript выполнения callback.

Связь с Automation QA: логика обработчика проверяется типами, но запускается только в тестовом коде.

### 3. Что означает callback с возвращаемым типом `void`?

Ответ: вызывающий код не использует возвращенное значение.

Объяснение: переданная функция может вернуть значение, но вызывающий код его игнорирует.

Типичная ошибка: считать `void` строгим запретом на `return`.

Связь с Automation QA: log handler обычно просто выполняет действие.

### 4. Когда callback должен возвращать boolean?

Ответ: когда он используется как predicate.

Объяснение: boolean показывает, подходит ли значение условию.

Типичная ошибка: возвращать строку вместо boolean.

Связь с Automation QA: фильтр статусов должен отвечать true или false.

### 5. Где типы callback полезны в QA-коде?

Ответ: в обработчиках логов, фильтрах, обработчиках результата и retry callbacks.

Объяснение: такие функции передаются в helpers.

Типичная ошибка: использовать `any` для параметров callback.

Связь с Automation QA: точный договор callback снижает ошибки при расширении helpers.

## Задание на отладку

Ответ:

```typescript
type LogHandler = (message: string) => void;

function writeLog(handler: LogHandler): void {
  handler('setup complete');
}
```

Объяснение: `LogHandler` принимает строку, поэтому helper должен передать строку.

Типичная ошибка: вызвать callback с аргументом неправильного типа.

Связь с Automation QA: лог-сообщение должно быть текстом.

## Задание Automation QA

Ответ:

```typescript
type LogHandler = (message: string) => void;
```

Объяснение: вызывающий код передаст строку и проигнорирует результат.

Типичная ошибка: использовать `() => void`, если обработчику нужно сообщение.

Связь с Automation QA: log handler получает текст события.

## Мини-проект

Ответ:

```typescript
type ResultHandler = (message: string) => void;

function processResult(message: string, handler: ResultHandler): void {
  handler(message);
}

processResult('passed', (message) => {
  console.log(message);
});
```

Объяснение: функция принимает сообщение и вызывает callback с этим сообщением.

Типичная ошибка: вызвать callback без аргумента.

Связь с Automation QA: так можно подключать разные обработчики результата.
