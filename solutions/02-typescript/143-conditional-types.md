# Решения: Conditional Types

## Концептуальные вопросы

### Ответ

`T extends U ? X : Y` выбирает один из двух типов. Это не `if` во время выполнения. Для generic-параметра union обычно распределяется по вариантам union.

### Объяснение

В conditional type `extends` означает assignability.

### Типичная ошибка

Считать conditional type проверкой во время выполнения.

### Связь с Automation QA

Conditional types помогают строить вспомогательные типы, но не валидируют реальные ответы API.

## Чтение кода

### Ответ

`A` получает `true`, `B` получает `false`.

### Объяснение

`string` подходит под `string`, а `number` нет.

### Типичная ошибка

Путать результат на уровне типов с boolean-значением во время выполнения.

### Связь с Automation QA

Так можно выбирать метку типа для разных моделей результата.

## Предскажите результат проверки

### Ответ

`Result` получает тип `string`.

### Объяснение

Conditional type распределяется по union: `string` остается, `number` и `boolean` превращаются в `never`.

### Типичная ошибка

Ожидать `string | never | never` как отдельный видимый тип.

### Связь с Automation QA

Так можно фильтровать варианты union-статусов.

## Анализ типа

### Ответ

В conditional type `extends` проверяет, можно ли один тип назначить другому.

### Объяснение

Это не связано напрямую с наследованием классов.

### Типичная ошибка

Переносить модель class inheritance на conditional types.

### Связь с Automation QA

Структурные контракты проверяются по совместимости формы.

## Задание на отладку

### Ответ

```ts
type Message<Result> = Result extends { ok: true } ? "ok" : "fail";
```

### Объяснение

Условие должно сравнивать тип целиком с ожидаемой структурой.

### Типичная ошибка

Пытаться читать свойство у generic-типа без ограничения.

### Связь с Automation QA

Так можно выбирать тип сообщения по форме результата.

## Задание Automation QA

### Ответ

```ts
type AssertionLabel<Result> = Result extends { passed: true }
  ? "passed"
  : "failed";
```

### Объяснение

Если тип результата совместим с `{ passed: true }`, выбирается `"passed"`.

### Типичная ошибка

Ожидать проверку реального результата теста во время выполнения.

### Связь с Automation QA

Это type-level helper для моделей assertion result.

## Мини-проект

### Ответ

```ts
type ToArray<Value> = Value extends unknown ? Value[] : never;

type Result = ToArray<string | number>;
```

### Объяснение

Для union получается `string[] | number[]`.

### Типичная ошибка

Ожидать `(string | number)[]`.

### Связь с Automation QA

Так можно строить типы коллекций по вариантам статусов или payload.
