# Решения: Generic Functions

## Концептуальные вопросы

### Ответ

Обобщённая функция сохраняет связь между типами, а `any` отключает проверку. Параметр типа существует только во время проверки TypeScript. Один параметр типа связывает вход и выход, если используется в обоих местах.

### Объяснение

`function first<Item>(items: Item[]): Item | undefined` говорит: результат связан с типом элемента массива.

### Типичная ошибка

Использовать generic, но внутри функции обращаться к свойствам, которые не гарантированы.

### Связь с Automation QA

Так вспомогательные функции не теряют тип test data.

## Чтение кода

### Ответ

`value` получает тип `string | undefined`.

### Объяснение

TypeScript выводит `Item` как `string`, потому что массив содержит строки.

### Типичная ошибка

Ожидать просто `string`, хотя массив может быть пустым.

### Связь с Automation QA

Выбор первого результата тестов тоже должен учитывать пустую коллекцию.

## Предскажите результат проверки

### Ответ

Да, TypeScript будет знать `wrapped.value.role`.

### Объяснение

`Value` выводится из объекта `{ id: string; role: string }` и сохраняется в поле `value`.

### Типичная ошибка

Заменить `Value` на `unknown` и потерять форму объекта.

### Связь с Automation QA

Так можно добавлять metadata к тестовым данным без потери типа.

## Анализ типа

### Ответ

`any[]` стирает тип элемента, поэтому результат становится небезопасным.

### Объяснение

Generic сохраняет связь, `any` ее разрывает.

### Типичная ошибка

Использовать `any`, чтобы быстро убрать ошибку компилятора.

### Связь с Automation QA

Во вспомогательных функциях для test data это приводит к поздним ошибкам.

## Задание на отладку

### Ответ

```ts
function createData<Data>(data: Data): Data {
  return data;
}
```

### Объяснение

`Data` связывает тип аргумента и результата.

### Типичная ошибка

Оставить `any` в результате функции.

### Связь с Automation QA

Helper возвращает данные того же типа, который получил.

## Задание Automation QA

### Ответ

```ts
function withMeta<Value>(value: Value) {
  return {
    value,
    createdAt: new Date().toISOString(),
  };
}
```

### Объяснение

Тип `Value` сохраняется в поле `value`.

### Типичная ошибка

Типизировать `value` как `unknown` без необходимости.

### Связь с Automation QA

Так можно добавлять служебную информацию к test data.

## Мини-проект

### Ответ

```ts
function pair<Expected, Actual>(expected: Expected, actual: Actual) {
  return { expected, actual };
}

const comparison = pair(200, "200");
```

### Объяснение

Два параметра типа сохраняют два независимых типа.

### Типичная ошибка

Использовать один параметр типа, если expected и actual могут быть разными.

### Связь с Automation QA

Это полезно для отчетов о сравнении expected и actual.
